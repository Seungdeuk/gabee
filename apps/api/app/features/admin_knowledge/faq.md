# 관리자 자주 묻는 질문

관리자 챗봇(Claude)에게 함께 주는 자료다. 규칙이 바뀌면 이 문서도 같이 고친다. 비밀값과 실제 id 는 쓰지 않는다.

## 관리자 계정은 어떻게 추가해?
서버 환경변수 ADMIN_USER_IDS 에 그 사람의 사용자 id 를 쉼표로 이어서 넣으면 됩니다. 실제 서버의 값은 운영 담당자가 바꿉니다.

## ADMIN_USER_IDS 는 어디에 넣어?
서버 환경변수에 넣습니다. 내 PC 에서는 apps/api/.env 파일에 넣고 서버를 다시 켜면 됩니다. 실제 id 는 코드, Git, 문서에 쓰지 않습니다.

## 관리자 목록이 비면 어떻게 돼?
아무도 관리자 화면에 들어올 수 없습니다. 안전을 위해 목록이 비어 있으면 모두 막습니다.

## 권한은 몇 종류야?
통합관리자 하나입니다. 목록에 있으면 서비스 관리와 운영 관리를 모두 볼 수 있습니다.

## 가족 owner 도 관리자야?
아닙니다. 가족의 owner 나 admin 이어도 ADMIN_USER_IDS 목록에 없으면 관리자 화면에 들어올 수 없습니다.

## 로컬에서 관리자 화면 여는 방법은?
서버를 켜고 브라우저에서 http://127.0.0.1:8000/admin/service/ui/ 를 엽니다. 내 사용자 id 가 .env 의 ADMIN_USER_IDS 에 있어야 로그인됩니다.

## 활성 사용자는 어떤 기준으로 세?
로그인하거나 앱이 자동으로 로그인을 연장해서 토큰을 받은 사람을 셉니다. 사용자 › 회원 카드의 숫자는 최근 7일 기준입니다.

## 계정 상태 카드는 무슨 뜻이야?
회원 계정을 정지하는 기능이 들어갈 자리입니다. 지금은 준비 중이라 정지 기능을 쓸 수 없습니다.

## 재방문 코호트 표는 어떻게 읽어?
같은 주에 가입한 사람들을 한 줄로 묶어서, 가입 1주, 2주, 4주 뒤에 다시 로그인한 비율을 보여 줍니다. 비율이 높을수록 사람들이 계속 쓰고 있다는 뜻입니다.

## 데이터는 주 단위로만 볼 수 있어?
아니요. 일 단위로도 볼 수 있습니다. 사용자 › 회원의 카드를 누르면 최근 30일 일별 그래프가 나오고, 기능·AI › AI 에는 최근 14일 일별 요청 수가 있습니다. 이용 분석 › 재방문·사용 시간의 재방문 코호트 표만 가입한 주 단위로 묶어서 보여 줍니다.

## 가입자가 30명 안 되면 왜 경고가 떠?
사람 수가 적으면 한두 명 때문에 비율이 크게 흔들립니다. 그래서 숫자는 흐름만 보라고 안내합니다.

## 지난 날짜 숫자가 왜 나중에 바뀌어?
지워진 로그인 기록이나 가족을 떠난 기록은 남지 않습니다. 그래서 지난 날짜 숫자는 지금 남아 있는 기록으로 다시 계산됩니다.

## 이메일 인증 안 해도 가족에 들어갈 수 있어?
네, 들어갈 수 있습니다. 기본 설정에서는 이메일이 선택이고, 인증하지 않아도 가족을 만들거나 참여할 수 있습니다.

## 참가 요청은 누가 승인해?
가족의 owner 나 admin 이 승인합니다. 승인된 사람은 일반 구성원(member)으로 들어옵니다. 가족의 초대 자동 승인이 켜져 있으면 승인 없이 바로 들어옵니다.

## AI 하루 한도는 몇 번이야?
기본값으로 AI 비서는 한 사람당 하루 10번, 가족당 하루 30번입니다. 일정 에이전트는 사람당 30번, 가족당 100번이고, 정산·채팅 에이전트는 사람당 60번, 가족당 200번입니다. 서버 설정으로 바꿀 수 있습니다.

## AI 한도를 늘리려면 어디를 바꿔?
서버 환경변수 AI_MAX_CALLS_PER_USER_PER_DAY 와 AI_MAX_CALLS_PER_GROUP_PER_DAY 를 바꿉니다. 호출이 늘면 비용도 늘어납니다.

## 답변 없이 완료로 바꿀 수 있어?
아니요. 답변을 저장해야 답변 완료가 됩니다. 답변 없이 완료로 바꾸려 하면 서버가 거절합니다.

## 답변을 고치면 사용자에게 알림이 또 가?
네. 답변 내용이 바뀌면 사용자에게 알림이 한 번 더 갑니다. 같은 내용을 다시 저장하면 알림이 가지 않습니다.

## 공지 올리면 사용자에게 알림이 가?
아니요. 지금은 알림을 보내지 않습니다. 저장하면 바로 앱의 더보기 › 공지사항에 보입니다.

## 공지가 앱 어디에 보여?
앱의 더보기 › 공지사항에 보입니다. 전체, 업데이트, 안내, 점검 칩으로 나눠서 볼 수 있습니다.

## 지운 공지를 되살릴 수 있어?
아니요. 지운 공지는 되돌릴 수 없습니다. 다시 올리려면 새로 써야 합니다.

## 공지 종류는 어떻게 골라?
새 기능이나 바뀐 점은 업데이트, 일반 소식은 안내, 서버 점검은 점검을 고릅니다.

## 새 글 표시는 어떻게 사라져?
사용자가 공지를 열어 보면 사라집니다. 읽은 기록은 그 폰에만 저장되어서, 앱을 지우거나 폰을 바꾸면 다시 새 글로 보입니다.

## 서버 상태가 오류면 무슨 뜻이야?
요청이 20건 이상일 때 5xx 비율이 5% 이상이면 오류로 표시합니다. 서버 쪽 실패가 많다는 뜻이라 바로 확인해야 합니다.

## 상태 바가 주의면 무슨 뜻이야?
5xx 오류나 새 오류가 있거나 5xx 비율이 1% 이상이라는 뜻입니다. 아직 오류 단계는 아니지만 살펴봐야 합니다.

## 오류율이 몇 퍼센트면 오류 상태야?
5xx 비율이 5% 이상이면 오류 상태입니다. 단, 요청이 20건 이상일 때만 그렇게 봅니다. 1% 이상이면 주의입니다.

## 503 오류는 언제 나와?
서버가 잠시 일을 못 할 때 나옵니다. DB 에 연결되지 않거나, 새 표가 아직 준비되지 않았거나, 외부 AI 호출이 실패할 때입니다. 표가 없는 기능만 503 이 나고 다른 기능은 그대로 됩니다.

## 401 403 오류는 왜 따로 세?
로그인이 풀렸거나 권한이 없는 경우라서 서버 고장이 아니기 때문입니다. 그래서 인증 실패로 따로 셉니다.

## 인스턴스 카드가 미수집이면 고장이야?
아닙니다. OPS_INFRA_ENABLED 가 꺼져 있거나 Cloud Run 이 아닌 곳에서 돌고 있으면 미수집으로 보입니다.

## 오류가 갑자기 늘면 뭐부터 봐?
운영 › 서버 상태에서 지금 확인할 오류와 문제 경로 TOP5 를 봅니다. 방금 배포했다면 이전 리비전으로 트래픽을 되돌리는 것을 검토합니다.

## 배포 후 이상하면 어떻게 되돌려?
Cloud Run 에서 이전 리비전으로 트래픽을 되돌립니다. 배포 담당자에게 먼저 알립니다.

## 공용 DB에 직접 마이그레이션해도 돼?
아니요. 공용 DB 는 Pull Agent 로만 반영합니다. 개인 PC 에서 직접 alembic 을 돌리지 않습니다.

## Pull Agent 는 뭐야?
공용 DB 에 새 표 같은 변경을 안전하게 반영하는 배포 프로그램입니다.

## 로그인은 얼마나 유지돼?
Access 토큰은 15분이고, Refresh 토큰은 30일입니다. 앱을 쓸 때마다 30일이 다시 늘어납니다.

## 관리자도 사용자 채팅 내용을 볼 수 있어?
아니요. 관리자 화면은 가족 채팅, 문서, 가계의 내용을 보여 주지 않고 개수만 셉니다.
