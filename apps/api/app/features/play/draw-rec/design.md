# 이게 뭐게 가비 추천 설계 (v1, 2026-11-18)

상태: 설계 초안(사용자 승인 전). 코드는 아직 건드리지 않았다. 이 문서 안의 **[내 결정]** 은 사용자가 정한 것이 아니라 에이전트가 정한 것이므로 읽고 고쳐 주세요.

## 1. 무엇을 왜
가족 놀이터 "이게 뭐게"는 내는 사람이 그림판에 직접 그린 그림과 정답을 올리고 가족이 맞힌다. 그림을 못 그리면 문제를 내기 어렵다. 골든벨의 "가비 추천"처럼, **AI가 정답 단어와 선 그림을 같이 만들어 주고 가족은 마음에 들면 그대로, 아니면 고쳐서 내게** 한다.

## 2. 사용자가 정한 것
- 정답은 **띄어쓰기·합성어 없는 한 단어**(케이크, 딸기, 선물, 텐트, 꽃다발, 해바라기, 돈가스, 돼지, 바다). "딸기 케이크"는 케이크·딸기로 나누고 "흑돼지"는 돼지로, "협재" 같은 고유 지명은 쓰지 않는다.
- 가족의 일정·대화에서 **개인정보가 아닌 공개 단어(흔한 사물)만** 뽑고, 부족하면 **흔한 단어로 채운다**.
- 그림은 **미리 만들어 두지 않고 호출해서 만든다.** 한 번 열 때 **5개**, **동시 호출**, **생각(추론) 최소화**.
- **단어별 그림 재사용**: 한 번 그린 그림은 다음 날·다른 가족도 쓴다. 보관 **30일**, 단어당 최대 **3종**.
- 캐시는 **가족 단위로 오늘 자정까지**. 추천을 열 때 만들고 **먼저 준비(백그라운드)는 하지 않는다**(15~40초 정도를 "준비 중" 화면으로 기다린다).
- 5개 호출 비용(몇 센트)과 하루 한 번 수준은 괜찮다.
- 방식 A(Claude가 선 좌표를 직접 작성)로 간다. 이미지 생성 모델과 Quick, Draw! 데이터는 쓰지 않는다.

## 3. 목표 / 아닌 것
목표: 가족이 그림 솜씨 없이도 이게 뭐게를 쉽게 낸다. 소재에 우리 가족 이야기가 묻어난다. 개인정보가 AI로 나가지 않는다.
아닌 것: 이미지 생성 모델, 그림 미리 제작·보관, 일정·대화 원문을 AI에 보내는 방식, 먼저 준비하기, 탐정단 추천.
실패로 보는 경우: 단어가 합성어·이름·장소로 나옴, 정답 글자가 그림에 들어감, 알아볼 수 없는 그림이 그대로 노출됨.

## 4. 이미 있는 것(조사 결과)
- 서버 `app/features/play/quiz_rec.py`(골든벨 추천)가 같은 모양이다: `ai_guard.run(feature, cache_key, call, cache_until)` 로 한도·캐시, `GET /play/quiz/recommendations` 가 `{state, items}` 를 돌려주고 상태는 `ok·no_data·used_up·preparing·cooldown·failed·ai_off`, 이미 낸 문제는 30일 숨김.
- 앱 `playground/screens/DrawCreateScreen.js` 의 그림은 `strokes: [{color, pts:[{x,y}]}]`(그림판 칸에 맞춘 좌표)이고 보낼 때 SVG를 PNG로 바꿔 `POST /play/draws` 로 올린다. 추천 선을 이 상태에 그대로 채우면 사용자가 이어 그리거나 지울 수 있고 업로드 흐름은 그대로다. 골든벨 화면(`QuizCreateScreen.js`)에는 "가비 추천/직접 내기" 전환·`< n / N >`·"이 문제로 쓰기"가 이미 있다.
- 시험(2026-11-18, Haiku 5.5, 호출 15번): 같은 단어 10개 중 8개는 알아볼 만하고(바나나·코끼리는 약함), 그림은 평균 선 6개·점 51개·약 600자(300토큰)이지만 호출당 출력이 1,667토큰이라 **대부분이 생각에 쓰인 토큰**이다. 호출 15번에 입력 6.4천·출력 25천 토큰. 스크립트·결과는 `draw_spike/`(레포 밖).

## 5. 접근과 선택
1. AI가 일정·대화를 읽고 단어까지 고름 — 대화 원문이 AI로 나가고 단어 규칙 검사가 많아져 **채택 안 함**.
2. **정해 둔 "그릴 수 있는 공개 단어 목록"에서 서버가 단어를 뽑고, 그림만 AI가 호출로 그림 — 채택.** 개인정보가 AI로 안 나가고 규칙(한 단어·공개 단어)이 목록으로 보장된다.
3. 그림을 미리 만들어 레포에 보관 — 사용자가 호출 방식을 원해서 **채택 안 함**.

## 6. 설계
**단어 뽑기(서버, AI 없음)** [내 결정: 세부]
- 재료: 공동 일정(골든벨과 같은 `shared_events`, 지난 30일~앞으로 30일, 제목·장소·메모)과 가족 전체방 최근 14일 대화. 1:1·개인 AI 방은 읽지 않는다(골든벨과 같음).
- 목록: 약 150~300개의 한 단어 사물(케이크·딸기·선물·텐트·꽃다발·해바라기·돈가스·돼지·바다 …). 초안은 에이전트가 만들고 사용자가 검토한다. 목록 파일은 코드와 함께 둔다.
- 찾기: 재료 글자에서 목록 단어를 Kiwi 명사·부분 문자열로 찾는다(예: "흑돼지"→돼지, "딸기 케이크"→딸기·케이크). 목록 밖 단어(고유명사·이름·장소·합성어)는 버린다.
- 5개를 못 채우면 목록에서 흔한 단어로 채운다. 최근 30일에 가족이 이게 뭐게에서 낸 단어는 뺀다.
- 정답이 되는 말이 둘 이상이면(예: 케이크/케익) `alt_answers` 로 같이 준다 [내 결정].

**그림 만들기(AI)**
- 단어별로 "어린이가 손으로 삐뚤빼뚤 그린 단순한 낙서 느낌"의 선 좌표를 요청한다. 좌표는 0~255(정규화), 선 3~12개·선마다 점 2~30개, 글자·숫자·색칠 금지. 단어만 보내고 가족 정보는 보내지 않는다.
- 5개 동시 호출, 생각 최소화(모델이 지원하는 방법으로), 호출 하나에 단어 하나.
- 서버 검증: JSON 형식·선·점 개수·좌표 범위 0~255·빈 선 없음. 실패한 단어는 한 번 다시 시도하고 그래도 안 되면 그 카드만 뺀다(5개가 안 돼도 됨). 구조 검사만 하고 "알아볼 수 있는지"는 판단하지 않는다.

**재사용·캐시·한도**
- 단어별 그림 저장소(새 테이블 한 개, 단어·좌표·만든 시각): **사용자 결정(다)** — 30일 안의 그림이 있으면 **기본은 호출 없이 재사용**하고(저장된 것 중 하나를 고름), 단어마다 **일정 확률(처음 값 30%)로 새로 그려서** 3종까지 쌓는다. 이미 3종이면 새로 만들 때 가장 오래된 것을 대체한다 [내 결정]. 저장된 게 없으면 항상 새로 그린다. 확률 값은 구현 뒤 시간·비용을 보고 조절한다(구현자 몫).
- 같은 가족에게 같은 그림이 다시 나오지 않게 하는 건 따로 하지 않고, 최근 30일에 낸 단어를 빼는 규칙으로 갈음한다(같은 단어가 안 나오므로 같은 그림도 안 나옴).
- 가족 캐시: `ai_guard` 캐시 키를 하루 단위로, 오늘 자정까지.
- 한도: 별도 기능 이름으로 골든벨과 같은 구조(쿨다운·사용자 하루·가족 하루) [내 결정: 값은 골든벨 5초·3·5와 같게 시작].
- 단어를 5개 다 목록에서 가져오므로 재료 없음 상태(`no_data`)는 없다. 나머지 상태는 골든벨과 같다.
- **생성은 요청 한 번 안에서 끝낸다**(그림 5개를 동시에 호출해 다 받은 뒤 응답). 같은 가족의 다른 사람이 만드는 중에 열면 `preparing` 을 돌려준다(골든벨의 뜻과 같음: "다른 가족이 만드는 중"). 같은 호출이 두 번 나가지 않게 하는 잠금은 골든벨의 `ai_guard` 방식을 그대로 쓴다. 앱 요청 타임아웃과 Cloud Run 요청 타임아웃은 15~40초(+여유)에 맞게 구현 때 점검한다. [내 결정]
- **일부만 성공해도 성공**: 그림이 1장 이상이면 성공으로 보고 오늘 자정까지 캐시한다(골든벨의 "1~2개만 남아도 성공"과 같음). 0장이면 실패로 보고 캐시하지 않아 다음에 열 때 한도 안에서 다시 시도한다. 빠진 카드를 나중에 채우지는 않는다. 새로고침은 실패·준비 중일 때만 있고, 성공했을 때 "다시 추천" 버튼은 1차에 없다. 실패한 호출을 한도에 세는지는 `ai_guard` 의 기존 동작을 따른다. [내 결정]
- **정답 변형(`alt_answers`)** 은 `POST /play/draws` 가 이미 받고 채점에도 쓰이므로(`docs/features/play.md`) 이번 범위에서 서버·DB 변경은 없다. 추천 카드의 정답 변형을 "이 문제로 쓰기"가 비슷한 정답 칸에 채운다.

**서버 API** (`GET /play/draw/recommendations` [내 결정: 이름]): `{state, items:[{id, word, alt_answers, strokes, source:"schedule"|"chat"|"common"}]}` 형태. 모든 실패·한도는 200으로 상태로 돌려준다(골든벨과 같음).

**앱**: 이게 뭐게 만들기 화면에 "가비 추천 / 직접 그리기" 전환. 카드에 그림 미리보기·정답 단어(내는 사람에게만)·출처 알약·`< n / N >`·"이 문제로 쓰기"(그림판 `strokes` 에 좌표를 그림판 크기로 키워 채우고 정답 칸을 채움, 고칠 수 있음). 상태별 문구는 골든벨과 같은 말투. 서버 주소가 없으면 기존 시안.

## 7. 제약
- 서버 환경: 새 테이블 마이그레이션(expand)이 필요하고 공용 DB 반영은 DB 담당자. 브랜치는 최신 `release/1.3` 에서 시작하고 이름·커밋 메시지는 사용자가 정한다.
- 운영 서버는 Cloud Run이고 응답 뒤 CPU가 줄 수 있어 먼저 준비하기는 이 범위에서 뺀다.
- 목표 시간은 처음 열 때 15~40초(추정, 아직 재지 않음). 구현 후 실제로 재서 맞지 않으면 방법을 조정한다.

## 8. 위험
- 알아볼 수 없는 그림(시험에서 바나나·코끼리)이 노출될 수 있다. 1차는 구조 검사만 하고, "이 그림 별로예요" 신고나 비전 검증은 하지 않는다. 쌓인 그림 중 나쁜 것을 가려내는 방법은 사용 뒤에 정한다.
- 목록에 없는 소재는 반영되지 않는다(예: 일정에 "팝콘"이 있어도 목록에 없으면 안 나옴).

## 9. 구현자에게 맡기는 것
목록의 구체적 단어와 정답 변형, 부분 문자열 vs Kiwi 명사 판단 세부, 생각 최소화 방법, 저장소 컬럼·인덱스, 한도 값 조정, 앱 좌표 환산, 상태 문구, 테스트 구성(골든벨의 `test_quiz_rec` 처럼 가짜 LLM)과 폰 확인(Expo Go + USB `adb reverse`).

## 구현 중 바뀐 결정(2026-11-18, 사용자)
- 성공 기준을 "그림 1장 이상이면 성공·캐시"에서 바꿨다: 그림은 1개라도 저장·표시하고 5개가 모이면 그날 캐시, 모자라면 일부만(partial) 보여 주며 다시 불러오면 채운다.
- 한도는 추천 한 번 = 시도 1회, 사용자 하루 3회·가족 5회·쿨다운 5초(골든벨 추천과 따로).
- 화면: "이 그림으로 쓰기"는 카드 그림 자리가 그림판으로 바뀌어 그 자리에서 고치고, 직접 그리기 탭은 추천과 별개로 늘 빈 화면.
- 처음 열 때 시간 추정(15~40초)은 실측 6.5초로 대체.
