# 0012. 폰 푸시는 Expo 푸시 서비스(→ FCM)로 보내고, 소통 메시지 푸시는 암호화해서 알림함에 저장하지 않는다

- 날짜: 2026-11-05
- 상태: 1단계(알림함 사건 푸시) 구현 중. 소통 메시지 푸시는 2단계 설계에서 확정한다.
- 결정:
  - 서버가 Expo 푸시 API(`https://exp.host/--/api/v2/push/send`)로 발송하고, 안드로이드는 Expo 가 FCM 으로 넘긴다. FCM 서비스 키는 EAS 에 올리고 **서버에는 비밀 키를 두지 않는다**(Expo 계정에서 푸시 보안을 켠 경우에만 서버 환경변수 `PUSH_EXPO_ACCESS_TOKEN` 을 쓴다).
  - 푸시는 알림함을 **대체하지 않고 추가**한다. `notify()` 가 알림을 저장하고, **커밋이 끝난 뒤**(`after_commit`) 백그라운드로 발송한다. 롤백되면 나가지 않는다. 발송 실패·타임아웃은 원래 기능에 영향을 주지 않는다(재시도 없음).
  - 발송은 `PUSH_ENABLED`(기본 false)로 켠다. 병합해도 켜기 전에는 운영 동작이 그대로다.
  - 알림함 사건(가입·고객센터 답변·일정 같이해요 등)은 고정 제목만 푸시한다(본문 없음).
  - **소통(가족 채팅) 메시지 푸시는 알림함에 저장하지 않고 푸시만 보낸다**(`push_only`). 내용은 기기 공개키로 암호화한 데이터 전용 푸시로 보내 Expo·구글은 암호문만 보게 하고, 암호화하기 전에 민감정보 값(전화·이메일·주소·주민번호·카드·계좌·비밀번호)만 가린다. 이 부분의 상세와 필요한 암호 라이브러리(새 의존성)는 2단계 설계에서 승인받는다.
  - 사용자별 설정(`push_settings`: 켜기·끄기, 내용 표시 방식 `full`/`sender`/`hidden`(기본 full), 끈 분류, 방해금지 시간)과 기기 토큰(`push_tokens`)을 DB 에 둔다.
- 이유:
  - Expo Go 에서는 안드로이드 원격 푸시가 SDK 53 부터 안 되므로 development build 가 필요하다. Expo 푸시 서비스는 서버 코드가 가장 작고(HTTPS 호출 한 번), iOS 를 나중에 붙일 때도 같은 코드로 확장된다.
  - 푸시는 Expo 와 구글 서버를 거치므로 채팅 원문을 그대로 실으면 외부 사업자가 읽을 수 있다. 우리 서버는 채팅을 평문으로 가지고 있어서 서버 쪽 AI 기능(@가비 등)에는 영향이 없고, 푸시 구간만 암호화하면 외부 사업자를 막을 수 있다.
  - 소통 메시지 알림은 알림함 요구사항에서 제외되어 있다(알림함은 지난 사건 기록, 메시지는 채팅방에서 본다).
- 대안과 버린 이유:
  - FCM 직접 연동: 외부 서비스가 하나 적지만 서버가 구글 비밀 키를 관리해야 하고 플랫폼별 코드가 늘어난다.
  - 채팅 자체 종단 간 암호화(E2EE): 서버가 원문을 못 읽어 @가비·대화 분석 같은 서버 기능을 쓸 수 없고 그룹 키 관리가 크다. 별도 프로젝트로 미룬다.
- 감수하는 위험:
  - 데이터 전용 푸시는 앱이 꺼진 상태에서 코드가 실행되어야 해서 제조사 배터리 절약 기능에 막히면 알림이 늦거나 안 올 수 있다. iOS 는 별도 네이티브 확장이 필요해 범위 밖이다.
  - 민감정보 마스킹은 규칙 기반이라 놓치는 값이 있을 수 있다.
