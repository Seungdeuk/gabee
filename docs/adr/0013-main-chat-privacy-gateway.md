# 0013. 메인 AI 채팅을 가명화 게이트웨이에 연결한다

- 날짜: 2026-11-02
- 상태: **대체됨(2026-11-04)** — 메인 채팅의 가명화·입력 거절은 [0014](0014-upload-llm-ocr-masking.md) 에서 걷어냈다(채팅은 DB 에 저장되지 않고 외부 전송은 공지로 처리). 이전 상태: 적용됨(탭 에이전트 경로는 제외). 앞 결정: [0011](0011-main-chat-langgraph.md)

## 맥락

메인 AI 채팅은 질문·앞 대화·도구 결과(기록 검색, 탭 에이전트 답)를 가림 없이 외부 모델로 보냈다(`high_risk_guard` 가 주민번호·카드·계좌·비밀번호만 막음).
가족채팅 AI 와 일정 에이전트만 가명화 게이트웨이(`shared/privacy`)를 거쳤다. 업로드한 문서는 정규식으로만 가려지고, 라벨 없는 이름은 가려지지 않았다.

## 결정

- 메인 채팅 그래프(`rag_graph`)에 `mask`(질문·앞 대화 가리기)와 `restore`(모델이 쓴 최종 답 되돌리기) 노드를 둔다. 가명화 세션은 요청 하나 동안만 산다.
- 도구 결과는 `ChatPrivacy.to_model` 이 **모르는 글자 값은 모두 가린다**(구조 값 `item_id`·`ref`·`date`·`score`·`sensitive`·`has_unread_parts`·`can_answer` 만 글자·숫자 하나일 때 유지,
  저장 경로 `source_path` 는 뺌). 결과 전체를 한 번에 가명화해 NER 이 묶음으로 돈다. `page` 는 본문 `## 제목` 글이 들어오므로 가린다.
- 모델이 도구에 넘긴 인자는 서버가 되돌려 실행한다. 탭 에이전트(`ask_*`)에 넘기는 질문은 되돌린 뒤에도 이름표·일반화 문구가 남으면 그 호출을 거부한다.
- 최종 답은 `ASSISTANT` 정책으로 되돌린다(이름·주소만 복원, 전화·이메일은 "(연락처)"·"(이메일)"). 조사 보정은 이름표 바로 뒤에서만 한다(모델이 쓴 `하나은행` 이 깨지지 않게).
  복원하지 못한 이름표 변형은 "(알 수 없는 항목)" 으로 바꾼다. 직통 응답(탭 에이전트의 실제 글)은 되돌리지 않는다.
- 개인정보 계층이 실패하면 외부 모델을 부르지 않고 503 `privacy_unavailable` 로 끝낸다. `ai_guard.run` 은 호출 도중 난 공통 오류도 사용 기록을 닫고(`status=error`)
  호출 수는 오류가 알려 준 만큼만 센다(외부 호출 전이면 0).

## 하지 않은 것 / 남은 위험

- **탭 에이전트(가계·돌봄·가족채팅)가 자기 모델을 부르는 경로는 연결하지 않았다.** 메인이 되돌려 넘긴 질문(실제 이름)과 에이전트의 도구 결과·시스템 프롬프트(요청자 이름)가 그쪽 규칙 가리기만 거쳐 나간다.
  탭 에이전트 통합 단계에서 다룬다. `high_risk_guard` 는 그때까지 유지한다.
- 탐지기의 한계는 그대로다: 010 없는 번호, 한글 숫자 전화, 낯선 이름·별명, 건물 이름 주소, 층 뒤 호수 등(`tests/test_main_chat_privacy.py` 의 xfail 표).
- 시험은 NER 을 끈 채(규칙 + 가족 이름 사전) 돈다. 서버 기본 `PRIVACY_NER_MODE=auto` 는 모델이 없으면 조용히 규칙만 쓴다.
- 문서 속 전화·계좌 번호는 답에서 "(연락처)"·"(민감 정보)" 로 보인다(정책상 복원하지 않음). 제품 영향이라 필요하면 정책을 따로 결정한다.

## 결과

- 가짜 가족 5명·기록 28개 측정에서 모델 요청에 샌 값: 이름 0/9, 전화 0/10, 이메일 0/3, 계좌 0/3, 주소 1/5(`301호`).
- 보안 매트릭스의 알려진 결함 2건(문서 API 원문, 메인 채팅 문장)과 `test_high_risk_guard` 의 "알려진 한계" 시험이 고쳐져 일반 단언이 됐다.
