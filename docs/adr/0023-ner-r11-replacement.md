# 0023. 가명화 NER 모델을 S0에서 R11(B-new seed 21)로 교체한다 — 사전 등록 게이트 미달을 인정한 별도 위험 수용 결정

- 날짜: 2026-11-24
- 상태: **제안(서명 전).** 코드·이미지 준비까지만 이 결정에 속한다. 운영 반영은 아래 "운영 반영 조건"이 모두 충족되고 배포 담당자가 승인한 뒤에만 한다. 위험 수용 결정서(`docs/security/NER_R11_OPS_RISK_ACCEPTANCE.md`)는 서명 전이다.

## 결정

가족 대화 가명화의 PERSON NER 모델을 기존 S0(`koelectra-small-v2b`, ONNX 지문 `46210943c45f`)에서 R11 B-new seed 21(ONNX SHA256 `3831601b7ffb6093a8d1b8c832e46ad140712c6e402f17b3054c3ec0f9ae4c94`, 지문 `3831601b7ffb`)로 교체한다. 추가 학습·데이터 생성·후처리 실험은 하지 않는다. R12·R12b 는 채택하지 않았으므로 적용하지 않는다.

## 사전 등록 평가와의 관계 (바꾸지 않는다)

봉인 독립 합성 평가셋 2,350문장의 사전 등록 판정은 **`KEEP_S0`** 이다. R11 은 개선됐지만 P1~P3 교체 기준에 못 미쳤다.

| 지표 | S0 | R11 | 차이 | 사전 등록 기준 |
|---|---:|---:|---:|---|
| Exact Recall | 75.22% | 84.12% | +8.90%p | +10%p 이상 → FAIL(P1) |
| 전체 노출률 | 17.07% | 10.23% | −6.84%p | −8%p 이하 → FAIL(P2) |
| Exact F1 | 80.98% | 87.37% | +6.39%p | +8%p 이상 → FAIL(P3) |

이 결정은 그 판정을 합격으로 다시 읽는 것이 아니다. 확인된 개선과 남는 위험을 알고도 운영에서 쓰기로 한 별도의 위험 수용이다. 평가는 합성 데이터이고 사람 검수를 하지 않았으므로 운영의 실제 노출률로 읽지 않는다.

## 이유

- R11 이 S0 보다 PERSON 지표 전부(Precision·Recall·F1·전체/완전/부분 노출률)에서 낫다.
- 모델 구조·입출력(tokenizer, labels)은 S0 와 같아서 서비스 코드 변경 없이 폴더만 바꾼다.

## 바뀌는 것

- `apps/api/Dockerfile`: NER 모델 폴더를 `ner-koelectra-small-r11b-s21` 로, `PRIVACY_NER_MODEL_FILE=model.onnx`, `PRIVACY_NER_MODE=required`(모델을 못 쓰면 가명화 입구가 503 `privacy_unavailable`, 외부 LLM 호출 전에 막는 fail-closed)로 지정하고, 빌드 때 모델 4개 파일의 SHA256 이 확정값과 다르면 빌드를 실패시킨다.
- `apps/api/scripts/check_ner_deploy_mode.py`: 배포 전 설정 게이트(읽기 전용).
- 문서: 운영 전환 런북·확인표·위험 수용 결정서(`docs/security/NER_R11_OPS_*.md`).

바뀌지 않는 것: 가명화 규칙, PERSON/ADDRESS 정책, 고위험 탐지, 대응표 저장 정책, 요청 단위 복원, API 계약.

## 알려진 위험 (결정서 3절에 전체)

- 일반명사 형태 이름(D1P)은 노출률 약 40%로 S0 와 사실상 같다. 교체로 해결되지 않는다.
- `required` 라서 모델 로딩 실패가 곧 NER 연결 입구의 503(가족채팅 AI·일정 에이전트 등)이다. 롤백은 이전 리비전·이미지가 남아 있어야 가능하다.
- 메인 AI 채팅·문서 OCR·사진 판별 등 NER 가 적용되지 않는 경로는 이 교체로 보호되지 않는다.

## 운영 반영 조건 (모두 충족해야 함)

1. 운영 환경 재측정(S2b)과 운영 확인표(S4-1~S4-6) 완료. 특히 운영의 현재 `PRIVACY_NER_MODE`·S0 해시.
2. 위험 수용 결정서 서명.
3. 이전 리비전·이미지 보존과 롤백 확인.
4. 배포 담당자 승인.
