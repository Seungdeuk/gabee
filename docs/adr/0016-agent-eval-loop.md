# 0016. Agent 평가는 새 패키지(`evals/agent_eval`)에 단계별로 쌓고, 개선은 개발셋에서만 반복하며 보안 위반은 하드 게이트로 막는다

- 날짜: 2026-11-10
- 결정:
  - **새 패키지 `apps/api/evals/agent_eval/`** 에 사례 스키마·매처·채점기·지표·저장·실행기를 만든다. 기존 `evals/tab_agents`(52건)는 회귀용으로 두고, 어댑터로 새 채점기에 `legacy` 묶음으로 넣는다.
  - **도구 인자는 관찰 훅으로 읽는다.** `shared/llm/tool_graph.py` 에 평가할 때만 켜지는 콜백(ContextVar)을 넣어 실제 도구 호출 인자와 단계·토큰을 받는다. 일정 Agent 의 인자는 도구 호출이 아니라 구조화 출력(`schedule/agent/chat.py`)이라 같은 방식의 관찰 지점을 따로 둔다. 둘 다 꺼져 있으면 동작이 달라지지 않는다는 시험을 함께 둔다(E3).
  - **평가 수준을 세 개로 나눈다.** L0(가짜 LLM, pytest, 항상), L1(실제 LLM + 고정 도구 응답, 수동), L2(실제 LLM + 합성 DB의 실제 도구, 수동). 비용이 드는 L1·L2 는 CI 에 연결하지 않는다.
  - **데이터는 합성만.** 개발 30 / 최종 테스트 20 으로 나누고, 테스트셋은 해시를 고정해 베이스라인과 최종 평가에서만 연다. 개선안을 만드는 모델에는 개발셋 실패만 준다.
  - **개선 대상은 프롬프트·도구 설명뿐**이다. 평가 중에는 메모리에서만 덮어쓰고, 통과한 안은 사람이 검토한 뒤 별도 PR 로 반영한다.
  - **보안·권한 위반은 하드 게이트**다. 하나라도 있으면 성능과 관계없이 채택하지 않는다.
  - **비용 상한**: 실행 1회 2달러, 루프 1회 15달러, 프로젝트 40달러(토큰 상한과 함께 먼저 닿는 쪽에서 중단). 실제 호출 전에는 추정 비용을 보여 주고 사용자 승인을 받는다.
  - 실행 기록은 `results/<run id>/`(git 제외)에 저장하고, 궤적에서 이메일·전화 패턴을 지운다.
- 이유:
  - 기존 평가는 도구를 이름으로만 보고(인자는 채점하지 않음) 답 문장·제안 수를 채점한다. 보안 위반을 따로 세지 않고 @가비 방 경로·1:1·소통·일정 사례가 없다. 숫자로 "좋아졌다"를 말하려면 같은 기준으로 전후를 재야 한다.
  - 같은 사례로 프롬프트를 고치고 같은 사례로 재면 과적합을 성능 향상으로 착각한다. 그래서 테스트셋을 격리한다.
  - 가족 데이터가 오가는 기능이라 성능이 올라도 다른 가족·1:1 내용이 새면 안 된다. 보안을 점수와 섞지 않고 통과/실패 조건으로 둔다.
- 대안:
  - **`tab_agents` 확장**: 구조가 도구 이름 비교에 묶여 있고 audience·room 을 실을 수 없어 매처·궤적·비용 기록을 넣기에 무겁다. 어댑터로 재사용만 한다.
  - **외부 평가 서비스·라이브러리 도입**: 의존성을 임의로 추가하지 않는 규칙에 맞지 않고, 가족 데이터가 합성이어도 궤적을 밖으로 보내게 된다.
  - **로그 파싱으로 인자 읽기**: 모델 호출 본문을 로그에 남기는 것은 원문을 로그에 남기지 않는 원칙과 충돌한다(메인은 질문·도구 결과를 가리지 않고 보내고, 탭 에이전트는 가명화한다). 형식이 바뀌면 깨지기도 한다.
  - **반환값의 `tool_calls` 만 쓰기**: `AskResult`·`AgentReply` 에는 인자가 있어 직접 호출 평가에는 충분하다. 그러나 `POST /ai-assistant/chat` 응답에는 도구 호출이 없고 일정 Agent 는 `tool_graph` 를 거치지 않아서 끝 단위(L2) 측정과 단계·토큰 집계에는 부족하다. 직접 호출 경로에서는 반환값을 같이 쓴다.
- 결과:
  - 문서는 [요구사항](../requirements/agent-eval.md). 구현은 E2~E8 로 나눠 PR 마다 올린다.
  - 한계: 사례가 50건이라 신뢰구간이 넓다(그래서 구간을 함께 보고한다). 합성 사례라 실제 가족 대화 분포와 다르고, 평가는 `claude-haiku-5-5` 기준이다. 일정 Agent 는 구조화 출력(의도·날짜·제목 등)까지 평가하고, 그 뒤 코드의 검증·분기는 L2 의 결과로만 확인된다.
  - 테스트셋 파일은 저장소에 있어 개선 PR 을 쓰는 사람과 Claude 도 볼 수 있다. 격리는 루프의 LLM 과 실행기 안에서만 보장한다.
  - 토큰 상한 수치는 모델 단가를 확인해 E2 에서, 루프 게이트 임계값은 베이스라인을 본 뒤 정한다(요구사항 문서의 `미정`).
