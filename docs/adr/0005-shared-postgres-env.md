# 0005. 팀 공용 PostgreSQL 개발 DB를 구축한다 (기존 MVP DB와 같은 서버, 다른 database)

- 날짜: 2026-10-22
- 결정: 기존 MVP(`family-secretary`) 때부터 쓰던 공용 DB용 PC(`192.168.0.44`)에, GaBee 2.0 전용 PostgreSQL 16.15 `gabee` database를 새로 만들고 `pgvector` 0.8.7 확장을 켰다. 접속 계정을 역할별로 둘로 나눴다 — 스키마 변경(DDL) 전용 `gabee_migrator`, 평소 FastAPI 실행용 `gabee_app`(DDL 권한 없음, 테이블 CRUD 권한만 있음). 기존 `family-secretary` database는 그대로 유지하고 손대지 않았다.
- 이유: 팀 5명이 공용으로 쓸 개발 DB가 필요했다. 계정을 분리한 이유는 "누가 실수로 스키마를 바꿔버리는" 사고를 막기 위함이다 — 일반 실행(`gabee_app`)에는 애초에 DDL 권한을 주지 않고, 스키마 변경은 `gabee_migrator` 계정으로 담당자만 실행하도록 운영 규칙(`CLAUDE.md`, `README.md`)으로 못 박았다. 완전히 새 PostgreSQL 서버를 하나 더 두는 대신 기존 MVP DB와 같은 서버를 쓴 이유는 이미 팀이 접근 가능한 PC/서버 자원을 재사용하는 것이 비용·운영 부담이 적기 때문이다.
- **같은 서버, 다른 database라는 점**: `gabee`와 `family-secretary`는 **논리적으로는 분리된 database**(서로의 테이블을 직접 조회·변경할 수 없음)이지만, **물리적으로는 같은 PostgreSQL 서버 프로세스와 같은 디스크를 공유**한다. 즉 `gabee` database 작업이 `family-secretary`의 데이터를 직접 건드리지는 않지만, 서버 자체를 재시작·종료하거나 디스크 용량을 다 쓰는 등 서버 레벨에 영향을 주는 작업은 두 database 모두에 영향을 줄 수 있다 — 그런 작업은 기존 MVP를 운영하는 쪽과 반드시 먼저 조율한다.
- **`gabee_app` 계정의 남는 위험**: `gabee_app`은 `CREATE TABLE`/`ALTER TABLE`/`DROP TABLE` 같은 DDL은 못 하지만, 일반 `INSERT`/`UPDATE`/`DELETE` 같은 데이터 CRUD 권한은 그대로 갖고 있다. 즉 코드에 버그가 있거나 누군가 직접 쿼리를 날리면 **다른 팀원이 테스트하던 데이터를 지우거나 바꿀 위험은 여전히 남아 있다** — 계정 분리는 "스키마 사고"만 막아주고, "데이터 사고"까지 막아주지는 않는다. 공용 DB의 데이터를 직접 조작하는 작업(스크립트 실행, 수동 SQL)은 신중하게 하고, 가능하면 개인 로컬 Docker DB나 별도 격리 DB에서 먼저 검증한다.
- **적용된 리비전은 "이 결정을 적을 당시" 기준이다**: 2026-10-22 작업 시점에 공용 DB에는 Alembic 리비전 `355a1a748ec5`(초기 스키마) → `9e28d84c1686`(billing-care) → `b6931fc30c66`(PR 4-A, 인증·가족 구성원) 세 개를 오류 없이 적용했다. 다만 이 ID들은 **그 순간의 상태를 적어둔 것일 뿐**이고, 실제로는 이미 그 다음 리비전(`6304cb91e46a`, billing settled and manager)이 `main`에 추가돼 있었다 — 즉 이 문서나 다른 문서에 적힌 리비전 ID를 "지금의 최신 head"로 가정하지 않는다. 공용 DB가 지금 실제로 어느 리비전에 있는지는 항상 `gabee_migrator` 계정으로 `alembic current`를 직접 실행해 확인한다(README.md "팀 공용 PostgreSQL 에 연결하기" 참고).
- 영향: `gabee_app` 계정으로 SQLAlchemy 연결 성공, FastAPI `/health`·`/docs` 정상 응답 확인, 테이블 CRUD 권한 확인함. 개인 로컬 Docker DB(`127.0.0.1:5433/gabee`)는 이 구축과 완전히 별개로 운영되고, 작업 시점 기준 여전히 최초 리비전(`355a1a748ec5`)에 머물러 있었다 — 공용 DB와 적용 상태가 다를 수 있다는 뜻이고, 둘 중 어느 쪽을 쓰든 작업 전에 `alembic current`로 직접 확인해야 한다.
- 이 문서에는 호스트·포트·database 이름·계정 이름만 적고, 비밀번호나 연결 문자열의 인증정보는 적지 않는다(`apps/api/.env`에만 두고 커밋하지 않는다).
