# 0007. 업로드 → 전처리 → knowledge → 채팅 연결: 가린 글자만 외부 모델로, 원본은 서버에서 직접

- 날짜: 2026-10-23
- 상태: 로컬 통합 브랜치 `integration/ingest-knowledge` 에서 구현·시험함 (푸시 전)
- 결정: 아래 7가지. 각각 이유와 한계를 적는다.

## 결정

1. **업로드 흐름**: `POST /ai-assistant/files` 가 바로 `received` 로 응답하고, 읽기(OCR)·가리기·분류·사진 설명·knowledge 저장은 백그라운드에서 한다. 처리 상태는 `photos.status`, 저장된 knowledge 기록의 id 는 파일 id 와 같게 둬서 DB 구조를 바꾸지 않고 잇는다. 처리 중 서버가 꺼져 `received` 로 15분 넘게 남은 파일은 `failed` 로 알려 준다.
2. **개인정보 가리기 확대**: 외부 모델(Claude)로 나가는 글이므로 일반 문서(영수증·고지서·엑셀 등)도 주민번호 외에 카드·전화·이메일·계좌 번호, 라벨이 붙은 이름·주소를 가린다. 주민번호는 하이픈 없는 13자리, 공백·점·긴 대시 구분, 전각 숫자도 가린다. (전처리 담당자의 기존 정책 "일반 문서는 주민번호만"을 바꾼 것 — 담당자 확인 필요)
   - 한계: 라벨 없는 이름·주소, 고객번호·환자번호는 아직 새어 나간다. 영수증의 가게 전화번호도 가려진다.
3. **민감 기록(처방전·신분증·통장·가족관계증명서)도 가린 글자로 채팅 근거에 쓴다.** 설정 `CHAT_INCLUDE_SENSITIVE`(기본 true)로 끌 수 있고, 끄면 검색·`get_item`·`list_items` 에서 빠지며 지침도 "볼 수 없다고 안내"로 바뀐다. 가린 값(홍**, ******-*******)은 되살리지 않는다.
   - 외부 API 로 가린 글자가 전송·처리된다는 점은 그대로다. ingest 문서의 "어떤 모델에도 보내지 않는다" 문구와 어긋나므로 팀이 문구 또는 동의 절차를 정해야 한다.
   - 기록은 사용자별이 아니라 **가족 그룹 단위**로 저장·검색된다. 같은 가족이면 누구든 민감 기록의 가린 내용을 물을 수 있다. (사용자 확인: 지금 설계로 충분함)
4. **원본 꺼내주기**: 답변의 출처에서 "원본 보기"를 누르면 앱이 `GET /ai-assistant/files/{id}/original` 을 로그인 토큰 헤더와 함께 호출해 원본 바이트를 받는다. 원본은 Claude 를 거치지 않는다.
   - 서버는 요청자의 가족 그룹이 기록의 그룹과 같을 때만 준다(다른 가족·로그인 없음은 404/401). 저장 경로의 첫 칸이 요청 그룹과 다르면 읽지 않는다(`raw_store.get_for_group`).
   - 이미지·PDF 말고는 내려받기로만 응답하고 `nosniff`·`CSP: sandbox`·`no-store` 를 붙인다.
   - 서명 URL 방식은 쓰지 않았다(비밀키·만료 관리가 늘고 주소가 새면 유효시간 동안 노출). 필요하면 나중에 얹는다.
   - 앱은 지금 이미지만 앱 안에서 연다. PDF 등은 `expo-file-system`·`expo-sharing` 이 필요해 보류.
5. **사진 설명(캡션)**: 글자 없는 사진은 로컬 Ollama `qwen2.5vl:3b` 로 한국어 설명과 키워드를 만든다(사진은 서버 밖으로 나가지 않음). 긴 변 768px 로 줄이고, 출력은 200토큰, 대기 60초로 제한한다. 지시문이나 예시를 되돌려 주는 답은 버린다. 저장되는 글에는 "자동으로 만든 설명이라 틀릴 수 있어요"를 붙인다.
   - 한계: 작은 모델이라 동물 종류 등을 틀린다(예: 사자 → 호랑이).
6. **스캔 PDF OCR(쪽 단위)**: PDF 의 쪽마다 글자 층을 보고, 글자가 8자 미만인 쪽(스캔·사진)만 `pypdfium2` 로 그림으로 바꿔 기존 OCR 로 읽는다(글자 있는 쪽은 그대로, 글자 없는 쪽 앞 20쪽까지, 긴 변 1280px). 글자 쪽과 스캔 쪽이 섞인 PDF 도 놓치지 않는다(사용자 지적으로 문서 전체 판단에서 쪽 단위 판단으로 바꿈). OCR 로 읽은 쪽이 있으면 `partial`(확인 필요)로 표시한다.
   - **의존성 추가**: `pypdfium2>=4`(사용자 허락 2026-10-23). 이미 `pdfplumber` 가 끌고 오던 패키지를 명시한 것이다.
   - OCR 입력 긴 변을 1600 → 1280px 로 줄였다(전처리 측정에서 더 빠르고 글자 오류율이 낮았음, 전체 시험으로 재확인 필요).
7. **앱**: `+` 버튼으로 앨범·카메라 사진 또는 파일(PDF·문서·엑셀)을 골라 업로드 → 상태를 2초 간격으로 120초까지 확인.
   - **의존성 추가(사용자 허락)**: `expo-image-picker`(사진), `expo-document-picker`(파일 선택, 2026-10-23), `@react-native-async-storage/async-storage`(대화 목록 기기 저장, 2026-10-23). 모두 Expo Go 에 포함된 모듈이다.
8. **사이드바**: ☰ 로 왼쪽 패널을 열어 "대화"(이전 대화 목록, 새 대화, 길게 눌러 삭제)와 "기록"(가족이 올린 사진·파일 목록, 상세에서 읽어 낸 글과 원본 보기)을 본다. 기록 목록은 기존 `GET /ai-assistant/knowledge/items` 를 쓰며 서버 변경은 없다.
   - **대화는 기기에만 저장**한다(서버 저장 안 함, 사용자 결정). 저장 키에 로그인 토큰에서 만든 값(`storageScope`)을 넣어 같은 폰의 다른 사용자와 섞이지 않게 했고, 저장 함수는 `storage/chatStore.js` 세 개뿐이라 나중에 서버 저장(대화 테이블+마이그레이션, 본인만 보는 범위, 삭제·보관 정책 필요)으로 바꿀 수 있다. 앱을 지우거나 다른 폰으로 옮기면 대화는 사라진다. 기록(올린 파일)은 서버에 있어 그대로 보인다.

## 아직 남은 것

- 보안 검토에서 나온 중간 이하 18건(압축 폭탄·1억 화소 이미지 상한, 원본 동시 저장 오류, 하루 호출 한도 우회, 얼굴 동시 등록 등)은 `docs` 가 아니라 작업 보드에 기록. 이 브랜치에서는 고치지 않음.
- 라벨 없는 이름·주소 가리기, 영수증 제목에 전화번호가 앞서는 문제.
- 사진 PDF·문서의 앱 안 열기(의존성 필요).
- 서버 PC 의 PostgreSQL(pgvector)에서의 실제 저장·검색 확인(Docker 또는 시험 DB 필요).

## 추가 결정 (2026-10-23): 확인 필요 기록은 사용자가 직접 확인·수정한다

- 글자가 흐리거나 종류가 애매해 `needs_review` 로 저장된 기록은 사용자에게 알리고, 원본과 비교해 고치거나 "확인 완료"하게 한다.
- **알림**: 확인이 필요한 기록이 있으면 ☰ 버튼에 점, 사이드바 "기록" 탭에 숫자, 기록 목록 맨 위에 배너와 "확인 필요" 표시가 뜨고, 올린 직후 채팅 답변에 "지금 확인하기" 버튼이 붙는다.
- **서버**: `GET /ai-assistant/knowledge/items` 응답에 `needs_review`(올린 파일 상태가 `needs_review` 이거나 읽지 못한 부분이 있는 기록)를 추가하고, `PATCH /ai-assistant/knowledge/items/{id}` 를 만들었다. 보낸 칸(제목·분류·날짜·본문)만 바뀌고 빈 요청은 "확인했어요"다. 본문은 저장 전에 개인정보 가리기를 다시 거치고(사용자가 원문을 입력해도 가려져 저장), 읽지 못한 부분 표시를 지우고, 검색용 조각과 임베딩을 다시 만든다. 같은 가족 그룹만 고칠 수 있다(다른 가족은 404). DB 컬럼 추가 없음.
- **한계**: 가족 누구나 고칠 수 있고, 누가 언제 고쳤는지 이력·"수정됨" 표시는 없다(DB 컬럼과 마이그레이션이 필요해 이번에는 뺐다). 기록 삭제 기능도 아직 없다. 사용자가 일부러 "민감"으로 바꾸는 기능은 없고, 이미 민감인 기록은 고쳐도 민감으로 유지된다.

## 추가 결정 (2026-10-23): 앱에서 PDF 원본 보기, 같은 파일은 출처 하나, 읽어 낸 글 보기 개선

- **PDF 원본을 앱에서 보기**: 앱에 PDF 뷰어를 넣는 대신(`expo-file-system`·`expo-sharing` 추가가 필요) 서버가 쪽을 그림으로 그려서 준다. `GET /ai-assistant/files/{id}/original/pages`(쪽 수, 최대 100)와 `.../pages/{n}`(JPEG, 긴 변 1600px). 원본 보기와 같은 가족 그룹 확인을 거치고, 사진이 아닌 파일은 404. 앱은 쪽 그림을 위아래로 넘겨 본다. 새 의존성 없음(이미 쓰는 `pypdfium2`). 워드·엑셀·PPT 원본은 아직 앱에서 열 수 없고 "읽어 낸 글로 확인" 안내가 뜬다(변환 도구가 없음).
- **같은 파일은 출처 하나**: 같은 파일을 두 번 올리면 기록이 둘 생기는데, 검색 결과에서 같은 원본 경로(같은 해시)는 점수가 높은 하나만 Claude 에게 넘기고, 답의 출처 번호도 같은 원본이면 하나로 합친다(`[1][1]` 도 `[1]`). 기록 자체의 중복 저장 방지와 삭제는 아직 없다.
- **읽어 낸 글 보기**: 기록 상세에서 마크다운 원문 대신, 위에 요약(날짜·금액·장소 등)과 태그, 아래에 읽어 낸 글(표는 칸으로, 소제목은 굵게, 읽은 순서 번호는 숨김)을 보여 준다.
