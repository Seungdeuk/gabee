# 0024. 가족 소통 채팅방의 자동 처리는 가족 AI 동의가 있을 때만 외부 AI 로 보내고, 가리기 없는 채팅 문서는 등록·재노출하지 않는다

- 날짜: 2026-11-26
- 상태: **구현됨(이 ADR 의 PR). 운영 반영은 별도 승인.** 정책 내용은 Draft PR #520 의 보안 결정(사용자 결정 2026-11-23)을 그대로 따르고, 구현만 #520 과 다르게 최소 변경으로 다시 했다(#520 은 참고용으로 유지).
- 대체 관계(역사 기록은 그대로 두고 이 ADR 이 대체한다): [0015](0015-family-room-photo-to-library.md)·[0014](0014-upload-llm-ocr-masking.md) 의 "결정 (2026-11-10)" 중
  **가족 소통 채팅방의 문서·사진에 한해** "AI 동의를 확인하지 않는다"를 대체한다. 메인 AI 직접 업로드의 기존 정책은 그대로다.

## 결정
1. **가족 채팅 목적의 외부 전송은 가족 AI 동의가 있을 때만**: 채팅 문서·사진의 문서함 등록(`library.register_chat_document`·`register_chat_photo`)은 가족 채팅 처리 범위
   (`app/shared/llm/consent_gate.family_chat`) 안에서 돈다. 그 안의 Claude(`transport.post_messages`)·Jev(`jev.ask`) 호출은 **보내기 직전마다** 동의를 다시 읽고, 없으면 보내지 않는다.
   - 동의 OFF → 등록 보류, 외부 호출 0회. 채팅 원본은 그대로. 문서로 판별된 사진은 `document` 가 아니라 `unsure` 로 적는다(`document` 로 적으면 확인 목록·재검사·일반 사진 확인이 모두 막혀 업로더가 손댈 수 없다. `unsure` 는 동의를 켠 뒤 재검사로 다시 판별·등록된다).
   - 처리 중 철회 → 그 뒤의 호출은 나가지 않고, 그 단계를 로컬 규칙으로 대신한 결과는 **등록하지 않는다**(재시도 없음). 마지막 호출이 나간 뒤 철회돼도 등록 직전에 동의를 다시 읽어 등록하지 않는다. 이미 나간 호출은 되돌릴 수 없다.
   - 동의를 읽지 못하면 막는다(fail-closed). 스레드 풀 작업(PDF 쪽 읽기·PPT 그림 설명)에도 범위를 넘긴다(`carry`).
   - 수동 "문서로 저장": 동의가 없으면 403 `ai_not_enabled`(앱이 이미 처리하는 기존 코드), 판별 상태는 바꾸지 않는다.
2. **재노출 차단**: 채팅 첨부에서 만든 기록은 가족 AI 동의가 마지막으로 켜진 시각(`ai_group_settings.updated_at`, 값이 실제로 바뀔 때만 옮긴다: 같은 값을 다시 저장해도 기준이 움직이지 않는다) 이후 것만 외부 AI 로 나가는 길(@가비·메인 채팅 도구
   `search_knowledge`·`get_item`·`list_items`·이름 확인 `list_name_checks`)에 보인다. 동의가 꺼져 있으면 채팅 기록은 모두 빠진다. 앱 문서함 화면은 바꾸지 않는다.
3. **가리기 필수(MASK OFF fail-closed)**: `INGEST_LLM_MASK=false` 이면 채팅 문서·사진 등록과 수동 저장(503 `masking_unavailable`)을 하지 않는다.
4. **메인 AI 직접 업로드(`/ai-assistant/files`)·@가비·메인 채팅·일반 채팅 메시지·소통 에이전트의 기존 정책은 바꾸지 않는다**(관문 범위 밖).

## 구현이 #520 과 다른 점
- #520 은 처리 목적(`Purpose`)과 `external`·`recheck`·`require_external` 인자를 처리 함수마다 넘겼다. 이 ADR 은 외부 호출의 유일한 관문(Anthropic `transport`, Jev)에서
  처리 범위(contextvar)로 판단한다: 새 외부 호출 경로가 생겨도 관문을 지나면 같은 규칙이 적용된다.
- 동의 OFF 일 때 문서로 판별된 사진의 상태: #520 과 같이 `unsure` 로 적는다(처음 구현은 `document` 로 두었으나 독립 리뷰에서 업로더가 손댈 수 없는 상태가 된다는 지적을 받아 바꿨다).
- 수동 저장 거절 코드: #520 `ai_consent_required` → 이 ADR `ai_not_enabled`(기존 공통 코드, 앱이 이미 안내 문구를 가진다).

## 보장하지 않는 것·잔여 위험
- **과거에 이미 저장된 기록의 안전성**: 기록에 "Claude 로 가렸는지"가 남지 않아(DB 칸 없음) 동의 시각 기준의 보수적 제외만 한다. 특히 과거 MASK OFF 로 저장된 채팅 문서는 구분하지 못한다.
  확인 절차(운영 담당자, 읽기 전용): 운영 설정 이력에서 `INGEST_LLM_MASK` 값과 기간을 확인하고, 그 기간에 만든 `knowledge_items`(source_attachment_id 있음)의 개수를 센다.
- 동의 확인과 실제 전송 사이의 아주 짧은 시간에 동의가 꺼지면 그 한 번의 호출은 나갈 수 있다(직전 확인 방식의 한계).
- 동의를 다시 켜도 보류된 채팅 문서는 자동으로 다시 처리하지 않는다(같은 파일을 다시 올리거나, 사진은 "문서로 저장").
- 수동 "문서로 저장"은 요청 때 동의를 확인한 뒤 판별 상태를 `document`(수동)로 적고 뒤에서 등록한다. 그 사이 철회되면 등록은 막히지만 상태는 `document` 로 남는다(아주 짧은 경합, 후속 과제).
- `INGEST_LLM_MASK=false` 이면 사진 판별 전에 멈춰 판별 상태가 `pending` 으로 남고, 15분 뒤 "멈춤"으로 보여 재검사할 수 있지만 다시 보류된다(운영은 가리기 켜짐이 전제).
