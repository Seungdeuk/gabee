# 0026. 날짜별 가족 타임라인과 AI 추억 발견을 분리하고, 타임라인 자동 후보·유사 묶기는 서버 스위치(기본 꺼짐)와 ADR 0020 조건에서만 연다

- 날짜: 2026-11-26
- 상태: **코드 구현됨(기본 꺼짐).** 자동 후보의 **운영 활성화는 승인 대기**다(아래 "승인 대기"). [0020](0020-family-photo-image-analysis-consent.md)·[0021](0021-auto-memory-exposure-policy.md) 의 동의 구조는 바꾸지 않는다.
- 관련: [0025](0025-local-ocr-removed-siglip-only-photo-judge.md)(SigLIP2 단독 문서 판별), [0024](0024-family-chat-external-ai-consent.md)(외부 AI 동의), `docs/requirements/timeline.md`.

## 결정
1. **날짜별 타임라인(기본 동작)**: 가족 전체방 사진 중 업로더가 일반 사진으로 확인한(`photo`) 것과 업로더가 직접 넣은 것만, 촬영일(없으면 보낸 날)·같은 업로드 묶음으로 보인다.
   **이미지 분석을 하지 않는다**(임베딩을 만들지도 쓰지도 않는다). D-8(애매한 사진은 업로더 확인 전까지 숨김)이 그대로 유지된다.
2. **자동 후보·같은 날 유사 사진 묶기(선택 기능)**: 서버 스위치 `TIMELINE_AUTO_CANDIDATES`(**기본 꺼짐**)가 켜져 있고, 사진마다 [0020] 의 3중 조건
   (`FAMILY_MEMORY_ENABLED`·가족 활성화·올린 사람의 동의)과 사진별 AI 분석 제외가 없을 때만, 아래 "이미지 분석 범위"에 든 사진을 로컬 SigLIP2 로 분석한다(`shared/photo_analysis_consent`, family_memory 가 등록).
   판별이 끝난 애매(`unsure`) 사진이 분석을 통과하고 margin ≤ 5 이면 업로더 확인 없이 자동 후보로 보이고, 같은 날·4시간 이내·코사인 ≥ 0.88 이면 한 묶음이 된다(값은 바꾸지 않았다).
3. **AI 추억 발견(family_memory)과 분리**: 이 ADR 은 추억 발견의 자격·작업·카드 동작을 바꾸지 않는다. 개별 확인 없는 자동 게시(E1, [0021])는 이번 출시 범위가 아니다.
4. **공통으로 유지하는 것**: 가족 전체방 사진만(1:1 방 제외), 가족 간 격리, 업로더만 개별 사진을 포함·제외(선택은 이력 줄로 영속, 재시작·재분류 뒤에도 유지),
   타임라인 상태 변경으로 문서함 판정을 바꾸지 않음, 모델 누락·추론 실패·문서 의심(margin > 5)·분석 전 사진은 자동 노출 금지, 채팅 원본 보존, 이미지 분류에 외부 AI 호출 없음.
5. **파생 데이터 삭제**: 동의 철회·가족 비활성화·사진 분석 제외 사건(`shared/memory_hooks`)에서 그 사진의 타임라인 분석 결과(margin·임베딩 파일, 쓰다 남은 `.tmp` 포함)를 지운다. 그룹·방 삭제 때도 지운다.
   대기열에 있던 분석 작업이 그 뒤에 끝나도 결과를 쓰지 않는다: 쓰기 직전에 (가) 그 사진을 지운 시각이 작업 시작 뒤인지 (나) 지금도 스위치·0020 조건을 만족하는지 새 DB 세션으로 다시 확인한다(`timeline_features.set_write_guard`).
6. **과거 사진(소급)**: 올린 사람이 동의하기 **전에** 올린 사진은 0020 의 소급 동의가 있어야 분석한다(0020 "과거 사진" 기본 꺼짐과 같다).
7. **스위치 꺼짐의 쪽 넘기기**: 분석이 없으므로 DB 커서로 끝까지 넘긴다(창 상한 3000장과 무관). 켜짐일 때만 최근 3000장 창 안에서 묶은 뒤 쪽을 나눈다.
8. **포함·제외 기록**: 자동 판별 줄(대기·애매·실패·자동 문서)에 대한 업로더의 제외·다시 넣기는(문서·대기·실패 줄은 자동으로 보이지 않으므로 넣은 뒤에만 뺄 수 있다) 판정 줄을 바꾸지 않고 이력 줄(`chat_photo_check_events`)로만 남긴다(뒤늦게 끝난 판별·문서함 등록과 어긋나지 않게).
   선택 기록이 없는 애매한 줄을 직접 넣으면 기존 일반 사진 확인(D-13)과 같다.

## 선택지와 D-8 의 관계(다시 명시)
- (가) "같은 날 유사 묶기는 0020 의 AI 추억 발견이 아니다"로 보고 동의 조건 없이 분석: **채택하지 않았다**(0020 의 동의 구조를 임의로 줄이지 않는다는 사용자 방침).
- (나) 서버 스위치(기본 꺼짐) + 0020 조건 재사용: **채택**. 스위치를 새로 둔 이유: `FAMILY_MEMORY_ENABLED` 는 추억 발견 기능의 스위치이고, 타임라인 자동 노출은 별도로 통제해야 해서다(분석은 두 스위치가 모두 켜져야 한다).
- D-8: 스위치 꺼짐 = D-8 유지. 스위치 켜짐 = **0020 조건을 만족한 가족·사진에 한해** 애매(`unsure`)한 사진도 margin ≤ 5 이면 자동 노출(D-8 의 타임라인 한정 대체). 이것은 승인 대기다.

## 잔여 위험·근거의 한계
- margin ≤ 5 는 일반 사진이라는 보장이 아니다. 공개 독립 Test 123장에서 문서 42장 중 3장을 놓쳤다(margin 2.14·2.89·3.21). 실제 한국어 문서·실제 가족 사진으로는 평가하지 않았다.
- **일반 사진을 따로 판정하는 기준(예: photo 쪽 임계값)과 그 안전성 근거는 없다**: 평가는 문서 탐지(문서→문서 재현율, 일반→문서 오분류)만 했다. 그래서 근거가 부족한 `unsure` 의 자동 노출은 기본으로 하지 않는다.
- 분석 결과 파일은 `DATA_DIR` 에 있다. 영속·공유 저장소가 확인되지 않으면 인스턴스 교체 때 다시 분석해야 하고(원본이 없으면 실패로 남아 숨김), 철회 때 다른 인스턴스의 파일은 지워지지 않을 수 있다.
  메모리 캐시·진행 중 목록·대기열 상한(100)·지운 시각 기록도 인스턴스마다 따로다(다른 인스턴스의 작업은 쓰기 직전 DB 재확인으로만 막힌다).
- 스위치(`TIMELINE_AUTO_CANDIDATES`·`FAMILY_MEMORY_ENABLED`)를 끄는 것은 사건이 아니라서 그 전에 만든 분석 파일이 디스크에 남는다(쓰이지는 않는다: 모든 읽기가 스위치·동의를 먼저 본다). 정리 작업은 후속 과제다.

## 이미지 분석 범위(2026-11-25 사용자 결정으로 축소 — 스위치 켜짐일 때만 적용)
| 판정 줄 상태 | 타임라인 분석 | 비고 |
|---|---|---|
| `photo`(업로더 확인) | 허용 | 같은 날 유사 묶기용. 노출은 분석과 무관하게 이미 된다 |
| `unsure`(자동) | 0020 조건 충족 시 후보 분석 허용 | **분석 허용 ≠ 자동 공개 허용**(아래) |
| `document` | 자동 분석 제외 | 예전 OCR 이 적은 자동 줄 포함. 업로더가 직접 넣어야만 보인다 |
| `pending` | 판별이 끝날 때까지 보류 | 업로드 직후 분석을 맡기지 않는다. 판별 뒤 조회 때 맡긴다 |
| `failed` | 자동 분석 제외 | 재검사로 판별이 다시 끝나면 그 결과를 따른다 |
| `excluded`·업로더 제외 | 제외 | |
- **사용자의 명시적 동작과의 관계(충돌 없음 확인)**: 업로더가 타임라인에 직접 넣은 사진(판정 줄과 무관)은 업로더가 일반 사진이라고 밝힌 것이라 `photo` 와 같이 보고 묶기용 분석을 허용한다(노출은 분석 결과와 무관).
  업로더의 제외는 모든 분석보다 우선한다. 재검사는 문서함 판별 줄을 다시 정하고, 타임라인은 바뀐 줄을 그대로 따른다. 대기열에서 기다리는 사이 줄이 범위 밖(문서·실패·제외)이 되면 쓰기 직전 재확인에서 결과를 버린다.
- **분석 허용과 자동 공개 허용은 다른 정책이다**: `unsure` 의 후보 분석을 허용한다고 해서 문서 점수(margin)가 낮은 사진이 일반 사진이라고 확정되거나 자동 공개가 안전하다고 판단하지 않는다(아래 잔여 위험).
  현재 코드는 스위치가 켜지면 분석을 통과한 `unsure` 를 자동 노출하므로, **스위치의 운영 활성화 = 자동 공개 승인**이다. 그래서 스위치는 기본 꺼짐이고 운영 활성화는 승인 사항으로 남긴다.

## 0020·0021·0026 의 관계
- **0020(가족 사진 이미지 분석 동의, 초안)**: 이미지 분석의 *전제 조건*(서버 스위치·가족 활성화·업로더 동의·소급 동의·제외·파생 데이터 삭제)을 정한다. 0026 은 이 조건을 **그대로 재사용**하고 줄이지 않는다.
  0020:9 는 추억 발견의 초기(E0) 분석 대상을 `photo` 로, `unsure` 포함(E1)은 별도 승인으로 정했다. 0026 의 `unsure` 후보 분석은 **날짜별 타임라인 한정**이며 추억 발견의 분석 자격(E0/E1)을 바꾸지 않는다. 문서·실패·제외 사진을 분석하지 않는다는 0020 의 원칙은 0026 에서도 같다.
- **0021(자동 추억 카드 노출, 초안)**: 추억 카드의 자동 게시(E1)는 독립 안전성 평가·별도 승인 뒤에만 연다. 0026 은 추억 카드를 만들지 않고 0021 의 게이트를 바꾸지 않는다. 다만 타임라인 자동 노출도 "개별 확인 없는 공개"라는 점은 같아서,
  0021 이 요구하는 수준의 안전성 근거는 아직 없다는 점을 잔여 위험으로 함께 적는다.
- **0026(이 ADR)**: 날짜별 타임라인 기본 동작(분석 없음)과, 스위치 뒤의 자동 후보·유사 묶기 범위·삭제·재확인 규칙을 정한다. AI 추억 발견·추억 카드 자동 생성은 이번 출시 범위가 아니다.

## 승인 대기(운영에서 켜기 전에)
- `TIMELINE_AUTO_CANDIDATES=true` 운영 활성화 = `unsure` 자동 공개와 그에 따른 D-8 의 타임라인 한정 대체(위 "선택지" 참고).
- `FAMILY_MEMORY_ENABLED`·가족 활성화·업로더 동의 화면(T31 고지문 포함)의 출시 승인 — 이미 0020 의 조건이다.
- 문서 미탐 잔여 위험의 수용 여부(업로더 제외로 사후 조치).
