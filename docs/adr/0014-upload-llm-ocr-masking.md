# 0014. 외부 API 로 나가는 내용은 공지로 처리하고, 업로드 문서의 글자 읽기·가리기는 Claude 로 한다

- 날짜: 2026-11-04
- 결정:
  - **외부 AI API(Claude)로 사용자 입력·문서 내용이 나가는 것은 설계 제약으로 삼지 않고, 사용자 공지(개인정보처리방침·Play 데이터 안전 양식)로 알린다.** 개인정보 보호의 초점은 **우리 DB 에 저장되는 내용**이다. 공지에는 "저장하지 않는다"는 표현 대신 "서비스 처리를 위해 Anthropic API 로 전송된다"를 쓴다(제공사의 보관 정책은 현재 약관을 확인한다).
  - **메인 AI 채팅은 입력을 막지도 가리지도 않는다.** 채팅 내역은 서버 DB 에 저장되지 않는다(폰에만 있다). 그래서 주민번호·카드·계좌·비밀번호 입력 거절(`high_risk_guard`)과 가명화 게이트웨이(`rag_privacy`)를 메인 채팅에서 걷어냈다. 문서 직접 입력(`/knowledge/items`)과 돌봄·가계 에이전트 채팅의 거절은 유지한다(DB 에 저장되는 경로). 메인 채팅이 탭 에이전트로 넘기는 질문에 고위험 값이 있으면 그 호출을 거절한다(가계·일정·돌봄 기록에 원문이 저장되지 않게).
  - **업로드 문서는 저장하기 전에 Claude 로 읽고 가린다**(`INGEST_LLM_OCR`, `INGEST_LLM_MASK`, 기본 꺼짐):
    1. 글자 꺼내기: 사진·스캔·PDF 는 Claude OCR(기본 Sonnet), Word·PowerPoint·텍스트·CSV 는 지금 방식, **Excel 은 서식 반영 전용 변환**(`converters.xlsx_to_markdown`: 금액 쉼표·날짜·병합 칸).
    2. 가리기: **Claude 는 가릴 값을 원문 그대로 인용해 알려 주고, 글을 바꾸는 일은 코드가 한다**(인용이 원문에 있는지 검증, 없으면 버린다). 가족 이름은 코드가 글자 일치로 **후보**를 찾고 Claude 가 후보마다 문맥으로 사람 이름인지 판단한다. 맞으면 코드가 `[가족:user_id]` 이름표를 단다(메타데이터 방식 유지). 판단이 빠진 후보는 가족으로 본다.
    3. 주소는 **개인·가족의 집(거주지)과 배송받는 곳만 가리고**, 병원·학교·가게·회사·관공서 같은 사업장·공공장소 주소와 행정구역 이름은 남긴다.
    4. 번호(전화·이메일·주민·카드·계좌·비밀번호)는 규칙이 한 번 더 가린다(안전망). 앞 라벨이 거래·주문·승인·운송장·사업자 번호 같은 개인과 무관한 번호이면 전화·계좌 규칙에서 뺀다.
    5. 분류·임베딩·pgvector 저장은 그대로다. 문서당 Claude 호출은 OCR 1번 + 가리기 1번(긴 글은 6천 글자 단위로 나눠 가리기 호출이 늘어난다).
  - **Claude 호출이 실패하면 가리지 않은 글을 저장하지 않고 파일을 `failed`(`llm_unavailable`)로 둔다.** 원본은 `raw_store` 에 보관되므로 나중에 다시 처리할 수 있다. 읽은 글(가리기 전)은 메모리에서만 쓰고 DB·로그에 남기지 않는다.
  - 기본값을 켜기 전 합격 기준: 새 평가 묶음에서 못 가린 비율이 기존(규칙+NER)보다 낮고, 엉뚱한 곳을 가린 문서가 기존 이하이며, 합성 문서 누출 1% 이하.
- 이유:
  - 규칙·NER 로 이름·주소를 문맥 없이 찾는 방식은 한계가 컸다(대화 600창에서 정답의 37% 를 못 가림, 엉뚱하게 가린 문서 68개). 같은 데이터에서 Claude 찾기 + 번호 규칙은 6% 와 10개였다(평가 보고서, 프롬프트 v3 기준). 프롬프트는 이후 v4(이름 보강)를 거쳐 **v5(개인 집·배송 주소만 가리고 사업장·공공 주소·행정구역은 둠, 호칭 붙은 이름·이름만 있는 경우 보강)가 현재 코드(`shared/llm/doc_ai.py`)의 버전**이다. 합격 기준 수치는 v5로 다시 쟀다: 대화 600창 주소 제외 누출 3.6%(기존 33.4%), 엉뚱한 문서 23개(기존 68), 합성 세트 누출 0.2%..
  - 글을 Claude 가 다시 쓰게 하면 가릴 곳이 아닌 곳까지 바뀌고(옮겨 적기만 해도 문장의 약 12% 에서 글자가 달라짐), 검증할 수 없으며, 출력 토큰이 글 길이만큼 든다. 위치만 인용하면 수십 토큰이고 코드가 검증한다.
  - 가족 이름을 글자 일치만으로 이름표로 바꾸면 이름이 일반 낱말과 같은 경우(예: '채용', '하나') 엉뚱한 사람의 기록으로 연결된다. 후보는 코드가 전부 찾고 판단만 Claude 가 하므로 놓침이 없고 코드가 낱말의 뜻을 알 필요도 없다.
  - 디지털 PDF 의 글자층 꺼내기는 표를 한 줄로 이어 붙이고 깨진 글자·머리말이 섞였다(문장 일치 88.5% 대 Claude 96%, 표 구조 0% 대 79%). Word·PowerPoint 는 MarkItDown 이 칸 구조를 그대로 살려 Claude 보다 나았고, Excel 은 MarkItDown 이 금액 쉼표·날짜 서식·병합 칸을 잃었다.
  - 상세 주소만 가리고 행정구역·사업장 주소를 남기면 "서울에 있는 병원"처럼 위치를 묻는 질문에 답할 수 있다. 가린 값은 저장된 글에서 되돌릴 수 없으므로(가족 이름만 되돌린다) 가리는 범위가 답할 수 있는 범위를 정한다. 정확한 값은 앱의 '원본 보기'로 안내한다.
  - **이름 오타 확인**: 가족 이름과 한 글자 차이인 이름은 지우지도 가족으로 달지도 않고 `[확인필요:<user_id>]` 로 남겨, 메인 채팅이 사용자에게 같은 사람인지 물어 확정한다(앱 화면·DB 칸 추가 없음). 정확히 같은 글자는 묻지 않고 Claude 의 문맥 판단에 맡긴다.
- 대안:
  - **로컬 NER 모델 파인튜닝·교체**: 받은 모델을 세 번 파인튜닝해 기존 서버 모델보다 낫게 만들었지만(블라인드 세트 이름 누출 401 → 56), 외부 전송을 제약으로 삼지 않기로 하면서 서버 교체는 하지 않았다.
  - **가명화 게이트웨이(토큰 치환·복원) 유지**: 채팅은 DB 에 저장되지 않으므로 불필요해 걷어냈다. 가족 채팅 AI 등 다른 경로는 그대로 쓴다.
  - **Claude 가 가린 글 전체를 돌려주기**: 위의 이유로 채택하지 않았다.
  - **가린 값을 암호화해 따로 보관하고 답할 때 복원**: 답할 수 있는 범위가 넓어지지만 새 테이블·키 관리가 필요하고 "DB 에 개인정보를 저장하지 않는다"는 원칙을 다시 따져야 해서 보류했다.
  - **분류까지 같은 호출에 합치기**: 분류는 이미 대부분 로컬(규칙 + 분류기, 확신이 낮을 때만 Jev)이라 모든 호출의 토큰만 늘어 채택하지 않았다.
- 결과:
  - 기본값이 꺼져 있어 기존 동작과 테스트는 그대로다. 켠 상태의 시험은 `ingest/tests/test_llm_ingest.py`(가짜 Claude)로 한다.
  - **요구사항 `ai_assistant-ingest.md` 의 "개인정보 (담당자 결정 2026-10-22)"와 다르다**: 그 규칙은 처방전·신분증 등 외 문서는 주민번호만 가리고 **처방전은 어떤 모델에도 보내지 않는다**고 했다. 이 결정을 켜면 처방전도 Claude 로 읽고 가린다. 팀(담당자) 확인이 필요하며 그 전에는 켜지 않는다.
  - 가린 표시는 `[이름]`·`[주소]`·`[연락처]`·`[이메일]`·`[주민번호]`·`[카드번호]`·`[계좌번호]`·`[생년월일]`·`[신분증번호]`·`[비밀번호]`, 가족은 `[가족:id]`다. 가린 개수만 `privacy.masked` 에 남고 값은 남지 않는다.
  - 한계·남은 일:
    - 평가는 가짜·공개 데이터(KDPII·schift·합성 문서·KDoc)로 했다. 동의를 받은 실제 사진으로 한 번 더 재야 한다.
    - 개인정보처리방침·Play 데이터 안전 양식·앱 안내 문구 수정(제3자 AI 로 전송 공지)은 사용자가 한다.
    - 원본 이미지(`raw_store`)의 보관 기간·삭제 정책은 정하지 않았다.
    - 호출 한도(`ai_guard`)와 업로드 Claude 호출의 연결, 실패한 파일의 자동 재시도(지금은 `/files/{id}/reprocess` 로 수동)는 후속 작업이다.
    - Word·PowerPoint 안에 붙은 그림 속 글자는 읽지 못한다(예전부터).
    - Claude 응답은 호출마다 조금 다를 수 있다(같은 입력의 가족 후보 판단을 10번 돌린 시험에서는 한 가지만 한 번 달랐다).
