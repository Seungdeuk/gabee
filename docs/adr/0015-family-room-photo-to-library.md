# 0015. 가족방 사진은 문서 사진만 골라 가족 문서함에 읽어 넣고, 판별에는 로컬 OCR 과 Claude(haiku)를 함께 쓴다

- 날짜: 2026-11-09
- 결정:
  - **가족 전체방에 올린 사진 중 종이 문서를 찍은 것은 가족 공유 문서함에 자동 등록한다.** 일반 사진은 등록하지 않고(타임라인은 후속 PR), 1:1 방 사진은 어디에도 넘기지 않는다.
  - **판별은 두 단계다.**
    1. 로컬 OCR(RapidOCR)로 사진을 긴 변 1024px 로 줄여 읽고, 확신도 0.6 이상인 줄의 글자(한글·영문·숫자) 수와 줄 수를 센다. 글자가 50자 미만이면 일반 사진으로 끝낸다(외부 전송 없음).
    2. `PHOTO_JUDGE_LLM=true` 이고 그 가족이 AI 사용에 동의했으면(`ai_guard`) 글자가 읽힌 사진(문서·애매)만 Claude haiku 5.5(`PHOTO_JUDGE_MODEL`, 비우면 `ANTHROPIC_MODEL`)에게 "문서 사진인가"를 묻는다. `document` 이고 확신 0.7 이상일 때만 등록한다. 꺼져 있으면(기본) OCR 판별이 문서일 때(100자·6줄 이상)만 등록한다.
  - **애매하거나 Claude 가 실패하면 자동 등록하지 않는다.** 사진 보기의 "문서로 저장"(`POST /family-chat/photos/{id}/library`)으로 가족 누구나 직접 문서함에 넣을 수 있고, 이 경로는 판별과 하루 상한을 건너뛴다.
  - **비용·메모리 상한**: 하루 상한은 없앴다(2026-11-09 사용자 결정, 비용은 월 예산·Claude 콘솔 사용 한도로 지킨다), 처리를 기다리는 사진 20장. 상한을 넘으면 자동 등록만 멈춘다.
  - 등록한 뒤의 읽기·분류는 기존 업로드 경로(`files.process_file`)를 그대로 쓰되, **서버가 다시 만든 사본**(채팅에 저장되는 긴 변 1600px JPEG, EXIF·위치 없음)을 넘긴다. 업로드 원본을 넘기면 촬영 위치가 문서함 원본으로 가족 모두에게 내려간다(리뷰에서 확인한 결함). 읽어 보니 글자가 거의 없는 사진은 문서함에 넣지 않고, 직접 저장만 예외다. 직접 저장도 민감 문서는 넣지 않는다. 다만 통장류로 잡힌 문서 중 학교·기관의 납부 계좌 안내문은 등록한다(사용자 결정 2026-11-09): 가리기 전 글에 통장·이체확인·거래내역·잔액 같은 개인 금융 낱말이 없고 납부·학교 같은 안내 낱말이 있을 때(`masking.is_account_notice`, opus 리뷰에서 "가린 뒤의 글로 판단하면 줄 하나에 혼자 있는 '통장'이 이름처럼 가려져 통장 사본이 빠져나간다"는 결함을 확인해 원문 기준으로 바꿨다).
  - 직접 저장은 사용자당 분당 10번까지로 막고, 같은 사진의 진행 중인 요청은 겹쳐 처리하지 않는다. 대기열 상한은 가족마다 센다.
- 이유:
  - 사진은 문서(PDF)보다 먼저 쓰이는 입력이다(종이 안내문을 찍어 가족방에 올린다). 가정통신문·학교 안내문·행사 안내문 사진은 Claude 읽기가 로컬 OCR 보다 확실히 좋았다.
  - 글자 수만으로는 "글자 많은 거리·시장 사진"과 문서가 갈리지 않는다. 평가(무료 라이선스 사진 227장 + 휴대폰 사진 15장, 정답 보정 후 237장): 로컬 OCR만 = 문서 82% 자동·애매 14%·거리 사진 7장 오인, Claude 만 = 문서 100%·오인 3장(1.8%), 혼합 = 문서 96%·오인 0장·Claude 호출 42%. 혼합이 오인이 가장 적고 호출이 절반 이하다. 휴대폰 사진 15장은 두 방식 모두 전부 맞혔다.
  - 확신도 기준: 0.7 이면 애매함 0%, 0.9 이면 오인 0장이지만 애매한 문서가 11%.
- 외부 전송 범위(공지 대상):
  - 기본값(`PHOTO_JUDGE_LLM=false`)에서 판별은 로컬 OCR 로만 한다. 다만 2026-11-09 부터 글자 읽기가 항상 Claude 라서(`INGEST_LLM_OCR` 기본 true, ADR 0014 갱신), **문서로 등록된 사진은 읽기 단계에서 Anthropic API 로 나간다.**
  - `PHOTO_JUDGE_LLM=true` 이면 **AI 사용에 동의한 가족의 글자가 읽힌 사진**(전체의 약 40%)이 판별을 위해 Anthropic API 로 나간다(긴 변 1024px JPEG, EXIF·위치·주석 없음). 판별 읽기가 실패한 사진과 동의하지 않은 가족의 사진은 나가지 않는다. 문서로 판정되면 읽기는 `INGEST_LLM_OCR` 설정을 따른다(켜져 있으면 Claude 로 읽는다). 이 전송은 민감 문서를 제외하기 **전에** 일어난다(민감 여부는 읽은 뒤에야 안다).
  - 멘토 확인: Anthropic API 는 보낸 내용을 학습에 쓰지 않는다(2026-11-06, 사용자 전달). 공식 계약·설정으로의 확인과 사용자 공지(개인정보처리방침)는 별도로 남아 있다.
- 대안:
  - **로컬 OCR 만**: 외부 전송이 없지만 간판 많은 사진을 문서로 오인(7장)하고 애매함이 14%다. 기본값으로 남겼다.
  - **모든 사진을 Claude 로 판별**: 문서 100% 이지만 모든 가족 사진이 외부로 나간다. 혼합이 같은 정확도를 절반 이하의 전송으로 낸다.
  - **모든 사진을 "문서로 저장" 버튼으로만**: 가장 안전하지만 요구한 자동 등록이 약해진다. 애매한 사진의 통로로만 남겼다.
  - **OpenCV 로 종이 윤곽·기울기 판별/보정**: 새 의존성이라 승인 전에는 쓰지 않는다(Claude 읽기는 기울어진 사진도 잘 읽었다).
- 결과:
  - 새 환경변수 `PHOTO_JUDGE_LLM`(기본 false), `PHOTO_JUDGE_MODEL`(기본 비움). 시험은 `conftest.py` 에서 끈다.
  - 한계: 대기열은 프로세스 메모리라 서버를 다시 시작하면 초기화된다. 평가 표본은 외국어·스캔 문서가 많고 정답 일부는 사람이 눈으로 보정했다. 문서로 확실하지 않은 사진(정류장 시간표, 손에 든 영수증 등)은 사람이 봐도 갈린다.
  - 혼합 방식의 평가 수치는 두 결과를 합쳐 계산한 값이고, 서버에 구현한 뒤 같은 사진으로 다시 확인하지는 않았다.

## 결정 변경 (2026-11-09): 민감 문서도 등록한다
- 사용자 결정: 채팅방 문서함과 AI 채팅의 기록은 둘 다 가족이 함께 쓰는 같은 문서함이므로, 가족 전체방에서 올린 문서는 민감 여부와 관계없이 등록한다. 위 결정 중 "민감 문서는 자동·직접 저장 모두 제외"와 신분·금융·의료 분류 이름 추가 제외는 폐기한다.
- 결과: 처방전·신분증·통장 사본 같은 문서도 등록되고 기록에 민감 표시가 붙는다. 계좌번호 등은 읽을 때 가려 저장하지만, 보관한 원본은 가족 누구에게나 보이고, `CHAT_INCLUDE_SENSITIVE`(기본 켜짐)에서는 가린 글이 @가비 답변 근거로 외부 Claude 에 전달된다(문서함 화면에서 직접 올린 문서는 원래부터 같았다). 읽기 단계는 기본 설정에서 로컬 OCR·규칙 가리기라 외부로 나가지 않지만(`INGEST_LLM_OCR`·`INGEST_LLM_MASK` 기본 꺼짐, ADR 0014), 등록된 민감 기록의 가린 글은 AI 에 동의한 가족이 @가비·AI 채팅에 질문할 때 외부 Claude 로 전달될 수 있다(`CHAT_INCLUDE_SENSITIVE` 기본 켜짐, 이것은 새로 생기는 경로다). 챙길 일 뽑기(`INGEST_REMINDERS`, 본문 최대 6000자를 Claude 로 보냄, AI 동의 확인 없음)는 가족방에서 온 민감 문서에서는 건너뛰어 새 경로가 생기지 않게 했다. 신분·금융·의료 이름만 민감한 분류도 민감 표시를 붙여 등록한다.
- 안내: 앱의 첫 안내와 "문서로 저장" 결과 문구가 "가족 모두가 볼 수 있어요"를 알린다. 1:1 방은 여전히 해당하지 않는다.

## 결정 (2026-11-09): 판별은 Claude 판별(B)로, 메뉴판·성분표·간판은 일반 사진
- 글자 수만으로는 읽을 가치가 있는 문서인지 구분하지 못해(메뉴판·성분표·긴 현수막이 문서로 등록됨) Claude 판별(`PHOTO_JUDGE_LLM=true`)을 쓰기로 했다. 기본값은 계속 false(외부 전송이 생기는 설정이라 서버마다 켠다).
- 판별 지침에서 메뉴판·시간표를 문서에서 빼고, 메뉴판·시간표·제품 포장·성분표·간판·현수막을 일반 사진으로 못박았다. 기준 전체는 `docs/requirements/family-library.md` "사진 판별 기준".
- 남은 일: 바뀐 지침으로 평가 표본(`scratchpad` 의 문서·거리 사진 표본)을 다시 돌려 오인·애매 비율을 확인한다.
