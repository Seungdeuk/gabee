# 0021. 자동 추억 카드의 노출은 문서 판별(D-13)과 분리된 "분석 자격"으로 정하고, 개별 확인 없는 자동 게시(E1)는 독립 안전성 평가와 별도 승인 뒤에만 연다

- 날짜: 2026-11-17
- 상태: **초안 정책 — 승인된 것은 문서 작성과 B안(분석 자격 분리) 방향까지다. E1 자동 공개 정책의 최종 승인은 별도이며 아직 없다. 코드·DB 변경, 모델 설치, 운영 활성화, 자동 게시는 승인되지 않았다.** 상세 요구사항은 `docs/requirements/auto-memory.md`, 안전성 평가 설계는 `docs/requirements/auto-memory-safety-eval.md`.
- 결정:
  - **D-13 유지:** 자동 판별이 `photo` 를 만들지 못한다는 규칙과 `chat_photo_checks` 의 상태·이력은 바꾸지 않는다. 추억 기능은 이 상태를 **읽기만** 하고, `photo`·`excluded` 등을 쓰거나 우회해 바꾸지 않는다. 날짜별 사진 타임라인의 노출 조건도 그대로다.
  - **별도 자격(B안):** 추억 분석에 쓸 수 있는지는 `family_memory` 가 따로 계산·기록하는 **분석 자격**으로 정한다(판별 상태와 별개의 판정, 판정 근거·버전 기록). 자격이 있는 사진도 날짜별 타임라인에 개별로 나오지 않고, **게시된 추억 카드 안에서만** 보인다.
  - **두 단계:**
    - **E0(임시 검증):** 업로더가 이미 `photo` 로 확인한 사진만 자격을 가진다. 파이프라인과 카드 품질을 내부에서 검증하는 단계이며 **최종 UX 가 아니다.**
    - **E1(최종 목표):** 사전 동의가 끝난 가족에서 개별 확인·생성 승인 없이 카드를 자동 게시한다. `unsure` 사진을 자격에 넣는 것은 D-13 의 완화가 아니라 **새로운 자동 공개 경로**이며, 아래 전환 조건을 모두 충족하고 소유자가 별도로 승인하기 전에는 열지 않는다.
  - **E1 의 자격(제안, 안전성 평가 통과가 전제):** 아래를 **모두** 만족해야 한다. OCR 글자 없음이나 SigLIP2 문서 유사도 낮음 하나만으로 자격을 주지 않는다.
    1. 동의 사슬(서버 스위치·가족 활성화·업로더 동의·사진별 제외 아님)과 가족 전체방·삭제 안 됨·타임라인 제외 아님.
    2. 판별 상태가 `document`·`failed`·`pending` 이 아니고, 판별 세부 결과(글자 없음/애매/Claude 불확실)가 기록돼 있음. 글자가 읽힌 `unsure`(애매) 사진은 제외.
    3. 문서 안전 신호 여러 개가 모두 통과(OCR 글자 수, 문서·스크린샷 유사도, 화면 비율 등 별도 신호; 구체 목록과 기준값은 안전성 평가 문서에서 확정).
    4. 같은 업로드 묶음(`batch_id`)·가까운 시각에 올린 사진 중 하나라도 문서 의심이면 그 묶음 전체 제외(여러 쪽 문서 누출 방지).
    5. 게시 직전 재확인에서 위 조건이 그대로임.
  - **E0 → E1 전환(모두 충족):** ① 카드 품질 게이트 통과 ② 독립 문서 누출 안전성 평가 통과 — **개발 단계 검증 기준(예: 부정 사례 400장 0건)은 규칙이 작동하는지 보는 초기 문턱일 뿐 자동 공개의 안전성 증거가 아니며, E1 최종 게이트(위험 허용 기준·독립 평가 규모·다양한 부정 유형 군집 기준)는 별도 정책 승인으로 정한다.** 기준은 평가셋 실행 전에 고정하고 평가셋은 개발·임계값 설정에 쓰지 않는다. 일반 사진 자격 통과율은 안전성이 아닌 사용성 지표다 ③ 동의받은 가족 파일럿의 그림자 모드(자격만 판정·기록, 게시 안 함) 사후 검토 결과 누출 0 ④ 개인정보 고지(T31·Play 양식) 갱신 ⑤ 즉시 중지 스위치와 롤백 시험 ⑥ 소유자의 별도 승인 ⑦ 단계 롤아웃(파일럿 가족 → 일부 → 전체, 단계마다 지표 확인). 구체 수치는 `auto-memory-safety-eval.md`.
  - **운영 중 안전:** 카드의 사진마다 "문서·개인정보가 있어요" 신고를 둔다. 신고되면 그 카드를 즉시 숨기고 해당 사진을 AI 분석에서 제외하며, 누출로 확인되면 자동 게시를 즉시 멈추고 원인을 분석한 뒤 다시 평가한다.
  - **동의·권한(ADR 0020 과 같은 틀, 추가 사항만):** 업로더별 분석 동의와 사진별 제외, 소급 분석은 업로더의 별도 명시 동의가 있을 때만(기본 꺼짐). 가족 전체에 게시된 카드의 **숨김·삭제는 가족 소유자와 관리자**가 한다. 업로더는 자기 사진의 분석 제외만 할 수 있고, 제외로 카드 조건이 깨지면 카드를 숨기거나 갱신한다. 카드 숨김은 채팅 원본 사진 삭제와 다른 기능이다. 철회·제외는 분석 시작·결과 저장·카드 게시 직전에 다시 확인한다.
  - **자동 생성 한도(임시 실험값):** 가족당 새 카드 게시는 7일에 최대 2개. 평가 결과로 조정한다. 갱신·재생성은 한도에 세지 않는다. 기준에 맞는 묶음이 없으면 카드 0개가 정상이다.
  - **규칙 기반 제목·이야기의 자동 생성(T41 변경안):** LLM 을 쓰지 않는 규칙 기반 문장은 검증된 facts 만으로 자동 생성을 허용하는 방향으로 한다. 정책 변경은 이 ADR 승인 뒤 `timeline.md` T41 에 반영한다(이번 PR 은 변경안만 적는다). 요청 때만 만드는 AI(LLM) 이야기는 그대로다.
  - **ADR 0020 과의 관계:** 0020 의 "분석 대상: 상태 `photo` 사진뿐"은 E0 에 해당한다. E1 은 이 ADR 이 정한 자격을 따르도록 0020 의 해당 문장을 수정한다(같은 PR). 0020 의 3중 조건, 철회, 가족 비활성화, 로그 금지는 그대로다.
- 이유:
  - 개별 확인을 계속 요구하면 "채팅에 올리기만 하면 가비가 알아서 추억을 만든다"는 목표가 이뤄지지 않는다. 반대로 문서가 추억에 섞이면 개인정보 사고라, 자동 공개는 증거가 갖춰진 뒤에만 열어야 한다.
  - 판별 상태에 자동 `photo` 를 만들면 날짜별 타임라인에도 같은 위험이 번지고, 평가·롤백이 어렵다. 별도 자격은 스위치 하나로 끌 수 있고 기존 타임라인과 D-13 시험을 건드리지 않는다.
  - 이전 실험(미탐 2.3%, 독립 장면 33개)과 서비스에 쓸 수 있는 학습 가중치·데이터 라이선스 부재로 지금은 자동 공개의 근거가 없다.
- 대안:
  - **A안(D-13 수정, 안전한 일부 자동 `photo`):** 위험이 날짜별 타임라인까지 번지고 근거가 부족해 채택하지 않는다.
  - **E0 를 최종 UX 로 유지(항상 업로더 확인):** 안전하지만 제품 목표를 이루지 못해 채택하지 않는다.
  - **유예 공개(일정 시간 뒤 자동 공개):** 누출 위험은 같고 사용자가 모르게 공개돼 채택하지 않는다.
- 결과·주의:
  - 이 ADR 병합만으로 운영에 아무 일도 일어나지 않는다. 모든 단계의 구현 PR 은 각각 별도 승인을 받고, 공용 DB 반영은 DB 담당자 승인 뒤에만 한다.
  - 자격 판정과 생성 결정(기준값·사유)은 기록하되 사진 내용·글자·임베딩을 로그에 남기지 않는다.
  - 철회 시 새 분석과 공개는 즉시 차단하고, 활성 저장소의 파생 데이터 물리 삭제 목표는 24시간(제안)이다. 백업은 별도로 만료·복원 시 재삭제 절차를 정의한다. 가족 탈퇴 시 해당 업로더의 분석은 즉시 중단하고 관련 카드를 숨기거나 재구성하며, 원본 채팅 사진은 D-7·채팅 데이터 보존 정책 확인 뒤 처리한다.
  - 미결정(별도 정책 승인 필요): **E1 최종 안전 기준(위험 허용 기준)과 독립 평가 규모**, 동의 기록 보관 기간(법적·운영 검토), 24시간 삭제 목표의 확정과 백업 절차, 원본 채팅 사진의 탈퇴 처리, 소급 분석 화면·고지.
  - 관련: ADR 0020, ADR 0015, `docs/requirements/timeline.md`(T05 D-13, T41, T42).
