# 0024. 로컬 OCR(RapidOCR)을 서비스에서 제거하고, 사진 분류는 SigLIP2 단독으로 하며, 메인 AI 직접 업로드(기존 유지)와 가족 소통 채팅방 자동 처리(동의 검사 강화)의 정책을 분리한다

- 날짜: 2026-11-23
- 상태: **결정됨(사용자). 운영 활성화는 승인되지 않았다.** `margin > 5` 의 **실제 한국어 문서 검증은 미완료**다. 병합은 Draft PR #520 의 미해결 항목(아래 "아직 결정·완료되지 않은 것")을 정한 뒤에 한다.
- 대체 관계: [0015](0015-family-room-photo-to-library.md) 의 "판별은 로컬 OCR + Claude(haiku)"와 "결정 (2026-11-10)", [0014](0014-upload-llm-ocr-masking.md) 의 "갱신 (2026-11-10)" 중 **가족 소통 채팅방의 문서·사진에 한해** "AI 동의를 확인하지 않는다"를 대체한다. **메인 AI 직접 업로드는 2026-11-10 결정 그대로 유지한다.** 가족방 문서 사진을 문서함에 자동 등록한다는 큰 결정과 1:1 방 사진·파일을 어디에도 넘기지 않는다는 결정도 그대로다.

## 결정 (사용자, 2026-11-23)
1. **로컬 OCR(RapidOCR PP-OCRv5 한국어)을 서비스에서 제외한다.** 사진 분류는 SigLIP2 ONNX, 문서 내용 추출은 Claude(`INGEST_LLM_OCR=true` 필수)가 한다. 코드는 `rapidocr` 를 import 하지 않고 의존성도 뺐다.
2. **사진 분류는 SigLIP2 단독**이다: margin > 5 이면 `document`, 아니면 `unsure`(`failed` 는 점수를 못 낸 경우). 일반 사진을 자동으로 `photo` 로 확정하지 않는다(D-13). 5 는 평가의 `T_RESCUE` 를 재사용한 **초기 기준**이다(새로 맞춘 값이 아니고, 이 작업에서 바꾸지 않았다).
3. **처리 목적에 따라 외부 AI(Claude·Jev) 전송 정책을 분리한다**(둘 다 사용자 결정):
   - **메인 AI 직접 업로드(`/ai-assistant/files`) — 기존 기능 유지.** 사용자가 메인 AI 에서 직접 올린 사진·PDF·문서는 지금처럼 Claude 가 읽고, Claude 가 개인정보를 가리고, 분류(Jev 포함)·챙길 일 뽑기를 한다. 가족 AI 동의 검사를 하지 않으며 이 PR 이 새로 403 으로 막지 않는다. 메인 AI 자체의 인증·AI 이용 조건·개인정보 보호 정책은 바꾸지도 우회하지도 않았다.
   - **가족 소통 채팅방 자동 처리 — 가족 AI 동의가 있을 때만 외부로 보낸다.** 문서 사진 자동 등록, "문서로 저장", 재검사, 채팅 문서(PDF·PPT 내부 이미지 포함)의 읽기·가리기·분류·챙길 일 모두 같다. 동의가 없으면 외부로 보내지 않고, **사진·문서 모두 채팅 원본 첨부는 그대로 두되 AI 문서함·지식베이스 자동 등록은 보류한다**(사용자 결정 2026-11-23, 선택지 (a)). 로컬 규칙으로만 가린 문서는 이름·주소가 남으므로 AI 검색 지식베이스에 등록하지 않는다. 동의를 켠 뒤에도 자동으로 다시 처리하지 않고 사용자가 명시적으로 다시 처리한다. 외부로 보낸 뒤 마스킹하는 것으로는 동의 문제가 풀리지 않으므로 **보내기 전에** 막는다.
   - 일반 가족 채팅 메시지와 소통 에이전트의 기존 개인정보 처리 정책은 바꾸지 않았다.
4. **처리 목적은 서버의 신뢰 가능한 호출 경계가 정한다**(아래 "구현"). 공통 처리 엔진(`files.process_file`)은 그대로 하나만 쓴다.
5. **fail-closed**: `external`(동의)은 `ingest_file`·`preprocess` 의 필수 인자이고 하위 함수 기본값은 False 다. 끼워 넣은 Jev 도 동의 없이는 부르지 않는다.
6. **배포 전략은 S1 + S2**다([구현 현황](../features/ai_assistant-ingest.md) "기능 OFF 동작과 배포 전략"): 활성화 준비(모델 배포, 정책·평가 결정)가 끝난 뒤 #520 을 병합하고(S2), 모델 포함 이미지와 `PHOTO_CLASSIFY_SIGLIP=true`·`INGEST_LLM_OCR=true` 를 **같은 리비전**으로 배포한다(S1).
7. 사진 판별에 Claude 를 쓰던 `PHOTO_JUDGE_LLM` 은 쓰지 않는다(값 무시).

## 2026-11-10 결정과 달라지는 범위 (정확히)
2026-11-10 결정은 "가족방 문서·사진을 읽고 가리는 단계에 채팅 문서만 따로 AI 동의를 확인하지 않는다(AI 채팅 업로드 `files.process_file` 에도 동의 확인이 없다)"였다.

## 구현: 처리 목적(`files.Purpose`)
- `files.process_file(..., *, purpose)` 의 `purpose` 는 **필수 키워드 인자(기본값 없음)** 다. 두 값뿐이다: `MAIN_AI_DIRECT_UPLOAD`, `FAMILY_CHAT_DOCUMENT`. 빠뜨리면 TypeError, 모르는 값이면 ValueError 다.
- **서버 코드가 정한다.** 요청 본문·쿼리·헤더 어디에서도 읽지 않는다. 호출 경계는 둘뿐이다: `/ai-assistant/files` 라우터(→ 메인 AI 목적, 인증·가족 확인 `current_user`·`current_group_id` 유지), `library.py` 의 채팅 문서·사진 등록(→ 채팅 목적, 가족방 권한 검사 유지). 시험이 두 경계의 실제 값, 요청 값 변조, 운영 코드에서 메인 AI 목적을 쓰는 파일(정의와 그 라우터뿐)을 점검한다.
- **짝 검증**: 메인 AI 목적은 채팅 첨부(`source_attachment_id`)가 없어야 하고 채팅 목적은 항상 있어야 한다. 어긋나면 ValueError 라서 채팅 문서를 메인 AI 정책으로 처리하는 오용이 막힌다.
- **동의는 두 겹**(채팅 목적만): 처리 시작 때 읽은 값(`external`)과 외부로 나가기 직전마다 다시 읽는 값(`recheck`)이 모두 참이어야 보낸다. 모르는 목적은 막는다. 메인 AI 목적은 두 겹을 거치지 않는다(기존 정책).
- `external=True` 같은 위험한 기본값은 없다: 진입 함수는 필수 인자, 하위 함수는 기본 False, `_process_once` 의 `purpose` 기본값은 가장 엄격한 쪽(채팅)이다.
- **`require_external`**(채팅 목적만 True): 동의가 막은 외부 단계(읽기·가리기·PPT 그림)를 로컬 규칙으로 대신하지 않고 `consent_required` 로 멈춘다. 그래서 동의가 처리 도중 철회돼도 로컬로만 가린 문서가 등록되지 않는다. 메인 AI 목적과 기존 호출은 기본값 False 라 달라지지 않는다.

## 재노출 차단 (사용자 결정 2026-11-23)
배경: 동의 없이 로컬 규칙으로만 가려 저장된 채팅 문서가 이름·주소를 담은 채 `@가비` 검색 결과로 Claude 에 전송되는 것이 확인됐다.
1. **앞으로 저장되는 기록**: 위 "보류"로 막는다(동의 없는 채팅 문서는 등록하지 않는다).
2. **이미 저장된 기록**: DB 에는 "어떻게 가려졌는지"를 나타내는 칸이 없다(`knowledge_items` 에는 `source_attachment_id`(채팅 첨부 여부), `created_at`, `sensitivity` 뿐). 그래서 새 칸·마이그레이션 없이 알 수 있는 사실로 판단한다: **채팅 첨부에서 만든 기록은 가족 AI 동의가 마지막으로 켜진 시각(`ai_group_settings.updated_at`) 이후에 만든 것만 외부 AI 에 보인다.** 동의가 켜진 채로 만든 채팅 문서는 Claude 가 가렸고, 그 이전 기록은 보호 여부를 알 수 없으므로 뺀다(기본 제외). 동의가 꺼져 있으면 채팅 문서는 모두 뺀다. 채팅 첨부가 아닌 기록(메인 AI 직접 업로드)은 항상 보인다.
3. **적용 지점**: 외부 AI 로 나가는 길인 `@가비`·메인 채팅 도구 4개(`knowledge/tools.py` 의 `search_knowledge`(기록 안 검색 포함)·`get_item`·`list_items`)에만 건다. 앱의 문서함 화면(사용자가 직접 보는 것)은 바꾸지 않았다. 검색은 SQL 조건(`chat_origin_verified`)이라 결과 수가 줄어도 상위 k 가 채워진다.
4. **감수하는 것(보수적 제외)**: 동의를 껐다 다시 켠 가족은 첫 동의 때 올라온 채팅 문서도 "보호 여부 불명"으로 빠진다(안전 쪽 오차). 다시 보이게 하려면 사용자가 파일을 다시 올려 처리해야 한다. 정확히 구분하려면 `knowledge_items` 에 가린 방식을 남기는 칸이 필요하다 — **DB 변경이라 이 PR 에서 하지 않았고 설계·영향을 보고했다**([구현 현황](../features/ai_assistant-ingest.md) "후속 설계").

## 가리기 필수: MASK OFF 재노출 결함 (사용자 승인 2026-11-23)
결함: `INGEST_LLM_MASK=false` 이면 `_mask` 가 동의 검사 전체를 건너뛰고 로컬 규칙(일반 문서는 주민등록번호 등만 가림)으로 대신했다. 그래서 가족 AI 동의가 **켜져 있어도** 채팅 문서가 이름·주소·전화번호를 담은 채 등록됐고, 등록 시각이 동의 시각 뒤라 재노출 차단 필터도 통과해 `@가비` 검색으로 Claude 에 전송됐다(재현: TXT·PDF × OCR ON/OFF 4조합 모두).
수정: 채팅 처리 목적(`require_external=True`)에서 실제 Claude 가리기가 꺼져 있으면 등록하지 않는다(fail-closed, 실패 코드 `masking_unavailable`, 재시도하지 않음).
- `ingest/service.py`: `preprocess` 시작(읽기·OCR 같은 외부 호출 전)과 `_mask`(공통 단계) 두 곳에서 막는다. 로컬 규칙으로 대신하지 않는다.
- `library.py`: `register_chat_document`·`register_chat_photo` 진입에서 파일 받기·판별·외부 호출 전에 멈춘다(채팅 첨부·판별 상태는 그대로).
- `photo_service.save_to_library`(수동 "문서로 저장"): 503 `masking_unavailable`, 판별 상태도 바꾸지 않는다.
- **메인 AI 직접 업로드는 바뀌지 않는다**(`require_external=False`): 기존 Claude 읽기·가리기·분류 정책을 유지하고, 운영자가 가리기를 껐을 때의 동작도 기존과 같다.
- 시험: `tests/test_chat_masking_required.py`(조합 매트릭스·등록 0건·조각 0건·@가비 전송 내용·동의 OFF·메인 AI·사진 자동/수동·처리 도중 철회). 수정을 되돌리면 실패함을 확인했다.
- **남는 위험(수정으로 보호되지 않음)**: 과거에 MASK OFF 로 이미 등록된 채팅 문서. 기록에 "Claude 로 가렸는지"가 남지 않고 시각 필터는 동의 시각만 보므로 구분하지 못한다. 운영 설정 이력을 확인하지 못했으므로 기존 기록이 안전하다고 단정하지 않는다. 확인 절차는 [구현 현황](../features/ai_assistant-ingest.md) "MASK OFF 로 이미 저장된 기록 확인 절차". 정확한 해결(`masked_by` 칸)은 DB 변경이라 이 PR 에서 하지 않았다.

## 이유
- 로컬 OCR 은 사진 한 장에 6~200초가 걸리고 큰 이미지 메모리를 쥐어서, 2GiB·1 vCPU 에서 SigLIP2 와 함께 돌릴 때 동시 업로드로 OOM 이 났다(2026-11-23 로컬 Docker 시험: OCR+SigLIP2 동시 12장에서 OOMKilled 2회, OCR 을 뺀 뒤 같은 조건에서 0회. 합성 이미지·n=1·Cloud Run 아님).
- OCR 한국어 인식 모델은 패키지에 들어 있지 않고 첫 호출 때 외부(modelscope.cn)에서 내려받는다 — 외부망이 없으면 모든 사진이 실패한다.
- 가족 소통 채팅방은 구성원이 올린 사진·문서가 자동으로 가족 전체의 문서함에 모이므로, 동의가 없는 가족의 사진·문서를 외부로 보내는 것은 개인정보 보호 원칙에 어긋난다. 반면 메인 AI 직접 업로드는 사용자가 AI 에게 읽게 하려고 직접 올리는 기능이라 기존 정책(공지로 알림, ADR 0014)을 유지한다.

## 감수하는 것·알려진 한계
- 정확도 기준이 바뀐다. 공개 독립 Test 123장에서 문서 재현율 42/42 → 39/42(93%), 일반→문서 오분류 0/81 은 같다. 놓친 문서는 `unsure` 로 남아 업로더가 확인한다. **실제 한국어 문서·가족 사진은 평가하지 못했고, 합성 한국어 문서의 margin 이 5.48~6.55 로 기준 바로 위에 몰려 있다.**
- `PHOTO_CLASSIFY_SIGLIP` 가 꺼져 있으면 모든 사진이 `unsure` 가 되어 문서 자동 등록이 멈춘다.
- **동의 때문에(또는 스위치 OFF 로) `unsure` 가 된 채팅 사진은 자동으로 다시 판별되지 않는다.** 재검사는 실패·지연 사진만 되므로, 동의를 켠 뒤에는 수동 "문서로 저장"을 써야 한다.
- **(고침) 동의 없이 로컬 가리기로 저장된 채팅 문서의 재노출**: 앞으로는 등록하지 않고(보류), 이미 저장된 기록은 동의 켜진 시각 이전 것을 외부 AI 검색에서 제외한다(위 "재노출 차단"). 남은 한계는 그 시각 기준이 보수적이라 정상 문서도 일부 빠질 수 있다는 점이다.
- **보류된 채팅 문서는 동의를 켜도 자동으로 등록되지 않는다.** 채팅 문서(PDF·글 등)에는 "문서로 저장" 같은 명시적 재처리 경로가 없어(`POST /family-chat/files`·조회만 있다) 지금은 **같은 파일을 다시 올려야** 한다. 문서용 "문서함에 저장" 요청 하나를 추가하는 것이 최소 변경안이다(보고 참고, 이 PR 에서는 하지 않았다).
- 처리 도중 철회해도 **이미 나간 호출**(한 번에 보낸 PDF 쪽 묶음 등)은 되돌릴 수 없다. 철회 뒤에 남은 단계만 막는다.
- **메인 AI 직접 업로드는 가족 AI 동의와 무관하게 외부 AI 로 간다**(기존 정책 유지). 보안 보고서의 "동의 없는 Jev 전송" 항목은 이 경로에 한해 "정책으로 유지"로 바꿨다. 이 경로에 동의 검사를 넣을지는 별도 정책 결정이다.

## 아직 결정·완료되지 않은 것 (운영 차단 조건)
- **운영 활성화는 승인되지 않았다.** `PHOTO_CLASSIFY_SIGLIP` 는 기본 꺼짐이고 운영에서 켜지 않았다.
- `margin > 5` 의 **실제 한국어 문서·가족 사진 검증은 미완료**다(평가 조건은 PR #520 본문). 임계값 재검토.
- Cloud Run: 요청 기반 CPU 에서 응답 뒤 작업이 멈추는 문제, 운영 NER 모델의 버전·SHA-256 확인.
- 실제 서비스의 **동의 문구와 개인정보처리방침**(별도 확인이 필요하다. 이 작업에서 바꾸지 않았다). 메인 AI 업로드 파일이 외부 AI 로 전송된다는 고지는 ADR 0014 대로 처리방침·스토어 양식에 의존하며 앱 안에 별도 안내가 없다(기존과 같다, 일치 여부 확인 필요).
- 위 "알려진 한계"의 보류 사진·문서의 명시적 재처리 경로(문서용), 가린 방식을 남기는 DB 칸(정확한 구분, 마이그레이션 설계 승인 필요), 동의 철회 시 이미 등록된 문서의 처리(이전부터 규칙이 없다).
- 앱 후속 작업(403·429·503 안내, 보류 사유 표시, 채팅 안내문 갱신).
