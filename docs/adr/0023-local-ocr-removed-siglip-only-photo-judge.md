# 0023. 로컬 OCR(RapidOCR)을 서비스에서 제거하고, 사진 분류는 SigLIP2 단독·문서 읽기는 Claude 만 쓰며, 동의 없는 가족의 외부 AI 전송을 막는다

- 날짜: 2026-11-23
- 상태: **결정됨(사용자). 운영 활성화는 승인되지 않았다.** `margin > 5` 의 **실제 한국어 문서 검증은 미완료**다. 병합은 Draft PR #520 의 미해결 항목(아래 "아직 결정·완료되지 않은 것")을 정한 뒤에 한다.
- 대체 관계: [0015](0015-family-room-photo-to-library.md) 의 "판별은 로컬 OCR + Claude(haiku)"와 "결정 (2026-11-10)", [0014](0014-upload-llm-ocr-masking.md) 의 "갱신 (2026-11-10)" 중 **"채팅 문서만 따로 AI 동의를 확인하지 않는다"** 를 대체한다. 가족방 문서 사진을 문서함에 자동 등록한다는 큰 결정과 1:1 방 사진·파일을 어디에도 넘기지 않는다는 결정은 그대로다.

## 결정 (사용자, 2026-11-23)
1. **로컬 OCR(RapidOCR PP-OCRv5 한국어)을 서비스에서 제외한다.** 사진 분류는 SigLIP2 ONNX, 문서 내용 추출은 Claude(`INGEST_LLM_OCR=true` 필수)가 한다. 코드는 `rapidocr` 를 import 하지 않고 의존성도 뺐다.
2. **사진 분류는 SigLIP2 단독**이다: margin > 5 이면 `document`, 아니면 `unsure`(`failed` 는 점수를 못 낸 경우). 일반 사진을 자동으로 `photo` 로 확정하지 않는다(D-13). 5 는 평가의 `T_RESCUE` 를 재사용한 **초기 기준**이다(새로 맞춘 값이 아니고, 이 작업에서 바꾸지 않았다).
3. **가족 AI 동의가 없는 가족의 외부 AI(Claude·Jev) 전송을 전반적으로 막는다(A안).** 사진·스캔 이미지는 물론 글 가리기·분류·PPT 그림 설명·챙길 일 뽑기도 동의가 있을 때만 쓴다. 글자를 외부로 보낸 뒤 마스킹하는 것으로는 동의 문제가 풀리지 않으므로 **보내기 전에** 막는다. 동의를 처리 시작 때뿐 아니라 **외부로 나가기 직전마다** 다시 읽어 처리 도중 철회를 반영한다.
4. **fail-closed**: `external`(동의)은 서비스 진입 함수(`ingest_file`·`preprocess`)의 **필수 인자**(빠뜨리면 TypeError)이고, 하위 함수 기본값은 False 다. 끼워 넣은 Jev 도 동의 없이는 부르지 않는다. 운영 코드의 호출처가 `external=` 를 넘기는지 시험이 점검한다.
5. **배포 전략은 S1 + S2**다([구현 현황](../features/ai_assistant-ingest.md) "기능 OFF 동작과 배포 전략"): 활성화 준비(모델 배포, 정책·평가 결정)가 끝난 뒤 #520 을 병합하고(S2), 모델 포함 이미지와 `PHOTO_CLASSIFY_SIGLIP=true`·`INGEST_LLM_OCR=true` 를 **같은 리비전**으로 배포한다(S1).
6. 사진 판별에 Claude 를 쓰던 `PHOTO_JUDGE_LLM` 은 쓰지 않는다(값 무시).

## 2026-11-10 결정과 달라지는 점
| 항목 | 2026-11-10 (ADR 0015·0014) | 이 ADR |
|---|---|---|
| 가족방 문서·사진을 읽고 가리는 단계의 동의 확인 | 하지 않는다(AI 채팅 업로드와 같은 방식) | **한다**: 동의가 없으면 외부로 보내지 않는다 |
| 직접 올리기 `/ai-assistant/files` | 동의 확인 없음 | 사진은 403 `ai_consent_required`, 글·PDF 는 받아서 로컬 처리 |
| 글 가리기·분류(Jev)·챙길 일·PPT 그림 설명 | 동의와 무관하게 외부 | 동의가 있을 때만 |
| 사진 판별 | OCR + (동의한 가족만) Claude 판별 | 로컬 SigLIP2 단독, 사진을 외부로 보내지 않음 |
| 처리 도중 철회 | 해당 없음 | 외부로 나가기 직전마다 재확인(이미 나간 호출은 되돌릴 수 없다) |

## A안 적용 범위
| 경로 | 동의 없을 때 |
|---|---|
| 가족방 사진 자동 등록 | 판별은 로컬로 하되 `document` 를 `unsure` 로 낮춘다. **사진은 채팅에 남고 문서함 자동 등록은 보류**한다 |
| "문서로 저장"(`save_to_library`) | 403 `ai_consent_required`(이미 등록된 사진은 `already`) |
| 사진 직접 업로드 | 403 `ai_consent_required` |
| 글·PDF·PPT·문서 파일(직접 올리기·채팅 문서) | 받는다. 글자 층·텍스트만 읽고 로컬 규칙으로 가린다. 스캔 쪽·PPT 그림은 읽지 않는다. 분류는 규칙·분류기, 못 정하면 사람 확인 |
| 재검사 | 판별은 로컬로 다시 하고, 문서여도 `unsure` 로 보류한다(외부 전송 없음) |
| 메인 채팅·knowledge ask·주간 뉴스·놀이 사진 추천 | 기존 동의 검사 그대로(이번에 바뀐 것 없음) |

## 이유
- 로컬 OCR 은 사진 한 장에 6~200초가 걸리고 큰 이미지 메모리를 쥐어서, 2GiB·1 vCPU 에서 SigLIP2 와 함께 돌릴 때 동시 업로드로 OOM 이 났다(2026-11-23 로컬 Docker 시험: OCR+SigLIP2 동시 12장에서 OOMKilled 2회, OCR 을 뺀 뒤 같은 조건에서 0회. 합성 이미지·n=1·Cloud Run 아님).
- OCR 한국어 인식 모델은 패키지에 들어 있지 않고 첫 호출 때 외부(modelscope.cn)에서 내려받는다 — 외부망이 없으면 모든 사진이 실패한다.
- 운영의 읽기·가리기가 이미 Claude 중심이라 로컬 OCR 은 사진 판별에만 남아 있었다.
- 동의가 없는 가족의 사진·문서를 외부로 보내는 것은 개인정보 보호 원칙에 어긋나고, 기존 보안 보고서도 "동의 없는 Jev 전송"을 중간 결함으로 지적했다.

## 감수하는 것·알려진 한계
- 정확도 기준이 바뀐다. 공개 독립 Test 123장에서 문서 재현율 42/42 → 39/42(93%), 일반→문서 오분류 0/81 은 같다. 놓친 문서는 `unsure` 로 남아 업로더가 확인한다. **실제 한국어 문서·가족 사진은 평가하지 못했고, 합성 한국어 문서의 margin 이 5.48~6.55 로 기준 바로 위에 몰려 있다.**
- `PHOTO_CLASSIFY_SIGLIP` 가 꺼져 있으면 모든 사진이 `unsure` 가 되어 문서 자동 등록이 멈춘다.
- **동의 때문에(또는 스위치 OFF 로) `unsure` 가 된 사진은 자동으로 다시 판별되지 않는다.** 재검사는 실패·지연 사진만 되므로, 동의를 켠 뒤에는 수동 "문서로 저장"을 써야 한다.
- **동의 없이 로컬 가리기로 저장된 문서는 이름·주소가 남고, 나중에 동의를 켜고 AI 비서가 조회하면 그대로 Claude 로 간다.** 메인 채팅은 조회한 문서를 다시 가리지 않는다(ADR 0014: 보호를 저장 때의 Claude 가리기에 맡겼다). 시험(`test_consent_ingest_flow.py`, xfail strict)으로 기록했고 **아직 고치지 않았다**(선택지는 구현 현황 문서).
- 동의가 없는 가족의 문서는 규칙 가리기라 Claude 가리기보다 덜 가린다. 스캔 PDF 쪽·PPT 그림은 읽지 못한다.
- 처리 도중 철회해도 **이미 나간 호출**(한 번에 보낸 PDF 쪽 묶음 등)은 되돌릴 수 없다. 철회 뒤에 남은 단계만 막는다.

## 아직 결정·완료되지 않은 것 (운영 차단 조건)
- **운영 활성화는 승인되지 않았다.** `PHOTO_CLASSIFY_SIGLIP` 는 기본 꺼짐이고 운영에서 켜지 않았다.
- `margin > 5` 의 실제 한국어 문서·가족 사진 검증(평가 조건은 PR #520 본문), 임계값 재검토.
- 실제 서비스의 **동의 문구와 개인정보처리방침** 반영(별도 확인이 필요하다. 이 작업에서 바꾸지 않았다).
- 위 "알려진 한계"의 보류 사진 재판별·로컬 가리기 문서의 재보호, 동의 철회 시 이미 등록된 문서의 처리(이전부터 규칙이 없다).
- 요청 기반 CPU(Cloud Run 응답 뒤 작업이 멈춘다), 운영 NER 모델의 버전·SHA-256 확인.
- 앱 후속 작업(403·429·503 안내, 보류 사유 표시, 안내문 갱신).
