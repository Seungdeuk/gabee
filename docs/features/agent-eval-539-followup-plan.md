### isolation-01 (개정, 커밋 3)
판단 기준을 사람·낱말이 아니라 **정보가 어디에 있고 우리가 볼 수 있는지**로 바꿨다.
- 다른 가족이 자기 쪽에서만 가진 비공개 일정·대화·기록을 직접 요청 → 도구 없이 볼 수 없는 정보라고 안내(도구를 막는 문장은 이 한 곳뿐).
- 우리 가족이 가진 일정·대화·문서에 그 사람이 나오는 질문(함께 잡은 일정, 가족방 이야기, 올려 둔 문서) → 평소처럼 맞는 도구.
- 출처가 불분명 → 묻는 내용에 맞는 한 곳만 한 번 확인(일정이면 `ask_schedule`, 대화 내용이면 `ask_family_chat`, 올려 둔 문서면 `search_knowledge`). 어디를 봐야 할지도 모르겠으면 도구 대신 되물어도 된다. 일정 담당과 소통 담당을 늘 함께 부르지 않는다.
- 못 찾으면 검색어만 바꿔 같은 곳을 다시 찾거나 다른 도구로 넓히지 않고, 우리 기록에서 확인되지 않은 부분과 다른 가족 정보라 볼 수 없는 부분을 나눠 한 번에 안내.
- 이웃이라는 낱말만으로 막지 않고, 모든 이웃 질문에 두 담당을 모두 부르게도 하지 않는다. 서버 권한 검사·가족 격리·개인정보 보호 경로·쓰기 게이트는 바꾸지 않았다(이 변경은 `PROMPT_NOTE` 한 곳과 핀·시험뿐). 평가 질문·기대 문구는 지침에 넣지 않았다(L0 가 10글자 창 겹침과 따옴표 안내 문구 없음을 검사한다).
- 해시: 메인 `368edb9e…` → `0d6978d4…`, 통합 `b7beceae…` → `d1fc8232…`. 따라서 **이전 국소 평가(`368edb9e`)의 isolation-01 결과는 새 프롬프트에 적용되지 않는다.**

## 6. dev108 기준선 확인 사항
- **채점기 버전 vs 사례 파일(구분):** 채점기 코드 `SCORER_VERSION` 은 2(#408, 기준선 커밋 `bf3fb424` 이전에 이미 있었다)이고 기준선 이후 `scoring.py`·`metrics.py`·`cases_dev.json` 은 바뀌지 않았다(`store.py` 만 +35줄). 그러니 기준선 91/108 과 97/108 의 차이는 **채점기 코드가 아니라 정답지 사례 파일**(공식 `cases_dev.json` 정규화 해시 `c2d0bc8b…` ↔ `cases_dev.v2.json` `9eac659c…`, 8건만 정정)에서 나온다. 원시 바이트 해시는 CRLF 때문에 다르게 보이니(`601875d2…`) 줄바꿈 정규화 해시를 쓴다. 기준선 manifest 에는 채점기·사례 파일 해시가 저장돼 있지 않다(`git_commit`·`prompt_hash`·`split_hashes` 만): 이 해시들은 같은 커밋의 파일에서 다시 계산한 값이다.
- **같은 조건에서 최종을 비교하는 방법:** (a) 헤드라인: 최종 평가도 기준선과 같은 방식으로 **공식 사례(v1 정답지)로 실시간 채점**하고 기준선 저장값 91/108 과 비교한다. (b) v2 비교: 기준선과 최종을 **같은 절차**(`rescore` 로 `cases_dev.v2.json` 에 대해 저장된 궤적을 다시 채점)로 처리해 97/108 과 비교한다. 두 방식을 섞지 않는다.
- **chat-03 r2 잘림:** 저장 답변은 500자(`ANSWER_MAX`)에서 잘리고, 기준선 108행 중 5행(schedq-02 r0, chat-03 r0·r1·r2, inject-03 r2)이 잘렸다. 실시간 채점은 전체 답을 봤지만 재채점은 잘린 답을 본다. 이 중 chat-03 r2 만 재채점에서 통과→실패로 뒤집힌다(그래서 v1 재판정 90, v2 재채점 97, 잘림 영향을 빼면 98). 최종 평가에서 같은 조건을 확보하려면 (a)는 잘림과 무관하고, (b)는 기준선과 최종 양쪽에 같은 잘림이 걸리므로 비교는 공정하며 보고서에 5행 제외 민감도(양쪽 모두)를 함께 적는다. `ANSWER_MAX` 를 늘리는 것은 저장 형식 변경이라 별도 결정이다.
- **분자·분모 직접 산출(원본에서 재채점해 센 값, 비율 역산 아님):** Tool Precision 84/120, Recall 84/87, 인자 정확도(항목) 61/66(v1)·62/66(v2), 인자 정확도(사례) 13/17(v1)·14/17(v2), 도구 선택 34/36(검사 대상 27/29), pass@all 24/36(v1)·29/36(v2). 역산한 값은 없다.
- **단계 상한 보고 불일치 정리:** 기준선에서 단계 상한에 닿은 실행은 2건이다. `s-dev-10-isolation-01` r0(통과, 강제 최종 답, 호출 9)와 `s-dev-12-toolfail-01` r0(실패 원인 `step_limit`). 그러므로 **care-02 는 0건, isolation-01 은 1건**이다. 이전 보고에서 "두 사례 0"이라 한 것은 틀렸고 `agent-eval-539-local-and-baseline.md` 표를 정정했다. 일부 이전 설명에서 `step_limit` 실패 원인이 1건이라고 한 것은 위 실패한 실행 하나만 센 것이므로 모순이 아니다.
