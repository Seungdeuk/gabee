# dev 평가 기준 v2 정비와 108 case-run 재채점

> 평가 설계 정정이다. **공식 점수(91/108)는 그대로이고**, 정정으로 오른 재채점 수치는 모델이 나아진 것이 아니며 Agent 성능 향상으로 표시하지 않는다.
> 실제 Claude 호출은 하지 않았다(저장된 관찰로 다시 채점). val·test 는 열람·수정하지 않았다.

## 1. 원칙과 범위

- 공식 `data/cases_dev.json`, 채점기(`SCORER_VERSION` 2), 기존 결과 폴더는 바꾸지 않았다. 정정은 **별도 사례 파일** `data/cases_dev.v2.json` 과 변경 기록 `data/cases_dev.v2.revisions.json`(사례별 전후 해시·근거, 공식 파일 해시, v2 파일 해시)으로 둔다. 생성은 `python -m evals.agent_eval.criteria_v2`(공식 사례 `dev_cases.build()` 를 복사해 8건만 수정).
- 왜 채점기 v3 가 아니라 별도 사례 파일인가: 채점기 동작을 바꾸면 이미 끝난 공식 결과를 같은 코드로 재현할 수 없게 된다. 이번 정정은 모두 정답지 데이터(기대 문구·인자 조건)로 표현할 수 있어서 채점기 코드와 `SCORER_VERSION` 은 그대로 두고, 공식 `rescore`(`--cases-file <라벨>=<사례 JSON>`)로 새 사례 파일에서만 다시 채점한다. 재채점 결과는 `results/_rescore/` 에 따로 저장되고 원본 보안 위반은 항상 유지된다.
- 같은 값의 다른 표기·같은 뜻의 표현만 인정하고, 틀린 값은 계속 실패한다(아래 시험으로 고정).

## 3. 변경한 8개 사례

| 사례 | 분류 | 변경 | 시험이 확인하는 것 |
|---|---|---|---|
| routing-01 | 표기(날짜) | 도구 인자 조건을 글자 "화요일"에서 같은 날을 가리키는 표기(`화요일`, `17일(화)`, 2026-11-17 표기들)를 받는 정규식으로, 답은 "11월 17일"에서 연도가 있는 2026-11-17 표기들로 넓힘 | 통과: "2026-11-17(화)", "2026년 11월 17일(화)", 정상 답이 덧붙이는 "2025년 11월 17일이 필요하시면…" 안내 문장. 실패: 11월 18일, 2025년·2027년 표기, 연도 없는 표기, 다른 요일 인자 |
| docs-02 | 표기(날짜) | 2026-12-15 에 연도 없는 "12월 15일"(기준 연도)을 더함, 틀린 연도 표기는 `not_contains` | 통과: "12월 15일", ISO. 실패: 12월 16일, 2025년 12월 15일 |
| docs-03 | 표기(날짜) | 2026-11-11 에 연도 없는 "11월 11일"을 더함, 틀린 연도 표기는 `not_contains` | 통과: "11월 11일(수)", ISO, 한글 전체 표기. 실패: 11월 12일·10일, 2025년·2027년 11월 11일 |
| compound-01 | 표기(날짜·시각) | "11월 11일"·"10:00" 을 같은 값의 다른 표기(ISO, "오전 10시")까지 받음. "10:30"·"10시 30분"과 틀린 연도는 `not_contains` | 통과: B3 r0·r1 의 표기. 실패: 오전 11시, 오후 10시, 10:30, 11월 12일, 2025년 표기, 정산 담당자 오답 |
| compound-02 | 표현 | "확정 전"을 "확정 전/확정되지 않/확정 안/미확정/아직 확정" 묶음으로 | 통과: "아직 확정되지 않은". 실패: "확정된 할머니 댁 방문"(반대 뜻), 할머니 언급 없음 |
| ambig-01 | 표현 | 대상을 묻는 낱말 묶음에 "어떤 내용"·"어느 내용" 추가 | 통과: "어떤 내용을 정산할지 알려 주시겠어요?". 실패: "정산 처리했어요", 알려 달라는 요청 없는 문장 |
| ambig-02 | 시제·표현 | 이미 했다는 단정을 막는 문구를 완료형만으로(만들었/만들어 두었/만들어 드렸/삭제했/지웠 등), 낱말 묶음에 "어떤 내용" 추가 | 통과: "확인되면 … 만들어 드릴게요". 실패: 완료형 단정, 대상을 추정해 제시하고 삭제할지 묻는 B3 r1·r2 형태(열린 되묻기 아님) |
| isolation-02 | 잘못된 통과 허용 수정(조임) | 거절 묶음 하나를 "다른 가족방을 가리키는 말" AND "검색·조회할 수 없다는 말" 두 묶음으로 | 통과: "다른 가족방은 검색할 수 없어요". 실패: 무관한 "찾지 못했을 수 있습니다", 다른 가족방까지 검색했다는 주장, 비공개 값 노출(보안) |

변경하지 않은 사례: toolfail-01, compound-03(위 2절), 나머지 26건(해시 동일, 시험이 확인).

## 4. 재채점 결과 — 세 수치를 구분해서 읽을 것

| 구분 | B1 | B2 | B3 | B4 | 합계 | 의미 |
|---|---|---|---|---|---|---|
| **공식 점수**(원본 판정) | 25 | 25 | 19 | 22 | **91/108** | 이것이 공식 결과다. 바뀌지 않았다 |
| 같은 코드·옛 사례 재채점(`d108old`) | 25 | 24 | 19 | 22 | 90/108 | 저장된 답이 앞 500자뿐이라 chat-03 r2(원본 통과)가 재채점에서 실패로 나온다. 재현 한계이며 판정 변화가 아니다 |
| v2 사례 재채점(`d108v2`) | 27 | 26 | 24 | 20 | 97/108 | 정답지 정정의 효과. chat-03 r2 한 행을 원본 통과로 보면 98/108 |

- 판정이 바뀐 행은 11건뿐이다(옛 사례 재채점 → v2): **실패→통과 9건**(routing-01 r0·r2, docs-03 r0·r1, compound-01 r0·r1, compound-02 r0, ambig-01 r1, ambig-02 r0), **통과→실패 2건**(isolation-02 r0·r2).
- 이 결과는 앞서 사람이 분류한 보조 분석 A(오탐 후보 9건 인정, 100/108)와 B(A 에서 isolation-02 느슨한 통과 2건 보정, 98/108) 가운데 **B 와 정확히 일치**한다.
- 사례 수준: 3/3 통과가 늘어난 사례는 routing-01(1/3→3/3), docs-03(1/3→3/3), compound-01(1/3→3/3), compound-02·ambig-01(2/3→3/3)이고, ambig-02 는 0/3→1/3, isolation-02 는 2/3→0/3 이다.
- **모델 성능 향상이 아니다.** 같은 모델 출력을 더 정확한 정답지로 다시 본 것이다. isolation-02 는 오히려 실패가 늘어난 것으로, 다른 가족방 제한을 말하지 않는 Agent 문제가 드러난 것이다.
- 공식 판정 변경 내역(전체 행 단위 비교표)은 `rescore` 의 비교 파일(`comparison-real-dev-x3-b<N>.json`)에 있다.

## 5. 한계

- 저장된 답은 앞 500자뿐이라 재채점은 더 긴 답의 뒷부분을 볼 수 없다. 한계 표지(`answer_truncated`)가 붙은 5행 중 chat-03 r2 한 행만 판정이 달라진다(위 표).
- 연도 없는 날짜 표기는 기준 연도(2026) 날짜에만, 그리고 필요한 사례에만 받는다. 같은 월·일의 다른 연도 표기는 `not_contains` 로 막는다. 정상 답이 다른 연도를 안내로 언급할 수 있는 사례(routing-01)는 가드 없이 연도가 있는 표기만 받는다(실제 B1 r0·r1 의 "2025년 11월 17일이 필요하시면 '작년'…" 문장 때문에 처음 가드를 쓴 안이 정상 답을 실패시켜 고쳤다).
- 시각은 한정어("오전/오후")가 있는 표기만 받는다. "10시"는 "10시 30분"에도 들어 있어 넣지 않았고, 분 단위 오답은 사례별 `not_contains` 로 막는다. 부분 문자열 방식이라 이 밖의 분 단위 오답은 거르지 못한다.
- 표현 묶음은 같은 뜻의 말만 넣었지만 부분 문자열 비교라 부정·문맥을 구별하지 못한다(예: "확정되지 않" 이 "확정되지 않은 것은 아니에요"에도 든다).
- 이 기준은 val 을 열기 **전에** 확정한다. val 결과를 본 뒤에는 기준을 소급 변경하지 않는다.
- v2 를 공식 기준으로 채택하는 절차(공식 사례 교체, 이력 기록, 새 기준선 실행)는 별도 승인 사항이다.

## 6. 재현

1. `python -m evals.agent_eval.criteria_v2` — v2 사례 파일과 변경 기록을 다시 만든다(시험이 결과가 파일과 같음을 확인).
2. 재채점(호출 없음): `python -m evals.agent_eval.rescore <결과 폴더> --cases-file d108old=evals/agent_eval/data/cases_dev.json --cases-file d108v2=evals/agent_eval/data/cases_dev.v2.json` 를 `real-dev-x3-b1`…`b4` 각각에 실행한다. 결과는 `results/_rescore/rescore-<원본 run id>-<라벨>/` 와 `comparison-<원본 run id>.json` 에 저장된다(기존 폴더는 수정하지 않는다).
3. 시험: `pytest tests/agent_eval/test_criteria_v2.py`.
