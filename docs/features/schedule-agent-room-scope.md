- 그래서 두 사람(A↔B) 사이의 부탁·일정 제목이 방 답·카드·직접 답에 실려 C 에게 보일 수 있었다.

## 수정(서버, 모델 호출 전에 거름 · 메인 프롬프트·NER 가림에 기대지 않음)
- 기준: 가족방에서 다룰 수 있는 데이터는 **방 구성원 모두가 원래 볼 수 있는 것**뿐이다. 가족방 구성원 = 가족 그룹 구성원 전원(`members.load`).
- 부탁: `together.visible_to_all(db, group_id, user_id, member_ids)` — 보낸 사람과 **받는 사람 전원**(서버 안에서 전부 읽음, 밖으로는 id 만)이 구성원 전원을 덮는 부탁만. `request_flow.load(..., room_member_ids=...)` 가 그 밖의 부탁을 목록에서 뺀다. 이 목록이 모델에 주는 줄·허용 id(`clean_fields`)·카드·직접 답의 유일한 출처라, 빠진 부탁은 id·날짜·제목·관계·받는 사람 어느 것도 나가지 않는다. 모델이 목록 밖 id 를 골라도 버린다.
- 일정: `reader.read(..., room_member_ids=...)` — 가족방에서는 `shared` 이면서 나와 공유 관계자(`shared_ids`)가 구성원 전원을 덮는 일정만. 구성원을 모르면 아무것도 남기지 않는다(fail-closed). 조회·재조회(need_wider)·제목으로 찾기·수정/삭제/체크 대상이 모두 이 목록에서 나온다.
- `handler._handle` 이 가족방일 때만 구성원 id 를 두 곳에 넘긴다. 개인 채팅은 그대로(내 부탁 전체·내 일정 전체).
- DB 스키마·API·하위 기능 삭제 없음. 변경 파일: `schedule/together.py`, `schedule/agent/request_flow.py`, `schedule/agent/reader.py`, `schedule/agent/handler.py`.

## 정상 기능 영향
- 개인 AI 채팅의 송수신 부탁 조회·내 일정 전체: 그대로(시험).
- 가족 전원이 받는 부탁, 가족 전원과 공유한 공동 일정, 구성원이 둘인 가족의 서로 공유 일정·부탁: 가족방에서 그대로 조회(시험).
- 가족방에서 **일부 구성원 사이의 부탁·일정은 더 이상 찾지 못한다**(조회·수정·취소 대상에서 빠짐 → "찾지 못했어요"). 그런 작업은 개인 채팅에서 한다. 의도된 보안 쪽 변경이다.
- 가족방 등록(공유 등록)·부탁 보내기(초안)·확인 카드 버튼은 목록과 무관해 그대로다. 1:1 방의 일정 Agent 차단(`agents.call`)도 그대로다.

## 인접 점검
- 습관·데일리 체크: 가족방은 `shared` 습관만 읽고, 습관의 `shared` 는 가족 전체 공개 의미라(구성원 현황) 같은 유형의 결함은 확인되지 않았다(수정하지 않음).
- 부탁 선택 상태(`resolve_choice`/`apply_choice`): 선택지는 같은 채널의 거른 목록에서 만들어지고, 처리 때도 보낸 사람 본인 것만 다룬다. 앱이 직접 보낸 선택(`/schedule/agent` 의 `choice`)은 호출한 사람 본인의 부탁만 다루며 그 응답은 방에 자동 게시되지 않는다(가족방 게시는 `ai_assistant` 방 경로만, 그 경로는 선택을 넘기지 않는다). 남은 위험으로 기록.
- 이전 대화 캐시(`ai_guard` 결과 캐시)는 프롬프트 해시가 키라 거른 목록이 바뀌면 키도 바뀐다.
