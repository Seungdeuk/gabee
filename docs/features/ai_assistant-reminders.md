# 기능 현황: 먼저 챙겨주기 (ai_assistant-reminders)

올린 문서의 날짜에서 챙길 일을 뽑고, 앱을 열 때 가비가 먼저 말을 건다. 결정은 사용자와 정했다(2026-11-05).

## 흐름
1. **뽑기** — 업로드가 저장되면(`INGEST_REMINDERS=true`일 때) Claude 가 문서에서 이미 찾은 날짜 중 챙길 일이 있는 것만 고른다. 일 이름·급함(`urgent`)·며칠 전부터(`lead_days` 1~3)를 정하고, 코드가 날짜가 문서에서 찾은 값인지 확인한다. 일정에는 바로 넣지 않고 `document_reminders` 에 둔다. 일정의 주인은 문서에 가족이 한 명 태그돼 있으면 그 사람, 아니면 올린 사람이다.
   - 뽑기 단계는 LangChain 체인(`doc_ai.REMINDER_CHAIN`: 입력 묶기 | Claude 호출 | 응답 읽기)이며, 날짜 검증·저장은 `reminders.plan` 의 일반 코드다.
2. **앱을 열 때** — 앱이 시작하거나 다른 앱에서 돌아올 때, 그리고 앱이 앞에 떠 있는 동안 5분마다(최소 5분 간격) `POST /ai-assistant/reminders/nudges` 를 불러 가비가 먼저 할 말을 받아 채팅에 넣는다. 백그라운드로 가면 멈추고, 가비가 답하는 중(thinking·reading)에는 건너뛴다. 서버는 한 번 준 말을 다시 주지 않는다.
   - **일정으로 잡을까요?** — 아직 일정에 없는 문서 날짜. 하루 한 번, 최대 3번. 같은 날짜에 같은 일이 이미 일정에 있으면(문서를 올리기 전부터 있었거나 올린 뒤 카드·채팅으로 만든 것) 묻지 않고 그 일정을 이어서 챙긴다. 문서보다 먼저 있던 일정은 일 이름이 겹치거나 시각이 같을 때만 같은 일로 본다.
   - **급한 일 미리 알림** — 일정 시각 기준 24시간 단위. 하루 전이면 24시간 전, 이틀 전이면 48시간 전·24시간 전, 사흘이면 72·48·24시간 전. 시각이 없으면 그날 아침 9시로 센다.
   - **지난 일 확인** — 일정 날짜가 지났는데 체크가 안 되어 있으면 한 번: "하셨나요?"(다시 잡자는 제안은 하지 않는다. 사용자가 먼저 "오늘로 다시 잡아줘"라고 하면 그때 잡는다.)
3. **답 반영** — 사용자가 채팅으로 답하면 모델이 `resolve_reminder`(schedule 일정으로 잡기 · done 했어요 · redo_today 오늘로 다시 잡기 · dismiss 그만 알리기)로 반영한다. 최근 물어본 챙길 일은 시스템 안내에 id 와 함께 붙는다(`REMINDER_NOTE`).

## 켜고 끄기
- 서버 전체: `INGEST_REMINDERS`(기본 false). 꺼져 있으면 아무것도 뽑지 않는다.
- 사람마다: `GET/PUT /ai-assistant/reminders/settings`, 채팅에서 "알림 꺼줘"라고 하면 `set_reminders`. 꺼져 있으면 새로 뽑지도, 말하지도 않는다(기본 켜짐).
- 일정 탭의 습관 체크(데일리 체크)는 대상이 아니다.

## 개인정보
- 일 이름은 가린 글에서 뽑고 `[..]` 표시(가족 이름표 등)를 뺀다. 문구는 고정 템플릿이고 일 이름만 들어간다. 푸시로 나가는 것은 없다(앱을 열 때 채팅에만 나온다).

## 한계·남은 일
- 앱이 열려야 말한다. 푸시(예약 푸시 4단계)가 생기면 `document_reminders` 를 읽게 붙일 수 있다.
- 앱의 켜고 끄기 스위치 화면은 아직 없다(채팅 명령과 API 만 있다).
- 사용자가 직접 만든 일정은 아래 "직접 잡은 일정"의 전날 한 번만 챙긴다.

## 직접 잡은 일정 (사용자 결정, 2026-11-09)
- 직접 잡은 내일 약속은 전날 처음 앱을 열 때 한 번만 묻는다: "내일(11월 10일) 오후 3시에 ‘치과’가 있어요. 준비는 되셨나요?" 같은 날 다시 묻지 않고, 당일이나 지난 뒤에도 묻지 않는다. 날짜를 옮기면 새 전날에 다시 묻는다.
- 대상: 내 일정 중 `source` 가 `manual`·`chat` 이고 시각이 있는 약속(`kind=1`). 종일(00:00~23:59), 체크한 일정, 지운 일정, 할 일, 문서와 이어진 일정은 뺀다. `INGEST_REMINDERS` 와 사람별 스위치를 그대로 따른다.
- 새 표나 칸 없이 `document_reminders` 에 `item_id=""` 줄로 물어본 기록을 남긴다. 그래서 채팅 답(`resolve_reminder`)이 그대로 통한다. 예약 푸시(시작 30분 전)와는 별개로 동작한다.

## 일정에 넣는 값
- 일정을 만들 때 제목·날짜는 챙길 일에서, **시각은 글에 있으면** 그 값을(`due_time`), **장소는 문서에 적혀 있으면**(`place`) 넣는다. 개인 집 주소·사람 이름·연락처는 문서 단계에서 이미 가려져 있고 장소·메모에서도 `[..]` 표시는 뺀다.
- 메모(`memo`)에는 문서의 핵심 내용 한두 문장(준비물·제출처·유의사항)만 적는다. 시각·장소는 되풀이하지 않는다. 비어 있으면 "올려 주신 문서에서 가져왔어요".

## 한꺼번에 말하기
- 한 번에 말할 것이 둘 이상이면 서버가 `message` 로 한 덩어리로 묶어 준다(`reminders.compose`). 첫 줄은 "확인해 드릴 게 N가지 있어요."이고, 종류마다 `## 제목`을 한 번 쓴다. 순서는 곧 있는 일(미리 알림) → 지난 일(하셨나요?) → 일정으로 잡을까요?이다. 항목마다 `**제목**` 줄 아래에 `- 일시:`, `- 장소:`, `- 준비물: **…**`, `- 남은 시간: 약 N시간` 불릿을 두고(값이 없으면 그 줄은 뺀다), 항목은 시각 순이다. 종류마다 끝에 질문 한 줄을 붙인다(미리 알림은 "준비물은 다 챙기셨나요?"/"준비는 되셨나요?", 지난 일은 "하셨나요?…", 일정으로 잡을까요?는 "일정에 넣어 드릴까요?…"). 하나뿐이면 문장 그대로 말한다.
- 앱은 `message` 하나만 말풍선으로 넣는다(`nudges` 목록은 그대로 두었다).

## 준비물 챙기기
- 문서에 준비물·제출 서류가 적혀 있으면 챙길 일과 함께 `prep`(쉼표로 이은 짧은 목록)로 저장한다. 없으면 비어 있다.
- 급한 일정 알림은 준비물이 있으면 "준비물은 ○○예요. 약 N시간 남았는데, 준비물은 다 챙기셨나요?"로, 없으면 "준비는 되셨나요?"로 묻는다. 한꺼번에 말할 때는 항목의 `- 준비물: **…**` 불릿으로 보여 주고, 질문은 종류 끝의 한 줄이다.
- 사용자가 "준비물 다 챙겼어"라고 답하면 `resolve_reminder` 의 `prepared` 로 반영한다. 일정이 끝난 게 아니므로 체크하지 않고, 남은 미리 알림만 그만둔다(일정이 지난 뒤 "하셨나요?"는 그대로 한 번 묻는다).
- 일정을 만들 때 메모에 준비물이 빠져 있으면 "준비물: …"을 덧붙인다.

## 같은 일은 하루에 한 번만
- 같은 챙길 일은 말했거나 사용자가 답한 날에는 더 묻지 않는다(`last_asked_on`). 앱을 5분마다 열어도 반복하지 않고, 다음 날부터 이어서 챙긴다. 급한 일은 하루에 한 번 알린다.
- 같은 날 항목이 여럿이면 날짜만으로 같은 일정으로 묶지 않는다. 이름이 겹치거나 시각이 같을 때만 같은 일로 보고, 다른 챙길 일이 이미 쓴 일정은 건너뛴다.
