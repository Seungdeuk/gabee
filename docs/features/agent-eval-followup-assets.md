# 후속 개발용 자산 보존 목록과 기술 과제 (2026-11-24, 개발 마감 전 범위 축소)

개발 마감(최종 dev108 평가 11/26)에 맞춰 개선 작업 범위를 축소했다. 이 문서는 이번 마감 전에 **진행하지 않는** 것과 후속 개발에서 재사용할 자산을 정리한다. 이 브랜치(`fix/seungdeuk-care-isolation-prompt`, PR #539)는 **병합하지 않고 삭제하지 않는다**(자산 보존용).

## 1. A 재평가 결과 확정(변경 없음)
- 공식 4/6 유지(care-02 3/3, isolation-01 1/3). 공식 합격 기준(6/6) **미충족**으로 기록한다. 의미 검토 결과는 `agent-eval-539-A-result.md` 에 별도 보존한다.
- 모델 호출 40→11회, 비용 약 65% 감소, 보안 위반·승인 없는 쓰기·단계 상한 0건은 인정한다. 단 **효율 개선을 전체 Agent 성능 향상이나 정확도 유지로 주장하지 않는다**(두 사례 각 3회, 공식 합격 기준 미충족, 독립 효과 미입증).
- 기존 평가 결과·정답지·채점기는 바꾸지 않았다.

## 2. isolation-01 개선 보류와 후속 기술 과제
isolation-01 의 문제는 단순한 문자열 채점 문제가 아니라 **하위 Agent 의 직접 응답 구조**와 관련된 실제 답변 품질 문제로 판단한다. #539 의 isolation 지침은 운영에 반영하지 않으며, 이번 마감 전에는 관련 아키텍처와 하위 Agent 프롬프트를 추가 수정하지 않는다. 후속 과제:

| # | 과제 | 메모 |
|---|---|---|
| T1 | 메인 Agent 와 하위 Agent 의 응답 제어 범위 차이 | `ask_schedule`·`ask_family_chat` 경로에서는 하위 Agent 의 마지막 답이 사용자에게 보이고 메인의 마지막 문장은 쓰이지 않는다(A 평가 isolation-01 r0·r1 은 일정 Agent 답, r2 는 소통 Agent 답). 메인 프롬프트는 도구 선택·횟수만 바꿀 수 있다 |
| T2 | 일정 Agent 답에서 검색 실패와 접근 불가의 구분 누락 | r0·r1 은 "일정에 없어요"만 말하고 "다른 가족 정보는 볼 수 없다"는 구분이 없었다 |
| T3 | 하위 Agent 프롬프트 개선 가능성 | 일정·소통 Agent 프롬프트에 "우리 기록에서 확인되지 않은 부분"과 "접근할 수 없는 부분" 구분을 넣는 방안. 해당 Agent 해시가 바뀌므로 핀·평가를 새로 해야 한다 |
| T4 | 구조화된 응답 및 공통 후처리 | 하위 Agent 가 `scope_note` 같은 구조화 필드를 돌려주고 공통 후처리가 문구를 붙이는 방안. 코드 변경이라 권한·보안 시험 범위가 넓다 |
| T5 | 최종 응답 재생성에 따른 비용·지연 | 메인이 하위 Agent 답을 받아 최종 답을 다시 쓰게 하면 호출 1회와 지연이 늘어난다(A 평가 isolation-01 은 호출 2~4회, 응답 7.5~9.2초) |
| T6 | 소통 Agent 의 반복 검색 | r2 에서 소통 Agent 가 `search_messages` 를 3번(옆집·모임·일요일) 불렀다. 전역 검색 횟수 제한은 두지 않기로 했으므로 소통 Agent 프롬프트 수준의 대안이 필요하다 |
