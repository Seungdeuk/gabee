# 구현 현황: 가계 (billing)

> **2026-11-02 팀 회의 결과: 하단 탭 이름이 "지갑"이 됐다(이전 "돌봄").** 지갑 탭에는 정산·지출·용돈과 **월말 정산 알림**(정산 담당자에게만)이 보인다. **구독 기능은 제외**해서 공동구독·결제일 알림·정산 요약은 화면에서 주석 처리했고, 정산 에이전트의 구독 도구(`list_subscriptions`, `get_upcoming_payments`)도 주석 처리했다(서버 구독 API는 그대로). 요구사항은 `docs/requirements/wallet.md`.

- 상태: 진행 중 (서버·앱 화면 연결과 브라우저 클릭 검증 완료, 실기기 미검증)
- 요구사항: `docs/requirements/billing.md` 없음. 2026-10-21 요청 메시지의 명세를 기준으로 구현했다.
- 브랜치: `billing-care`

## 구현된 것
### 서버 (`apps/api/app/features/billing`)
- 지출 추가·내역: 항목, 금액(정수 원), 날짜. **낸 사람은 요청 바디에서 받지 않고 로그인한 사용자로 서버가 정한다**(`permissions.md` 규칙 2; 바디에 `paid_by`를 보내도 무시). 삭제는 `deleted_at` 소프트 삭제.
- 비용 정산 `GET /billing/settlement`: 구성원별 잔액, 최소 송금 목록, 송금 완료 표시(`POST /billing/settlement/payments`)와 취소.
  - 지출마다 나눌 사람끼리 정수로 나누고 나머지 원은 앞 사람(가족 그룹 가입 순서)부터 1원씩 더한다. 잔액 합계는 항상 0.
  - 송금 목록은 큰 금액부터 맞추는 방식이라 송금 횟수가 최대 (사람 수 - 1)번이다. 수학적 최소 횟수는 보장하지 않는다.
- **정산하기(대상 태그)**: 정산하는 사람이 지출을 고르고 대상 태그를 걸어 정산한다. 태그는 "정산하기"를 누를 때 걸린다(그 전 지출은 기본 `all`=가족 전체).
  - 고정 태그 3개(`GET /billing/settlement/tags`): 부모님 대상(`parents`: 부모 역할이 아닌 구성원이 부담), 자녀 대상(`children`: **미성년 자녀가 있으면 부모님이 부담, 없으면 성인 자녀(child)끼리**), 가족 전체(`all`). 규칙은 `service.py`의 `_fixed_tags` 한 곳에서 바꾼다.
  - 미성년 자녀 표시: `PUT /billing/settlement/minors`(정산 담당자·그룹을 만든 사람만, 부모 역할은 고를 수 없음). 가족 구성원 모델에 나이 정보가 아직 없어 정산 설정(`billing_settings.minor_ids`)에 둔다. 가족 그룹 쪽에 생년·미성년 필드가 생기면 그 값으로 옮긴다.
  - **미정산 지출은 잔액·송금 목록에서 제외**한다(`GET /billing/settlement`은 정산하기를 마친 지출만 계산, 응답의 `unsettled_count`·`unsettled_total`로 개수를 알려 준다). `GET /billing/summary`는 미정산까지 포함한 월 요약이다.
  - 직접 고르기(`custom`): 고정 태그로 채워진 인원에서 사람을 더하거나 빼서 `participants`로 보낸다. 지출에는 `target_tag`와 `split_among`(태그+나눌 사람)이 저장되고, 잔액·최소 송금 계산은 기존 것을 그대로 쓴다.
  - `POST /billing/settlement/tag`: 같은 달의 지출 여러 건에 한 번에 건다. 송금 완료 표시가 있는 달은 `settlement_locked`로 거절(송금 완료를 먼저 취소).
- **월말 정산 알림(정산 담당자에게만)**: 지출에 "정산됨" 상태(`settled_at`, `settled_by`)를 추가했다. "정산하기"를 누르면 정산됨이 되고, 그 전 지출은 미정산이다.
  - 정산 담당자: `GET·PUT /billing/settlement/manager`. 지정하지 않으면 그룹을 만든 사람이 담당자다. 변경은 지금 담당자나 그룹을 만든 사람만 할 수 있다(`not_manager` 403).
  - `GET /billing/settlement/reminder`: 월말 마지막 5일에는 이번 달, 월초 5일까지는 지난 달의 미정산 지출을 **담당자에게만** `show=true`로 알린다(`REMINDER_DAYS`). `on=YYYY-MM-DD`는 화면 테스트용 날짜.
  - 지금은 앱 안 배너만이다. 푸시 알림은 후속(새 라이브러리·기기 토큰 저장·서버 예약 작업이 필요하다).
- **용돈 장부**: 용돈 계좌를 실시간 연동하지 않고(보안) 남은 용돈을 **가비 앱 안 장부**로 관리한다. 은행·계좌와 연결하지 않으며 실제 송금은 직접 하고 기록만 남긴다.
  - 고정 주기 `PUT·DELETE /billing/allowances/{child_id}/plan`: 매주(요일) 또는 매월(일, 없는 날이면 말일) + 금액 + 방식. **자동(auto)**: 지급일이 지난 분을 장부를 열 때 입금으로 기록한다(서버에 정해진 시간 작업이 없어서. 같은 지급일은 한 번만, 취소한 줄도 다시 만들지 않음, 최대 24건 따라잡기). **리마인드(remind)**: 지급일이 지나면 부모에게만 `pending`으로 알리고 `POST …/plan/pay {due_date}`("지급했어요")로 기록한다. 주기를 바꾸면 오늘부터 새로 센다(지난 날짜 소급 없음). 주기를 꺼도 내역은 남는다.
  - 장부 `GET /billing/allowances`(자녀별 잔액·받은 돈·쓴 돈·최신순 내역과 줄마다 잔액·주기·pending·권한 표시). 수동 지급 `POST …/credits`, 사용 기록 `POST …/uses`(잔액보다 크면 `over_balance`), 취소 `DELETE …/entries/{id}`(지우지 않고 `voided` 표시, 입금 취소로 잔액이 음수가 되면 `balance_negative`).
  - **용돈 요청·승인**: 자녀 **본인만** `POST /billing/allowances/{child_id}/requests {amount, memo}`로 요청한다(대기 5건까지, `too_many_requests`). 부모(또는 그룹을 만든 사람)가 `POST …/requests/{id}/approve {amount?, note?}`로 승인하면 **장부에 입금 한 줄**(source `request`, 메모 "용돈 요청: …")이 생기고(금액을 바꿔 승인 가능), `…/reject {note?}`로 거절한다. 자녀는 대기 중인 자기 요청을 `DELETE …/requests/{id}`로 취소한다. 승인·거절·취소는 대기(`pending`) 상태에서 한 번뿐이다(`not_pending`). 응답 `requests`는 대기 중(오래된 순) 다음에 최근 처리한 10건, `can_request`는 본인에게만 true 다.
  - **월별 요약**: 응답 `months`는 최근 6개월(이번 달부터)의 받은 용돈·쓴 돈이다(취소한 줄 제외, 기록이 없는 달은 0).
  - 권한(정한 것): 주기·지급·남의 내역 취소는 **부모 역할 또는 그룹을 만든 사람**(`not_allowance_manager` 403). 사용 기록은 **본인 또는 위 권한자**. 모든 구성원이 서로의 잔액·내역을 본다(투명성). 오늘 이후 날짜는 기록할 수 없다.
  - **기능 변경**: 이전의 "월 예산 + 남은 금액" 방식(`PUT /allowances/{child_id}` 등)을 이 장부 방식으로 바꿨다. 이전 테이블(`allowances`, `allowance_uses`)은 데이터 보존을 위해 남겨 두고 제거는 후속 PR(destructive 승인)에서 한다. 이전 월 예산·사용 기록은 리비전 `719215db61ba`가 장부로 **복사**한다(예산 = 그 달 1일자 입금 "월 용돈 (이전 방식)", 사용 기록 = 사용 줄, 기록한 사람은 "이전 기록"; 옮긴 id 로 중복 방지, 이전 테이블은 그대로).
- 구독·통신비 관리(1단계): 항목 추가·수정·삭제(`POST·PATCH·DELETE /billing/subscriptions`), 통신사(SKT·KT·LG U+·알뜰폰·기타, 통신비만), **월 청구 금액(`monthly_fee`, 청구서에 찍힌 할인이 빠진 금액)**과 **결합 할인 금액(`discount_amount`)**, 매월 결제일, 가족 할인 상태(확인 필요/적용 가능/적용 중). 두 금액은 사용자가 청구서를 보고 **최초 1회(또는 바뀔 때 직접 수정)** 입력하며, 서버는 할인을 계산하거나 보장하지 않는다("예시, 실제 적용은 통신사에서 확인" 문구는 `notice`로 유지). 응답의 `list_price`는 청구 금액 + 할인 금액(정가), `monthly_total`은 청구 금액의 합, `discount_total`은 입력한 할인의 합이다. 구독료 지출은 청구 금액으로 만든다. 삭제는 소프트 삭제.
  - **서비스 목록(카탈로그)**: 구독하지 않는 OTT를 화면에 한꺼번에 늘어놓지 않는다. 처음엔 항목이 비어 있고, `GET /billing/subscriptions/catalog`(OTT 10종·결합 할인 2종, 이미 추가한 것은 `added`)에서 사용자가 골라 `POST`로 추가한 것만 화면에 뜬다. 목록에 없으면 "직접 입력". (이전 버전은 기본 5개를 자동으로 만들었으나 이 요구로 없앴다. 이미 만들어진 그룹의 **아무도 손대지 않은** 기본 항목은 리비전 `9eb94b284ac7`이 소프트 삭제로 감춘다 — 상태·금액·할인·결제일·통신사·결제한 사람·나눌 사람을 하나라도 손댄 항목, 사용자가 직접 만든 항목은 남긴다. 행은 지우지 않으며 되살리는 downgrade 는 없다.) 항목은 그룹당 30개까지.
  - 통신사 연동은 하지 않는다(개인 가입 정보를 열어 주는 공개 API를 확인하지 못함, 가입 정보는 개인정보).
- **구독료를 월별 지출로 만들기(3단계)**: 항목마다 결제한 사람(`payer_id`)과 나눌 사람(`split_among`, 비면 가족 전체)을 지정한다. 항목을 만들 때 결제한 사람을 **보내지 않으면 등록한 사람, `null`을 보내면 "결제한 사람 없음"**이다.
  - `GET /billing/subscriptions/monthly?month=`: 그 달에 만들 수 있는 항목(`ready` 만들 수 있음 / `created` 이미 만듦 / `no_fee` 금액 없음 / `no_payer` 결제한 사람 없음)과 건수·합계.
  - `POST /billing/subscriptions/monthly {month}`: 금액이 있고 결제한 사람이 있는 항목만 **미정산 지출**(카테고리 "구독", `subscription_id` 연결)로 만든다. 날짜는 결제일(그 달에 없는 날이면 말일, 결제일이 없으면 1일). **같은 달에 다시 눌러도 중복으로 만들지 않고**, 만든 지출을 지우면 다시 만들 수 있다.
  - 서버에 정해진 시간에 도는 작업이 없어 사용자가 버튼으로 만든다(자동 생성은 후속). 만든 지출은 정산하기를 눌러야 잔액에 들어간다.
  - 리뷰 참고: 결제한 사람은 항목에 저장된 값이다(`permissions.md` 규칙 2의 "요청 본문의 paid_by"가 아니라 구독 항목의 설정).
- **결제일 알림(구독 4단계)**: `GET /billing/subscriptions/upcoming?on=`. 결제일(`billing_day`)이 **3일 안(오늘 포함)**으로 다가온 구독을 **그 항목의 결제한 사람(`payer_id`)에게만** 알린다(결제일이 없거나 결제한 사람이 없는 항목은 제외, 31일처럼 없는 날은 그 달 말일, 이번 달 결제일이 지났으면 다음 달). 항목마다 다음 결제일·남은 일수·금액과, 그 달 구독료 지출을 이미 만들었는지(`expense_made`)를 돌려준다. 앱은 가계 화면 위쪽 배너(`UpcomingBanner`)로 보여 주고 "구독 보기"로 구독 탭에 이동한다. `on=YYYY-MM-DD`는 화면 테스트용 오늘 날짜(앱의 `EXPO_PUBLIC_DEV_TODAY`). 푸시 알림은 새 라이브러리·기기 토큰 저장·서버 예약 작업이 필요해 후속이다.
- 처음 한 번만 만드는 돌봄 샘플 7개는 `app/shared/seed_lock.py`로 잠가 동시 요청에도 중복으로 만들지 않는다(구독 기본 항목은 위 카탈로그로 바뀌어 더는 만들지 않는다).
- 테스트: `tests/test_billing.py`, `tests/test_billing_features.py`. DB: Alembic 리비전 `9e28d84c1686`.

### 앱 (`apps/mobile/src/features/billing`)
- 가계 탭은 돌봄 탭에 합쳐졌다(`BillingScreen`과 가계 라우트 제거). 화면 조각은 `public.js`로 내보내 `CareScreen`이 쓴다: `MonthSwitcher`(월 이동), `MoneySection`(정산·지출·용돈), `SettleSummary`(현황판용 정산 요약), `SubscriptionTab`, 두 배너. 서버 호출은 `api.js`.
- `SettleForm`(정산 탭): 지출 선택 → 고정 태그 3개 → 나눌 사람 → 정산하기. "대상 태그" 줄 오른쪽의 작은 스위치(라벨 "직접", 꺼짐은 "켜기", 켜짐은 "켜짐" + 색 표시, 스크린리더 이름은 "직접 고르기")를 켜면 고정 태그로 채워진 인원을 그대로 두고 더하거나 뺄 수 있고, 한 줄 배너의 "← 고정 태그로" 버튼으로 언제든 돌아간다. 직접 고른 지출은 목록에서 "✎ 직접 고름" 표시로 고정 태그 지출과 구분한다. 정산하기를 마치면 고정 태그로 되돌아간다.
- `SubscriptionTab`/`SubscriptionForm`: 서비스 목록에서 골라 추가(또는 직접 입력)·수정(이름, 통신사 칩, 월 청구 금액, 결합 할인 금액, 결제일, 결제한 사람, 나눌 사람)·삭제, 월 합계(청구 금액)·할인 합계·정가, 상태 변경, "이번 달 구독료 지출 만들기"(미리보기·건수·합계, 월 이동 반영). 지출 탭에는 "구독" 표시가 붙는다.
- `ReminderBanner`(가계 탭 상단): 담당자에게 "정산 안 한 지출 N건 · 월말까지 N일"과 "정산하기" 버튼을 보여 준다. `ManagerRow`(정산하기 카드 위): 담당자 표시와 변경. 지출에는 "미정산" 표시가 붙고, 정산하기를 누르면 대상 태그 표시로 바뀐다.
- 지출 추가에서는 낸 사람·나눌 사람 선택을 뺐다(낸 사람은 로그인한 나, 나눌 사람은 정산하기에서 정한다).
- 금액 입력칸(지출 추가, 구독의 월 청구·결합 할인 금액, 용돈 주기·지급·사용·요청·승인 금액)은 입력하는 동안 세 자리마다 쉼표를 보여 준다(`format.js` 의 `formatMoneyInput`). 서버에는 쉼표를 뺀 정수만 보내며 `parseWon` 도 쉼표가 있는 글자를 읽는다. 결제일·지급일 같은 날짜 칸에는 쓰지 않는다.
- 지출 탭: 평소에는 "+ 지출 추가" 버튼만 보이고, 누르면 항목·금액 입력칸이 펼쳐진다(추가하거나 취소하면 접힌다). 내역은 5개씩 보여 주고 "더보기 (남은 N개)"로 5개씩 늘리며, 전부 펼치면 "접기"가 나온다. 달을 바꾸면 다시 5개로 돌아간다. 각 지출의 금액 아래에 구독·정산 태그와 삭제 버튼을 한 줄에 오른쪽 정렬로 놓는다(자리가 모자라면 줄바꿈). 시험: `apps/mobile/tests/billingformat.test.js`(쉼표 변환·숫자 해석·더보기 계산). 화면 렌더링 자체는 자동 시험이 없고 실기기·시뮬레이터에서 직접 확인이 필요하다.
- 서버 주소(`EXPO_PUBLIC_API_URL`)가 없으면 기존 임시 데이터 화면(`BillingPreview`)을 그대로 보여 준다.
- 공통으로 `shared/components`(Button, Field, Segmented)와 `shared/hooks/useResource`를 추가했다.

## 확인 방법
- 서버 확인용 화면: `apps/api/scripts/dev_console.py` → `/console`.
- 앱: `EXPO_PUBLIC_API_URL=http://<서버> EXPO_PUBLIC_DEV_TOKEN=<토큰> npx expo start --web`. 로그인 화면이 붙기 전까지 `EXPO_PUBLIC_DEV_TOKEN`(개발용 토큰)으로 인증한다.
- 2026-10-22 Edge 브라우저(Expo 웹)에서 정산·지출·용돈·구독 클릭 흐름 검증(서버 응답까지 대조).

## 정한 것 (확인 필요)
- 용돈 대상 "자녀" = 가족 그룹에서 역할이 `parent`가 아닌 구성원. 주기·지급은 부모 역할이거나 그룹을 만든 사람만 하도록 했다(2026-10-23 사용자 확인; `docs/contracts/permissions.md`에 용돈 규칙이 없어 이 문서가 기준).
- 송금 완료 후 지출을 삭제하면 완료한 송금은 그대로 남고 남은 잔액이 반대 부호가 될 수 있다.
- 월 기준은 한국 시간(서버). 앱의 월 이동은 기기 시간 기준으로 시작한다.

- **확인 필요**: 고정 태그 "부모님 대상"과 "자녀 대상"이 현재 같은 사람들(자녀)로 채워진다(구성원이 parent/child뿐일 때). 두 태그의 분담 인원을 다르게 하려면(예: 자녀 대상은 부모가 부담) `FIXED_TAGS`만 고치면 된다.

- 자녀 대상 정산은 지출마다 어느 자녀 몫인지 고르지 않고 "가족에 미성년 자녀가 있는가"로 정한다. 미성년과 성인 자녀가 섞인 가족에서 성인 자녀 몫을 정산할 때는 "직접 고르기"를 쓴다.
- 미성년 자녀가 있는데 부모 역할 구성원이 없으면 자녀 대상 정산은 `no_participants`로 거절된다.
- 알림 기준(마지막 5일 / 월초 5일)과 문구는 임시 값이다. `service.py`의 `REMINDER_DAYS`와 앱 `ReminderBanner`에서 바꾼다.

## 남은 것

- 구독 항목 추가·삭제, 영수증 연결, 균등이 아닌 분담.
