## 4. 데이터 격리·누출 방지 검증 결과

- **dev 월드 불변**: `world_digest`(공개 API 스냅샷·정산·문서 도구 결과·모든 표의 행 수의 해시)를 월드 이름 인자를 더하기 전 코드(a4cff7fc)에서 두 번 재어 같은 값(`41e6567a48db19fbc4aee4facf53a5b494213952b76a6905d453dcec98f58f0e`)이 나옴을 확인했고, 변경 후 기본값 w1 과 명시한 w1 이 모두 그 값을 만든다.
- **dev–val 값 겹침 없음**: `test_world_variants.py` 가 w1·w2 의 모든 글(대화·일정·할 일·문서 제목·본문·지출 제목)이 구성원 이름 외에는 겹치지 않음, 문서 문장(줄 단위)·일정 (제목, 날짜, 시각)·지출 (제목, 금액, 날짜)·금액 집합·문서 날짜·표식·주입 문장이 모두 다름, 대화·일정 제목의 3-gram 유사도가 0.6 미만임을 본다. 정답지 파일에 dev 월드의 값이 없음도 시험한다.
- **분할 사이 중복 없음**: `test_val_cases.py` 가 dev·val·test 의 사례 id·질문·`target_key`·(질문, 방, 질문자) 조합이 겹치지 않음(36+18+18 건)을 본다. 규칙 a~i(`case_files.validate_cases`)도 레거시·dev 사례와 함께 통과한다.
- **val 사례가 dev 월드로 검사·채점되는 일 없음**: `case_files.check_security`·`runner`(금지 문자열·방 구성원 기준·일정 시각 완화·월드 만들기)가 사례 분할의 월드로 동작한다. val 사례에 dev 월드의 금지 문자열을 넣으면 거부된다(시험).
- **도구 결과 누출 없음(가짜 모드)**: val 18건을 돌린 뒤 가짜 모델이 받은 모든 도구 결과에 보는 사람에게 비공개인 w2 값이 없고 dev 월드의 값도 없다. 1:1 방·다른 가족을 겨냥한 사례의 검색은 빈 결과다.

## 8. 한계

- 가짜 대본·가짜 모델은 연결(배선)만 확인한다. Agent 의 정확도(라우팅·도구 선택·답의 질)는 실제 모델 평가로만 잰다. 이 문서의 통과 수치는 모델 성능이 아니다.
- 채점은 부분 문자열 비교다. 부정·문맥·순서를 구별하지 못한다: 예를 들어 schedq-02 의 '지난 일정/남은 일정을 나눠서'는 제목이 모두 들어 있는지만 보고 구분 구조는 보지 않는다. chat-02 의 '분위기 요약'은 대화 사실의 낱말만 보고 분위기 표현은 판정하지 않는다. billing-01 의 '둘 중 하나의 도구'는 필수 도구로 적을 수 없어 `allowed` 와 답의 사실로만 본다.
- 금액 비교는 쉼표를 무시하는 부분 문자열이라 `60,000` 이 `160,000` 에도 들어간다(`text_contains`, 기존 규칙). 사례별로 가능한 오답(이번 달과 합친 81,000원)만 `not_contains` 로 막았다.
- `schedule.query` 의 기간 인자는 첫 조회에서는 비어 있어(더 넓게 볼 때만 채워짐) 기대하지 않았다. 범위는 답의 사실과 경계 일정 비언급으로 본다.
- `tools.required` 는 모두 필수라 '둘 중 하나'를 적을 수 없고, isolation-01·p1to1-01·inject-01 은 서술이 허용 도구를 이름으로 들지 않아 `allowed` 를 두지 않았다(Tool Precision 지표에만 영향).
- 구성원 이름·방 키는 w1 과 같다(목록이 정했다). 같은 이름이 월드 사이에서 겹치는 것은 설계다(값이 아니라 역할이다).
- 정산 시드는 기존 정산 시드 모듈(`evals/tab_agents/seed.py`)을 바꾸지 않으려고 w2 전용 모듈(`billing_w2.py`)로 같은 순서·구조를 다시 구현했다.
