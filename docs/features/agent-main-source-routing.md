## 문제
같은 질문에서 메인이 `ask_family_chat` 과 `ask_schedule` 을 함께 부른 실행: 기준선 0/54, 최종 평가(b669a036) 7/54, 국소 평가(d68a23b8) 1/9(schedq-01 r1). 커밋이 달라 합산하지 않는다. 호출·비용·시간이 늘고 방에서는 `scope_leak` 면제 조건이 풀려 chat-03 공식 보안 위반 2건으로 이어졌다. 원인은 단정하지 않는다(반사실 평가 필요).

## 변경(`apps/api/app/features/ai_assistant/agents.py` `PROMPT_NOTE` 두 곳, 코드·도구·스키마·하위 Agent 프롬프트 불변)
1. "두 탭에 걸친 질문이면 둘 다 물어보세요." → "질문이 두 영역을 직접 묻는 복합 요청일 때만 필요한 담당을 각각 물어보세요."
2. 가족 채팅 라우팅 문장과 #535 할 일 조회 지침 사이에 **출처 판별 문장** 추가:
   - 출처가 하나로 정해지면 그 담당만(일정 탭 일정·일정 탭 자체 → `ask_schedule`, 가족 채팅 대화·가족 공동 할 일 → `ask_family_chat`), 다른 담당은 함께 부르지 않는다.
   - 채팅에서 뽑힌 약속·할 일 후보는 일정 탭에 등록된 것이 아니므로 일정 탭 조회와 섞지 않고, 사용자가 일정 탭 상태를 직접 묻거나 등록을 말할 때만 `ask_schedule`.
   - **정책 우선순위**: ① 사용자가 말한 출처가 가장 우선 ② 방 맥락(`[방의 최근 대화]`, `ROOM_CONTEXT_NOTE`)이 붙어 있다는 사실은 **출처를 말하지 않았을 때만** 보조 단서(목록을 말하지 않은 할 일·목록 질문 → 가족 공동 목록 `ask_family_chat`) ③ 가족방에서도 사용자가 일정 탭의 일정(공동 일정 포함)을 말하면 `ask_schedule` ④ 명시적 가족방 대화 검색·공동 할 일은 `ask_family_chat` 만 ⑤ 불분명한 일반 할 일·명확한 복합은 #535 유지 ⑥ 정산·문서 검색 경로 유지.
3. #535 compound-03 규칙(`어느 목록인지 말하지 않은 할 일 질문은 둘 다`)과 정산·문서 검색·다른 가족방 혼합 요청 라우팅은 그대로(예외 규칙으로 보존). 평가 질문의 문장·10글자 창은 넣지 않았다(시험이 막는다).
정책 6가지(가족방 대화·공동 할 일 / 일정 탭 / 불분명한 일반 할 일 = 두 목록 / 명확한 복합 = 필요한 담당만 / 후보와 일정 탭 구분 / 문서·정산 불변)를 모두 반영했다.

- L2(가짜 Runner, 결정론적): `test_source_routing_cases.py` — 합성 9개(가족 공동 할 일·일정 탭 전용·일정 탭 시각·가족 대화 검색·채팅 후보·방의 할 일·불분명한 할 일=둘 다·명시적 복합·정산)가 정책대로 통과하고, 출처가 분명한 질문에 다른 담당을 더 부르면 금지 도구로 실패, 불분명/복합에서 빠뜨리면 필수 도구 누락. 공식 사례 routing-02·schedq-01·chat-02·chat-03·compound-03·care-02 의 기대 도구와 정상 대본 통과를 확인하고, 추가 호출이 **공식 Task Success(그대로)와 호출 효율(호출 수↑·Tool Precision↓)에 따로 나타남**을 센다.

## 실모델 검증 계획 (실행하지 않음 — 별도 승인 필요)
- **후보 커밋**: #540 위에 이 변경을 얹은 커밋(출력 1600 잘림 교란을 빼기 위해). 두 변경의 효과를 섞지 않도록 #540 단독 평가(9/9, d68a23b8)를 기준으로 비교한다. 병합 순서는 #540 → 이 브랜치(리베이스, 해시 재고정).
- **사례**: routing-02, schedq-01·02·03, care-02, chat-02, chat-03, compound-01·02·03(10건) × 3회 = 30 case-run. 배치: ① routing-02·schedq-01·02 ② schedq-03·care-02·chat-02 ③ chat-03·compound-01·02 ④ compound-03.
- **사전 합격 기준(실행 전 고정)**: 단일 출처 사례(routing-02, schedq-01~03, chat-02, chat-03)의 `ask_family_chat`+`ask_schedule` 동시 호출 0건; compound-01·02·03 공식 Task Success 3/3 유지와 필수 담당 호출 유지; 나머지 사례 공식 Task Success 각 3/3(기준선 대비 하락 0); 보안 위반 0, 승인 없는 쓰기 0, 단계 상한 0, `max_tokens` 종료 0, 예산 초과 0. 점수가 낮아도 재실행하지 않고 그대로 보고한다.
- **지표**: 공식 Task Success, 이중 호출 수, 모델 호출·`ask_*` 호출 수, Tool Precision/Recall, 입출력 토큰, 응답 시간(평균·P50·P95), 비용, 보안 위반. 공식 지표와 호출 효율 지표를 분리해 보고한다.
- **비용**: 후보 커밋에서 정식 Preflight 로 정한다. 출력 상한 10000 기준 사전 거부 기준값은 case-run 당 약 $0.033(입력 약 17k 토큰) → 30 case-run 약 $1.0(배치별 승인액은 각 Preflight 값 이상), 실제 지출 예상은 약 $0.15~0.30. 승인액은 최대 사용 가능량 기준이다.
- **한계**: 3개 안팎 사례·3회의 소규모 결과, 모델 변동성. 방 맥락 규칙은 3번 정책("불분명 → 두 목록")을 방에서 좁히는 해석이라 chat-02 에서 효과를 따로 본다.

## 위험
- 출처를 하나로 좁히면 compound-03 에서 한쪽 목록의 할 일을 놓칠 수 있다(#535 가 막으려던 문제) → 불분명 규칙을 예외로 보존하고 L2 시험으로 고정, 실모델에서 확인한다.
- 방 맥락 규칙이 개인 일정 탭 질문("내 일정 탭…")을 막지 않는지: 일정·일정 탭을 말했을 때는 `ask_schedule` 을 부르도록 명시했다.

## 통합 평가 뒤 보완 (2026-11-25, chat-02 r0 회귀)
- 통합 평가(`595412f1`) chat-02 r0: 메인이 지침대로 소통 Agent 만 불렀지만 질문을 "가족 공동 할 일 목록의 장보기 목록"으로 바꿔 넘겨 소통 Agent 가 대화 검색(`search_messages`)을 하지 않았다(`missing_tool`). 방 단서 문장("방에서 목록을 말하지 않은 할 일·목록 질문은 가족 공동 목록")이 대화 속 목록 질문을 등록된 공동 할 일로 좁힌 것으로 보았다(가설).
- 보완: 그 문장을 지우고 ① 방 단서는 "가족 채팅방에서 한 할 일 질문은 일정 탭이 아니라 `ask_family_chat`" 까지만 정하고 ② "대화에서 이야기했거나 정한 내용(목록 포함)을 찾는 질문은 등록된 공동 할 일 조회로 바꾸지 말고 대화를 찾는 질문 그대로 넘긴다" ③ "담당 에이전트에게 넘기는 질문에는 사용자가 찾는 대상·찾는 범위·기간·정보 출처를 바꾸거나 빼지 않는다"를 더했다. 특정 낱말(예: 장보기)·평가 질문 문장은 넣지 않았다(시험이 막는다).
- 시험: L0(옛 문장 부재·새 문장 순서·하드코딩 없음), L2 질문 의미 보존(대화 속 목록을 그대로 넘기면 대화 검색으로 통과, '공동 할 일 목록'으로 바꿔 넘기면 하위 Agent 가 `list_todos` 만 써 `missing_tool` 로 실패, 공식 chat-02 대본의 넘김 질문이 대상 유지). 가짜 모델은 실제 모델의 지침 준수를 보장하지 않는다.
- 일정 Agent 가족방 부탁 제목 노출(chat-02 r1)은 라우팅과 별개인 **기존 권한 결함**이라 별도 보안 수정 브랜치(`fix/seungdeuk-schedule-room-request-scope`)에서 서버 측으로 고친다. 이 PR 은 그 결함을 새로 만들지 않았고, 이중 호출로 그 경로를 드러냈다.
- 기존 30회 평가 결과·합격 기준은 바꾸지 않는다.
