## 구현된 것
앱(`apps/mobile/src/features/schedule/`), mock 데이터 기준. 서버 연동 없음.
- `constants.js`: 형태·체크 라벨, 막대·주제·점 색(임시 값)
- `model.js`: 항목 타입(JSDoc), 정렬, 필터(대상은 나·공동·구성원, 같은 줄은 "또는", 줄끼리 "그리고")와 공동 여부 판단(`filter.js`, 서버 값이 없는 mock 은 공유 대상·만든 사람으로 판단)
- `mock.js`, `store.js`: 오늘 기준 샘플과 메모리 저장소(추가·수정·삭제·체크)
- `utils/date.js`: 주(월~일 / 일~토)·달 계산, 한글 날짜·시간 표기
- `components/`: EventCard(compact/detailed), CheckMark, FormTag, FilterChip, SectionHeader, WeekStrip, BottomSheet
- 메인 화면(`screens/ScheduleScreen.js`, 와이어프레임 v1.2 기준): 헤더 + 주간 스트립(월~일, 일정 있는 날 점), 오늘·내일 카드(체크 수 표시·체크 동작), 함께하기 한 줄, 먼저 권해드려요. 달력 아이콘(배경 없음, `IconButton`)과 주간 스트립 날짜는 달력으로 이동(그 날짜 선택)
- 먼저 권해드려요(`suggestions.js`): 기능별 카드 2장. 확인 카드(오늘 내 약속·할 일만 한 장에서 하나씩, 약속 먼저·시간 빠른 순 → 할 일, 확인하면 버튼이 복숭아로 바뀐 뒤 체크 연동 + 다음 항목, 전부 끝나면 "오늘 일정을 모두 확인했어요 👏"), 추가 카드(내 약속·할 일에 없는 추천. 문장은 두 줄로 첫 줄 "날짜 줄인 이름"(예: "11/2 제주 여행 여권 챙기기"), 둘째 줄 "일정으로 추가해 드릴까요?"로 약속·할 일을 구분하지 않고, 버튼(추가 / 나중에 / 새로고침)은 문장 아래 줄 오른쪽(확인 카드도 같은 모양). 추가하면 제안한 형태(약속 또는 할 일)로 미리 채운 등록 화면이 열리고 저장하면 메인으로 돌아와 바로 다음 추천이 나옴. 저장하지 않으면 그대로). 추천을 다 보여 주면(하루 15개 제한 포함) "오늘 추천은 여기까지, 내일도 챙겨 드릴게요 💛"로 마무리. 버튼은 처음엔 흰색이고 고른 쪽이 복숭아색, "나중에"는 복숭아로 표시된 채 카드 유지(다시 누르면 해제), 전체 새로고침은 없고 카드마다 새로고침(↻)으로 다른 항목·제안을 봄. 추천 요청은 `POST /schedule/suggestions` 로 보내고 본문 `chat` 에 최근 7일 이내 개인 AI 채팅에서 내가 한 말만 최신순 최대 30줄(줄당 200자) 싣는다(`suggest_chat.js`, 서버 저장 없음, 대화를 못 읽으면 빈 배열). 챙길 것·추가 제안 문장은 임시 보여 줄 추천이 없으면 서버 상태(`suggestion_slot.js` `emptySlotView`)로 슬롯 문구를 정한다(글자와 이모지 사이에 공백 없음): 참고 데이터 없음 "지금은 추천드릴 게 없어요🌱", 데이터는 있는데 AI 결과가 비었거나 걸러짐 "어울리는 일정을 생각중이에요…"(데이터가 있는데 없다고 하지 않는다), 오류 "아직 준비 중이에요⏳", 오늘 호출을 다 썼는데 받은 추천이 하나도 없음 "일정을 찾지 못했어요. 내일 다시 찾아볼게요😢"(서버 상태 `spent_empty`), 오늘 추천을 받아 전부 확정했거나 호출 소진 "오늘 추천은 여기까지, 내일도 챙겨 드릴게요💛"(새로고침 버튼은 앞의 세 가지에서만).
- 달력 화면(`screens/CalendarScreen.js`, 와이어프레임 v1.1 기준): [달력|목록] 전환, 대상(나·공동·구성원)·주제 필터 칩 두 줄(켜고 끄기), 월 달력(점 최대 3개·약속 먼저, 달 이동, 접기·펴기 버튼. 음력 1일(초하루)인 칸에는 날짜 아래에 "10.1"(윤달은 "윤 10.1") 작은 글자가 항상 보이고 켜고 끄는 스위치는 없다. `lunar.js` `firstDayLabel`), 선택한 날짜 목록과 [모두|약속|할 일]. `calendar.js`(점·필터·날짜별 항목·시간 구분), `components/MonthCalendar·FilterRows·SegmentedControl·AddButton`
- 목록 모드(`components/ListMode.js`): 오늘(비어도 표시, 확인·완료 수 표시) → 다가오는 것(월 구분선, 숫자 없음) → 지난 것(기본 접힘, 최근 3개 + "이전 기록 N개 더 보기", 흐리게·체크 없음, 없으면 숨김). 구역 제목을 눌러 접고 펴며, 필터를 하나라도 켜면 자동으로 목록, 모두 해제하면 달력으로 돌아옴. 달력 모드에서 목록이 길면 아래로 스크롤할 때 달력이 접히고 맨 위로 오면 펴짐

- 등록 화면(`screens/RegisterScreen.js`, 와이어프레임 v1.2 기준): 형태 [약속|할 일] 선택(입력 항목은 같음), 제목·날짜 필수, 주제·공유 칩, 시간·장소·메모 선택, 저장하면 mock 저장소에 추가하고 진입했던 화면으로 복귀, 제목 옆 ‹·취소. 날짜 시트(`components/DateSheet.js`: 오늘·내일·토·일 빠른 선택 + 월 달력(음력 1일은 날짜 아래에 "10.1", 윤달은 "윤 10.1") + "직접 입력"). 직접 입력은 YYYY-MM-DD 한 칸이고 연도까지 받으며, 연·월·일 영역을 터치하면 영역이 블록으로 선택돼 숫자를 치면 그 영역이 새로 채워지고(월에서 9 → 09처럼 첫 숫자가 크면 0을 붙여 다음 영역으로 자동 이동, 범위 밖 숫자는 무시) 올바른 날짜가 되면 아래 달력이 그 날짜로 이동하고, 반대로 달력에서 날짜·달을 고르면 입력 칸의 숫자도 바뀐다(양방향). 직접 입력일 때만 입력 칸 오른쪽 끝에 양력/음력 스위치(`components/LunarToggle.js`)가 나타나고(기본 양력), 스위치를 바꿔도 칸의 숫자는 그대로이고 "그 숫자를 음력(양력)으로 본다"만 바뀌며, 아래 달력이 그에 해당하는 양력 날짜를 가리킨다(예: 양력 2026-03-25를 음력으로 바꾸면 칸은 2026-03-25 그대로이고 달력은 음력 2026년 3월 25일의 양력으로 이동. 반대도 같다. 음력으로 입력한 날짜가 평달과 윤달 둘 다 있을 때(예: 2025년 6월 1일과 윤6월 1일)만 "6월 1일 / 윤6월 1일" 두 칸이 양력 날짜와 함께 나와 고르게 하고(기본 평달) 양력일 때나 겹치지 않을 때는 나오지 않는다. 없는 날짜는 "없는 날짜예요", 저장·달력은 항상 양력). 변환은 `lunar.js`(`korean-lunar-calendar`, 오프라인, 양력 1000-02-13~2050-12-31). 확인 버튼은 없고 "빠르게 고르기"를 누르면 입력 칸이 사라지고 오늘·내일·토요일·일요일 줄로 돌아간다. 시간 시트(`components/TimeSheet.js`·`TimeWheel.js`): 왼쪽에 시작·끝을 한 줄씩(라벨, 오전|오후 두 글자 버튼, 작은 HH:MM 입력 칸), 오른쪽에 시(0~23)·분을 돌려 고르는 24시간 시계(분은 5분 단위). 화면은 모두 24시간 표기이고 입력 칸과 시계는 같은 값을 공유해 어느 쪽에서 바꿔도 바로 반영된다. 시·분 영역을 터치하면 블록으로 선택되고, 오전|오후는 입력할 때의 변환 보조다(오후를 골라 두고 11을 치면 23:00, 13~23시는 쓴 그대로). 버튼을 누르면 지금 시각이 12시간 옮겨진다. 종일을 켜면 아래는 흐려지고 반응하지 않으며, 끝은 시작 + 1시간으로 자동 채움. "시간 없음"은 시간 라벨 옆 글자 버튼. 입력 칸은 `components/BlockInput.js`, 계산은 `utils/time.js`. 등록 화면 날짜 칸에는 연도를 함께 보이고, 확정된 시간은 24시간 옆에 오전·오후 표기를 괄호로 덧붙인다(14:00 – 16:00 (오후 2:00 – 오후 4:00)). 등록 화면 날짜 칸에는 연도를 함께 보인다(2026년 10월 24일 토요일). 진입: 메인 "약속 · 할 일 추가하기", 달력 날짜 옆 +, 목록 오늘 옆 +, 먼저 권해드려요의 "추가"·"아직이요"(미리 채움 + 안내 문구)
- 상세 화면(`screens/DetailScreen.js`, 와이어프레임 v1.2 기준): 카드를 누르면 열림(메인·달력·목록). 형태 배지, 주제(있을 때만), 제목(공동 일정이면 앞에 "공동" 이름표), "내가 만들었어요"/"OO가 공유했어요", 정보 카드(날짜(연도 포함)·시간·장소·공유·메모, 값 없으면 줄 숨김), 확인·완료 줄(눌러서 켜고 끄기, 목록 카드 체크와 같이 움직임). 수정·삭제는 만든 사람에게만 보이고, 공유받은 사람은 보기와 확인·완료만 가능. 수정은 등록 화면을 현재 값으로 채워 열고(제목줄 "수정", 형태 변경 가능) 저장하면 상세로 돌아옴. 공유 칩은 원본 주인에게만 보이고(공유받은 사람의 수정 화면에는 없음) 현재 공유 대상이 채워져 있으며, 사람을 빼고 저장하면 "받은 분 일정도 같이 사라져요" 확인 팝업이 뜸. 삭제는 화면 가운데 확인 팝업(`shared/components/ConfirmDialog.js`, 공유한 사람 안내 포함)
- 같이(보내는 쪽, `screens/TogetherScreen.js`·`TogetherStatusScreen.js`·`RequestDetailScreen.js`, 와이어프레임 v1.1 ①③④ 기준): 보내기(내용·날짜 필수, 받는 사람(안 고르면 모두에게)·누구(관련된 사람)·시간·장소·메모 선택, 제목 "같이, 곁에" + ‹ 와 취소, 날짜·시간은 등록과 같은 시트, 메인 추천 샘플로 열리면 안내 문구와 미리 채움), 주고 받은(= 같이의 메인 화면, 전 현황: 오른쪽 위 "같이하기", 보낸 탭은 답을 기다려요 / 함께해요(수락됐고 아직 안 지난 것) / 지난 최근 3개 + 이전 기록 더 보기, 처음엔 받은 탭이고 보내면 보낸 탭으로 열림), 보낸 것 상세(상태 배지·내가 보냈어요·정보 카드·받는 분 줄 옆 [바꾸기]로 받는 사람 바꾸기 시트(`components/RecipientsSheet.js`, 규칙은 `recipients_edit.js`)·함께해요(수락한 사람만 이름+수락)·하단 [부탁 취소하기]는 수락한 사람이 있어도 가능, 확인 팝업이 수락자 일정 삭제를 미리 알림). 일정 메인 브리핑(오늘/내일)에는 내가 보낸 부탁이 부탁 카드(`components/RequestCard.js`, 금색 막대·"함께" 태그·수락 현황 배지)로 일정 사이에 시간순으로 섞이고(`request_view.js`) 오늘 진행률에는 세지 않으며 누르면 이 상세가 열림. 상태는 기다려요/수락/취소됨(어렵다는 답은 보낸 사람에게 반영하지 않음). 저장소는 `requests.js`(mock), 진입은 메인 함께하기의 샘플·같이하기·"주고 받은 ›". 보내기 취소·보내기 후에는 주고 받은으로 가고 ‹는 일정 메인으로 간다. 색은 같이하기 복숭아, 선택된 탭 갈색(밝은 글자), 기다려요 노랑
- 같이(받는 쪽, `screens/ReceiveScreen.js`, 라우트 `together-receive`): 주고 받은의 받은 탭(답을 기다려요 / 함께해요 = 답했고 날짜가 안 지난 것(어렵다고 한 것도 포함, "어려웠어요" 배지) / 지난 = 날짜가 지난 것, 보낸 사람이 취소한 것은 안 보임)에서 카드를 누르면 받기 화면. 보낸 사람(OO가 보냈어요)·날짜·시간·장소·누구·메모, 같은 날 시간이 겹치는 내 일정이 있으면 "같은 시간에 ... 일정이 있어요 / 일정 보기", 다른 사람이 먼저 수락했으면 "OO가 함께해요". "내 일정에 어떻게 넣을까요?"는 약속 | 할 일(기본 할 일)이고 "수락할게요"·"어렵겠어요"는 같은 너비의 노란 선택 버튼이고 그 밑 복숭아 "저장"을 눌러야 정해지며 저장하면 주고 받은으로 돌아감. 수락하면 `requests.js` 의 `acceptRequest` 가 날짜·시간·장소·메모 그대로 내 약속·할 일로 넣고(공동 일정, 보낸 사람과 공유) 어렵겠어요는 보낸 사람에게 알리지 않음. 날짜가 지나기 전에는 "답 바꾸기"로 다시 정할 수 있고(수락했다 어렵게 바꾸면 만든 내 일정이 지워지고, 다시 수락하면 약속·할 일을 새로 고를 수 있음) 지나면 못 바꿈. 약속 | 할 일 토글은 선택 칸이 갈색. 메인 함께하기 오른쪽 "주고 받은 ›" 왼쪽에 아직 답하지 않은 받은 개수(날짜 안 지난 것) 숫자 배지. 알림(푸시)·서버 연동은 아직 없음(mock).

- 끌기 구현(가족 순서·편집 화면, `components/SortableList.js`): React Native 기본 `PanResponder`(gesture-handler 를 쓰지 않는다). 줄마다 responder 하나. 호출 순서: ① `onPanResponderGrant`(닿음) → 꾹 누름 타이머(`ROW_MENU_HOLD_MS` 450ms) ② 타이머 전에 `holdDecision`(`logic.js`)이 "fail"(10px 넘게 움직임, `HOLD_CANCEL_PX`)이면 타이머를 지우고 responder 를 내준다(`onPanResponderTerminationRequest` true → 스크롤이 받음) ③ 타이머가 끝나면 줄을 들어 올리고(scale 1.02, 그림자) `onDragActive(true)`로 바깥 ScrollView 를 `scrollEnabled=false` 로 잠근다 ④ `onPanResponderMove`(armed 후)에서 `dragTargetIndex(from, g.dy, stride, count)`로 놓을 자리를 구하고 줄을 translateY 로 따라 옮긴다. 이때 `onPanResponderTerminationRequest` 는 false 라서 responder 를 빼앗기지 않는다 ⑤ `onPanResponderRelease`/`Terminate`: 타이머 정리, armed 였으면 스크롤 잠금을 풀고 자리가 바뀌었을 때만 `onReorder(from, to)` 한 번(저장은 부모). 줄 안의 화살표·연필·휴지통·눈 버튼은 자식 Pressable 이 responder 를 먼저 잡아서 끌기가 시작되지 않는다. 햅틱은 expo-haptics 가 설치되어 있지 않아서 넣지 않았다. 정렬 모드·흔들림(Wiggle)·자동 스크롤은 없다.
- 탭 줄의 가족 칩: 칩은 눌러서 고르기만 한다(일반 가로 ScrollView). 순서 바꾸기는 가족 순서 바꾸기 화면에서만 한다. 나는 고정.
- 헤더(데일리 체크 메인): ① "‹ 일정" 줄 ② 제목 줄(오늘의 안녕 … 연필+편집, 오른쪽 끝) ③ 날짜 줄.

## 데일리 체크 2차(앱만, 대략 구현)
- 온보딩(`screens/DailyOnboardingScreen.js`, 라우트 `daily-onboarding`): 처음 열고 항목이 없을 때만. 추천 아홉 개(물 마시기·영양제 먹기·안부 전화는 처음부터 고른 상태, 알림장 확인과 추천 다섯 개) 중에서 고른다. "이대로 시작하기"는 고른 항목을 만들고, "건너뛰기"는 아무것도 만들지 않는다. 둘 다 온보딩 완료 표시를 남긴다. 예시 데이터 버튼은 없다.
- 응원 보내기(`components/CheerSheet.js`): 가족 탭 하단 "응원 보내기"(전화 버튼과 나란히)를 누르면 시트. 종류 세 개(사랑해요·최고예요·잘하셨어요), 한마디 두 개 또는 직접 쓰기, "가족 대화방(도란도란)에도 남기기" 표시(표시 값만 저장, 채팅으로 보내지 않음). 보내면 이 폰에만 기록한다.
- 받은 응원(내 탭 맨 위, `components/CheerStrip.js`): 오늘 받은 응원 중 고마워를 아직 안 누른 것은 가로로 넘기는 카드(폭 312, 점 인디케이터, "오늘 받은 응원 안 누른 수 / 전체", "지난 응원 보기")로 바로 보인다. "고마워"를 누르면 그 카드가 사라지고, 전부 누르면 한 줄 배너("오늘 받은 응원 N개 · 이름, 이름")로 바뀌어 누르면 모아보기로 간다. "답장하기"는 안내 알림만 띄운다(가족 대화방 연동은 서버 일). 오늘 받은 응원이 없으면 아무것도 안 보이고, 가족 탭에서는 보이지 않는다. 지난 응원 모아보기(`screens/DailyCheerHistoryScreen.js`, 라우트 `daily-cheer-history`)는 받은·보낸 응원을 날짜별로 보여 준다. 받은 응원 전체 화면(`DailyCheersScreen`)은 메인에 흡수해 삭제했다.
- 전화(`components/CallSheet.js`, `components/CallDoneSheet.js`): 가족 탭 하단 "OO에게 전화"를 누르면 확인 시트. 가린 번호(mock)와 가비 이야깃거리를 보여 준다. 이야깃거리는 AI 가 아니라 고정 규칙(`logic.js` `talkingPoints`): 완료한 것을 최대 두 개 "…하셨어요 / …여쭤보세요"로, 완료한 것이 없으면 기록 없는 항목 하나를 짚는다. "전화 걸기"는 `Linking.openURL("tel:…")`를 쓰고 실패해도 앱은 계속 동작한다. 앱으로 돌아오면(AppState active) "통화 잘 하셨나요?" 시트가 뜨고, 메모(나만 보는 로컬 값)를 쓰고 "완료로 체크하기"를 누르면 오늘 목록의 "안부 전화"를 포함하는 항목을 완료 처리한다(없으면 안내 문구).
- 서버 자리: `daily/api.js` 의 응원(`listCheers`·`sendCheer`·`toggleCheerThanked`)과 전화(`listFamilyPhone`, 통화 메모는 서버에 보내지 않는 로컬 값)는 지금 폰 저장·mock 이다. 상대 폰으로 가는 전송, 알림, 가족 대화방 연동은 서버가 생긴 뒤의 후속 작업이다.
- 개발용(`__DEV__` 에서만, 편집 화면 하단): "예시 데이터 채우기"는 시안 값(내 항목·오늘 기록·받은 응원)으로 덮어쓰고 가상 가족 모드 플래그(`gabee.schedule.daily.devFamily.v1.*`)를 켠다. 가상 가족은 다섯 명(엄마·아빠·아들·딸·할머니, `logic.js` `DEV_FAMILY`, 기록·전화 mock 은 `mock.js`)이고, 목록에 덧붙이는 조건(`withDevFamily`)은 플래그가 켜졌거나, 개발 빌드이고 실제 가족(나 말고 구성원)이 한 명도 없을 때다(플래그와 무관하게 보인다). 같은 id 가 이미 있으면 중복하지 않는다. "데일리 체크 초기화"는 이 사용자의 `gabee.schedule.daily.*` 저장값을 모두 지워 다음에 온보딩이 뜨게 하고 플래그도 끈다(`api.js` `resetAll`). 탭 줄은 가로 스크롤이고 "편집" 칩은 고정이다. 가족 순서 바꾸기 화면은 세로 스크롤 안에서 목록이 늘어난다(끄는 중에는 스크롤이 잠기고, 화면 밖으로 끌어 자동 스크롤하지는 않는다).
