# care-02 C1 분리 변경과 독립 검증 계획 (2026-11-24)

범위: 메인 어시스턴트 `PROMPT_NOTE` 의 **건강 질문 의도·출처 지침** 하나. 최신 `release/1.4`(`b669a036`)에서 새 브랜치(`fix/seungdeuk-care02-c1-health-routing`)를 만들고 기존 PR #539 의 care-02 커밋 하나만 적용했다. #539 전체, isolation 지침, 신규 이웃 사례, w1nb 시드, 게이트 변경은 **포함하지 않는다**(`git diff origin/release/1.4` 의 프롬프트 변경은 건강 문단 하나). 공식 사례·정답지·채점기·기존 결과는 바꾸지 않았다.

## 1. 변경 내용
- 네 가지 정보 출처 라우팅: 구조화된 건강 기록·수치 → 도구 없이 지원하지 않는 기능이라 확인할 수 없다고 안내 / 가족이 한 말(과거 발언) 검색 → `ask_family_chat`('채팅' 낱말 없어도) / 올려 둔 진료 서류 → `search_knowledge` / 출처 불분명 → 도구 없이 건강 기록이 없음을 안내하고 가족 대화 검색을 한 문장으로 제안. 가족 대화 내용은 "대화에서 그렇게 말했다"까지만 전하고 의학적 사실처럼 말하거나 진단하지 않는다.
- 시험: care L0 8건(`test_main_prompt_care_health.py`), care L2 12건(`test_care_routing_cases.py`), 프롬프트·val 핀 재고정과 문서(`agent-eval-val-data.md` 9-9).
- 해시: 메인 `fddef66a…`, 통합 `0ac446e0…`(#539 의 첫 커밋과 같은 값, 같은 프롬프트). 소통·정산·일정 프롬프트 해시와 사례·채점기 해시 등 나머지 핀은 불변.

## 2. 기존 #539 결과의 지위
care-02 는 #539 평가에서 2/3(첫 평가, isolation 첫 지침 포함 프롬프트)과 3/3(A 재평가, isolation 개정 포함 프롬프트)이었다(합 5/6). **참고 자료일 뿐 이 독립 프롬프트(`fddef66a…`)의 성능이 아니다.** 두 평가 모두 다른 프롬프트에서 나왔고, 실패 1건은 기대 문구 묶음에 없는 표현("확인해 드리기 어려워요") 때문이었다.

## 4. 독립 실모델 평가 계획(최소 범위, 실제 호출은 별도 승인 전까지 없음)

- **프롬프트 해시:** 메인 `fddef66a…`, 통합 `0ac446e0…`. 모델·설정은 dev 108 과 동일(`claude-haiku-5-5`, `anthropic_max_tokens=2048`, 단계 상한 4).
- **사례와 반복(권장, 5사례×3회 = 15 case-run):**

  - `s-dev-01-routing-02`(메인에서 가족 대화 검색 보존), `s-dev-06-docs-01`(메인에서 문서 검색 보존)
