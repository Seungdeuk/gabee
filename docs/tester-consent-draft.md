## 1. 동의서 본문

gabee 팀은 AI 에이전트(가비)가 요청을 제대로 처리하는지 확인하려고 테스트를 하고 있어요.
테스트에 참여하시면서 아래와 같이 일부 정보를 모으고 쓰려고 하니, 읽어 보시고 동의 여부를 정해 주세요.

### 1) 무엇을 위해 모으나요? (수집·이용 목적)
- 가비가 요청을 잘 처리했는지(성공·실패) 확인해요.
- 오류가 났을 때 어느 기능(탭)에서 어떤 도구를 쓰다가 났는지 찾아 고쳐요.
- 어떤 기능에서 가비가 자주 틀리는지 모아 보고 품질을 높여요.
- 위 목적 외에는 쓰지 않아요.

### 2) 어떤 정보를 모으나요? (수집 항목)
대화 내용이 아니라 **사용 기록(메타데이터)만** 모아요.

| 항목 | 설명 |
|---|---|
| 요청 시각 | 가비에게 요청한 날짜와 시간 |
| 사용한 기능 | 어느 탭에서 요청했는지(AI 채팅, 소통, 일정, 가계, 돌봄) |
| 호출된 도구 이름 | 가비가 일을 하려고 쓴 기능의 이름 |
| 성공 여부 | 처리가 잘 끝났는지 |
| 업/다운 | 가비의 답에 남기는 좋아요(업)·싫어요(다운) 평가 (임시 정의, 팀 확정 필요) |
| 사용자 식별자 | 저장함. 이름·연락처가 아닌 가명 처리한 값 (임시 결정, 팀 확정 필요) |

## 4. 확정이 필요한 항목

비어 있는 것
1. 시행일, 버전 관리 방식
2. "업/다운"의 정의
3. 사용자 식별자 저장 여부와 가명 처리 여부
4. 보관 기간, 삭제 방법·시점, 삭제 확인 절차
5. 열람 기록을 남기는지
6. LLM 제공자, Supabase, GCP 각각의 서버 국가·리전과 이전 시기·방법
7. 동의 거부 시 앱 이용 제한 여부
8. 열람·정정·삭제·처리정지 요청 방법과 문의처
9. 실제 적용된 안전 조치
10. 만 14세 미만 테스터 허용 여부와 동의 방법

구현과 문안이 맞는지 확인할 점
- 이 코드 기준으로 사용 기록(요청 시각·기능·도구 이름·성공 여부·업/다운)을 저장하는 DB 테이블이나 로그 기능이 확인되지 않았어요. 먼저 실제 저장 방식이 정해져야 항목 표가 맞아요.
- 사용자가 보낸 채팅 내용이 LLM 제공자에게 전달돼요. "대화 내용을 모으지 않아요"는 **우리 사용 기록 DB**에 대한 말이고, LLM 호출 자체에서 내용이 오가는 것과는 별개예요. 이 구분이 오해 없게 쓰였는지 확인해야 해요.
- 가족 AI 사용 동의(소통방의 AI 켜기)는 이미 있어요. 이 동의서와 겹치지 않게 역할을 나눠야 해요.
- 동의 시각과 동의서 버전을 저장하는 기능은 아직 없어요(새로 만들어야 함).
- 시작 화면에서 동의를 받는 흐름도 아직 구현되지 않았어요.
