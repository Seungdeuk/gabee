# UI/UX 공통 작업 규칙

기준: 팀 디자인 파일 "GaBee / UI Kit"(가족의 일상을 챙기는 AI 비서 — 따뜻함·친근함·안정감·신뢰감). 화면은 Mobile 390 기준, 좌우 24px 인셋.

이 문서는 **디자인 파일의 값**을 기준으로 하고, `apps/mobile/src/theme/index.js`(실제 코드의 디자인 토큰, CLAUDE.md가 "디자인 값은 여기에만 둔다"고 정한 단일 출처)와 비교해 **일치/불일치/누락**을 표시한다. 새 화면을 만들 때는 색상·간격·글자 크기를 하드코딩하지 않고 `theme/`의 토큰만 쓴다(CLAUDE.md 기존 규칙 그대로) — 이 문서는 그 토큰들이 디자인 파일과 맞는지 확인하는 기준표다.

## 1. 색상

| 역할 | 디자인 값 | `theme/index.js` 현재 값 | 상태 |
|---|---|---|---|
| Brand / Cream | `#FEECBF` | `colors.surfaceStrong` `#FEECBF` | 일치 |
| Text / Brown | `#553B29` | `colors.text` `#553B29` | 일치 |
| Action / Peach | `#FEB49A` | `colors.peach` `#FEB49A` | 일치 |
| Surface / Ivory | `#FFFCF7` | `colors.background` `#FFFCF7` | 일치 |
| State / Complete | `#456C57` | `colors.success` `#456C57` | 일치 |
| State / Error | `#AD4949`(디자인 파일, 채택 안 함) | `colors.danger` `#C2503A` | **결정됨 — 코드 값(`#C2503A`) 유지.** 디자인 파일 값은 적용하지 않는다. |

피치 버튼에는 항상 다크 브라운(`colors.text`) 텍스트를 쓴다(흰 글자 금지). 크림(`surfaceStrong`)은 배경·AI 안내용, 오류/완료는 색만이 아니라 문구·기호를 항상 같이 표시한다(색각이상 대응).

**없는 것**: 디자인 파일에 있는 "Badge/Unrecorded(미기록)" 전용 중립색이 `theme/index.js`에 없다. `placeholder`/`disabled`는 입력 필드용이라 상태 배지에 그대로 쓰면 의미가 섞인다 — 새 중립 토큰(예: `colors.neutral`, `colors.neutralSoft`)이 필요하다(미정, 2번 참고).

## 2. 타이포그래피

디자인은 전체를 **Noto Sans KR**로 지정한다. **결정됨, 적용 완료**: `@expo-google-fonts/noto-sans-kr`을 설치하고(`apps/mobile/package.json`), `app/_layout.js`에서 Fredoka와 함께 4개 굵기(400/500/600/700)를 불러오며, `theme/font`의 모든 항목에 `fontFamily`를 지정했다(숫자 `fontWeight`는 쓰지 않는다 — 굵기별 글꼴 파일 자체가 그 굵기다). `StartScreen.js` 등 `font.*` 토큰을 안 쓰고 글자 스타일을 직접 적은 화면은 아직 기본 글꼴을 쓴다 — 그런 화면을 고칠 때 `font.*` 토큰으로 옮기면 자동으로 Noto Sans KR이 적용된다(범위 밖이라 이번에 일괄 수정하지 않음).

| 디자인 토큰 | 크기/굵기 | 현재 `theme/font`에 대응 항목 |
|---|---|---|
| Display | 30 Bold | 없음(가장 가까운 `page` 26/700) |
| Heading(섹션 제목) | 20 Bold | `title` 20/700 — 일치 |
| Parent(부모님 모드) | 19 Regular, 큰 글씨 | 없음 — 접근성 모드 전용 스타일 신설 필요 |
| Body | 16 Regular | `body` 15/400 — 근접(1px 차이) |
| Label(버튼/입력 항목) | 14 Medium | 없음(버튼은 17/700 하드코딩, `StartScreen.js` 등) |
| Caption | 13 Regular | `caption` 13/400 — 일치 |

## 3. 컴포넌트 규칙

- **Button/Primary**: 배경 `peach`, 글자 `text`(다크 브라운), 높이 56, Radius 16, 16 Bold. `theme.radius.button = 16`과 일치.
- **Button/Secondary**: 흰 배경, 1px 테두리(`colors.border`), Primary와 같은 높이(56).
- **Button/Disabled**: 회색 — 현재 `colors.disabled`(`#CBBBAE`, 입력용)를 재사용할지 버튼 전용 회색을 새로 둘지 미정.
- **"부모님 모드·큰 버튼"**: 디자인에 명시된 접근성 변형 — 고령 사용자를 위해 버튼을 더 크게 키우는 모드가 있다는 뜻이다. 지금 코드에는 이런 모드 분기가 없다 — 어떤 화면에 적용할지, 글자 크기 배율을 얼마로 할지는 미정.
- **Input**: Default/Focus(테두리 강조)/Error(빨간 테두리 + 안내 문구) 3상태. Radius 14 — `theme.radius`에 입력 전용 radius가 없다(지금은 `sm`/`md`로 대충 씀). Input radius 토큰 추가 필요.
- **Card**: AI 카드(크림 배경 + 안에 승인 전 배지 + 행동 버튼), 일반 카드(소유자가 허용한 가족만 열람 — 접근 범위를 카드에 명시). Radius 22 — 현재 `theme.radius.card = 20`, 2px 차이(불일치, 사소하지만 기록).
- **Shadow**: 디자인은 `0, 4, 16, #553B2909`(x,y,blur,색) 단일 토큰을 쓰는데, 지금 코드는 화면마다 그림자 값을 따로 적는다(예: `StartScreen.js`의 `shadowOpacity: 0.14, shadowRadius: 20`). 공통 `theme.shadow` 토큰이 없다 — 추가 필요.

## 4. 상태 배지 — 의미를 섞지 않는다

디자인 파일이 직접 명시한 규칙이라 그대로 옮긴다. 배지를 쓰는 모든 화면(돌봄, 가계, 기록 등)이 지켜야 한다.

- **미기록 ≠ 건강 이상** — 기록이 없다는 것은 "안 좋다"는 뜻이 아니다.
- **미확인 ≠ 미복용** — 가족이 아직 안 본 것과 약을 안 먹은 것은 다른 일이다.
- **승인 ≠ 실제 결제** — AI 제안을 승인한 것과 결제가 끝난 것은 다른 상태다.
- **생성 완료 ≠ 할 일 완료** — 기록/문서가 만들어진 것과 해야 할 일을 끝낸 것은 다른 상태다.

새 배지나 상태 문구를 만들 때 이 네 쌍을 혼동하는 표현(예: "기록 없음"을 경고색으로 표시)을 쓰지 않는다.

## 5. 내비게이션 — 결정됨

디자인 파일의 하단 탭 제안(홈 / 가족 / 기록 / 결제 / 리포트)은 **채택하지 않는다.**

하단 탭은 지금 코드·CLAUDE.md 그대로 유지: **AI 채팅(`chat`) / 소통(`family-chat`) / 일정(`schedule`) / 가계(`billing`) / 돌봄(`care`)**. 이 UI Kit은 색·타이포·버튼/입력/카드/배지 같은 컴포넌트·토큰 레벨의 참고 자료로만 쓰고, 화면 구성(IA)은 바꾸지 않는다. 디자인 파일의 "Handoff" 화면 인벤토리(6번)도 이 5탭 구조 안에서 각 화면이 어느 탭에 속하는지로 해석한다(예: "기록·문서·근거 기반 AI" 영역은 돌봄/가계/AI채팅에 걸쳐 들어감).

## 6. 화면 인벤토리(참고용)

디자인 파일의 "Handoff" 영역은 8개 구역·총 68개 화면을 이렇게 나눈다(번호는 디자인 파일 자체 색인, 코드 화면 수와 1:1 대응은 아님):

01–10 초기 진입·가족 설정 · 11–20 홈·생활 돌봄 · 21–30 가족·소통·공동 할 일 · 31–40 기록·문서·근거 기반 AI · 41–48 공동 지출·가족 결제·구독 · 49–54 가족 리포트·AI 다음 행동 · 55–60 알림·설정·권한 · 61–68 빈 상태·오류·철회

`01–10 초기 진입·가족 설정`이 `docs/requirements/family-group.md`(통합 인증·가족 구성원 설계)가 다루는 범위와 겹친다 — 그 문서의 PR 4-E(모바일 UI)에서 이 구역 화면들을 이 문서의 토큰으로 만든다.

## 7. 공통 간격·반경

| 토큰 | 값 |
|---|---|
| Spacing | 4 / 8 / 12 / 16 / 24 / 32 |
| Screen | 너비 390, 콘텐츠 좌우 인셋 24 |
| Radius | Input 14 · Button 16 · Card 22 |
| Shadow | `0, 4, 16, #553B2909` |

`theme.spacing`(4/8/12/16/20/24)은 대체로 일치하지만 `xl: 20`이 디자인의 간격 단위(16 또는 24)에는 없는 값이다 — 의도적으로 넣은 중간값인지, 디자인 쪽 32가 코드에 없는 것과 함께 확인이 필요하다(사소한 항목, 급하지 않음).

## 결정됨

- State/Error 색상: 코드 값 `#C2503A` 유지(디자인 파일 `#AD4949`는 채택 안 함).
- 내비게이션: 하단 탭은 지금 구조(AI 채팅/소통/일정/가계/돌봄) 그대로 유지, 디자인 파일의 탭 제안은 채택 안 함.
- Noto Sans KR: 도입 확정, 적용 완료(2번 참고).
