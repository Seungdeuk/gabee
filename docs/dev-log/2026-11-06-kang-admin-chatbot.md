# 2026-11-06 통합관리자 권한·운영 탭·관리자 챗봇 (kang)

- 관리자 권한을 통합관리자 하나로 합쳤다. scope 는 `admin`, 허용 목록은 `ADMIN_USER_IDS` 하나다. 서비스 관리와 운영 관리 API 가 같은 목록을 쓴다(`ops-admin.md` 확정 19차, 유님 확인 필요).
  - 배포 순서: 실제 서버에 `ADMIN_USER_IDS` 를 먼저 넣고 → 코드 배포 → 옛 목록 2개 삭제. 순서를 어기면 아무도 관리자 화면에 못 들어간다.
- 서비스 관리자 화면에 운영 탭(서버 상태)을 붙였다. 운영 대시보드(#284)를 iframe 으로 띄우고 로그인은 한 번으로 끝난다. API 서버 이미지에 `apps/api` 만 들어가서 `service_admin/static/ops/` 에 복사본을 뒀다. 원본을 계속 둘지는 유님과 정한다.
- 관리자 화면에 어두운 화면 스위치를 넣었다. 고른 모드는 브라우저에 저장되고 운영 탭에도 적용된다.
- 관리자 챗봇을 넣었다(`POST /admin/knowledge/ask`). 오른쪽 아래 버튼, 대화 비우기, 최근 오류 탭 3개의 추천 질문, 주제별 질문을 쓸 수 있다.
  - 임베딩 RAG, 하이브리드 검색, 온톨로지까지 만들고 시험했으나 결정에 따라 뺐다. 지금은 Claude API 만 쓴다. 코드 백업은 저장소 밖에 있다.
  - 규칙은 `admin_knowledge/faq.md`, 답 형식은 `answer_format.md` 에 있다.
  - 지금 숫자는 `live.py` 가 화면과 같은 조회 함수로 읽어 개수와 오류 종류·경로·횟수만 Claude 에게 준다. 이름, 이메일, 사용자 id, 오류 메시지, trace id 는 보내지 않는다.
  - `ASK_MAX_TOKENS` 를 500 으로 두니 복잡한 질문에서 빈 답이 왔다. 2000 으로 올렸다.
- 랭체인·랭그래프는 받아서 확인했다가 필요 없어서 지웠다. 흐름이 곧고 `shared/llm` 으로 충분하다.
- 팀에 알릴 것:
  - `test_every_llm_caller_goes_through_a_guard` 에 `admin_knowledge/service.py` 가 걸린다. 공통 관문이 가족 기준이라 관리자에 못 쓴다. 관문을 넓힐지 예외로 둘지 정해야 하고, 그때까지 사용 기록(`ai_usage_logs`)이 남지 않는다.
  - `live.py` 와 `service.py` 가 다른 기능의 내부 함수(`service_admin`, `ops_admin`, `ingest/masking`)를 직접 부른다. 기능 간 import 규칙과 맞지 않아 공통으로 옮길지 정해야 한다.
  - `shared/auth.py`, `shared/config.py`, `.env.example`, 운영 라우터, 공용 시험 파일을 고쳤다.
  - FAQ 의 공지 종류 고르는 법, 되돌릴 때 담당자에게 알리기는 근거 문서가 없다. 확인이 필요하다.
  - 하루 한도 100번은 임시값이고 서버 메모리에 있다. 월 예산과 함께 정해야 한다.
  - 로그인 토큰이 15분이라 운영 탭을 켜 두면 만료 뒤 401 이 반복된다. 자동 연장과 만료 시 운영 탭 정지가 필요하다.
- 시험: 내 PC 시험 서버에서 부하 600회 실패 0건, 탭 8개와 챗봇 확인. 가짜 데이터만 썼고 실제 DB, Cloud Run, 실제 휴대폰은 아직 확인하지 못했다.

## 이후 변경 (2026-11-09 ~ 11-16)

- 하루 한도 100번(위 임시값)은 11-09 에 없앴다.
- 위 "랭체인·랭그래프는 지웠다"는 11-11 에 다시 바꿨다. 지금 구조는 아래와 같다.
  - 도구 명단: 각 기능이 자기 폴더의 `admin_facts.py` 에서 `shared/admin_facts.register()` 로 숫자 함수를 올린다(`service_admin`, `ops_admin`). 챗봇은 명단만 읽어서, 위에 적은 "다른 기능의 내부 함수를 직접 부른다" 문제는 `service_admin`·`ops_admin` 쪽은 풀렸다. `ingest/masking` 은 아직 직접 부른다.
  - `live.py` 가 명단을 랭체인 도구로 바꾸고, `graph.py`(랭그래프)가 Claude ⇄ 도구 반복을 돈다(최대 4번). 날짜를 골라 묻는 도구(회원·AI 사용량, 최대 90일)도 넣었다.
  - 메인 AI 채팅의 `rag_graph.py` 와 같은 방식이라 기능은 같고, 단계 추가와 추적이 쉬워졌다. 대신 숫자 질문은 Claude 를 2번 부른다(측정 2.0~3.6초).
- 랭스미스 기록 스위치를 넣었다(`ADMIN_LANGSMITH_ENABLED`, 기본 꺼짐). 관리자 챗봇 그래프에만 붙고 서버 전체 추적(`LANGSMITH_TRACING`)은 쓰지 않는다. ADR 0011 의 "랭스미스는 꺼 둔다"와 기본값은 같지만, 켤 수 있는 스위치가 생긴 것은 팀에 공유해야 한다.
- `test_every_llm_caller_goes_through_a_guard` 는 이제 통과한다. 고쳐진 것이 아니라 그 시험이 `run_agent(` 글자를 찾는데 그 호출이 없어져서다. 관리자 챗봇은 여전히 공통 관문을 거치지 않는다.
- 비교 실험(11-16, 24문항): FAQ 를 통째로 넣는 지금 방식은 FAQ 질문 7/7, 문서에만 있는 질문 0/10. 문서 조각 검색을 더하면 문서 질문 4~6/10 으로 오르지만 0.4초 느려지고 입력이 1.5배다. 지금은 그대로 둔다.
- 팀에 알릴 것(추가): `faq.md` 의 AI 비서 하루 한도(사람 10, 가족 30)가 코드 기본값(`ai_assistant_max_calls_per_user_per_day` 100, 가족 300)과 다르다. 실제 서버 값을 확인한 뒤 FAQ 를 고쳐야 한다.
