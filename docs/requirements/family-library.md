# 요구사항: 가족 공유 라이브러리 (GaBee 2.0, 1단계: 채팅 문서·문서 사진 자동 등록)

> **2026-11-23 갱신(사용자 결정, [ADR 0024](../adr/0024-local-ocr-removed-siglip-only-photo-judge.md))**: 로컬 OCR 을 제거했고 사진 판별은 로컬 SigLIP2 단독(margin > 5)이며 문서 속 글자는 Claude 만 읽는다. **가족 소통 채팅방**의 문서·사진 자동 등록은 **가족 AI 동의가 있을 때만** 외부 AI(Claude·Jev)로 보낸다(동의가 없으면 사진은 채팅에 남고 자동 등록 보류, "문서로 저장"은 403 `ai_consent_required`, 글·PDF 는 외부 AI 없이 로컬 규칙으로 가려 저장하고 스캔 쪽·PPT 그림은 읽지 않음). 이는 2026-11-10 결정("채팅 문서만 따로 AI 동의를 확인하지 않는다")을 **채팅방에 한해 대체**한다. **메인 AI 직접 업로드(`/ai-assistant/files`)는 기존 정책 그대로**(Claude 읽기·가리기·분류, 동의 검사 없음)이며 명시적인 사용자 결정이다. 아래 "판별: 로컬 OCR"·"PHOTO_JUDGE_LLM"·2026-11-10 서술은 당시 결정 기록이다. **운영 활성화는 승인되지 않았고**, `margin > 5` 의 실제 한국어 문서 검증은 미완료다. 실제 서비스의 동의 문구·개인정보처리방침은 별도 확인이 필요하다.

> 전체 구상: 가족 채팅방에 올린 사진·파일이 별도 업로드 없이 **가족 공유 라이브러리**(사진 타임라인 + 가족 공유 문서함)에 모이고, @가비가 문서를 찾아 방에 공유하며, 주간 가족 뉴스가 이를 쓴다. 이 문서는 그중 **1단계(문서 파일·문서 사진 자동 등록)** 의 결정이다. 다음 단계(타임라인·문서함 화면·@가비 문서 검색·가족 뉴스)는 각각 이어서 정한다.

## 목적
가족 구성원이 가족 채팅방에서 평소처럼 문서를 공유하면 같은 문서를 문서함에 다시 올리지 않아도 가족 공유 문서함에 등록되어, 문서함(기록)과 @가비 문서 검색에서 쓸 수 있게 한다. GaBee 는 개인 파일 저장 서비스가 아니라 **가족 그룹 전체가 함께 쓰는 서비스**다.

## 결정 사항 (2026-11-06, 사용자)
- **범위: 가족 전체방의 문서 첨부만.** 1:1 대화방의 파일은 등록하지 않는다(방 단위 권한을 가진 자료가 가족 전체 권한의 문서함으로 새지 않게 하려는 것). 이전 결정 "채팅 문서는 AI 분석·@가비·검색에 쓰지 않는다"(`family-chat.md` 문서 파일 첨부, 2026-10-30)는 **가족 전체방 문서에 한해 바꾼다.** 1:1 방 파일은 그대로 쓰지 않는다.
- **사진은 문서 사진만 골라 자동 등록한다**(2026-11-09, 사용자: 종이 안내문을 찍어 올리는 일이 문서 파일보다 많다). 가족 전체방 사진을 보내면 서버가 뒤에서 문서 사진인지 판별해, 문서면 문서 파일과 같은 읽기 경로로 문서함에 넣는다. 일반 사진은 등록하지 않는다(사진 타임라인은 다음 PR, AI 없이 첨부 메타데이터로 만든다). 결정 근거와 평가는 `docs/adr/0015-family-room-photo-to-library.md`.
  - **판별**: ① 로컬 OCR 로 글자 수·줄 수를 센다(문서 100자·6줄 이상, 일반 사진 50자 미만, 사이는 애매함; 외부 전송 없음). 읽기 자체가 실패한 사진은 등록하지도 외부로 보내지도 않는다. ② `PHOTO_JUDGE_LLM=true` **이고 그 가족이 AI 사용에 동의했으면**(`ai_guard`) 글자가 읽힌 사진(문서·애매)만 Claude haiku 에게 "문서 사진인가"를 묻고, 문서이고 확신 0.7 이상일 때만 등록한다(간판 많은 거리 사진은 문서가 아니다). 설정이 꺼져 있거나 가족이 AI 에 동의하지 않았으면 ①만으로 판단하고(문서로 읽힌 것만 등록) 외부로 나가지 않는다.
  - **애매하거나 판별이 실패하면 자동 등록하지 않는다.** 사진을 눌러 여는 사진 보기의 **"문서로 저장"**(`POST /family-chat/photos/{id}/library`)으로 가족 누구나 직접 넣는다. 직접 저장은 판별·(하루 상한은 없다) 글자가 거의 없어도 사진 기록으로 문서함에 남는다. 이미 등록돼 있으면 `already` 로 답하고 한 번만 등록한다. 1:1 방 사진은 저장할 수 없다(409). 응답 `queued` 는 "저장을 시작했다"는 뜻이다: **읽어 보니 읽지 못하면 직접 저장해도 문서함에 넣지 않는다**(앱 문구가 이를 알린다). 민감 문서(처방전·신분증 등)도 직접 저장하면 들어간다(2026-11-09 변경). 요청은 사용자당 분당 10번까지(429), 같은 사진의 진행 중인 요청은 겹쳐 처리하지 않는다.
  - **상한**: 하루 상한은 없앴다(2026-11-09 사용자 결정, 비용은 월 예산·Claude 콘솔 사용 한도로 지킨다), 가족마다 처리 대기 20장(한 가족이 다른 가족을 막지 않는다). 넘으면 자동 등록만 멈추고 직접 저장은 된다.
  - **중복 저장**: 문서함이 사진을 자기 원본 보관소(`DATA_DIR/raw`)에 한 번 더 복사한다(사진 한 장당 약 0.3~8MB). 채팅 사진 파일을 참조하는 방식으로 줄이는 것은 후속 과제다.
  - **문서함 원본은 서버가 다시 만든 사본**이다: 채팅에 저장되는 긴 변 1600px JPEG(EXIF·촬영 위치·주석 없음)를 읽고 보관한다. 업로드 원본(위치 정보가 남아 있다)은 문서함으로 넘기지 않는다(문서함 원본은 가족 누구나 내려받는다). 자동 등록과 직접 저장이 같은 사본을 쓴다. 대신 읽는 해상도는 1600px 가 상한이다(평가에서 1600px 로 줄여도 Claude 읽기 품질은 같았다).
- **민감 문서도 등록한다**(2026-11-09 사용자 결정, 이전 결정은 "자동 등록에서 제외"였다): 채팅방 문서함과 AI 채팅의 기록은 둘 다 가족이 함께 쓰는 같은 문서함이므로, 가족 전체방에서 올린 문서는 처방전·신분증·통장 사본 같은 민감 문서도 등록한다(문서 파일·문서 사진·직접 "문서로 저장" 모두). 기록에는 **민감 표시**(`sensitivity=sensitive`)가 붙고, 계좌번호 같은 개인정보는 읽을 때 이미 가려 저장한다. **알아 둘 점**: ① 보관한 원본(가리기 전 사진·파일)이 가족 누구에게나 보인다. ② `CHAT_INCLUDE_SENSITIVE`(기본 켜짐)이면 민감 기록의 가린 글이 @가비 답변 근거로 외부 Claude 에 전달된다(문서함 화면에서 직접 올린 문서는 원래부터 같았다). ③ AI 리포트의 "공유한 문서" 집계에서는 민감 표시 문서를 뺀다. ④ 앱 안내 문구가 "민감한 문서도 가족 모두가 볼 수 있고 AI 에 전달될 수 있어요"라고 알린다. ⑤ 챙길 일 뽑기(`INGEST_REMINDERS`, 문서 본문이 Claude 로 나가는 단계)는 가족방에서 온 민감 문서에서는 건너뛴다. ⑥ 신분·금융·의료 이름만 민감한 분류(진단서·외국인등록증·통장 사본 등)도 등록하되 민감 표시를 붙인다(`is_sensitive(strict)`). 1:1 방의 문서·사진은 여전히 등록하지 않는다.
- **지원하지 않는 형식은 등록하지 않는다**(hwp·hwpx·예전 doc/xls/ppt 등 `ingest.detect` 가 읽지 못하는 것). 문서함에 "읽지 못함" 기록이 쌓이지 않게 읽기 전에 거르고, 원본도 따로 보관하지 않는다(채팅 파일로만 남는다).
- **연결 방식(A안)**: `knowledge_items.source_attachment_id`(채팅 첨부 id, nullable, **유일**)로 잇는다. 새 라이브러리 테이블은 만들지 않는다 — 사진 타임라인은 `message_attachments`, 문서함은 `knowledge_items` 가 곧 라이브러리다. 파일은 채팅 쪽(`DATA_DIR/chat_files`)과 원본 보관소(`DATA_DIR/raw`, 같은 내용은 한 번만)에 있고, 기록은 같은 첨부를 한 번만 가리킨다.
- **삭제**: 채팅 메시지를 지우면 연결된 문서함 기록·검색 조각·보관한 원본(다른 기록이 쓰지 않을 때)도 함께 지운다.
- **안내**: 가족방에 처음 문서를 올릴 때 한 번 "가족 문서함에 자동으로 모여요"를 알린다(문서마다 끄는 스위치는 두지 않는다).
- **알림**: 채팅에 이미 올라온 파일이라 "가족 문서함에 새 문서가 올라왔어요" 푸시·알림은 한 번 더 보내지 않는다.
- AI 비용·개인정보: 읽기(OCR·가리기)는 기존 업로드 뒷처리를 그대로 쓰고(`files.process_file`), 외부 LLM 사용(`INGEST_LLM_OCR`/`INGEST_LLM_MASK`)은 #333 이후 기본 켜짐이다(기존 업로드와 같은 설정을 쓴다).
  - **이전과 달라지는 점**: 채팅 파일은 예전에는 외부로 나가지 않았다(family-chat 2026-10-30 결정). 이제 가족방 문서는 사용자가 따로 누르지 않아도 기존 업로드와 **같은 읽기 경로**를 탄다. 그래서 위 설정이 켜져 있으면 채팅 문서도 Claude 로, 분류가 애매하고(0.7 미만) `TYPESAFE_API_KEY` 가 있으면 가린 글 앞 3000자가 분류 보조(Jev)로 나갈 수 있다. 이 전송은 민감 문서를 "제외"하기 **전에** 일어날 수 있다(민감 여부는 읽은 뒤에야 안다).
  - 외부 전송을 쓰지 않는 서버(위 설정을 모두 끄고 키도 없는 서버)에서는 바뀌는 것이 없다. 기본값에서는 문서로 등록되는 채팅 문서·사진이 읽는 과정에서 Claude 로 나간다. 채팅 문서에서만 외부 전송을 막는 옵션은 아직 없다(필요하면 후속 결정). (2026-11-10 결정으로 만들지 않기로 했다: 아래 "2026-11-10 결정" 참고.)
  - **사진**: 기본(`PHOTO_JUDGE_LLM=false`)에서는 사진 판별이 로컬 OCR 만 쓴다. 켜면 **AI 사용에 동의한 가족의 글자가 읽힌 사진(표본의 약 40%)** 이 판별용으로 Anthropic API 로 나간다(긴 변 1024px JPEG, EXIF·위치·주석 없음). 읽기에 실패한 사진과 동의하지 않은 가족의 사진은 나가지 않는다. 문서로 판정된 사진의 읽기는 위 `INGEST_LLM_OCR` 설정을 따른다. 1:1 방 사진은 어디에도 넘기지 않는다.
- **2026-11-10 결정(사용자): 채팅 문서만 따로 AI 동의를 확인하지 않는다.** 가족방 문서·사진을 읽고 가리는 단계는 AI 채팅 업로드와 같은 방식(Claude API, `INGEST_LLM_OCR`·`INGEST_LLM_MASK` 기본 켜짐, #333)이고, AI 채팅 업로드(`files.process_file`)에도 동의 확인이 없으므로 채팅 문서에도 따로 두지 않는다. 위 "이전과 달라지는 점"의 "채팅 파일은 예전에는 외부로 나가지 않았다(family-chat 2026-10-30 결정)"와 처방전 미전송(2026-10-22) 서술은 가족 전체방 문서·사진에 한해 **대체됨**이다(1:1 방 파일은 그대로 보내지 않는다). 사진 판별 2단계(`PHOTO_JUDGE_LLM`)의 동의 확인(`library.py` `ai_guard.is_enabled`)은 유지한다. 개인정보처리방침·스토어 고지 반영이 필요하다(로드맵 T31). 근거: `docs/adr/0015-family-room-photo-to-library.md` "결정 (2026-11-10)".
- **학교 납부 계좌 안내는 등록한다**(2026-11-09, 사용자): 가정통신문·납부 안내문에는 학교 계좌번호와 "예금주"가 자주 나와, 읽기 단계가 통장류(`bankbook`)로 잡아 자동 등록에서 빠졌다. 통장류로 잡힌 문서 중 **안내문**만 일반 문서로 등록한다(`masking.is_account_notice`, 판단은 가리기 **전** 글로 한다): 통장·보통예금·입출금·이체확인·거래내역·잔액·받는분·출금/입금계좌 같은 **개인 금융 낱말이 하나도 없고**, 납부·납입·수납·회비·가정통신·학부모·학교·유치원·어린이집·학원 같은 **안내 낱말이 있을 때**. 계좌번호는 읽을 때 `****` 로 가려 저장하지만 보관한 원본 사진에는 보인다. 통장 사본·이체확인증·거래내역은 민감 표시를 달아 등록한다(2026-11-09 변경: 이전에는 제외, 계좌번호는 가려 저장). 문서 파일·사진 모두 같고, 일반 문서로 등록된 안내문은 확인·수정해도 다시 민감 문서로 바뀌지 않는다. 남는 위험: 안내 낱말(학교·회비 등)이 있는 개인 금융 문서, "통장" 같은 낱말 없이 영문으로만 된 은행 문서(영문 은행 문서는 원래부터 통장류로 잡히지 않아 계좌번호가 가려지지 않는 기존 한계). 통장류로 가려진 안내문 본문은 "이름으*" 처럼 과하게 가려질 수 있다.
- (폐기, 2026-11-09) 민감 문서 제외 규칙과 신분·금융·의료 분류 이름 추가 제외(`CHAT_EXTRA_SENSITIVE_WORDS`, `is_sensitive(strict)`)는 없앴다. 분류를 못 하거나 "기타 문서"로 나온 문서가 등록되는 것은 그대로다.
- 처리 한계: 읽기는 서버 안의 작업 2개짜리 대기열에서 돈다. 서버를 끄거나 다시 시작하면 대기 중인 문서는 등록되지 않는다(채팅 파일로는 남고, 다시 올리면 등록된다). 재시도를 다 써도 못 읽은 문서는 기록·원본을 남기지 않는다.
- E2EE 는 이번 범위가 아니다. 서버가 읽어 문서함·검색에 쓰는 자료(가족 전체방 문서)와 향후 E2EE 로 보호할 자료의 경계는 별도 설계에서 정한다(서버 OCR·임베딩 검색이 필요한 문서함은 서버가 내용을 처리하는 자료다).

## 흐름
1. 가족 구성원이 가족 전체방에 문서를 올린다(`POST /family-chat/files`) → 기존대로 저장되고 메시지가 만들어진다.
2. 저장이 성공하면 `shared/chat_library` 통로로 `ai_assistant` 에 알린다(`family_chat` 이 `ai_assistant` 내부를 직접 부르지 않는다).
3. `ai_assistant.library` 가 백그라운드에서: 형식 확인 → 이미 등록했는지 확인 → `photos` 행 만들기 → `files.process_file`(읽기·가리기·분류) → `knowledge_items` 저장(`source_attachment_id` 채움, 민감 문서는 민감 표시를 붙여 저장하고 챙길 일 뽑기는 건너뜀).
4. 메시지를 지우면 `chat_library.attachment_removed` 로 연결된 기록을 `files.delete_record` 로 함께 지운다.
5. 채팅 전송은 어떤 경우에도 이 등록 때문에 실패하지 않는다(등록 실패는 로그에 종류만 남긴다).

## 이번 단계에서 하지 않는 것
- 사진 타임라인, 문서함 화면, @가비 문서 검색·방 공유, 주간 가족 뉴스, 기록 삭제 권한 제한(올린 사람만), 기록 목록·상세의 민감 문서 가림(기존 동작 그대로).

## 사진 판별 기준 (2026-11-09 사용자 결정)
가족 전체방에 올린 사진 중 AI 채팅의 기록(가족 공유 문서함)으로 넘어가는 것은 **문서로 판별된 사진**뿐이다. 모든 사진은 채팅방의 사진·동영상 탭에 남는다. 1:1 방의 사진·문서는 기록으로 넘기지 않는다.

**판별 방식: B(Claude 판별)**. `PHOTO_JUDGE_LLM=true`(서버 `.env`, 기본값 false)로 켠다. 켜져 있고 그 가족이 AI 사용에 동의했을 때만 쓰며, 아니면 아래 1단계(글자 수)만으로 판별한다.
1. **서버에서 글자 읽기(로컬 OCR)**: 100자 이상·6줄 이상이면 "문서 후보", 50자 미만이면 일반 사진(등록하지 않고 외부로도 보내지 않음), 그 사이는 애매(자동 등록하지 않음, 사진 보기의 "문서로 저장"으로 직접).
2. **Claude 판별(글자가 읽힌 사진만)**: 문서인지 일반 사진인지 가르고 확신 0.7 이상일 때만 등록한다. 애매하거나 실패하면 등록하지 않는다.
3. **등록 뒤 전체 읽기**: `INGEST_LLM_OCR`(기본 켜짐)에 따라 Claude 로 읽고 가린다. 글자가 거의 없으면 버린다.

**문서로 보는 것**: 가정통신문, 학교·기관 안내문, 공고문, 영수증, 고지서·청구서, 서류, 편지, 신문·잡지 기사, 안내 포스터 한 장(정면으로 찍은 것).
**일반 사진으로 보는 것**: 풍경·사람·음식·동물·건물·거리·시장·상점 풍경, 그리고 글자가 많아도 **메뉴판·시간표, 제품 포장·성분표, 간판·현수막**.
- 판별 지침은 `app/shared/llm/doc_ai.py` 의 `PHOTO_JUDGE_SYSTEM` 이고, 시험은 `app/shared/llm/tests/test_photo_classify.py` 가 문서/사진 목록을 지킨다.
- 자동 등록에서 빠진 문서(애매하거나 지침에서 일반 사진으로 본 것)는 사용자가 "문서로 저장"으로 넣을 수 있다. 하루 자동 등록 상한은 없다.
- 지침을 바꾸면 이전 평가(문서·거리 사진 표본)와 달라질 수 있어, 바꾼 뒤에는 평가를 다시 돌려 오인·애매 비율을 확인한다(아직 이 지침으로는 평가하지 않았다).
