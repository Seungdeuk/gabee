# 기능: 일정

## 목적
가족이 약속과 할 일을 한 곳에서 보고, 등록하고, 서로 확인한다. 일정 에이전트가 빠뜨린 것을 먼저 권해 준다.

## 용어
- 탭 이름과 총칭은 "일정", 형태는 "약속"(그날 그 시간에 일어나는 것)과 "할 일"(체크하면 끝나는 것). 약속의 체크는 "확인했어요", 할 일의 체크는 "완료했어요".
- 공동 일정 = 공유받았거나 내가 공유했거나 부탁을 수락해서 생긴 일정(나머지는 나 혼자). 제목 앞에 "공동" 이름표가 보이고 나 혼자 일정은 표시가 없다. 서버가 목록 응답에 `shared`(공동 여부)·`shared_ids`(나와 얽힌 사람, 나 제외)를 계산해 내려준다(저장하지 않음). "누구"(관련된 사람) 입력은 더 쓰지 않는다: 등록·수정·브리핑·상세에서 빼고 API 의 `who_ids` 와 DB 컬럼도 없앴다. 가족 구성원 이름은 별명 → 이름 순(관계는 쓰지 않음)
- 주제 = 하나, 기본 선택 없음, 고르지 않으면 분류 없음. 기본 주제는 경조사, 나머지는 사용자가 만들고 색을 고름.
- 공유 = 보여줄 가족 구성원(계정 있는 사람만). 안 고르면 나만.
- 화면 글자에서는 "부탁"을 쓰지 않는다. "함께"는 영역·상태, "같이"는 동작. 브리핑의 부탁 카드 태그는 "함께"다. 예외: 보낸 부탁 상세의 "부탁 취소하기"와 취소 팝업(사용자가 시안으로 승인).

## 화면
- 메인: 주간 스트립(달력 아이콘 → 달력), 오늘·내일 카드(체크 수 2/3), 일정·할 일 추가하기, 함께하기(같이하기), 먼저 권해드려요 카드.
- 달력: [달력 | 목록], 필터 두 줄(대상: 나·공동·가족 구성원, 주제), 월 달력(점: 약속 복숭아 / 할 일 초록, 날짜당 최대 3개), 선택 날짜 목록. 음력 1일(초하루)은 날짜 아래에 작은 글자로 항상 표시. 날짜 직접 입력에서 양력/음력 스위치로 음력 날짜를 쓰면 해당하는 양력으로 바꿔 저장.
- 등록: 형태 [약속 | 할 일]만 고르고 입력 항목은 같음. 제목(필수), 주제·공유, 날짜(필수)·시간·장소, 메모. 날짜·시간은 시트로 선택. 저장하면 진입했던 화면으로 돌아감.
- 상세: 보기·수정·삭제. 수정·삭제는 만든 사람만. 삭제는 가운데 확인 팝업.
- 같이: 보내기, 받기, 현황(받은 | 보낸), 보낸 것 상세.
- 채팅: 일정 탭에서는 제공하지 않는다(메인 채팅이 일정 에이전트를 부른다).
- 화면별 상세 규칙은 프로젝트 위키 `schedule-*` 문서를 따른다.

## API
- 서버 일정은 사람마다 자기 줄(`user_id`)을 가진다. 앱은 우선 mock 데이터로 만들고, 서버 연동은 별도로 합의한다.
- `POST /schedule/events`: 제목과 시각(`start_date` + 선택 `start_time`·`end_time`, 또는 옛 방식 `starts_at`) 외에 형태 `kind`(1 약속·2 할 일), `place`, `memo`(옛 이름 `note`), 공유 대상 `share_with`(가족 구성원 id 목록)를 받는다. 공유 대상을 고르지 않으면 나만 갖고, 고르면 그 사람마다 복사본이 생긴다. 구성원이 아닌 사람이 있으면 400 `invalid_share_target`.
- 복사본은 만들어진 뒤로는 받은 사람의 일정이다(`origin_id` 는 출처 표시일 뿐). 원본을 고치거나 지워도 복사본은 그대로이고, 복사본의 확인·삭제는 받은 사람이 자기 줄에서 한다.
- `GET /schedule/events`: 내 줄만 준다(삭제된 것 제외). 주인이 없는 옛 일정(`user_id` 없음)은 그룹 전체가 본다.
- `POST /schedule/events/{id}/confirm`: 내 줄만 확인한다.
- `PUT /schedule/events/{id}/checked`: 요청 `{checked: true|false}`. 내 줄의 확인(약속)·완료(할 일) 표시를 정한다. 같은 값을 다시 보내도 그대로이고, 내 줄이 아니거나 지워진 일정은 404. 체크는 각자 자기 줄에서 하고(공유받은 복사본은 따로), 일정을 고친 것이 아니라서 `edited_at` 은 바뀌지 않는다.
- `DELETE /schedule/events/{id}`: 그 줄의 주인만 지운다(삭제 시각 `deleted_at` 만 채움). 주인이 아니면 403 `not_owner`, 내 줄이 아니면 404.
- `PATCH /schedule/events/{id}`: 그 줄의 주인만 고친다(아니면 403 `not_owner`, 내 줄이 아니거나 지워진 것은 404). 바꿀 값만 보낸다: `title`, `start_date`, `start_time`, `end_time`, `kind`, `place`, `memo`, `topic_id`, `share_with`. 보내지 않은 값은 그대로이고, 시간(`start_time`·`end_time`)은 `null` 로 보내면 지운다(시간 없음, 시작이 없어지면 끝도 없어진다). 끝나는 시간이 시작보다 늦지 않으면 400 `invalid_time`, 보낸 값이 하나도 없으면 400 `nothing_to_update`. 고친 시각 `edited_at` 을 남기고(`share_with` 만 보낸 요청은 일정을 고친 것이 아니라 남기지 않는다) 옛 컬럼(`starts_at`·`note`)도 맞춘다. 원본을 고쳐도 복사본은 그대로이고, 복사본은 받은 사람이 자기 줄에서 고친다.
  - `share_with` 는 공유 대상 전체를 다시 정한다. 원본 주인만 바꿀 수 있다(복사본 주인이 보내면 403 `not_share_owner`, 가족 구성원이 아닌 사람이 있으면 400 `invalid_share_target`, 지워진 일정은 404). 새로 든 사람에게는 지금 값으로 복사본이 생기고, 빠진 사람의 복사본은 고쳤든 체크했든 지워진다(소프트 삭제, 출처 `origin_id` 도 끊어 공유 목록에서 빠진다). 다시 넣으면 새 복사본이 생기고 지워진 것은 그대로다. 받은 사람이 스스로 지운 복사본은 공유 대상으로 남아 있는 한 다시 만들지 않는다. 일정 삭제는 복사본에 영향이 없다.
- `GET /schedule/events/{id}/sharing`: 읽기 전용, 저장 없이 그때그때 계산한다. 응답 `{shared_by, shared_with}`. 복사본이면 `shared_by` 는 원본 주인(원본이 지워졌어도), 아니면 `null`. `shared_with` 는 원본에서 나온 모든 복사본 주인의 id(받은 사람이 자기 복사본을 지웠어도 남고, 나도 받은 사람이면 포함). 공유 안 한 일정은 `[]`. 내 줄이 아니거나 없으면 404.
- 주제는 사람마다 자기 것이다. 이름(`name`, 30자)과 색(`color`, `rose`·`amber`·`green`·`sky`·`purple` 중 하나, 기본 `rose`)을 가진다. 기본 주제 "경조사"는 사람마다 처음 목록을 읽을 때 만들고, 지운 뒤에는 다시 만들지 않는다. 같은 사람의 지우지 않은 주제끼리는 이름이 겹칠 수 없다.
  - `GET /schedule/topics`: 내 주제 목록(지운 것 제외). `POST /schedule/topics`: `{name, color}` 로 만든다. 이름이 겹치면 409 `topic_exists`.
  - `DELETE /schedule/topics/{id}`: 내 주제만 지운다(`deleted_at` 만 채움). 그 주제를 붙였던 내 일정은 `topic_id` 를 비운다.
  - 일정 `POST`·`PATCH` 는 `topic_id` 를 받고 일정 응답에도 `topic_id` 가 있다. `PATCH` 에서 `null` 이면 주제를 지운다. 없거나 지웠거나 남의 주제면 400 `invalid_topic`. 공유 복사본에는 주제를 붙이지 않는다.
- 옛 컬럼(`starts_at`·`note`·`created_by`·`status`)은 당분간 새 컬럼과 함께 채운다. 제거는 별도 PR(담당자 승인 후).
- 에이전트(`POST /schedule/agent`)도 호출한 사람의 일정만 읽는다.
- `GET /schedule/suggestions`: 응답 `{suggestions: [{id, title, kind, start_date, place, later}], exhausted, state, can_refresh}`. 추천은 참고용이고 사람마다 하루 `schedule_card` 호출 한도(기본 3회, 한 묶음 = LLM 한 번 = 같은 `created_at` 의 제안 최대 5개)까지 만든다. 오늘(서버 로컬 날짜) 만든 추천만 보며 날짜가 지난 것은 빼고, 보여 줄 때마다 순서를 섞는다. 대기(pending) 제안이 있으면 호출이 남았어도 AI 를 부르지 않고 그것을 돌려준다. 대기가 없고 호출이 남았으면 새로 만든다("나중에"만 남았거나 전부 확정이어도 호출). 호출이 비었거나 오류면 "나중에"(status 3) 제안을 대신 돌려주고, 호출을 다 썼으면 "나중에" 제안을 계속 돌려주며 전부 확정되면 빈 목록과 `state: "exhausted"`(= `exhausted: true`)를 준다(다음 날 다시 만든다). `state` 는 `ok`(보여 줄 추천 있음) / `exhausted`(오늘 추천은 여기까지) / `no_data`(참고 데이터가 전혀 없어 AI 를 부르지 않음, 한도도 안 씀) / `filtered`(데이터는 있는데 새로 만들 게 없음, 호출 1회로 셈) / `preparing`(AI 호출 오류). `can_refresh` 는 새로고침이 의미 있는가(하루 한도 소진·AI 꺼짐·키 없음이면 false). 하루 한도 초과(429 `ai_daily_limit_*`)는 오류가 아니라 `exhausted` 로 답한다. 이미 있는 제안은 대기·확정·나중에 모두 다시 만들지 않는다. 모델에는 내 일정(지난 2주~앞으로 60일)의 제목·날짜·시간만 보내고(개인정보는 가림, 가족 이름은 보내지 않음), 결과는 오늘~60일 안의 날짜만 받고 이미 있는 일정·제안과 같은 것은 버린다. AI 를 부를 때만 동의(403 `ai_not_enabled`)와 카드 한도(429)를 본다. 채팅의 `recommend` 의도도 같은 공급을 써서 `suggestion` 카드로 답한다.
- `PUT /schedule/suggestions/{id}/later` `{later: bool}`: 추천 카드의 "나중에" 표시. true 면 status 3(나중에), false 면 1(대기)로 되돌린다. 확정된 추천·남의 추천·없는 추천은 400 `invalid_suggestion`. AI 를 부르지 않는다.
- `POST /schedule/events` 에 `suggestion_id` 를 보내면 그 제안(내 대기 제안만, 아니면 400 `invalid_suggestion`)으로 등록한 것으로 보고, 일정에 연결하며 제안을 확정한다(같은 트랜잭션). 공유 복사본에는 연결하지 않는다.
- 같이해요(부탁). 보낸 사람은 `events_requests.user_id`, 받는 사람은 `events_request_recipients` 줄들이다. 응답 `RequestOut` = `{id, from_id, title, start_date, start_time, end_time, place, memo, created_at, canceled, recipients: [{user_id, status: waiting|accepted|declined}], my_event_id, edited_at}`. 받는 사람 목록은 보낸 사람에게는 전원(어렵겠어요 포함)이고, 받는 사람에게는 내 줄과 수락한 사람만 내려준다(누가 또 받았는지, 대기·거절은 모른다). `edited_at` 은 받는 사람을 바꾼 마지막 시각(바꾼 적 없으면 null). `my_event_id` 는 호출한 사람이 수락해서 만든 지워지지 않은 일정 id 다. 그룹 밖 사람은 보지 못한다(404).
  - `POST /schedule/requests`: `{title, start_date, start_time, end_time, place, memo, to_ids}` → 201. 받는 사람은 1~20명(중복은 하나로), 나는 뺀다, 모두 같은 가족 구성원이어야 한다(아니면 400 `invalid_recipients`). 시간 규칙은 일정과 같다(시작 없이 끝 불가, 끝이 시작보다 늦지 않으면 400 `invalid_time`).
  - `GET /schedule/requests`: 내가 보냈거나 내가 받는 사람인 부탁, 만든 시각 내림차순(같으면 id).
  - `POST /schedule/requests/{id}/answer`: `{answer: accepted|declined, kind: 1|2|null}`, 받는 사람 본인만(아니면 404). 수락이면 `kind` 필수(400 `kind_required`). 수락하면 받는 사람 본인의 일정만 만든다: `user_id`·`created_by` 는 수락한 사람, `source: "request"`, 제목·날짜·시간·장소·메모는 부탁 그대로이고 보낸 사람에게는 일정을 만들지 않는다. 종일(00:00~23:59) 부탁을 할 일로 수락하면 시간은 비운다. 이미 답한 사람이 다시 답하려면 부탁 날짜가 지나지 않아야 한다(400 `answer_locked`, 첫 답은 날짜와 무관). 다른 `kind` 로 다시 수락하면 이전에 만든 일정을 소프트 삭제하고 새로 만들고, 어렵겠어요로 바꾸면 그 일정을 소프트 삭제한다. 취소된 부탁에는 답할 수 없다(400 `request_canceled`).
  - `POST /schedule/requests/{id}/cancel`: 보낸 사람만(받는 사람이면 403 `not_owner`). 수락한 사람이 있어도 취소되고, 그 사람들이 수락해서 만든 일정은 같이 소프트 삭제한다(받는 쪽 알림 없음). 이미 취소한 것은 그대로 200.
  - `PUT /schedule/requests/{id}/recipients`: `{to_ids}` = 바뀐 뒤의 받는 사람 전체. 보낸 사람만(받는 사람이면 403 `not_owner`, 그룹 밖은 404), 답을 했든 안 했든 바꿀 수 있다. 최소 1명(422), 나 또는 가족이 아닌 사람이 있으면 400 `invalid_recipients`, 취소된 부탁은 400 `request_canceled`. 빠진 사람의 답 줄은 지우고 그 사람이 수락해서 만든 일정은 같이 소프트 삭제한다(일정의 `recip_id` 를 먼저 비움). 새로 든 사람에게는 새 부탁으로 가고, 빠졌다가 다시 든 사람도 새 대기 줄이다. 바뀐 게 있으면 `edited_at` 을 남기고 없으면 그대로 돌려준다. 부탁 내용(제목·날짜 등)은 바꿀 수 없다: 바꾸려면 취소하고 다시 보낸다.

## 데이터
- 항목: 형태, 제목, 날짜(필수), 시작·종료 시간(선택), 종일, 장소(직접 입력), 메모, 주제, 공유 대상, 만든 사람, 확인·완료 여부.
- 목록 순서: 약속 먼저(종일 → 시간순), 그다음 할 일(시간순, 시간 없는 것은 마지막).
- 에이전트는 일정 목록 줄 끝에 `| 공동`을 붙여 공동 일정을 알고, 가족 채팅(`channel: family`)에서는 공동 일정만 읽는다(나 혼자 일정은 가족 앞에 나오지 않음). 원본 주인의 개인 채팅에서는 `| 공유:id,id` 로 공유 대상도 알고, 채팅으로 공유 대상을 추가·제거할 수 있다(원본 주인만, 공유받은 사람에게는 공유 대상을 알려 주지 않음).

## 데일리 체크(1차, 앱만)
- 목적: 하루에 챙길 일(한 번 체크 또는 횟수 세기)을 나와 가족이 함께 본다. 일정 메인에서 체크 아이콘으로 연다.
- 내 항목: 이름, 체크 방식(한 번 체크 / 횟수 세기, 횟수는 하루 목표 숫자+단위), 반복 요일(월~일, 평일만·주말만·모두 선택·선택 해제 빠른 선택), 알림 스위치(아직 준비 중이라 비활성), 가족에게 보이기 스위치. 추가·수정·삭제. 메인에서 내 줄을 길게 누르면 줄마다 점 세 개가 나타나고, 점을 누르면 수정·삭제 메뉴가 뜬다. 바깥을 누르면 닫힌다. 항목 순서는 편집 화면에서 ∧∨ 화살표로 한 칸씩 옮기거나 줄을 꾹 누른 채 끌어서 바꾼다.
- 처음 열 때(온보딩 완료 표시가 없고 항목이 없을 때) 추천 습관을 골라 시작한다. 건너뛰기 가능. 예시 데이터는 자동으로 넣지 않고 개발용 버튼으로만 채운다.
- 오늘 목록: 요일이 오늘에 해당하는 항목만. 체크·횟수 증감은 날짜별로 저장한다.
- 날짜별 기록과 메모: 체크·횟수는 날짜마다 한 줄로 쌓고 지우거나 초기화하지 않는다. 오늘 포함 7일 전까지의 날짜는 나중에 체크하거나 횟수를 고치고 메모를 쓸 수 있다(완료 시각은 실제로 기록한 시각). 메모는 습관마다 날짜별로 남고(앱 50자), 쓸 때 "메모 내용 공유하기"를 켜야 가족 탭에 보인다(기본 꺼짐). 메모 아이콘은 습관 이름 옆에 두고, 메모가 있으면 노란 아이콘 + 두 번째 줄에 10자까지 보이며 눌러서 전문을 본다. 습관을 지워도 지난 기록은 남긴다(소프트 삭제). 반복 요일을 바꾸면 바꾼 날부터 적용되고 지난 날짜는 예전 요일을 따른다. 목록에는 그날 반복 요일에 해당하는 습관만 보인다.
- 가족 탭: 가족 구성원마다 탭("이름 완료/전체"), 보기 전용. 가족에게 보이기가 꺼진 항목은 안 나온다. 기록이 없는 것은 안 했다는 뜻이 아니라는 안내를 둔다.
- 가족 순서 바꾸기: 나는 맨 앞 고정(잠금), 가족 탭은 ∧∨ 화살표로 한 칸씩 옮기거나 줄을 꾹 누른 채 끌어서 순서 변경, 숨기기·다시 보기.
- 2차(앱만, 대략): 온보딩(추천 습관 고르기, 건너뛰기), 응원 보내기(가족 탭, 종류·한마디·대화방 표시), 받은 응원(고마워 표시, 지난 응원 모아보기), 가족 전화(전화 앱 열기, 고정 규칙 이야깃거리, 통화 뒤 "안부 전화" 완료 체크 — 오늘 아직 완료가 아닐 때만 묻는다, 메모 없음). 응원 전송·알림·가족 대화방 연동, 답장, 서버 저장과 가족 실제 기록은 서버가 생긴 뒤 후속이다. 앱 연동 뒤에는 습관·기록·응원·온보딩을 서버(`/schedule/check`)에 저장하고, 이 폰에는 가족 탭 순서만 둔다. 전화는 번호 없이 전화 앱 키패드를 연다. 가족 전화번호를 서버에 두는 것은 나중에 한다.

## 미정
- 확인·완료 상태를 사람별로 둘지, 공유받은 사람의 수정 권한, 삭제 후 되돌리기, 반복 일정의 수정·삭제 범위.
- 할 일에도 종일을 넣을지(장소는 약속과 같이 넣기로 함), 반복·알림·첨부, 장소 지도 서비스.
- 기한이 지났는데 완료하지 않은 할 일의 표시 방식.
- 같이: 자동 마감 시점·재알림, 다른 시간 제안, 현황 진입 위치.
- 먼저 권해드려요 카드 노출 개수·순서, 제안을 미리 만들어 저장하는 구조(호출 비용).
- 약속·할 일·주제 색(디자인 토큰 미정의).
- 메인 오케스트레이터와의 입출력 형식, 일정 에이전트 설계.
