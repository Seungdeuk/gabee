# 기능: 서비스 관리자 (service_admin)

## 목적
서비스 관리자가 가비를 쓰는 **사람과 가족**의 상태를 한곳에서 본다. 회원·가족 그룹·승인 대기·가족/사용자별 AI 이용량·문의를 본다.
가족이 쓰는 앱 기능이 아니다.

관리자는 둘로 나눈다(2026-11-03 결정). 이 문서는 **서비스 관리자**만 다룬다.

| 구분 | 보는 것 |
|---|---|
| 서비스 관리자 (이 문서) | 가입 수·활성 사용자·승인 대기, 가족·사용자별 AI 이용량, 계정별 인증 실패 내역, 문의·신고 |
| 운영(인프라) 관리자 (별도 문서, 다른 담당자) | 요청·응답·오류율, 인프라·DB·배포, 전체 AI 토큰·오류·비용, 기능별 호출 집계(식별자 없음), 로그인 실패율(비율만) |

## 권한
- 모든 서비스 관리자 API 는 공통 함수 `Depends(require_operator("service_admin"))` 를 거친다(운영 담당자가 구현, 병합 전).
  - JWT(Bearer) 정식 회원만 통과한다. 레거시 `X-Gyeot-Token` 은 401.
  - 허용 목록은 환경변수 `SERVICE_ADMIN_USER_IDS`(쉼표로 구분한 사용자 id)다. 목록에 없으면 403 `operator_required`. 비었거나 없으면 아무도 통과하지 못한다.
  - 가족 owner·admin 이어도 목록에 없으면 403 이다. 운영 관리자 목록(`OPS_ADMIN_USER_IDS`)과 서로 포함하지 않는다.
  - `REQUIRE_TESTER_CONSENT` 가 켜진 환경에서는 관리자 계정도 테스터 동의가 필요하다.
- 허용할 사용자 id 는 코드·Git·문서·테스트에 쓰지 않는다. 운영 담당자에게 개인 채널로 전달하고, 운영 담당자가 서버 환경변수에 넣는다.
- 별도의 DB 관리자 칸(`users.is_staff` 등)은 만들지 않는다.

## 화면
- 가비 앱 계정으로 로그인한다(`POST /family-group/auth/login`). 허용 목록에 없으면 "서비스 관리자 계정이 아니에요"를 보여 준다.
- 메뉴(2026-11-02 결정을 역할 경계에 맞춤, 2026-11-03 테스터 관리·사용자 피드백 제외). 첫 화면은 회원 관리다.
- **1차는 지금 DB 에 있는 데이터만 쓴다(2026-11-03 결정).** 새 표가 필요한 항목(문의·신고, 계정 정지, 로그인 실패 내역)은 미정으로 둔다.

### 회원 관리
| 항목 | 데이터 출처 |
|---|---|
| 전체 회원 수, 최근 7일 가입 수 | `users.created_at` |
| 활성 사용자 수(최근 7일) | `refresh_tokens.issued_at` — 로그인과 자동 토큰 갱신 때 새 줄이 생긴다(미정 4) |
| 가족 없는 회원 수 | `group_members` 에 없는 `users` |
| 이메일 인증한 회원 수 | `users.email_verified_at` 이 있는 수(이메일 주소는 보여 주지 않는다) |
| 회원 목록: 이름, 아이디, 가입일, 마지막 접속, 가족 여부, 이메일 인증 여부 | 위 표들. 최근 가입순 최대 200명 |

### 가족 그룹 관리
| 항목 | 데이터 출처 |
|---|---|
| 가족 그룹 수, 구성원 수별 그룹 수 | `groups`, `group_members` |
| 1명뿐인 가족 수 | `group_members` 수가 1인 그룹 |
| 승인 대기 수, 가장 오래 기다린 신청의 신청 시각 | `join_requests`(`status=pending`, `requested_at`) |
| AI 기능을 켠 가족 수 | `ai_group_settings.enabled` |
| 가족 목록: 이름, 대표 이름, 구성원 수, 승인 대기 수, AI 켬 여부, 만든 날 | 위 표들. 최근 생성순 최대 200개 |

### AI 이용 현황
| 항목 | 데이터 출처 |
|---|---|
| 오늘·최근 7일·최근 30일 요청 수 | `ai_usage_logs` |
| 가족별 최근 30일 요청 수(많은 순, 최대 200) | `ai_usage_logs.group_id` + `groups.name` |
| 사용자별 최근 30일 요청 수(많은 순, 최대 200) | `ai_usage_logs.user_id` + `users.name` |
| 가족별·사용자별 오류 수(최근 30일) | `ai_usage_logs.status=error` |
| 하루 한도에 걸린 사람(최근 30일): 이름, 가족, 걸린 날 수, 마지막으로 걸린 시각 | `ai_usage_logs.status=rejected` + `error_code`(`ai_daily_limit_user`/`ai_daily_limit_group`) |

- **요청 수**는 `ai_usage_logs` 행 수다. 사용자가 AI 기능을 한 번 쓰면 1이고, 저장된 답을 다시 쓴 경우와 오류도 포함한다. AI 를 실제로 부른 횟수가 아니다(2026-11-03 결정). 메인 AI 비서가 안에서 부른 탭 에이전트는 메인 요청 1번에 포함된다(`status=nested` 줄은 요청 수에서 뺀다).
- 날짜 경계는 한국 시간 자정이다. 기록은 90일만 남는다.
- 기능별 합계(식별자 없음)는 운영 관리자 범위라 여기서 보여 주지 않는다.
- 하루 한도에 걸린 요청은 `status=rejected` 줄로 남는다(브랜치 `feature/kang-ai-usage-nested` 에서 추가, 병합 후 사용). 같은 사람이 계속 눌러도 60초 안에는 한 줄이다. 요청 수에서는 뺀다.

### 문의·신고 (2단계, 2026-11-04 결정)
사용자가 앱에서 문의·신고를 보내고, 서비스 관리자가 상태를 바꾸고 답변한다. 새 표 `support_tickets` 가 필요하다.

| 칸 | 뜻 |
|---|---|
| `id` | 번호 |
| `user_id`, `group_id` | 보낸 사람, 그때의 가족(없으면 비움) |
| `kind` | `inquiry`(문의) / `report`(신고) |
| `title`, `body` | 사용자가 직접 쓴 제목과 내용 |
| `status` | `new` → `working` → `done` |
| `answer`, `answered_at` | 관리자 답변과 답변 시각 |
| `created_at` | 받은 시각 |

- 신고에는 **사용자가 쓴 글만** 담는다. 가족 채팅 내용은 붙이지 않는다(관리자는 가족 대화를 보지 않는다).
- 신고 대상은 따로 고르지 않고 글로 받는다.
- 답변 알림: 관리자가 답변을 저장하면(새 답변이나 고친 답변) 보낸 사람에게만 알림함 "고객센터" 분류로 "문의에 답변이 달렸어요" 한 줄이 간다. 가족이 없어도 받고(`group_id` 비움), 문의 제목·내용·답변은 알림에 담지 않는다. 상태만 바꾸면 알림이 없다. 사용자는 앱의 "내 문의"에서 답변 내용을 본다(2026-11-04 변경: 1차에는 알림이 없었다).
- 상태는 마지막 값만 남긴다. 변경 이력 표는 만들지 않는다.
- 답변해야 답변 완료(`done`)가 된다. 답변을 저장하면 자동으로 `done` 이 되고, 답변은 다시 저장해 고칠 수 있다(2026-11-05 결정, 답변 없이 `done` 은 422 `answer_required`).
- API(안): 앱 `POST /support/tickets`, `GET /support/tickets/mine` / 관리자 `GET /admin/service/tickets`, `PATCH /admin/service/tickets/{id}`(상태, 답변).
- 앱 문의 화면(Expo)은 다른 팀원이 만든다(2026-11-04). 서버와 관리자 화면은 서비스 관리자 담당.

### 공통
- 가족 안의 채팅·문서·정산 내용과 회원 이메일 주소는 어느 메뉴에도 나오지 않는다. 개수·이름·시각만 쓴다.
- 휴대폰 너비에서도 가로 스크롤 없이 보인다(넓은 표는 표 안에서만 스크롤).

## API (1차, 모두 읽기 전용)
경로 접두어는 미정 1. 아래는 `/admin/service` 로 적는다.

- `GET /admin/service/me`: `{id, name, login_id}`. 화면이 처음 열릴 때 권한 확인용.
- `GET /admin/service/members`: 위 "회원 관리" 항목.
- `GET /admin/service/groups`: 위 "가족 그룹 관리" 항목.
- `GET /admin/service/ai-usage`: 위 "AI 이용 현황" 항목.
- 응답: 로그인 안 함·레거시 토큰은 401, 허용 목록에 없음은 403 `operator_required`.
- 새 엔드포인트마다 테스트를 1개 이상 둔다.

## 데이터
- 1차는 새 표나 칸을 만들지 않는다. 이미 있는 `users`, `groups`, `group_members`, `join_requests`, `refresh_tokens`, `ai_group_settings`, `ai_usage_logs` 를 읽기만 한다.
- 다른 기능의 모델 파일은 import 하지 않고 공용 메타데이터의 표로 읽는다.

## 완료 조건 (1차)
- 허용 목록에 있는 계정만 서비스 관리자 API 와 화면 데이터를 받는다. 가족 owner 라도 목록에 없으면 403.
- 회원·가족 그룹·AI 이용 메뉴가 DB 값을 보여 준다.
- 테스트: 비로그인 401, 레거시 토큰 401, 목록에 없는 회원 403, 목록에 있는 회원 200, 각 집계 값 확인.
- 문서: `docs/contracts/permissions.md` 운영자 절의 "서비스 관리자" 소제목 아래, `docs/contracts/openapi.json` 갱신.

4. "활성 사용자"의 정의: 1차 제안은 "최근 7일 안에 `refresh_tokens` 새 줄이 생긴 사람"(로그인·자동 갱신 포함). 확인이 필요하다.
5. 2단계(새 표 필요): 계정 정지(효과·저장 위치), 계정별 로그인 실패 내역(무엇을 남길지, IP 저장 여부). 문의·신고는 위 절에서 정했다(앱 화면은 다른 팀원).
6. `permissions.md` 운영자 절의 공통 부분(scope 개념, `require_operator`)을 누가 쓸지.
