# 기능: 서비스 관리자 페이지

## 목적
관리자가 가비 서비스의 회원·가족 그룹·기능 사용·AI 이용·문의를 한곳에서 본다.
가족이 쓰는 앱 기능이 아니다. 운영 지표(서버 상태, 비용, 마케팅)는 다른 담당자가 따로 만든다.

## 진행 단계 (DB 연결 기준)
1. **1단계(완료)**: 마이그레이션은 `users.is_staff` 하나만. 이미 있는 표로 회원·가족 그룹·기능 관리를 실제 데이터로 보여 준다. 나머지 메뉴는 예시 화면.
2. **2단계**: 새 표(계정 정지, 문의·신고)와 앱에서 문의를 보내는 화면. AI 이용 현황은 이미 있는 `ai_usage_logs` 를 읽어 먼저 연결했다(2026-11-03). 문의·신고는 `support_tickets` 표와 서버 API 를 연결했다(2026-11-04, 앱 화면은 남음).

## 화면
- 서버가 `/admin/ui` 로 내려주는 HTML 페이지 한 장(파일 `apps/api/app/features/admin/static/`). 새 라이브러리는 쓰지 않는다.
- 가비 앱 계정으로 로그인한다(`POST /family-group/auth/login`). 관리자가 아니면 "관리자 계정이 아니에요".
- 메뉴 5개(2026-11-02 결정, 2026-11-03 테스터 관리·사용자 피드백 제외). 첫 화면은 회원 관리다.

| 메뉴 | 주요 구성 | 1단계 |
|---|---|---|
| 회원 관리 | 가입자 수, 가입일, 마지막 로그인, 계정 상태 | 실제(계정 상태는 2단계) |
| 가족 그룹 관리 | 가족 그룹 수, 구성원 수 | 실제 |
| 기능 관리 | 일정·소통·돌봄·정산 기능별 최근 7일 사용 현황(보기만) | 실제 |
| AI 이용 현황 | AI 기능 사용 횟수, 기능별 사용량 | 실제(2단계에서 먼저 연결) |
| 문의 및 신고 | 문의 현황, 처리 상태, 답변 | 실제(2단계, 2026-11-04) |

- 문의·신고는 제목을 누르면 사용자가 쓴 내용과 답변 칸이 펼쳐진다. 상태 버튼(처리 시작 → 처리 완료)과 답변 저장은 서버에 바로 반영된다.
- 가족 안의 채팅·문서·정산 내용과 회원 이메일은 어느 메뉴에도 나오지 않는다. 기능 관리는 개수만 센다.

## API (문의·신고 상태·답변 바꾸기만 쓰기, 나머지는 읽기 전용)
- `GET /admin/me`: `{id, name, login_id}`
- `GET /admin/members`: 전체 수, 최근 7일 가입 수, 활성 사용자 수(최근 7일 안에 로그인·자동 갱신으로 토큰을 받은 사람), 가족 없는 회원 수, 이메일 인증한 회원 수, 최근 가입순 최대 200명(이름, 아이디, 가입 시각, 가족 여부, 마지막 로그인 시각, 이메일 인증 여부). 이메일 주소는 돌려주지 않는다
- `GET /admin/groups`: 그룹 수, 1명뿐인 가족 수, 승인 대기 수와 가장 오래된 신청 시각, AI 를 켠 가족 수, 최근 생성순 최대 200개(이름, 대표 이름, 구성원 수, 승인 대기 수, AI 켬 여부, 만든 시각), 구성원 수별 그룹 수
- `GET /admin/features`: 기능별 최근 7일 사용 수·쓴 가족 수, 그 전 7일 사용 수, 전체 가족 수
- `GET /admin/ai-usage`: AI 기능 사용 요청 수 — 오늘·최근 7일·최근 30일, 최근 14일 하루별, 최근 30일 기능별. **요청 수**는 `ai_usage_logs` 행 수다(사용자가 한 번 쓰면 1, 저장된 답을 다시 쓴 경우·오류 포함, AI 를 실제로 부른 수가 아님, 2026-11-03 결정). 날짜 경계는 한국 시간 자정. 기록은 90일만 남는다. `status` 가 `nested`(메인 비서 안에서 부른 에이전트 표시)·`rejected`(한도 거절) 인 줄은 요청 수에서 뺀다. 단 최근 30일 기능별 사용량에는 `nested` 도 그 에이전트 횟수로 넣고, 직접 쓴 수(`direct`)와 AI 비서가 부른 수(`via_assistant`)를 나눠 돌려준다(2026-11-03 결정, 화면에 "직접 N회 · AI 비서가 부름 M회"로 적는다). 최근 30일 가족별·사용자별 요청 수와 오류 수(각 최대 200), 하루 한도에 걸린 사람(`rejected` + `ai_daily_limit_user`/`ai_daily_limit_group`, 걸린 날 수·마지막 시각)도 돌려준다
- `GET /admin/support`: 상태별 건수(`new`·`working`·`done`), 신고 수(`reports`), 최근순 최대 200건(번호, 종류, 제목, 내용, 상태, 답변·답변 시각, 받은 시각, 보낸 사람 이름·아이디, 가족 이름). 내용은 사용자가 직접 쓴 글뿐이다
- `PATCH /admin/support/{id}`: 본문 `{status?, answer?}`. 준 것만 바꾸고 답변을 쓰면 답변 시각도 적는다. 둘 다 없으면 422 `nothing_to_update`, 없는 번호면 404. 성공은 204. 문의 표가 아직 없는 DB 에서는 이 두 경로만 503
- 앱 쪽(`support` 기능): `POST /support/tickets`(`{kind, title, body}`, 201), `GET /support/tickets/mine`(내가 보낸 것, 최근순 최대 100건). 로그인한 본인 것만 다룬다
- 로그인 안 함·레거시 토큰: 401. 로그인했지만 관리자가 아님: 404(관리자 경로가 있다는 것을 알리지 않는다).

## 데이터
- `users.is_staff`(boolean, NOT NULL, 기본 false): 관리자 표시. 가족 안의 owner·admin 역할과 별개. 앱·API 로는 바꿀 수 없고 DB 에서 직접만 켠다.

## 완료 조건 (1단계)
- `/admin/*` 는 Bearer(JWT) 정식 회원이면서 `is_staff` 가 true 인 사용자만 통과한다. 가족 owner 라도 `is_staff` 가 false 면 404.
- `/admin/ui` 에서 관리자 계정으로 로그인하면 실제 데이터 메뉴 4개가 DB 값을 보여 준다.
- 휴대폰 너비에서도 가로 스크롤 없이 보인다(넓은 표는 표 안에서만 스크롤).
