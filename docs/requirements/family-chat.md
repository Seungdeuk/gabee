# 기능: family-chat (가족 채팅·소통)

> 2026-10 사용자(팀) 요청으로 기록한 요구사항이다. 아직 구현되지 않은 항목은 "예정"으로 표시한다. 기존 서버 `family_chat`(단체 메시지 목록·전송)과 모바일 소통 탭(임시 데이터)을 먼저 확인하고 이어서 만든다 — 중복 개발하지 않는다.

## 범위(순서)

| 단계 | 기능 | 설명 | 상태 |
|---|---|---|---|
| AI 1 | **AI 대화 분석(통합)** | 요약·중요 메시지·일정 후보·할 일 후보를 한 번의 AI 호출로 | 서버 구현됨(이 문서의 "AI 기능") |
| AI 2 | 답장·주제 추천 | 구성원이 요청할 때만 답장 후보·대화 주제 제안 | 서버 구현됨 |
| AI 3 | @가비 문서 검색·질문 답변 | 저장된 문서에서 찾기, 요약·질문 답변 | 예정(설계만) |
| AI 4 | 자동 분석 | 쌓인 대화를 모아서 자동으로 분석 | 예정(설계만, 기본 꺼짐) |
| Chat 1 | 가족 채팅방 · 메시지 송수신 | 가족 구성원이 함께 대화하는 공간, 실시간 전송·조회 | 가족 채팅방·메시지 송수신 구현(폴링, 실시간 소켓은 아님) |
| Chat 2 | 1:1 채팅 · 읽음 표시 | 특정 가족 구성원과 개별 대화, 메시지 확인 여부 | 서버 구현됨(대화방 구조·1:1 방). 앱 화면은 다음 PR |
| Chat 3 | 사진·파일 공유 | 사진이나 문서를 채팅방에 공유 | 사진 보내기·방별 사진 모음 서버 구현(`GET /family-chat/media`), 파일·동영상 업로드는 예정 |
| Chat 4 | 공동 할 일 · 가족 연락처 | 가족 간 부탁과 할 일 공유, 구성원 연락처 관리 | 서버 구현(공동 할 일), 앱 예정 — 결정은 아래 "Chat 4" 절 |
| Chat 5 | 대화 검색 | 카카오톡 돋보기처럼 글자 일치 검색(임베딩 없음)과 결과 위치로 점프 | 서버 구현(`GET /family-chat/search`, `messages?around_id=`), 앱 예정 |

## Chat 4: 공동 할 일 · 가족 연락처 (2026-10 사용자 결정)

**공동 할 일** — 가족 전체가 함께 보는 목록.
- 필드: 제목, 담당자(한 명, 선택), 기한(날짜만, 선택), 완료 표시. 반복·알림·하위 항목·댓글은 이번 범위가 아니다.
- **접근 범위: 가족 전체 공유**(1:1 방 안에서만 보이는 할 일은 만들지 않는다). 가족 구성원 누구나 추가·수정·완료할 수 있고, 지우기는 만든 사람이나 가족 관리자만 한다.
- **일정과의 구분**: 날짜+시간이 있는 약속은 일정(schedule), 날짜가 없거나 "언제까지"만 있는 부탁·할 일은 공동 할 일이다.
- AI 분석의 "할 일 후보"는 구성원이 확인하고 눌렀을 때만 할 일로 등록된다(`source=chat`). AI 가 직접 등록하지 않는다.

**가족 연락처** — 소통 탭 연락처 카드에서 들어가는 구성원 목록.
- 이름(표시 이름)·관계·프로필 사진을 보이고, 누르면 그 사람과 1:1 대화를 시작한다. 내가 그 사람에게 붙이는 별명·메모는 기존 별명 API(`/family-group/groups/me/nicknames`)를 쓴다.
- **전화번호는 다루지 않는다**(이번 범위 제외 — 새 개인정보 수집이므로 필요해지면 별도 결정).

## 고정 메시지 → 게시판 (2026-10 사용자 결정, 10-29 이름·동작 변경)

채팅방 안에서 중요한 메시지(약속 장소, 준비물 등)를 위에 고정해 두는 기능.

- 가족 전체방과 1:1 방 모두 쓴다.
- **방 안의 모든 구성원이 고정·해제**할 수 있다. 관리자나 쓴 사람만으로 제한하지 않는다.
- **방당 최대 2개**, 최근에 고정한 것이 남는다. 3번째를 고정하면 가장 오래된 고정이 자동으로 풀린다(오류 없이 교체).
- **텍스트 메시지만** 고정한다. 사진은 이후 검토한다.
- 같은 메시지를 다시 고정해도 그대로다(순서·고정한 사람 불변). 고정은 메시지를 지우거나 바꾸지 않는다.
- **게시판(10-29)**: 앱 화면에서는 "고정 메시지"를 "게시판"이라 부르고 메시지 메뉴의 "공지"로 올린다(서버 주소 `/family-chat/pins` 는 그대로). **올릴 때의 본문을 사본으로 저장해, 원본 메시지를 보낸 사람이 지워도 게시판에는 남는다**(내리면 사본도 지운다). 개수는 방당 2개 그대로이고 올리기·내리기는 구성원 누구나 한다.
- **나만 숨기기(10-29)**: 사용자마다 게시판 공지를 자기 화면에서만 숨기고 되돌릴 수 있다. 다른 구성원에게는 그대로 보이고, 공지가 내려가면 숨김 기록도 사라진다.
- 고정 내용은 AI·외부로 보내지 않는다. 접근 범위는 그 방의 구성원과 같다(다른 가족·참여하지 않은 1:1 방에는 존재도 드러나지 않는다).

## 메시지 삭제 (2026-10-29 사용자 결정)
- 내가 보낸 메시지만 지울 수 있다(시간 제한 없음). 남이 보낸 메시지와 가비의 답은 지울 수 없다.
- 지우면 **본문과 사진을 서버에서도 지운다**(사진 원본·썸네일 파일 포함). 단 그 메시지를 게시판(공지)에 올려 둔 경우에는 올릴 때의 본문 사본(앞 200자)이 게시판에 남는다 — 지우려면 공지에서 내려야 한다(사용자 결정). 대화 목록에는 같은 자리에 "삭제된 메시지입니다"가 보이고, 검색·사진 모음·AI 분석에는 나오지 않는다.
- 이미 지운 메시지를 다시 지워도 같은 결과(멱등). 앱 화면(팝업 메뉴, 삭제 표시)은 후속 작업이다.
- 안 읽은 수에는 삭제된 메시지도 읽기 전까지 센다(열면 "삭제된 메시지입니다"가 보인다).
- 화면을 열어 둔 다른 가족에게도 삭제가 전달돼야 하므로, 서버는 지워진 메시지 id 를 조회할 수 있게 한다(`GET /family-chat/messages/deleted`). 사진은 단말 캐시에도 남지 않게 앱이 지운다.

## 메시지 답장 (2026-10-29 사용자 결정)
- 같은 방(같은 가족, 내가 들어갈 수 있는 방)의 지우지 않은 메시지에만 답장할 수 있다. 지운 메시지에는 답장할 수 없다(400 `reply_deleted`).
- 답장 메시지에는 원본의 미리보기(보낸 사람 이름, 글자 40자까지, 사진 여부)가 붙는다. 원본이 나중에 지워지면 미리보기는 내용 없이 "삭제된 메시지"로만 나온다. 답장의 답장도 바로 위 원본 하나만 보인다.
- 앱 화면(팝업 메뉴의 답장, 말풍선 위 원본 표시, 누르면 원본으로 이동)은 후속 작업이다.

## 메시지 반응 (2026-10-29 사용자 결정)
- **한 사람이 한 메시지에 반응 하나**(카톡·인스타 DM 방식). 다른 이모지를 누르면 바뀌고, 같은 걸 다시 누르는 취소는 앱이 삭제 요청으로 처리한다.
- 이모지는 6개만 쓴다: ❤️ 👍 😂 😮 😢 🙏. 내 메시지·남의 메시지·가비의 답 모두에 누를 수 있다. 지운 메시지에는 누를 수 없고, 메시지를 지우면 반응도 함께 지운다.
- 메시지마다 이모지별 사람 수와 내가 눌렀는지를 보여 준다(누가 눌렀는지는 이번 범위가 아니다). 앱 화면(팝업 메뉴의 반응, 더블탭 하트)은 후속 작업이다.

## 메시지-일정 연결 (2026-10 사용자 결정)

채팅에서 AI 후보를 확인해 일정/할 일로 등록하면 원본 대화 메시지와의 연결을 남겨, 서랍의 "가족 일정 · 할 일" 목록·말풍선의 "등록됨" 표시·원본 메시지로 이동에 쓴다.

- 연결은 채팅 쪽(family_chat)에만 저장한다. 일정(schedule) 모델은 바꾸지 않는다. 일정의 제목·날짜·시간은 등록 시점의 복사본이라, 일정이 나중에 바뀌거나 지워져도 목록은 복사본을 보여준다(한계로 받아들임).
- 같은 메시지에서 같은 일정/할 일을 다시 등록해도 연결은 하나다. 글자가 있는 텍스트 메시지만 연결한다. 방당 최대 200개.
- 연결은 **등록한 사람만** 지울 수 있다. 접근 범위는 그 방의 구성원과 같다(다른 가족·참여하지 않은 1:1 방에는 존재도 드러나지 않는다).
- 일정 화면에서 '원본 대화 보기'는 이번 범위가 아니다(서버에 `target_id` 조회만 준비).
- 연결 내용은 AI·외부로 보내지 않고 로그에 남기지 않는다.

## 호출 최소화 정책

AI(Anthropic) 호출은 비용이 들고 개인 대화가 외부로 나가므로, 아래 표의 동작만 AI 를 부른다. 나머지는 모두 AI 없이 동작한다.

| 동작 | AI 호출 | 비고 |
|---|---|---|
| 일반 채팅 메시지 전송 | **0** | 메시지를 보내도 AI 를 부르지 않는다. 자동 분석도 메시지 전송 중에는 돌지 않는다 |
| 대화 분석 요청 | 최대 **1** | 같은 범위를 다시 요청하면 캐시에서 꺼내 0 |
| 답장 추천 요청 | 1 | 캐시 적중 시 0 |
| 주제 추천 요청 | 1 | 캐시 적중 시 0 |
| @가비 키워드 검색 | **0** | 입력할 때마다 AI 를 부르지 않는다. PostgreSQL 키워드 검색이 먼저, 필요할 때만 pgvector |
| 원본 문서 확인·공유 | **0** | 원문을 그대로 보여 주거나 공유하는 데는 AI 를 쓰지 않는다 |
| 문서 요약 요청 | 1 (예정) | 요청할 때만 |
| 문서 질문 답변 | 1 (예정) | 요청할 때만 |
| 자동 분석 | 설계 기준 0~1 | 기본 꺼짐. 아래 "자동 분석 설계" 참고 |

- 같은 요청이 TTL 안에 다시 오면 **캐시**에서 꺼내 AI 를 부르지 않는다(가족 그룹별로 격리).
- 같은 요청이 동시에 두 번 들어와도 **한 번만** 부른다(가족 그룹별 동시 실행 제한, 나머지는 409).
- 사용자별 **쿨다운**, 사용자별·가족 그룹별 **하루 한도**를 둔다.
- **새 메시지**가 분석 범위에 들어오면 캐시 키가 바뀌어 결과를 새로 만든다(옛 결과를 계속 보여 주지 않는다).
- API 가 실패하면 **재시도하지 않는다**. 실패한 호출도 한도에는 센다. 무제한 재시도는 금지한다.

## AI 기능 (통합 분석)

- 구성원이 "대화 분석"을 눌렀을 때 최근 대화(기본 100개, 최대 200개; 글자 수 한도를 넘으면 오래된 것부터 뺀다)를 **한 번의 호출**로 보내 네 가지를 함께 받는다.
  1. 요약: 핵심 내용 위주 3~6문장. 잡담·인사는 뺀다.
  2. 중요 메시지: 결정·약속·요청·긴급 연락(최대 5개), 메시지 번호와 한 줄 이유.
  3. 일정 후보: 날짜·시간이 있는 약속(최대 8개). 장소도 대화에 있을 때만 쓴다.
  4. 할 일 후보: 누군가에게 부탁했거나 해야 하는 일(최대 8개). 담당자·기한이 불명확하면 비운다.
- **지어내지 않는다**: 날짜·시간·장소·담당자·기한이 대화에 분명히 없으면 null 로 둔다. 서버는 AI 결과를 검증해서 존재하지 않는 메시지 번호, 잘못된 날짜·시간 형식, 대화에 나오지 않은 이름을 버린다.
- **사용자 확인 후 등록**: 일정 후보와 할 일 후보는 **후보일 뿐**이다. 구성원이 내용을 확인하고 눌러야 일정·할 일로 등록된다. AI 가 직접 등록하지 않는다.
- 답장 추천과 주제 추천은 분석과 **별도 요청**이다. 분석 결과에 섞어 만들지 않고, 구성원이 눌렀을 때만 부른다.
- 응답에는 분석에 쓴 메시지 수와 번호 범위, 캐시 적중 여부, 호출 수를 함께 보여 준다(구성원이 어디까지 봤는지 알 수 있게).

## 자동 분석 설계 (예정, 아직 구현하지 않음·기본 꺼짐)

목표: 대화가 많이 쌓였을 때 매번 사용자가 누르지 않아도 분석이 준비되게 하되, 호출은 **모아서** 한다.

- **조건(설정값)**: 마지막 분석 이후 새 메시지가 `AI_AUTO_ANALYSIS_MIN_NEW_MESSAGES`(제안 기본 30)개 이상이고, 마지막 자동 분석 후 `AI_AUTO_ANALYSIS_MIN_INTERVAL_SECONDS`(기본 3600초)가 지났을 때만 한다. 기본값 `AI_AUTO_ANALYSIS_ENABLED=false` 이면 아무 것도 하지 않는다. 설정 키는 `app/shared/config.py` 에 이미 자리가 있다.
- **누가 호출하는가 (제안)**: 스케줄러(cron·백그라운드 워커)는 두지 않는다. 대신 **구성원이 소통 탭을 열 때** 앱이 가벼운 확인 요청(AI 호출 없음)을 보내 "새 대화 N개가 쌓였어요. 요약할까요?" 같은 안내를 띄운다. 구성원이 누르면 그때 분석을 한 번 호출한다(사용자 요청 기반 유지). 완전 자동 실행은 아래 질문을 정한 뒤에만 한다.
- **메시지 전송 중에는 호출하지 않는다**: 일반 전송 응답을 늦추지 않고, 전송 요청 안에서 AI 를 부르지 않는다.
- **동의·한도·캐시와의 관계**: 자동 분석도 반드시 `ai_guard.run` 을 거친다. 가족 그룹이 AI 기능에 동의하지 않았으면 0회(동의 없이 자동으로 켜지 않는다). 하루 한도와 동시 실행 제한은 수동 요청과 같은 칸을 쓴다. 범위가 같으면 캐시가 적중해 0회다.
- **마지막 분석 범위 저장(스키마 변경 필요)**: 캐시는 TTL 이 지나면 사라지므로, "마지막으로 분석한 메시지 번호"를 기억하려면 `ai_group_settings` 에 컬럼을 더하는 Alembic 리비전이 필요하다. 이번 범위에서는 제안만 한다.
- **열린 질문(팀 결정 필요)**: (1) 자동 실행 시 호출을 누구의 한도로 셀지 — 소통 탭을 연 구성원인지, 시스템 전용 한도인지. (2) 구성원별 자동 분석 끄기 여부. (3) 자동으로 돌리는 것이 "사용자가 요청할 때만 호출" 요구와 충돌하지 않는지 — 충돌하면 안내 배너 방식만 쓴다.

## @가비 문서 검색 정책 (예정)

- 구성원이 `@가비` 로 저장된 문서를 찾을 때, **입력할 때마다 AI 를 부르지 않는다**.
- 먼저 PostgreSQL 키워드 검색(가족 그룹 안에서만)으로 찾는다. 키워드로 찾기 어려울 때만 pgvector 의미 검색을 쓴다.
- 원본 문서 확인과 공유는 AI 없이 한다.
- 요약과 질문 답변만 AI 를 부르며, 요청할 때 한 번이다. 가족 그룹별 접근을 먼저 검증한다(그룹 멤버가 아니면 문서 본문을 보내지 않는다).

## 개인정보 원칙

- **동의**: 가족 그룹의 AI 기능은 기본 꺼짐이다. 가족 소유자 또는 관리자가 켜야 쓸 수 있고(`PUT /family-chat/ai/settings`), 켜기·끄기는 관리자만 한다. 꺼져 있으면 AI 요청은 403 `ai_not_enabled` 이다.
- **최소 전송**: 대화 글자와 이름만 보낸다. 사용자 id·계정·연락처는 보내지 않는다. 다른 가족 그룹의 대화는 절대 보내지 않는다. 분석 프롬프트는 전화번호·주소·계좌·주민등록번호를 그대로 옮기지 말고 일반화하도록 한다.
- **저장하지 않는다**: 대화 원문과 문서 원문은 AI 결과 캐시나 사용 기록에 저장하지 않는다. API 키는 어디에도 저장·출력하지 않는다. 사용 기록에는 기능 이름, 호출 수, 토큰 수, 캐시 적중, 상태, 오류 종류, 모델 이름만 남긴다.
- **예외(알고 있을 것)**: 분석 결과(요약 글과 후보 목록)는 캐시에 TTL(기본 600초) 동안 저장된다. 대화 원문은 아니지만 결과에는 대화 내용이 일부 담긴다. 캐시 기간은 짧게 두고, 가족 그룹별로 격리한다.
- **외부 AI 사용**: 현재 family-chat AI 는 Anthropic 을 쓴다(사용자가 요청한 경우에만). 개인정보가 많은 글자를 로컬 모델(Ollama)로 처리하는 대안은 "남은 것"에 둔다.

## 모델·설정

- 모델: `ANTHROPIC_MODEL`(없으면 기본 `claude-haiku-5-5`). 예전 이름 `LLM_MODEL` 도 읽는다. 모델 이름은 캐시 키에 들어가므로 모델을 바꾸면 이전 캐시는 쓰이지 않는다.
- 키: `ANTHROPIC_API_KEY`(서버 환경변수에만). 키가 없으면 503 `llm_unavailable`.
- 한도·캐시·동시 실행 값은 `.env.example` 의 `AI_*`, `ANTHROPIC_MAX_TOKENS` 항목을 따른다.
