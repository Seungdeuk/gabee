# 기능: AI 자동 추억 카드 (가족 타임라인 자동 게시)

> **상태: 요구사항 초안(문서만).** 코드·DB·모델·운영 활성화는 승인되지 않았다. 정책 결정은 ADR 0021(노출·자격)과 ADR 0020(동의·자체 서버), 안전성 평가 설계는 `auto-memory-safety-eval.md`. 수치(★)는 **임시 제안값**이며 평가 뒤 조정한다. **PR0 문서 승인과 E1 자동 공개 정책의 최종 승인은 구분한다:** E1 의 안전 기준값과 독립 평가 규모는 별도 정책 승인 전까지 확정하지 않고, 확정 뒤 최종 평가셋 실행 전에 고정한다.

## 목적
- 가족이 평소처럼 가족 전체방에 사진을 공유하면, 서버가 **의미 있는 사진 묶음만** 골라 추억 카드(대표 사진·제목·1~3문장 이야기·사진 목록·유형·기준 날짜/주제)로 만들어 **개별 확인·생성 승인 없이** 가족 타임라인에 자동 게시한다.
- 사진을 전부 나열하지 않는다. 기준에 맞는 묶음이 없으면 **카드 0개가 정상**이다. 품질은 "몇 장을 분류했나"가 아니라 "얼마나 의미 있는 추억을 발견했나"로 본다.
- 이 기능은 다음과 다르다(섞지 않는다): 채팅 "대화 분석하기"(텍스트, 사진 미포함) · 가족 문서함(문서 판별·관리, SigLIP2 로 대체하지 않음) · 사진·동영상 탭(모든 미디어 조회) · 날짜별 사진 타임라인(`photo` 로 확인된 사진, 변경 없음) · 묶음 카드 #435(같은 `batch_id` 한 카드).

## 현재 구조 요약 (코드 확인, 2026-11-17)
- 업로드 → `message_attachments`(`kind` image|file, `batch_id`, `taken_at`; EXIF 는 촬영 시각만 남김) → 가족 전체방이면 `chat_photo_checks` `pending` → 서버 스레드풀(2개, 가족당 대기 20, 메모리 큐라 재시작 시 유실)이 OCR(+동의한 가족은 Claude haiku)로 판별 → `document`·`unsure`·`failed`. 자동 판별은 `photo` 를 만들 수 없다(D-13, 시험으로 고정). 업로더가 확인해야 `photo`, 타임라인은 `photo` 만 표시.
- `unsure` 는 "글자 없음", "애매", "Claude 불확실"을 섞은 값이고 **세부 판정은 저장하지 않는다.**
- 사진·동영상 탭은 image·file 만 보이고 동영상 수는 0이다(동영상 업로드·저장 없음). 동의는 가족 단위 `ai_group_settings` 뿐이고 업로더별 동의·사진별 AI 제외는 없다. 서버에 torch 의존성은 없고 onnxruntime 은 있다.

## 단계: E0 와 E1
| | E0 (임시 검증) | E1 (최종 목표) |
|---|---|---|
| 자격 | 업로더가 `photo` 로 확인한 사진 | 아래 "E1 자격" 전부 충족한 사진(`unsure` 포함 가능) |
| 사용자 확인 | 필요(일괄 확인으로 부담 축소) | 불필요 |
| 목적 | 발견·선정·문구 파이프라인과 카드 품질 내부 검증 | 개별 확인 없는 자동 게시 |
| 개시 조건 | ADR 0021 승인 + 구현 PR 승인 | ADR 0021 전환 조건 ①~⑦ 전부 + **E1 최종 안전 기준·평가 규모의 별도 정책 승인** + 소유자 별도 승인 |
- E0 는 최종 UX 로 간주하지 않는다. E1 은 독립 안전성 평가 통과 전에는 공개하지 않는다.

### 분석 자격 규칙
- 판별 상태(`chat_photo_checks`)는 읽기만 한다. 자격은 `family_memory` 가 별도로 계산해 **판정·근거 코드·규칙 버전**과 함께 기록한다(내용·글자·임베딩 값 제외).
- **항상 제외:** 1:1 방 사진, `document`·`failed`·`pending`, 삭제된 사진, 타임라인에서 뺀(`excluded`) 사진, 사진별 AI 제외, 업로더 미동의·철회, 가족 미활성화, 서버 스위치 꺼짐.
- **E0:** 위 제외에 걸리지 않고 상태가 `photo`(`manual`)인 사진.
- **E1 자격(모두 충족):** ① 동의 사슬(서버 스위치·가족 활성화·업로더 동의) ② 위 제외 조건 없음 ③ 판별 세부 결과가 기록돼 있고 "글자가 읽힌 애매" 아님 ④ 문서 안전 신호 여러 개 통과(OCR 글자 수, 문서·스크린샷 유사도, 화면 비율 등 — 목록·기준값은 안전성 평가 문서) ⑤ 같은 `batch_id`·가까운 시각(★ 10분) 업로드 중 문서 의심이 하나라도 있으면 묶음 전체 제외 ⑥ 게시 직전 재확인.
- 자동 판별이 `unsure` 를 `photo` 로 바꾸는 일은 없다. E1 자격이 있어도 날짜별 타임라인에는 나오지 않고 카드 안에서만 보인다.

## 동의·철회·소급 분석 규칙
| 상황 | 규칙 |
|---|---|
| 활성화 | 가족 소유자·관리자만 가족 기능을 켜고 끈다. 켜도 업로더 동의 전에는 그 사람 사진을 분석하지 않는다. 새 구성원에게는 안내를 보이고 본인 동의 전 미분석 |
| 동의 | **업로더별 AI 이미지 분석 사전 동의 필수**(가족별, 버전·동의 시각·철회 시각만 기록). 새 업로드 분석 동의와 **소급 분석 동의는 별개**이고 소급은 별도 명시적 동의가 필수이며 기본 꺼짐. 기록 보관 기간은 법적·운영 검토 전까지 미확정 |
| 재확인 지점 | 작업 등록 / 워커 시작(이미지 읽기 전) / 결과 저장 직전 / 카드 게시 직전. 하나라도 빠지면 중단(실패가 아니라 취소). 카드 조회 때도 철회된 사진이 든 카드는 숨긴다(fail-closed) |
| 사진별 제외 | 업로더가 자기 사진을 분석에서 제외. 작업 취소, 특징 삭제, 카드에서 사진 제거 후 조건 확인(깨지면 숨김·갱신). 다시 포함하면 새 사진처럼 자격 재계산 |
| 동의 철회 | **새 분석 작업과 공개를 즉시 차단**(요청 안에서 논리적 차단) → 영향받은 카드는 **재생성 전까지 숨김** → 그 사람 사진의 특징(임베딩 등) 삭제 → 조건이 깨지면 카드 삭제, 아니면 재생성. **활성 저장소의 파생 데이터 물리 삭제 목표는 ★24시간(제안, 미확정).** 백업은 활성 저장소와 별개이므로 **백업 만료 기간과 복원 시 재삭제(복원 직후 삭제 목록을 다시 적용) 절차를 별도로 정의**하며 정의 전까지 백업 삭제 시점은 확정하지 않는다 |
| 가족 비활성화 | 그 가족의 특징·카드·작업 삭제 |
| 소급 분석 | 기존 사진이 대상이 되려면 해당 업로더의 소급 동의 필요. 가족 활성화만으로 일괄 분석 금지. 대상은 그 업로더가 올린 가족 전체방 사진 중 삭제·제외·문서·1:1 방이 아닌 것, 자격은 E0/E1 과 동일. 실시간 큐와 분리된 최저 우선순위 작업이며 속도 제한. 특징에 `origin`(live/retro)을 남겨 소급 동의 철회 시 소급분만 삭제 가능 |
| 가족 탈퇴·나감 | 그 업로더의 **AI 분석을 즉시 중단**(동의 종료로 취급)하고 관련 카드를 숨기거나 재구성하며 파생 데이터는 철회와 같이 삭제한다. **원본 채팅 사진은 AI 기능과 별개로 기존 D-7(계정 탈퇴 경로 확인 전)과 채팅 데이터 보존 정책을 확인한 뒤 처리한다(이 문서에서 정하지 않음)** |
| 로그 | 사진 내용·라벨·이야기·임베딩 로그 금지, 외부 전송 금지, 가족 간 비교 금지 |

## 카드 유형과 생성 조건
공통: 자격 있는 사진만, 확인된 촬영일(`taken_at`)이 필요한 유형은 업로드일로 대체하지 않으며 연도·계절을 추정하지 않는다. 조건을 못 넘으면 카드를 만들지 않고 **결정 기록**(기준값·사유)만 남긴다. 아래 수치는 ★제안.
| 유형 | 묶음 근거 | 최소 조건(★) |
|---|---|---|
| 이벤트 | `taken_at` 시간 근접, 같은 `batch_id`, 시각 유사도(SigLIP2), 추가 근거. 같은 날 다른 사건은 분리, 이어진 여러 날은 연결. 시간만 비슷하다고 합치지 않음 | 5장 이상, 근거 2종 이상 |
| 기간 | 같은 연도·계절·연속 날짜 + 공통 시각 특징 | 8장 이상, 3일 이상, 촬영일 확인 사진만 |
| 주제 | 눈·바다·음식·케이크 등 **검증된 주제**(주제별 보정 임계값, 파일럿 임계값 재사용 금지) | 4장 이상, 서로 다른 3일 이상 |
| 과거의 오늘 | 실제 촬영일의 월·일(±3일) 과거 사진 | 3장 이상, 2개 연도 이상 |
- **카드 선정 기준:** 주제·이벤트 신뢰도, 사진 수, 근접 중복 비율(정확 해시·pHash·SigLIP2 우선, DINOv2 필수 아님), 시각 다양성, 대표 사진 품질, 다른 카드와의 사진 겹침, 자격·개인정보 조건. 사진 수가 많다는 이유만으로 선정하지 않는다.
- **카드 수 상한(임시 실험값):** 가족당 새 카드 7일에 최대 2개. 갱신·재생성은 세지 않음. 우선순위와 조정은 평가 뒤.
- **동일 입력 반복 분석은 중복 카드를 만들지 않는다**(그룹 키 해시로 멱등).
- **대표 사진·문구:** PoC 확정 방식(주제·선명도·노출·중심성·중복도)과 규칙 기반 제목·이야기. 가중치·임계값은 운영 최적값이 아니라 설정으로 분리. 확인되지 않은 가족 관계·인물·장소·감정·사건명은 쓰지 않고 불확실하면 일반 문장으로 대체. 규칙 렌더러를 모듈로 분리해 나중에 로컬 LLM 과 비교(별도 실험).

| `publish` | 카드 저장(멱등), 게시 직전 자격 재확인, 숨김·갱신(stale), 조회 API | 사진 판별 |
- `family_chat` 은 `family_memory` 를 import 하지 않는다. 기존 `shared/chat_library.py` 처럼 `shared/` 의 등록형 훅(`media_posted`·`media_removed`·`check_changed`)으로만 알리고, `family_memory` 가 시작할 때 등록한다. `family_memory` 는 `family_chat` 의 표를 좁은 읽기 인터페이스로만 읽는다.
- 웹 프로세스는 torch·ONNX 모델을 읽지 않는다. 워커가 죽어도 채팅·사진 업로드는 영향이 없다. `family_memory` 표가 없으면 해당 기능 라우터만 503(`schema_ready`).
- 작업 큐는 DB 기반을 우선하고(Redis 등 신규 인프라 없음), 서버 재시작 시 임대가 풀려 복구한다. 업로드 경로에서 SigLIP2 를 동기 실행하지 않는다.

## AI 모델·실행 환경
- 후보는 SigLIP2 B/16-224. DINOv2 는 필수가 아니다(중복 제거는 정확 해시·pHash·기존 임베딩 우선, 비교는 별도 계획).
- 텍스트 쪽 임베딩은 미리 계산해 저장하는 방안을 평가한다(운영에서는 이미지 쪽만 실행 — 효과는 미측정).
- **Torch vs ONNX Runtime 비교 계획:** 같은 이미지 집합(★100장 이상)으로 ① 장당 시간(p50·p95, 독립 프로세스, 예열 후, 배치 1·8, 동기화 검증) ② 최대 RSS·로드 시간·모델 파일 크기 ③ 결과 일치도(임베딩 코사인 ★0.999 이상, 태그 점수 최대 차이, 주제 1순위 일치율, 카드 선정 사진 집합 일치) ④ 전처리(224 리사이즈) 동등성. 구성: Torch fp32 CPU, ONNX fp32 CPU, 가능하면 ONNX 양자화(결과 일치도 통과 시만), GPU 가 있으면 별도.
- **개발 PC(i7-8700, RTX 3050)의 PoC 측정은 운영 성능이 아니다.** 운영 서버의 CPU·RAM·GPU 사양을 확인하기 전에는 성능·동시 처리량을 확정하지 않는다. 의존성(torch·transformers 또는 ONNX 변환 도구)과 모델 설치는 별도 승인 뒤에 한다.

## 동영상 (별도 트랙)
- 이번 MVP 는 사진만. 동영상은 업로드·저장·썸네일·재생이 아직 없어 별도 개발 트랙(영상 처리 도구 의존성은 별도 승인)이다.
- 인터페이스만 고려: 동영상 → 대표 프레임 추출 → 프레임별 `ImageFeatureExtractor` → 영상 단위 집계 → 사진·동영상 혼합 그룹. 프레임도 문서 안전 신호를 적용한다.

## 평가
- 지표: 이벤트 그룹화 정확도, 잘못된 병합·과도한 분리 비율, 주제 적합도, 불필요한 카드 비율, 놓친 추억 비율, 추억 간 사진 중복, 대표 사진 만족도, 제목·이야기 사실성, 다시 보고 싶은 정도, 사진 수 대비 카드 수, 처리 시간·자원, **문서가 카드에 게시된 사례(핵심 안전 지표)**.
- 사진이 하나도 선정되지 않는 시나리오도 정상으로 포함한다. 데이터는 공개 라이선스 사진 + 통제된 합성 시나리오 → 이후 동의받은 가족 파일럿 순서이며, **합성과 실제 촬영 이벤트 지표를 따로 보고**한다.
- 기존 파일럿 라벨·임계값(같은 파일럿에서 설정, 미검증)은 운영 근거가 아니다. 사람 1명+GPT 1명 50:50 평가는 탐색적 참고만이다.
- 안전성 평가는 `auto-memory-safety-eval.md`. 거기서 **개발 단계 검증 기준(400장·카테고리 40장 등)**은 규칙이 작동하는지 보는 초기 문턱이고 운영 자동 공개의 안전성 증거가 아니며, **E1 최종 게이트(위험 허용 기준·평가 규모)는 별도 정책 승인 전까지 미확정**이다. "일반 사진 자격 통과율"은 안전성이 아니라 사용성 지표다. 합성 카드는 독립 표본이 아니므로 이미지·원본 군집 단위와 구분해 보고한다.
