# 자동 추억 — 동의·철회·삭제 코드 요구사항

> **상태: 요구사항 정리(문서만).** 코드·DB 변경은 승인되지 않았고, 구현은 `auto-memory.md` 의 PR1 이후에 별도 승인으로 한다. 정책의 출처는 ADR 0020(동의·자체 서버)과 ADR 0021(자격·노출)이며 이 문서는 그 정책을 **구현자가 바로 쓸 수 있는 요구사항·시험**으로 옮긴 것이다. 정책을 새로 정하지 않는다. 미정 항목은 끝의 "미결정"에 둔다. 기준 코드는 `release/1.3` @ `438a4c26`.

## 1. 현재 코드의 연결 지점 (2026-11-18 확인)

| 필요한 동작 | 지금 코드 | 비고 |

| 작업 큐·워커 | 없음 | `auto-memory.md` 의 DB 큐 설계를 따른다 |

## 2. 동의 요구사항

- **C-01 (3중 조건, ADR 0020).** 분석 한 건은 서버 스위치(환경변수, 기본 꺼짐) AND 가족 활성화 AND 업로더 동의가 모두 참일 때만 시작한다. 판정은 한 함수(`consent`)가 하고, 하나라도 거짓이면 사유 코드와 함께 "분석 안 함"을 돌려준다.
- **C-02 (스위치 분리).** 가족 활성화는 `family_memory_settings` 에 둔다. `ai_group_settings` 값을 읽거나 쓰지 않는다. 기본값은 꺼짐이며 행이 없으면 꺼짐이다.
- **C-03 (권한).** 가족 활성화·비활성화는 `require_manager`(owner/admin). 동의·철회·사진별 제외는 **본인 사진에 한해** 모든 구성원. 남의 동의를 대신 바꾸는 API 는 없다. member 의 가족 활성화 시도는 403.
- **C-04 (업로더별 동의 기록).** `member_memory_consents` 에는 가족 ID, 사용자 ID, 동의 버전, 동의 시각, 철회 시각, 소급 동의 시각만 둔다. 동의 문구 원문은 저장하지 않고 버전 번호만 둔다. 보관 기간은 미결정이므로 삭제 배치를 만들지 않는다.
- **C-05 (신규 구성원).** 켜진 가족에 가입한 사용자는 동의 행이 없으므로 미동의다. 사용자 앱은 안내를 보여 주되, 동의 전 사진은 분석하지 않는다.
- **C-06 (소급 동의 분리).** 새 업로드 분석 동의와 소급 분석 동의는 별개 필드다. 소급 동의 없이 과거 사진을 작업으로 등록하는 코드 경로가 없어야 한다. 가족 활성화만으로 일괄 분석하지 않는다.
- **C-07 (사진별 제외).** `photo_analysis_exclusions` 로 업로더가 자기 사진을 분석에서 제외한다. 타임라인 노출과 별개이며 기존 `chat_photo_checks.excluded` 를 읽지도 쓰지도 않는다. 다시 포함하면 새 사진처럼 자격을 다시 계산한다.
- **C-08 (재확인 4지점).** 같은 자격 함수를 ① 작업 등록 ② 워커가 이미지를 읽기 전 ③ 결과 저장 직전 ④ 카드 게시 직전에 부른다. 하나라도 거짓이면 작업은 실패가 아니라 **취소**로 끝나고 파생 데이터를 저장하지 않는다. 카드 조회 때도 철회된 사진이 든 카드는 숨긴다(fail-closed).
- **C-09 (자격 입력 읽기 전용).** 자격 함수는 `chat_photo_checks` 상태를 읽기만 한다. 자동 판별이 `photo` 를 만들 수 없다는 D-13 시험은 그대로 통과해야 한다.

## 3. 철회 요구사항

- **W-01 (즉시 차단).** 철회 요청이 커밋되는 순간부터 그 사람의 새 분석 작업 등록과 카드 게시가 거부된다. 이미 큐에 있는 작업은 C-08 의 ②에서 취소된다. 차단은 요청 처리 안에서 동기로 이뤄지고 워커의 다음 주기를 기다리지 않는다.
- **W-02 (순서).** 같은 트랜잭션에서 ① 철회 시각 기록(= 차단) → ② 그 사람 사진의 대기·진행 작업 취소 → ③ 영향받은 카드를 `hidden` 으로 바꾼다. 여기까지 실패하면 전체를 롤백해 철회가 반쯤 적용된 상태를 남기지 않는다.
- **W-03 (파생 데이터 삭제).** ②·③ 뒤에 그 사람 사진의 `memory_media_features`(임베딩·태그 점수·안전 신호·해시)를 삭제한다. 목표 시한은 활성 저장소 기준 24시간(제안, 미확정). 삭제는 재시도 가능하고 여러 번 실행해도 결과가 같아야 한다(멱등).
- **W-04 (카드 처리).** 철회로 카드 조건(예: 최소 사진 수)이 깨지면 카드를 삭제하고, 아니면 남은 사진으로 재생성한다. **재생성이 끝나기 전에는 그 카드를 노출하지 않는다.**
- **W-05 (소급분만 철회).** 특징에 `origin`(live/retro)을 남겨, 소급 동의만 철회하면 소급분만 삭제한다.
- **W-06 (영향 범위).** 철회는 기본 채팅·날짜별 사진 공유·`chat_photo_checks`·원본 사진에 아무 영향을 주지 않는다.
- **W-07 (로그).** 철회·삭제 로그에는 개수와 사유 코드만 남기고 사진 내용·라벨·이야기 본문·임베딩·파일 경로를 남기지 않는다.

## 4. 삭제 요구사항

| 사건 | 지울 것 | 구현 위치 |
|---|---|---|
| 업로더 철회 | 위 W-01~W-05 | `family_memory` 서비스 |
| 사진별 제외 | 그 사진의 작업·특징, 카드에서 그 사진 제거 → 조건 확인(깨지면 숨김·갱신) | `family_memory` 서비스 |
| 채팅 사진 삭제(`delete_message`) | 그 첨부의 작업·특징, 카드에서 제거 → 조건 확인 | `chat_library` 와 같은 등록식 훅을 새로 둔다(`attachment_removed` 호출 옆) |
| 가족 비활성화 | 그 가족의 특징·카드·작업 전부 | 가족 활성화 끄는 서비스(권한 `require_manager`) |
| 가족 나가기 | 그 사용자의 분석 즉시 중단(동의 종료), 파생 데이터는 철회와 같이 삭제, 관련 카드 숨김·재구성 | `member_exit.member_left` 가 부르는 훅. **같은 트랜잭션**이어야 한다(실패하면 나가기도 취소되는 기존 규칙 유지) |
| 마지막 구성원이 나가 가족 삭제 | 추억 표 전부 | `group_purge.purge_group` 목록에 추가 |

- **D-01 (원본은 별개).** 카드 숨김·삭제는 채팅 원본 사진을 지우지 않는다. 가족 나가기 때 원본 채팅 사진 처리는 AI 기능과 별개이며 D-7·채팅 데이터 보존 정책을 확인한 뒤 정한다(이 문서에서 정하지 않음).
- **D-02 (훅 규칙).** 삭제 훅은 `chat_library` 처럼 `app/shared/` 의 등록식으로 만들어 `family_chat`·`family_group` 이 `family_memory` 내부를 import 하지 않게 한다. 훅이 등록되지 않은 환경(기능 꺼짐)에서도 삭제 경로는 정상 동작해야 한다.
- **D-03 (퍼지 목록).** 새 표를 만들면 `group_purge` 의 삭제 대상과 `docs/contracts/db.md` 에 같은 PR 에서 추가한다. 빠뜨리면 가족 삭제 뒤 파생 데이터가 남는다.
- **D-04 (백업).** 백업의 만료 기간과 복원 직후 삭제 목록을 다시 적용하는 절차는 별도로 정의한다. 정의 전까지 코드는 "백업까지 지워졌다"고 말하는 문구·로그·응답을 만들지 않는다.

## 5. 시험 요구사항 (각 PR 에 같이 작성)

1. 서버 스위치 꺼짐 → 분석 함수가 호출되지 않음(호출 횟수 0을 확인).
2. 가족 비활성·업로더 미동의·사진 제외·1:1 방·`document`·`failed`·`pending`·삭제 사진 → 각각 자격 거짓과 올바른 사유 코드.
3. C-08 4지점: 각 지점 직전에 철회하면 작업이 취소되고 특징이 저장되지 않음(4개 모두).
4. 철회 직후 같은 요청 안에서 새 작업 등록 거부, 카드 `hidden`, 재생성 전 조회에서 그 카드가 보이지 않음.
5. 철회 삭제를 두 번 실행해도 결과 동일(멱등), 중간 실패 후 재시도로 끝까지 삭제됨.
6. `delete_message` 로 사진 삭제 → 특징·카드 항목 제거. 훅 미등록 환경에서도 삭제 성공.
7. `leave_group`: 추억 훅이 예외를 던지면 가족 나가기도 롤백됨(기존 `member_exit` 시험 패턴 재사용). 성공하면 그 사용자의 파생 데이터가 없고 다른 구성원 것은 그대로.
8. `purge_group` 후 추억 표에 그 가족 행이 0.
9. `family_memory_settings` 를 켜도 `ai_group_settings` 값이 변하지 않고 그 반대도 같음.
10. member 의 가족 활성화·남의 동의 변경 시도는 403. 한 가족의 동의가 다른 가족 사진에 영향을 주지 않음.
11. 로그 수집으로 사진 내용·임베딩·경로가 남지 않음을 확인.

## 6. 미결정 (별도 정책 승인 필요)

- 동의 기록 보관 기간(법적·운영 검토).
- 24시간 삭제 목표의 확정, 백업 만료 기간과 복원 시 재삭제 절차.
- 철회된 카드 재생성 대기 시간 상한.
- 가족 나가기 때 원본 채팅 사진 처리(D-7·채팅 보존 정책).
- 소급 분석 화면·고지, 신규 구성원 안내 문구.
