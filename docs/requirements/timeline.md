# 기능: 가족 사진 타임라인·추억(가족 공동 앨범)

> 상태: **초안(2026-11-10)**. 결정 대기 항목이 많아 이 문서만으로 구현하지 않는다. `docs/requirements/timeline.md` 로 넣기 전에 "미정"의 결정을 받는다.
> 관련: `family-library.md`(문서함·사진 판별), `family-chat.md`(사진 보내기·앨범 묶음), `report.md`(주간 리포트), ADR 0014·0015, 로드맵 T05·T38~T43·T25·T26.

## 목적
가족 구성원이 가족 채팅방에 평소처럼 사진을 올리면, **다시 올리지 않아도** 가족 모두가 함께 보는 **가족 공동 앨범**에 날짜별로 쌓이고, 가족이 함께 댓글·추억·성장 기록을 남겨 회상할 수 있게 한다. 단순한 사진 목록이 아니라 미테네(Mitene)처럼 "가족이 같이 쓰는 앨범"이 목표다. AI 기능(이야기·사진 설명·검색·영상)은 그 위에 단계적으로 붙인다.

## 사용자 요구 (2026-11-10 사용자 요청)
1. 사진 **촬영일** 기준으로 연·월·날짜별 자동 정리
2. 가족 채팅방에 공유한 사진을 **재업로드 없이** 타임라인에 표시
3. 가족별 사진 댓글과 공동 추억 이벤트
4. 가족이 직접 입력하는 성장 기록
5. AI 가비가 사진·댓글·관련 일정에 **근거하여** 추억 이야기 생성
6. E5-small·pgvector 를 활용한 자연어 추억 검색
7. 장기적으로 가족 추억 영상 제작
8. 주간 가족 뉴스와 타임라인 추억 연결

## 확정 / 미정 한눈에
| 구분 | 내용 |
|---|---|
| 확정(기존 결정 유지) | 가족 전체방 사진만 다룬다. 1:1 방 사진·개인 AI 대화는 타임라인·추억·AI 에 넣지 않는다. 문서 사진(가족 문서함에 등록된 것)은 타임라인에 섞지 않는다. 재업로드 없이 기존 채팅 사진을 그대로 쓴다. 여러 장 묶음(`batch_id`)은 타임라인의 기본 단위다(`family-chat.md` 앨범 묶음). 타임라인 1단계는 AI 없이 만든다(2026-11-06). 위치(GPS)·기기 정보는 저장하지 않는다 |
| 확인된 사실 | 지금 서버는 사진을 저장할 때 EXIF 를 모두 지우고 촬영일을 읽지 않으며, DB 에 촬영일 칸이 없다(날짜는 보낸 시각뿐). 앱도 촬영일을 보내지 않는다. 그래서 **이미 올라간 사진의 촬영일은 알 수 없다** |
| 미정(사용자 결정) | 아래 "미정" 절 Q1~Q20 |

## 화면 (초안, 시안 없음 — 확인 필요)
- 진입: 마이 > **타임라인**(지금 "준비 중", `features/more/menuItems.js:11`).
- 타임라인 목록: 연·월 머리글 → 날짜 → 묶음(1장/2장 나란히/3장 이상 격자, 기존 앨범 말풍선 규칙과 같게). 월별 대표 사진. 위로 갈수록 최근.
- 사진 보기: 기존 사진 뷰어 재사용, "원본 메시지로 가기"(채팅방에서 그 메시지로 이동), 반응(기존 메시지 반응), 댓글.
- 추억 이벤트: 만들기(사진 고르기 → 제목·설명·날짜) → 보기(사진 묶음·댓글·AI 이야기).
- 성장 기록: 대상(가족 구성원 또는 이름표) → 날짜·종류·값·메모·사진(선택).
- 추억 검색(후속), AI 이야기(후속), 영상(후속).
- "N년 전 오늘"·즐겨찾기·가족여행 일지는 후속 후보(2026-11-06 메모의 후속 목록).

## 자동 수집 규칙 (타임라인)
- **대상**: 가족 전체방(`chat_rooms.kind = family`, 옛 `room_id` 없는 메시지 포함)의 사진 첨부(`message_attachments.kind = image`)만.
- **제외**: 1:1 방 사진, 메인 AI 채팅(서버에 저장되지 않음), 가족 문서함에 등록된 사진(문서로 판별됐거나 "문서로 저장"한 사진 — Q5), 지운 메시지의 사진(첨부가 지워짐), 가족이 "타임라인에서 빼기"한 사진(후속).
- **재업로드 없음**: 채팅에 저장된 1600px 사본과 400px 썸네일을 그대로 쓴다. 새 파일을 만들지 않는다.
- **묶음 유지**: 같은 `batch_id` 는 한 묶음으로 보인다. 묶음 안 촬영일이 다르면 묶음 대표 날짜 규칙을 따른다(Q4).
- **날짜**: 촬영일이 있으면 촬영일, 없으면 **보낸 날(한국 시간)**. 이미 올라간 사진은 모두 보낸 날 기준이다(복구 불가). 촬영일 저장에는 DB 칸 추가가 필요하다(Q1).
- **촬영일을 얻는 방법(결정 대기)**: 서버가 업로드 원본에서 촬영 시각 태그만 읽고(위치·기기 태그는 읽지 않음), 원본에 없으면 앱이 사진 고를 때 읽은 촬영 시각만 함께 보낸다. 범위 밖(1990년 이전·미래) 값은 버린다. 시간대는 Q3. 웹은 촬영일 출처가 없다(확인 필요).
- **문서 판별 지연**: 문서 사진 판별은 보낸 뒤 뒤에서 돌아, 문서 사진이 잠깐 보였다가 빠질 수 있다(알려진 한계, 표시 방법 Q 확인 필요).

## 추억 이벤트·댓글·성장 기록 (T40)
- **추억 이벤트**: 가족 누구나 가족방 사진 여러 장(묶음·날짜를 넘어)을 골라 하나의 추억으로 묶는다. 제목·설명·기간·대표 사진. 업로드 묶음(`batch_id`, 자동)과는 다른 단위다.
- **댓글**: 사진 한 장 또는 추억 이벤트에 가족이 댓글을 단다. 채팅방에는 올라가지 않는다. 수정·삭제 권한은 Q10. 반응은 기존 메시지 반응을 그대로 쓴다.
- **성장 기록**: 가족이 직접 입력한다(대상·날짜·종류·값·메모·사진 선택). 대상 범위와 민감도는 Q11.
- **주간 뉴스 승인**: 추억 이벤트마다 "주간 뉴스에 넣어도 돼요" 표시(기본 꺼짐, Q15).
- **이전 결정과의 관계**: 2026-11-06 에 "별도 업로드/추억 직접 만들기는 폐기"로 정했다. 이 절은 그 결정을 바꾸는 것이라 확정이 필요하다(Q6).

## AI 추억 이야기 (T41, 후속)
- **요청할 때만** 만든다(자동 생성 없음). 한 번 만든 이야기는 저장하고, 다시 볼 때는 AI 를 부르지 않는다. 다시 만들기는 사용자가 누를 때만.
- **근거**: 추억 이벤트의 제목·설명·댓글, (있으면) AI 사진 설명, 같은 기간의 **가족 공유 일정**. 개인 일정·개인 AI 대화·1:1 대화·금액·건강 기록(성장 기록 포함 여부 Q11)은 쓰지 않는다.
- **근거 없는 추측 금지**: 근거에 없는 사건·인물·감정·장소를 쓰지 않는다. 설명이 없는 사진은 "사진 N장"으로만 언급하고 사진 속 활동을 추측하지 않는다(2026-11-06 원칙). 문장마다 근거(어느 이벤트·댓글·일정)를 연결해 저장한다. 근거가 연결되지 않는 문장은 보여 주지 않는다.
- **사용자 수정·저장·공유**: 가족이 고쳐 저장한다. 공유 범위는 Q14.
- **외부 전송·한도**: 가족이 AI 사용에 동의한 경우만(기존 AI 동의), 이름·연락처는 가명화해 보낸다. 사진 파일은 보내지 않는다. 하루 횟수 상한(Q19).

## AI 사진 설명 (T42, 출시 후)
- 허용된 사진에만 짧은 설명·키워드를 만들어 검색에 쓴다. **일반 사진(얼굴·집·아이)이 외부 AI 로 나가는 새 경로**라 문서 읽기(2026-11-10 T21 결정)와 다르게 다룬다.
- **동의(결정 대기, Q8)**: 추천안은 가족 AI 동의 + 그룹의 "사진 AI 설명" 스위치(기본 꺼짐, 소유자·관리자) + 사진별 "AI 설명 제외".
- **대상**: 가족방 사진, 문서함 미등록, 제외 표시 없음. 1:1 사진·문서 사진은 보내지 않는다. 보내는 사진은 위치·기기 정보가 없는 축소본.
- **처리 시점(Q9)**: 추천안은 추억 이벤트에 넣은 사진만 요청할 때.
- **비용**: 같은 사진은 한 번만, 가족별 하루 상한(Q19).
- **삭제**: 사진(메시지)을 지우면 설명과 검색 색인도 함께 지운다.
- **이전 결정과의 관계**: 2026-11-06 "사진 내용은 AI 가 읽지 않는다(날짜·장수만)"를 바꾸는 일이라 확정이 필요하다(Q7). 개인정보처리방침·스토어 고지(T31) 갱신 대상.

## 추억 검색 (T38)
- **검색 대상**: 추억 이벤트 제목·설명, 가족 댓글, AI 이야기, (있으면) AI 사진 설명. 날짜·올린 사람 조건.
- **사진 자체는 글자 검색으로 찾을 수 없다**: 글이 붙은 사진만 내용으로 찾히고, 나머지는 날짜·올린 사람으로만 찾는다.
- **1단계**: 글자 일치(AI 0회). **2단계**: 기존 E5-small·pgvector 의미 검색 재사용(문서함과 섞지 않는 별도 색인).
- **역할 경계**: 임베딩 모델 선택·학습, 조각 나누기, 순위 매기기, 검색 품질 평가는 **RAG 담당 팀원 영역**이다. 이 기능은 어떤 글을 색인할지, 권한(가족 그룹)·삭제 동기화, 화면·API 를 정한다.
- 출시 범위(MVP 포함 여부)는 사용자 확정 필요(로드맵 T38).

## 추억 영상 (T43, 후속)
- 사진 고르기·시간순·AI 제목/자막(스토리보드)·재생.
- 지금 영상 렌더링·저장·배포 기반이 없다. 1단계는 앱에서 사진 슬라이드쇼로 재생하는 안을 검토한다(Q17).
- 가족이 찍은 동영상 올리기(T10)와는 다른 기능이다.

## 주간 가족 뉴스 연결
- 주간 뉴스(T25·T26)는 타임라인·추억 없이도 만들어져야 한다. 추억 이벤트는 **가족이 뉴스 포함을 허락한 것만** 선택 입력으로 읽는다(없으면 빼고 만든다).
- 뉴스 생성 시점·대상(가족별/구성원별)은 T25 에서 정한다.

## API (초안 — 이름·필드는 확정 전, `openapi.json` 이 기준)
- 타임라인: 월별 요약(월·사진 수·대표 사진), 월/날짜 범위 목록(사진·묶음·날짜·촬영일 여부·원본 메시지 id).
- 추억 이벤트: 만들기·고치기·지우기·사진 넣기/빼기·목록·상세.
- 댓글: 사진·이벤트에 달기·고치기·지우기.
- 성장 기록: 넣기·고치기·지우기·목록.
- (후속) 이야기 만들기·저장·고치기, 사진 AI 설명 설정·제외, 추억 검색.
- 모든 API 는 가족 그룹을 요청에서 받지 않고 로그인한 사용자의 가족 멤버십으로만 정한다. 다른 가족 데이터는 존재도 알리지 않는다(404).

## 데이터 (초안 — DB 변경은 Alembic 으로만, 모두 추가(expand))
- 사진 첨부에 촬영 시각 칸 1개(비어 있을 수 있음) — Q1 확정 시.
- 추억 이벤트, 이벤트-사진 연결, 댓글, 성장 기록, (후속) 이야기·사진 설명·사진별 표시·그룹 설정, (후속) 검색 색인.
- 삭제 정책: 사진(메시지)을 지우면 연결·댓글·설명·색인을 함께 지운다. 가족을 지우면 모두 지운다. 1:1 방 데이터는 처음부터 없다.
- 지우거나 이름을 바꾸는 위험 변경은 없다. 공용 DB 반영은 DB 담당자 통합 절차를 따른다.

## 개인정보·권한·삭제 정책
- 가족 그룹 단위로만 보이고, 가족 구성원만 읽고 쓴다.
- 위치·기기 정보는 저장하지 않는다(촬영 시각만).
- 외부 AI 로 나가는 것: 이야기(가명화한 글, 가족 AI 동의 시), 사진 설명(별도 동의 시 축소 사진). 타임라인·댓글·성장 기록 자체는 외부로 나가지 않는다.
- 로그에 사진 내용·댓글·성장 기록 값을 남기지 않는다.
- 구성원이 가족을 나갈 때 그 사람의 댓글·이벤트 처리(Q18).

## 완료 조건 (단계 1·2 기준 초안)
- 가족방 사진이 연·월·날짜·묶음으로 보이고, 촬영일이 있으면 촬영일·없으면 보낸 날로 정리된다.
- 1:1 사진·문서 사진·지운 사진이 나오지 않는다. 다른 가족 데이터에 접근할 수 없다(시험).
- 위치·기기 정보가 저장되지 않는다(시험).
- 추억 이벤트에 가족방 사진만 넣을 수 있고, 사진을 지우면 이벤트 연결·댓글이 정리된다. 가족 삭제 시 함께 지워진다(시험).
