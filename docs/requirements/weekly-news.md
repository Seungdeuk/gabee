# 기능: 주간 가족 뉴스(가비의 "이번 주 우리 가족은?")

> 상태: **초안(2026-11-10)**. **확정(2026-11-10 사용자): 한 주에 한 번 생성, DB 에 저장, 구성원별로 따로(처음엔 가족별 하나였다가 같은 날 변경: 일정 줄이 사람마다 달라서).** **나머지(Q1 실행 방식, Q4~Q11)도 2026-11-10 사용자가 "추천하는 방식으로" 확정했다.** 구현은 T26 에서 단계별로(새 표는 Alembic, 구현 전 계획 확인). 사용자 확인 뒤 확정하고, 코드는 그 다음에 쓴다.
> 로드맵: T25(이 문서) → T26(생성·저장 구현). 사용자 지정 순위 1순위(2026-11-10). 평가 연결: T35(Agent 평가).
> 관련: `report.md`(규칙 기반 주간 리포트, 이 기능의 입력과 대체 화면), `family-library.md`(문서함), `schedule.md`, `agent-eval.md`, `timeline.md`(사진 타임라인 초안).

## 목적
가족이 한 주를 돌아보는 짧은 "뉴스"를 가비가 써 준다. 가족 일정과 완료한 할 일 같은 **공유 기록만** 재료로, 모든 문장이 근거 기록으로 되짚어지게 만든다. 평가하기 쉽고 비용을 통제할 수 있도록 **조회할 때마다 AI 를 부르지 않는다.**

## 사용자 요구
1. 마이 > AI 리포트(`/report`) 에서 이번 주·지난 주 "가족 뉴스"를 본다(주 이동은 기존 리포트와 같은 범위: 이번 주부터 8주 전).
2. 뉴스는 **구성원마다 따로** 만들어진다. 내 뉴스는 내 일정 줄 기준이고, 다른 구성원의 뉴스는 볼 수 없다. 같은 사람이 여러 번 열어도 그 주 뉴스는 한 번만 만든다.
3. 뉴스의 각 문장은 근거(일정·할 일·문서)가 있고, 누르면 그 기록으로 이동한다.
4. AI 가 만든 것임을 화면에 표시한다. 실패하면 기존 **규칙 기반 리포트**가 그대로 보인다(뉴스만 "만들지 못했어요").

## 재료(입력)와 제외
| 쓴다 | 쓰지 않는다 |
|---|---|
| **내 줄의** 가족 공유 일정(`kind=1`, `shared=true`)과 완료한 공유 할 일 — 제목·날짜·시간·담당자 이름(가명). 일정은 사람마다 자기 줄을 갖기 때문에 구성원마다 재료가 달라진다 | 공유가 아닌 개인 일정(**1단계 제외, Q11 확정**), 개인 AI 대화, **1:1 방**의 모든 것, 다른 구성원의 개인 줄 |
| 문서함에 올라온 문서의 **종류·제목·날짜**(민감 문서 제외, 본문 안 보냄) | 민감 금융·건강·신분 문서, 문서 본문·가린 글(1단계) |
| (후속) 승인된 추억 이벤트(T40), 타임라인 사진 **장수·날짜**(T05) | 사진 속 내용(사진 설명은 T42, 출시 후), 얼굴·위치 |
| (후속·선택 저장 필요) 구성원이 "뉴스에 포함"으로 고른 채팅 문장 | 채팅 원문 전체, 검색으로 긁은 대화 |
집계 기준(월~일, KST, 오늘 이후/지난 주 구분)은 `report.md` 의 기준을 그대로 쓴다.

`shared=true` 는 DB 컬럼이 아니라 서버가 그때그때 계산하는 값이다(`schedule.service.with_sharing`) — 재료 수집은 저장된 값을 읽는 것이 아니라 그 계산 결과를 쓴다.

## 생성 흐름(초안)
1. 구성원이 `/report` 에서 그 주의 뉴스를 요청한다(앱은 항상 같은 읽기 API).
2. 서버는 `(group_id, user_id, week_start)` 저장본이 있으면 그대로 돌려준다(AI 호출 없음).
3. 없고 **지난 주 이전이거나 이번 주가 충분히 지났을 때만**(Q1: 이번 주는 일요일 저녁 이후 또는 "지금까지"로 표시) 생성한다. 같은 사람의 요청이 동시에 와도 한 번만 만든다(`(group_id, user_id, week_start)` 고유 + 생성 중 상태).
4. 서버가 재료를 모아 **근거 id 를 붙인 목록**을 만들고, `app/shared/llm` 래퍼로만 호출한다(`ai_guard.run`: 가족 AI 동의·하루 한도·쿨다운, 이름은 기존 가명화 게이트웨이를 거친다).
5. 응답은 구조화(JSON: 기사 제목·문장 목록, 문장마다 `source_ids`)로 받고, **서버가 검증**한다: 존재하지 않는 근거 id·재료에 없는 숫자·이름이 있으면 그 문장을 버리거나 전체를 실패 처리(규칙 기반 폴백).
6. 저장 후 반환. 실패는 짧은 재시도 대기 후에만 다시 시도(같은 원인으로 호출이 반복되지 않게).

## 화면
- 기존 `/report` 화면에 "가족 뉴스" 영역을 더한다(위치: 가비의 한마디 아래). **Figma 시안 없음 — 확인 필요.**
- 상태: 뉴스 있음 / 만드는 중 / 이번 주 아직(일요일 저녁 이후 생성) / 재료 없음(공유 기록이 없는 주) / 만들지 못함(규칙 기반 리포트만) / AI 동의 없음(안내).
- 문장을 누르면 근거(일정 탭 해당 날짜·문서 상세)로 이동. 다시 만들기 버튼은 두지 않는다(비용 통제, Q7).

## API(초안 — 이름·필드는 확정 전, `openapi.json` 이 기준)
- `GET /report/news?week_start=YYYY-MM-DD` → `{status, week_start, title, items:[{text, source_ids}], sources:[{id, kind, ref, label}], generated_at, model}`. `GET` 은 부작용이 없는 읽기 전용이라 저장본이 없어도 만들지 않고 상태(위 화면 상태 중 뉴스 있음·아직·재료 없음·만들지 못함 등)만 돌려준다. 생성은 별도 `POST` 로 하며 경로·필드는 T26-a3 에서 정한다(Q8 확정).
- 요청한 사람 본인의 뉴스만 돌려준다(`user_id` 는 요청에서 받지 않고 인증된 사용자로 고정). 모든 가족 데이터는 `current_group_id` 로만 받는다. 서비스를 직접 부르는 코드는 `ensure_group_member` 를 먼저 쓴다.

## 데이터(초안 — DB 변경은 Alembic 으로만, 모두 추가(expand))
- 새 표 `member_weekly_news`: `id, group_id(FK CASCADE), user_id(FK CASCADE), week_start(date), status(ok/failed/pending), body(JSON), sources(JSON), model, prompt_version, input_tokens, output_tokens, created_at` — 고유 `(group_id, user_id, week_start)`.
- `group_purge`(가족 삭제)에 포함한다. **가족을 나가는 구성원의 뉴스는 함께 삭제**한다(본인 기록이라 남길 이유가 없음, Q9 확정). 다른 구성원 뉴스에 남는 나간 사람의 이름은 표시 이름으로 처리한다(Q9 확정). 위험 변경 아님(추가 전용).

## 개인정보·권한·삭제
- 공유된 기록만, 1:1·개인 대화·민감 문서 제외. 외부 전송은 `family-library.md` T21 결정처럼 가족 AI 동의가 있을 때만(`ai_guard`), 이름은 가명화 후 전송.
- 구성원이 일정을 지워도 **이미 저장된 뉴스**는 남는다 — 이 점은 화면에 안내한다(Q9 확정). 가족이 삭제되거나 그 구성원이 가족을 나가면 해당 뉴스는 삭제된다.
- LLM 호출 입력·출력은 로그에 남기지 않는다(토큰 수·상태만).

## 비용·평가
- 호출 단위: **구성원당 주 1회**(가족 인원수만큼 늘어난다. 6인 가족이면 가족별 방식의 6배. 구성원이 그 주에 한 번도 열지 않으면 호출하지 않는다). 입력 상한(근거 항목 N개·글자 수)과 출력 토큰 상한을 설정으로 둔다. 모델은 환경변수(초안 추천: Haiku 급, `app/shared/llm` 설정으로, 값은 코드에 고정하지 않는다). 품질이 부족할 때만 올린다.
- 평가(T35 연계): Faithfulness(문장이 근거에 맞는가), Source Attribution(근거 id 일치), 금지 재료 누출 0건, 그룹 권한 격리, 비용. 평가셋은 가짜 가족 데이터로 만든다. **실제 호출은 사용자 승인과 상한(예: 평가 1회 $2) 안에서만.**

4. T26-c: 앱 영역·상태 화면(시안 확인 후), 실기기 확인.
5. 후속: 타임라인(T05)·추억 이벤트(T40) 입력 추가, 채팅 "뉴스에 포함" 선택(별도 표).

## 완료 조건(초안)
- 같은 `(가족, 구성원, 주)` 에 AI 호출이 한 번만 일어난다(동시 요청 포함).
- 개인 일정·1:1·민감 문서·가족 밖 데이터가 입력에 들어가지 않는다(시험).
- 근거 없는 문장은 저장되지 않는다(검증기 시험), LLM 실패 시 규칙 기반 리포트가 그대로 보인다.
- 다른 구성원·다른 가족의 뉴스는 보이지 않는다(권한 시험), 가족 삭제·가족 나가기 시 뉴스도 지워진다.
- 외부 전송 전 가명화·동의 확인이 거친다(기존 보안 매트릭스 시험 통과).
