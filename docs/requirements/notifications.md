# 요구사항: 알림함 (notifications)

> 상세 설계는 `docs/superpowers/specs/2026-10-28-notifications-design.md`, 구현 계획은 `docs/superpowers/plans/2026-10-28-notifications.md`.

## 목적
메인 화면(첫 탭, AI 채팅)에서 지난 사건 기록을 모아 보는 앱 안 알림함. 소통(가족 채팅) 메시지 알림은 제외하고, 일정·가계·돌봄·가족 그룹·AI 기록의 사건을 담는다. 알림마다 분류를 구분해 보여 준다.

## 결정 사항
- 형태: 앱 안 알림함(서버 저장, 읽음 표시). 폰 푸시는 알림함을 대체하지 않고 추가로 보낸다(설계 `docs/superpowers/specs/2026-11-05-push-notifications-design.md`, 결정 `docs/adr/0012-push-via-expo.md`).
- 성격: 지난 사건 기록 + 분류 구분(일정·가계·돌봄·가족 그룹·AI 기록).
- 대상: 그 데이터를 볼 수 있는 사람만 받는다. 본인이 한 행동은 알림이 없다.
- 방식: 공용 알림 서비스(`app/shared/notifications.py`의 `notify()`)를 각 기능이 사건 자리에서 호출한다.
- 알림 문구는 고정 템플릿으로 짧게 쓴다. 금액·위치·건강 정보·AI 요약·채팅 내용은 넣지 않는다.

## 범위 밖
- 시간 기반 알림(정산 마감 임박·구독 결제 예정)과 알림 삭제는 아직 범위 밖이다(푸시 4단계에서 예약 푸시로 다룬다). 폰 푸시와 푸시 설정(분류별 끄기·방해금지·내용 표시 방식)은 푸시 설계서의 단계로 연결한다.

## 단계
- 1차: 공용 기반 + 가족 그룹 가입 요청(관리자에게)·가입 승인(신청자에게) 연결 + 앱 알림함.
- 푸시 PR 1: 새 공유 일정·할 일 배정·정산하기·송금 완료·용돈 요청과 처리·가족 문서함 새 문서(민감 문서 제외)를 연결했다(문구는 고정, 일정 변경·취소는 공유 복사본이 독립이라 제외). 아래 2차에서 이어 간다.
- 2차(팀원 영역 협의 후): 일정·가계·돌봄·AI 기록·구성원 변경 연결. 일정(같이해요 도착·답)은 연결했다. 문구는 고정("같이해요가 도착했어요", "같이해요에 답이 왔어요")이고 제목·날짜·장소·메모·수락 여부는 담지 않는다. 나머지는 탭별로 따로 연결한다.
- 푸시 2단계 서버(소통): 새 글·사진·파일 푸시를 고정 문구("새 메시지가 도착했어요")로, 암호화 없이 보낸다. 같은 묶음 사진·연달아 보낸 글은 한 번만.
- 푸시 1단계(기반): 기기 푸시 토큰 등록·해제, 사용자별 푸시 설정(켜기·끄기, 끈 분류, 방해금지 시간, 내용 표시 방식), 알림함 사건을 푸시로 발송. 푸시에는 알림 제목(고정 문구)만 담고 금액·장소·건강 정보·AI 요약은 담지 않는다. 소통(가족 채팅) 메시지 푸시는 2단계이며 알림함에 저장하지 않고 푸시만 보낸다.
