# 기능: 문의·신고 (support)

## 목적
사용자가 앱에서 서비스 관리자에게 문의나 신고를 보내고, 관리자가 남긴 답변을 본다.
서비스 관리자는 관리자 페이지에서 목록을 보고 상태를 바꾸고 답변한다(관리자 쪽은 `docs/requirements/service-admin.md`).

## 화면
- 앱: 문의 보내기, 내 문의(상태·답변) 화면. **다른 팀원이 만든다**(2026-11-04).
- 관리자 페이지 "문의 및 신고" 탭: 서비스 관리자 페이지와 함께 별도 PR 로 연결한다.

## API
- `POST /support/tickets`: 본문 `{kind, title, body}`. `kind` 는 `inquiry`(문의) / `report`(신고), `title` 1~100자, `body` 1~2000자. 201 + 만든 문의.
- `GET /support/tickets/mine`: 내가 보낸 것, 최근순 최대 100건. 상태(`new`/`working`/`done`)와 답변(`answer`, `answered_at`) 포함.
- 로그인한 본인 것만 다룬다. 가족이 없어도 보낼 수 있다. 비로그인 401, 잘못된 입력 422.

## 데이터
- 새 표 `support_tickets`: `id`, `user_id`, 보낼 때의 가족 `group_id`(없으면 비움), `kind`, `title`, `body`, `status`, `answer`, `answered_at`, `created_at`.
- 인덱스 `(user_id, created_at)`, `(status, created_at)`.

## 정한 것 (2026-11-04)
- 신고에도 **사용자가 직접 쓴 글만** 담는다. 가족 채팅 내용은 붙이지 않는다(관리자는 가족 대화를 보지 않는다).
- 신고 대상(사람·메시지)은 따로 고르지 않고 글로 받는다.
- 답변 알림은 1차에 보내지 않는다. 사용자는 "내 문의"에서 답변을 본다.
- 상태는 마지막 값만 남긴다. 변경 이력 표는 만들지 않는다.

## 완료 조건
- 위 두 API 와 표가 있고, 본인 것만 보인다.
- 테스트: 비로그인 401, 보내기·내 목록, 남의 것 안 보임, 가족 없는 회원, 잘못된 입력 422.

## 미정
- 보내기 횟수 제한(도배 방지).
- 새 문의가 오면 관리자에게 알릴지(메일·메신저 등).
