# 기능: 체류시간 (usage)

> 상태: 초안 (2026-11-19). 정밀한 기록이 아니라 "대략 하루에 몇 분, 어느 탭을 오래 쓰나"를 보는 것이 목적이다.

## 목적
관리자 페이지에서 사용자가 앱을 하루에 얼마나 오래, 몇 번 쓰는지와 어느 탭에 오래 머무는지를 본다.
사람 수(하루·7일·30일 활성 사용자)는 이미 `refresh_tokens.issued_at` 으로 보고 있어서 다시 만들지 않는다.

## 재는 방법 (앱)
- 앱이 화면에 떠 있는 동안(AppState `active`)만 잰다. 시간은 "앞에 온 시각"과 "뒤로 간 시각"의 차이로 계산하고 타이머를 쓰지 않는다.
- 지금 경로(`usePathname`)로 탭을 나눈다: `chat`(AI 채팅), `family-chat`(소통), `schedule`(일정), `care`(지갑), `my`(마이), 그 밖은 `other`. 화면 안의 내용(어떤 방·어떤 일정)은 보내지 않는다.
- 앱이 백그라운드로 갈 때 한 번 보낸다. 보내다 실패하면 버린다(휴대폰에 보관하지 않음). 앱이 갑자기 꺼지면 그 사용분은 빠진다.
- 실행 횟수: 앱이 앞으로 올 때 1번. 단, 백그라운드에 30분 미만 있다가 돌아오면 같은 사용으로 보고 세지 않는다.
- 로그인한 사람만 잰다. 안드로이드·아이폰 모두.
- 성능: 값은 변수(ref)에만 두고 화면을 다시 그리지 않는다. 경로 확인은 화면 없는 작은 컴포넌트 하나에서만 한다.

## API
- `POST /usage/report` (로그인 필요, 가족 없어도 됨) → 204
  - 본문 `{day, opens, tabs}`. `day` 는 사용한 날(기기 날짜, YYYY-MM-DD), `opens` 0~20, `tabs` 는 탭 이름 → 초(0~86400, 한 번에 4시간을 넘으면 4시간으로 자름).
  - `day` 가 오늘(한국 시간) 기준 7일보다 오래됐거나 내일보다 뒤면 422. 모르는 탭 이름은 422.
  - 같은 사람·날·탭 줄에 더한다. 하루 합계는 86400초를 넘지 않게 자른다.
- `GET /admin/service/analytics` 응답에 `usage`(아래)와 `usage_ready` 추가.

## 데이터
- 새 표 `usage_daily` (사람·날·탭마다 한 줄, 기본키 `(user_id, day, tab)`)

| 칸 | 뜻 |
|---|---|
| `user_id` | 누구 (`users.id`) |
| `day` | 날짜 |
| `tab` | 탭 이름 또는 `app`(앱 전체 합계·실행 횟수 줄) |
| `seconds` | 그날 그 탭에 머문 초 합계 |
| `opens` | 그날 실행 횟수(`app` 줄에만, 나머지는 0) |
| `updated_at` | 마지막으로 더한 시각 |

- 원본 기록("몇 시 몇 분에 무엇을")은 저장하지 않는다. 로그에도 남기지 않는다.

## 화면 (관리자, 데이터 분석 탭 "체류시간" 구역, 최근 30일)
- 1명당 하루 평균 사용 시간(기록이 있는 날 기준), 1명당 하루 평균 실행 횟수, 기록된 사용자 수
- 탭별 사용 시간 비율
- 날짜별 1명당 평균 사용 시간(30일 막대)
- 사람 이름·개인별 시간은 보이지 않는다. 표가 없는 DB 에서는 이 구역만 "준비 중".

## 완료 조건
- 서버 시험: 비로그인 401, 저장·누적, 모르는 탭·잘못된 날짜·범위 밖 값 422, 하루 상한, 가족 없어도 저장, 본인 것만.
- 관리자 시험: 평균·탭 비율·날짜별 값, 표 없음 처리.
- 앱: lint, 탭 이름 판정 함수 확인.
- 문서: openapi.json, db.md, features/usage.md.

## 미정
1. 개인정보처리방침 문구("앱 사용 시간(탭별 하루 합계)을 저장한다") — 팀 확인.
2. 보관 기간(제안: 90일, AI 사용 기록과 같게)과 지우는 방법. 이번에는 지우는 작업을 넣지 않았다.
3. 30분 기준값.
