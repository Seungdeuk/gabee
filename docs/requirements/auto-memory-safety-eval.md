# AI 자동 추억 — 문서 누출 안전성 평가 설계 (E0 → E1 전환용)

> **상태: 평가 설계 초안(문서만).** 이 문서의 수치(★)는 제안값이다. **PR0 문서 승인은 "개발 단계 검증 기준"의 방향 승인이고, E1 자동 공개의 최종 안전 기준·평가 규모는 별도 정책 승인 전까지 확정하지 않는다.** 확정 뒤에는 최종 평가셋 실행 전에 기준을 고정하고, 고정 뒤 변경은 새 버전과 사유 기록, 새 최종 평가셋이 필요하다. 평가셋 수집·모델 설치·실제 가족 사진 사용은 이 문서로 승인되지 않는다.

## 1. 무엇을 막는가
- **누출 정의:** 문서·스크린샷·개인정보가 드러나는 인쇄물·화면 사진이 (a) 추억 분석 자격을 통과하면 **자격 누출**, (b) 게시된 추억 카드에 들어가면 **게시 누출**이다. 핵심 안전 지표는 게시 누출이고, 자격 누출은 선행 지표다.
- 기존 판별 정책에서 메뉴판·성분표·간판은 일반 사진으로 본다(허용 범주). 허용 범주는 누출로 세지 않되 별도로 보고한다.
- E1 은 `unsure` 사진을 자격에 넣으므로 **기존 문서 판별의 미탐이 곧 노출 위험**이다. 이전 실험(미탐 2.3%, 독립 장면 33개)은 근거로 쓰지 않는다.

## 2. 기존 문서 판별에서 생길 수 있는 미탐 위험
| 위험 | 이유 | 대응 |
|---|---|---|
| `unsure` 에 섞인 문서 | 세부 판정 미저장: "글자 없음"과 "애매"가 구분 안 됨 | 판별 세부 결과 저장(PR2), E1 은 "글자가 읽힌 애매" 제외 |
| OCR 미탐 | 저해상도·기울임·반사·저조도·손글씨·작은 글자·세로쓰기, 한글·영문 외 문자, 1600px 축소 | 부정 사례에 변형 포함, OCR 이외 신호와 AND 결합 |
| 글자가 적은 문서 | 카드·신분증·통장(숫자 위주), 바코드·QR, 봉투·약 포장 | 카테고리별 최소 표본, 문서 유사도 신호 |
| 스크린샷·화면 촬영 | 글자는 많지만 문서가 아닐 수 있고 아이콘 위주 화면은 글자가 적음 | 스크린샷 신호(화면 비율·UI 요소 유사도), 카테고리 분리 |
| 이미지 속 문서 | 문서가 배경·모서리에 일부만 나오는 사진 | "이미지 속 문서" 변형을 별도 축으로 포함 |
| 여러 쪽 문서 | 한 쪽만 놓쳐도 누출 | 같은 묶음·가까운 시각 업로드 전체 격리 |
| 모델 신호의 한계 | 문서 유사도는 제로샷이라 미검증 | 기준값은 개발셋에서만 정하고 최종셋은 1회만 |
| 판별 시점 이후 변화 | 재판별에서 `document` 로 바뀜 | 게시 직전 재확인, 카드 상시 숨김 처리 경로 |
| 라벨·분포 편향 | 한국 서류·가족 환경과 다름, 평가자 오라벨 | 이중 라벨, 한국어 서류 포함, 불일치 사례 재검토 |
| 사용자 오확인 | (E0) 업로더가 문서를 일반 사진으로 확인 | E0 에서도 문서·안전 신호 재검사 후 카드에 포함 |

## 3. 평가 데이터 설계
- **분리:** 개발셋(자격 규칙·임계값 설계에 사용)과 **최종셋(봉인: 설계 담당이 내용을 보지 않고, 규칙 동결 뒤 1회만 실행)**. 최종셋 제작·라벨링 담당은 임계값 설정자와 다른 사람으로 한다. 두 셋의 출처·촬영자·장면이 겹치지 않게 한다.
- **부정 사례(문서) 카테고리 8종:** ① 영수증·결제 내역 ② 신분증·카드 ③ 처방전·진료·약 봉투 ④ 공문·안내문·계약서·가정통신문 ⑤ 책·인쇄물 쪽 ⑥ 스크린샷(채팅·은행·쇼핑·지도 앱) ⑦ 화이트보드·메모·손글씨 ⑧ 모니터·휴대폰 화면을 찍은 사진. 각 카테고리에 기울임·반사·저조도·부분 가림·저해상도·작은 글자·한글/영문/한자·여러 쪽 묶음·**이미지 속에 문서가 일부만 나온 경우**·**글자가 적은 문서**를 섞는다.
- **출처 축(따로 보고):** ① 실제로 촬영한 가짜 문서(종이 문서를 카메라로 찍은 것) ② 합성 렌더(가짜 개인정보로 만든 문서 이미지 + 증강) ③ 화면 캡처·가짜 계정 목업 ④ 라이선스를 확인한 공개 이미지(내부 평가 전용). 합성만으로는 실제 촬영의 노이즈·반사·구도를 대표하지 못하므로 ①을 비중 있게 확보한다. **실제 가족·개인 문서나 실제 개인정보는 쓰지 않는다.**
- **긍정 사례(일반 사진):** 공개 라이선스 사진과 합성 시나리오(풍경·음식·행사·실내 등)와 허용 범주(메뉴판·간판 등)를 포함해 사용성(자격 통과율)을 본다.
- **카드 단계:** 합성 앨범 시나리오(일반 사진에 문서를 ★1~10% 섞음)로 카드 생성까지 돌려 게시 누출을 센다.
- **표본 독립성:** 이미지 단위 평가와 합성 카드 단위 평가를 **구분해서 보고**한다. 합성 카드는 같은 이미지를 여러 앨범에 재배치해 만든 것이라 카드 수가 독립 표본 수가 아니다. 카드 단계의 유효 표본은 **서로 다른 원본 문서(여러 쪽은 한 건)·촬영 장면·촬영자의 수**로 센다. 같은 원본에서 파생한 변형은 하나의 군집으로 묶어 평가하고, 군집을 나눠 두 셋에 넣지 않는다.
- 합성과 실제 촬영 데이터의 지표는 따로 보고한다. 이후 동의받은 가족 파일럿은 그림자 모드(게시 없음)로 사후 사람 검토한다.

## 4. 기준: 개발 단계 검증 vs E1 최종 게이트

### 4-1. 개발 단계 검증 기준 (초기 개발 검증용, ★ 제안)
이 기준을 통과해도 **운영 자동 공개의 안전성이 입증된 것이 아니다.** 규칙·파이프라인이 최소한 작동하는지 확인하는 문턱이다.
| 기준 | 내용 | 통과 |
|---|---|---|
| D1 자격 누출 | 개발 최종셋 문서 부정 사례 ★400장(독립 원본 기준) 중 자격 통과 수 | 0건. 0/400 의 95% 단측 신뢰상한 ≈ **0.75%** |
| D2 카테고리별 | 8종 각 ★40장 | 각 0건. 0/40 의 95% 단측 상한 ≈ **7.22%**(카테고리별 통과는 안전성 입증이 아니라 결함 탐지용) |
| D3 카드 단계 | 합성 앨범 카드 ★300개(이미지 단위와 군집 독립성 구분 보고) | 문서 사진 게시 0건 |
| D4 신호 독립성 | 규칙의 각 신호를 하나씩 뺐을 때 누출 변화 보고 | 한 신호만 빼도 누출이 생기면 규칙 재설계 |
| D5 재현성 | 실행 설정·모델·규칙 버전 기록, 재실행 결과 동일 | 필수 |
- 신뢰상한은 단측 Clopper–Pearson(0건이면 1−0.05^(1/N))으로 계산해 보고한다. "표본에서 0건"은 위험 0이 아니다.

### 4-2. 사용성 지표 (안전성 기준이 아님)
- **일반 사진 자격 통과율**(★50% 이상을 목표로 보고)은 E1 이 E0 와 차이가 있는 가치가 있는지 보는 **사용성 지표**다. 안전성 합격 여부와 섞지 않는다. 낮으면 규칙을 재설계하되 안전 기준을 낮춰서 맞추지 않는다.

### 4-3. E1 최종 게이트 (미확정, 별도 정책 승인 필요)
- 아래 항목은 **별도 정책 승인 전까지 확정하지 않는다.** PR0 승인은 이 항목의 수치를 승인하지 않는다.
  1. **위험 허용 기준:** 자동 공개에서 허용할 문서 누출 위험(예: 카드당·사진당 허용 확률, 사고 1건의 영향 등급). 정하는 주체는 소유자·개인정보 검토.
  2. **독립 평가 규모:** 0건 관측 시 상한 U 를 보이려면 N ≥ ln(0.05)/ln(1−U) 장이 필요하다(참고 계산): U=1% → 약 300장, 0.1% → 약 3,000장, 0.05% → 약 6,000장. 위험 허용 기준에 맞는 U 와 평가 규모를 정책에서 정한다.
  3. **다양성 요건:** 실제 문서, 이미지 속 문서, 스크린샷, 글자가 적은 문서 등 여러 부정 유형을 **유형별 군집 기준**으로 충족(이미지 수가 아니라 서로 다른 원본·촬영자·장면 수).
  4. **카드 단계 증거:** 합성 카드가 아니라 서로 독립인 원본·장면 단위로 게시 누출을 측정하고, 동의받은 가족 파일럿 그림자 모드의 사후 사람 검토 결과를 포함.
  5. **운영 중 감시와 사고 대응**(7절) 포함.
- 고정 절차(E1 최종 게이트 확정 뒤): (1) 기준·규칙 버전 커밋과 승인 날짜 기록 (2) 개발셋으로만 임계값 설정 (3) 규칙 동결 커밋 (4) 최종셋 1회 실행 (5) 결과 그대로 보고. 불합격이면 최종셋으로 임계값을 조정하지 않고 원인 분석 후 규칙을 바꿔 **새 최종셋**으로 재평가.

## 5. 카드 품질 게이트 (E0 → E1 필요 조건, ★ 제안)
- 독립 사람 평가자 **2명 이상**(AI 평가 제외)이 최종 카드를 블라인드 평가한다.
- Q1 "만들 가치 없음" 판정 카드 ≤ ★20% · Q2 이벤트 잘못된 병합 ≤ ★10%(실제 촬영 이벤트 기준), 과도한 분리 ≤ ★20% · Q3 제목·이야기 사실 오류 **0**(전수 감사) · Q4 "다시 보고 싶다" 평균 ≥ ★3.5/5 · Q5 카드 간 사진 겹침(Jaccard>★0.5) 0쌍 · Q6 철회·제외·삭제 반영 시험 전부 통과 · Q7 주당 상한 준수 100% · Q8 처리 시간·메모리가 실제 운영 서버 사양에서 합의한 예산 이내.
- 사진 하나도 선정되지 않는 시나리오가 오류 없이 처리돼야 한다.

## 6. E0 → E1 체크리스트
1. 카드 품질 게이트 Q1~Q8 통과 2. 개발 단계 검증 D1~D5 통과 3. **E1 최종 게이트(4-3) 통과 — 별도 정책 승인으로 확정된 기준** 4. 동의받은 가족 파일럿 그림자 모드 ★4주(자격 판정만 기록, 게시 없음) 사후 사람 검토에서 누출 0 5. 개인정보 고지(T31·Play 데이터 안전 양식) 갱신 6. 즉시 중지 스위치·롤백 시험 7. 소유자 별도 승인 8. 단계 롤아웃(파일럿 가족 → 일부 → 전체, 단계마다 신고율·누출 점검).

## 7. 운영 중 안전
- 카드의 사진마다 "문서·개인정보가 있어요" 신고. 접수 즉시 카드 숨김 + 사진 분석 제외 + 기록.
- **누출 1건 확인 시 E1 자동 게시를 즉시 중지**하고 원인 분석 후 규칙을 바꿔 새 최종셋으로 재평가한다. 재개는 소유자 승인.
- 신고율·숨김률·카드당 사진 제외율을 주기적으로 본다(사진 내용은 보지 않고 건수만).

## 8. 미정
- E1 위험 허용 기준과 독립 평가 규모(4-3), 수치(★)의 최종값, 평가셋 제작 인력과 일정, 합성·촬영 문서 생성 방법, 가족 파일럿 규모·기간, 사고 대응 담당자.
