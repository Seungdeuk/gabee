# 설계: 1:1 대화에서도 AI 사용

> 상태: 초안(검토 대기). 구현 전에 이 문서를 확인받는다. 기반: `docs/features/family-chat.md`, `docs/features/ai_assistant-tab-agents.md`, `docs/adr/0011-ai-call-minimization.md`.

## 1. 목표와 결정 (사용자 결정, 2026-11-05)

- 사람과 사람의 **1:1 방**에서도 가족 전체방처럼 **AI 도우미(대화 분석·일정 후보·할 일 후보·답장 추천·대화 주제 추천)** 와 **`@가비` 호출**을 쓴다.
  - 이전 정책 "1:1 대화는 AI 로 보내지 않는다"(`docs/features/family-chat.md`, 2026-10-26 커밋 `7308ff1`)를 **바꾼다.** 1:1 대화 내용(상대 메시지 포함)이 AI 로 보내지는 것을 사용자가 허용했다.
- **동의 방식은 새로 만들지 않는다.** 동의 켜기·끄기 버튼과 설정은 없앴으므로(회원가입 때 동의를 받는다) 1:1 에도 새 동의 화면·설정·테이블을 두지 않는다. 지금 가족방이 쓰는 게이트(가족 AI 설정이 꺼져 있으면 분석을 누를 때 자동으로 켬, 하루 호출 한도·쿨다운, 동시 실행 제한)와 개인정보 가리기(`shared/privacy`, 가명화)를 **그대로** 쓴다.
- **일정 에이전트도 1:1 에서 쓴다. 단 공유는 상대 한 명에게만** 한다. 조회는 두 사람이 함께 가진 일정만 보여 준다.
- 1:1 방에 "AI 를 썼다"는 알림 줄은 넣지 않는다(동의 버튼이 없으므로 별도 표시도 만들지 않는다).

## 2. 지금 구조(확인한 것)

- 서버: `ai_repository.recent_messages(db, group_id, ...)` 가 `family_messages(group_id)` 로 **가족 전체방 메시지만** 읽는다(1:1 은 쿼리에 안 나옴). AI API 는 `/family-chat/ai/{preview,analysis,replies,topics}`(요청에 방 정보 없음). `@가비` 는 `POST /ai-assistant/chat` + `audience: "room"` 이고 답을 `family_chat/assistant.post_as_assistant(group_id, …)` 로 **가족 전체방에만** 저장한다.
- 일정 에이전트 방 모드(`channel="family"`): `reader.read` 가 `e.shared` 인 공동 일정만 읽고, `register.respond(share_all=True)` 가 공유 대상을 **가족 전체(나 제외)** 로 정하며, 습관은 공개 습관만, 부탁은 받는 분·수락 현황을 모델에게 주지 않는다.
- 앱: 1:1 방(`direct`)에서는 AI 도우미 버튼(✨, `ChatRoomScreen.js`)과 `@가비` 예시를 숨기고, `@가비` 로 시작하는 글은 "1:1 대화에서는 @가비를 쓸 수 없어요"(`DIRECT_NOT_ALLOWED`) 안내를 보인다.

## 3. 서버 설계

### 3.1 AI 도우미 API (분석·답장·주제·미리보기)

- 요청에 선택 필드 `room_id`(문자열, 없으면 가족 전체방)를 추가한다(`ai_schemas.py`).
- `ai_repository.recent_messages(db, group_id, limit, after_id, room_id=None)`: `room_id` 가 있으면 **그 방 메시지만** 읽는다. 읽기 전 service 에서 **호출한 사람이 그 방의 참가자이고 그 방이 이 그룹 소속인지** 확인한다(아니면 404, 방 존재를 드러내지 않는다). 1:1 방이 아닌 값은 가족 전체방과 같은 규칙으로 처리한다.
- 결과 캐시 키에 방 id 를 넣는다(분석 범위의 첫·마지막 메시지 id 와 개수는 그대로). 한도·동의·쿨다운은 사용자·그룹 기준 그대로다(방 단위 별도 한도는 만들지 않는다).
- 가명화에 쓰는 이름 사전(`member_names`)은 가족 구성원 전체 그대로(1:1 상대 이름도 포함된다).
- 가비의 답(`ASSISTANT_USER_ID`)과 지운 메시지는 분석에서 빼는 기존 규칙을 그대로 쓴다.

### 3.2 @가비 (`/ai-assistant/chat`)

- 요청에 선택 필드 `room_id` 를 추가한다(`audience: "room"` 일 때만 의미). 1:1 방이면 위와 같은 참가자 확인 뒤, 답을 그 1:1 방에 가비 이름으로 저장한다(두 사람에게만 보인다). 저장 규칙(카드·제안이 딸린 답, AI 가 답하지 못한 안내는 저장하지 않음)은 가족방과 같다. 개인 대화(`audience: "me"`)는 변하지 않는다.
- `family_chat/assistant.post_as_assistant` 와 `shared/room_assistant.post` 에 대상 방 인자(`room_id`, 없으면 가족 전체방)를 추가한다. 가비 계정은 1:1 방의 참가자가 아니므로, 방 메시지 조회가 **보낸 사람이 아니라 보는 사람의 참가 여부**로 접근을 정하는지 구현 때 확인하고 시험한다(가비 메시지가 제3자에게 보이면 안 된다).
- 메인 에이전트의 도구 중 가족 데이터(정산·돌봄·기록)는 가족 단위라 1:1 에서도 같게 쓴다.

### 3.3 일정 에이전트(1:1 모드)

- `AgentRequest` 에 선택 필드 `peer_id`(1:1 상대 id)를 추가한다. `peer_id` 가 있으면 방 모드(`channel="family"`)에 더해 아래를 적용한다.
  - **조회**: `reader.read` 에서 `e.shared_ids` 에 `peer_id` 가 있는 일정만 읽는다(상대와 공유되지 않은 공동 일정, 나 혼자 일정은 1:1 답에 나오지 않는다).
  - **등록 공유 대상**: `register.respond(share_all=True)` 의 대상을 `[peer_id]` 하나로 한다(가족 전체 아님). 확인 카드의 "공유 대상"·제목도 상대 한 명으로 나온다.
  - 부탁(`request_*`): 받는 사람 후보를 상대 한 명으로 제한한다. (구현 때 `request_flow` 의 수신자 결정 지점을 확인해 상대 한 명만 허용한다.)
  - 프롬프트 문구: `FAMILY_NOTICE` 의 "가족 채팅방" 표현을 1:1 에서는 "1:1 대화방(상대 한 명)"으로 바꾼다.
- 확인 카드의 확인 요청(`POST /schedule/agent/confirm`)에 선택 필드 `room_id` 를 추가해, `post_to_room: true` 일 때 결과 알림을 **그 방**(1:1 이면 그 1:1 방)에 올린다. 알림 문장은 1:1 이면 "…등록하고 상대에게 공유했어요." 로 서버가 만든다(제목 한 줄 30자 제한 등 기존 안전장치 그대로).
- 공유 대상이 상대 한 명이라는 것은 **서버가** 다시 검증한다(확인 요청의 초안 `share_ids` 는 클라이언트가 돌려주는 값이므로, `room_id` 가 1:1 이면 `share_ids` 를 상대 한 명으로 강제한다).

### 3.4 개인정보·권한 정리

- 1:1 내용이 AI 로 가는 것은 **호출한 사람이 눌렀을 때만**이다(자동·일괄 분석 없음).
- 호출자가 그 방 참가자가 아니면 거부, 다른 그룹·다른 1:1 방 메시지는 읽지 않는다.
- 1:1 AI 결과(분석 캐시)는 사용자·방 기준으로만 재사용한다(다른 사람 요청에 섞이지 않게 캐시 키에 사용자와 방을 포함한다. 기존 캐시 키가 그룹 단위라면 사용자까지 넣는지 구현 때 확인한다).
- 가명화(`shared/privacy`) 규칙은 가족방과 같고, `required` 모드에서 엔진을 못 쓰면 요청을 보내지 않는다.

## 4. 앱 설계

- `ChatRoomScreen`: 1:1 방에서도 AI 도우미 버튼(✨)을 보이고 `AiPanel` 에 `roomId` 를 넘긴다. `@가비` 입력 예시(`mentionHintsVisible`)와 호출(`parseMention`)을 1:1 에서도 허용하고 `DIRECT_NOT_ALLOWED` 안내는 지운다.
- `api.js`: `analyzeChat`·`askAssistantInRoom` 등에 `roomId` 를 실어 보낸다(가족방은 없음 → 이전과 같은 요청). `ScheduleConfirmCard` 가 확인 요청에 `room_id` 를 같이 보낸다(`postToRoom` 이 켜진 카드만).
- `AiPanel`: 후보 등록(일정·할 일 후보)은 가족방과 같다. 1:1 에서 "할 일 후보 → 함께하기" 받는 사람 규칙(`candidateToRequestBody`)은 1:1 에서 상대 한 명으로 한다(구현 때 확인).
- 1:1 방에서 AI 를 처음 쓸 때 별도 안내·동의 화면은 없다.

## 5. 문서·시험

- 문서: `docs/features/family-chat.md`("1:1 대화는 AI 로 보내지 않는다" 줄을 바꾸고 결정 기록), `docs/features/ai_assistant-tab-agents.md`(1:1 모드·공유 대상), `docs/requirements/family-chat.md`·`schedule-agent.md`, `docs/contracts/openapi.json`(`room_id`·`peer` 필드).
- 서버 시험: 참가자 아닌 사람 거부(분석·@가비·확인 알림), 1:1 분석이 그 방 메시지만 읽고 가족방·다른 1:1 방과 섞이지 않음, 캐시가 방·사용자별로 분리, @가비 답이 올바른 1:1 방에 저장되고 제3자·다른 방에서 안 보임, 일정 조회가 상대와 공유된 일정만, 등록 공유 대상이 상대 한 명(초안의 `share_ids` 를 바꿔 보내도 강제), 확인 알림이 올바른 방에 올라감, 기존 가족방 동작 그대로.
- 앱 시험: `roomId` 전달, 1:1 에서 버튼·예시 노출, 가족방 요청은 이전과 같은 본문.

## 6. PR 분할

1. **AI 도우미(분석 등) 1:1** — 서버 3.1 + 앱 AI 패널 + 문서·시험.
2. **@가비 1:1(질의응답)** — 서버 3.2 + 앱 멘션 + 문서·시험.
3. **일정 에이전트 1:1** — 서버 3.3 + 앱 확인 카드 + 문서·시험.

각 PR 은 독립으로 병합할 수 있게 하되 2는 1과, 3은 2와 코드가 겹친다. **쌓은 PR 은 앞 PR 을 병합한 뒤 다음 PR 의 기준 브랜치를 `release/1.2` 로 직접 바꿔야 하므로**(자동으로 안 바뀐다) 순서대로 올리고 병합한다.

## 7. 구현 때 확인할 열린 질문 (설계 승인과 별개)

- 가비 메시지가 1:1 방 조회에서 참가자에게만 보이는지(보낸 사람이 방 참가자가 아닌 경우).
- 분석 캐시 키의 현재 단위(그룹/사용자)와 1:1 에서 사용자·방 분리 방법.
- `request_flow` 의 부탁 수신자 결정 지점과 1:1 에서 상대 한 명 제한 방법.
- 1:1 방 참가자 확인 함수(기존 방 조회 헬퍼 재사용 가능 여부).
- 개인정보: 상대가 가족을 나갔는데 1:1 방이 남아 있는 경우(기존 한계) AI 를 계속 쓸 수 있는지(나간 사람 메시지·방 접근 규칙).
