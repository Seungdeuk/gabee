# 설계: 앱 푸시 알림 (Expo 푸시 서비스 경유)

> 상태: 초안 2(검토 대기). 이 문서는 **1단계(기반)** 의 설계이고, 전체 단계는 9절에 있다. 요구사항 `docs/requirements/notifications.md`는 "폰 푸시는 범위 밖"이라 이 설계가 승인되면 함께 고친다.
> 기반: 알림함(`app/shared/notifications.py` `notify()`, 2026-10-28 설계 `2026-10-28-notifications-design.md`).

## 1. 목표와 확인한 이해

- 알림함에 새 알림이 생기면 앱이 꺼져 있거나 다른 화면에 있어도 **폰에 푸시**가 온다.
- 푸시는 알림함을 **대체하지 않고 추가**한다. 같은 사건·같은 문구를 쓰고, 푸시를 누르면 앱이 열려 알림함으로 간다.
- 푸시가 실패해도 알림함 저장과 원래 기능(일정 보내기, 문의 답변 등)은 영향받지 않는다.
- 확인 환경: 팀은 안드로이드 폰, 작성자는 iOS 라 BlueStacks(안드로이드 에뮬레이터). **Expo Go 에서는 안드로이드 원격 푸시가 SDK 53 부터 안 되므로 development build(EAS) 가 필요하다.**

## 2. 범위 밖 (이번에 하지 않는다)

- iOS 푸시(Apple 개발자 계정·APNs 설정이 정해지면 같은 코드로 확장. 이번에는 안드로이드만 확인한다).
- 시간 기반(예약) 푸시(일정 시작 전·할 일 마감·정산 기한 — 4단계), 소통 메시지 푸시(2단계), 푸시에 이미지·버튼.
- 푸시 영수증(receipts) 후속 조회. 이번에는 발송 응답(tickets)의 `DeviceNotRegistered` 만 처리한다.
- 웹(`Platform.OS === "web"`)은 등록하지 않는다.

## 3. 개인정보 규칙 (필수)

- **알림함 사건**(가입·고객센터 답변·일정 같이해요 등)은 알림 제목(고정 템플릿)만 푸시한다. `body` 는 보내지 않는다. 금액·장소·건강 정보·AI 요약은 담지 않는다.
- **소통 메시지 푸시(2단계)는 사용자 설정 `preview_mode` 를 따른다. 기본값은 `full`(사용자 결정, 2026-11-05).**
  - `full`: 제목 = 보낸 사람 이름, 본문 = 메시지 원문 앞부분(최대 100자). 사진·파일은 원문 대신 "사진을 보냈어요" 같은 종류만.
  - `sender`: 제목 = 보낸 사람 이름, 본문 = "새 메시지가 도착했어요".
  - `hidden`: "새 메시지가 도착했어요"만.
- 소통 메시지는 푸시 내용을 암호화하고 민감정보 값을 가린 뒤 보낸다(아래 "결정: 소통 메시지 푸시는 암호화…" 절). 그래도 푸시가 Expo 푸시 서비스와 구글(FCM)을 거치는 것은 같으므로 완화책:
  - 방 구성원 권한을 확인한 받는 사람의 토큰으로만 보낸다. 1:1 은 대화 참가자에게만 보낸다.
  - 문구는 서버에 저장하지 않고 로그에 남기지 않는다(알림함 저장도 소통 메시지는 하지 않는다).
  - 권한 요청 전에 "알림에 메시지 내용이 보일 수 있어요. 마이 > 알림 설정에서 바꿀 수 있어요" 를 안내한다.
  - 사용자가 설정에서 `sender`·`hidden` 으로 바꾸거나 알림을 끌 수 있다.
- `data` 에는 이동용 `notification_id`(있으면), `kind`, `event`, 대상 id 만 넣는다.
- 이 외부 경유는 ADR 로 남긴다. 사용자는 "A 방식으로 진행"이라고 답했지만 의존성 추가·EAS 빌드 사용은 따로 확인하지 못했으므로 이 설계 검토에서 다시 확인받는다.
- 푸시 토큰은 기기 식별자라 로그에 남기지 않는다(앞 6자리만 남긴다).

## 4. 서버 설계

### 4.1 데이터: `push_tokens` (Alembic 새 리비전, expand 만)

| 컬럼 | 설명 |
|---|---|
| `id` | PK |
| `user_id` | FK users, 인덱스. 한 사용자가 여러 기기를 가진다 |
| `token` | Expo 푸시 토큰(`ExponentPushToken[...]`), **유니크**. 같은 기기에 다른 사용자가 로그인하면 소유자를 옮긴다(upsert) |
| `platform` | `android` / `ios` |
| `device_label` | 선택(로그인 기기 이름과 같은 값) |
| `created_at`, `last_seen_at` | 등록·마지막 갱신 시각 |

- 가족(그룹)과 무관한 개인 데이터라 `group_id` 가 없다.

### 4.1b 데이터: `push_settings` (같은 리비전, 사용자당 한 줄)

| 컬럼 | 설명 |
|---|---|
| `user_id` | PK, FK users |
| `enabled` | 전체 푸시 켜기·끄기(기본 켬) |
| `preview_mode` | `full`(기본) / `sender` / `hidden` — 소통 메시지에만 쓴다 |
| `muted_kinds` | 끈 알림 분류 목록(JSON, 예: `["billing"]`). 기본 빈 목록 |
| `quiet_start`, `quiet_end` | 방해금지 시간(앱 로컬 시간대, 둘 다 비면 없음) |
| `updated_at` | 갱신 시각 |

- 줄이 없으면 기본값으로 본다(조회 때 만들지 않는다). `GET`·`PUT /notifications/push-settings`.
- 방해금지 시간에는 푸시를 **보내지 않는다(억제)**. 알림함에는 그대로 남는다. 예약해서 나중에 보내는 것은 4단계 이후 검토한다.
- `schema.py` 의 기능 등록(`SHARED_MODEL_FEATURES`)에 이 테이블을 쓰는 기능을 등록한다.

### 4.2 API (새 `features/notifications` 에 추가, 요청·응답은 Pydantic)

- `PUT /notifications/push-token` `{token, platform, device_label?}` → 204. 로그인 사용자 기준으로 upsert(소유자 이동 포함). 토큰 형식(`ExponentPushToken[`·`ExpoPushToken[` 로 시작) 검증, 아니면 422.
- `DELETE /notifications/push-token` `{token}` → 204. 본인 소유 토큰만 지운다(없으면 그냥 204).
- 로그아웃 때 앱이 먼저 위 DELETE 를 부른다(서버 `logout` 에 끼워 넣지 않는다 — 기존 인증 코드를 건드리지 않기 위해).

### 4.3 발송: `app/shared/push.py` (새 파일)

- **공통 차단 규칙**(발송 직전에 받는 사람마다 적용): 푸시 꺼짐(`enabled`)이거나 해당 분류가 `muted_kinds` 에 있으면 제외, 방해금지 시간이면 제외, 발신자 본인 제외, 구성원·접근 권한이 없으면 제외, 같은 사건·같은 받는 사람 중복은 한 번만. (보고 있는 같은 방 제외는 2단계.)
- `notify()` 는 알림 한 줄을 저장한 뒤, **그 세션에 "보낼 푸시" 목록**(`db.info["pending_push"]`)에 받는 사람·제목·`data` 를 쌓기만 한다.
- 세션 `after_commit` 이벤트에서 그 목록을 꺼내 **백그라운드 스레드**로 발송한다. 커밋이 안 되거나 롤백되면 푸시도 나가지 않는다(알림은 없는데 푸시만 가는 일이 없다).
- 발송: `httpx` 로 `POST https://exp.host/--/api/v2/push/send`(한 번에 최대 100개, 제목만, `channelId="default"`, `priority="high"`). 타임아웃 5초, 재시도 없음.
- 응답 tickets 에서 `details.error == "DeviceNotRegistered"` 인 토큰은 `push_tokens` 에서 지운다(별도 세션).
- 어떤 오류도 호출 쪽으로 던지지 않는다(로그에는 종류만, 토큰·문구 제외).
- 설정: `PUSH_ENABLED`(기본 **false**, `ops_errors_enabled` 와 같은 방식). 꺼져 있으면 토큰 등록 API 는 동작하지만 발송은 하지 않는다. 새 환경변수는 `.env.example` 에만 추가한다. 선택 `PUSH_EXPO_ACCESS_TOKEN`(Expo 계정에서 푸시 보안을 켰을 때만).
- `notify(group_id=None, …)` 개인 알림(고객센터 답변)도 같은 경로로 푸시한다.

### 4.4 시험

- 토큰 등록·소유자 이동·삭제·형식 오류·다른 사용자 토큰 삭제 불가. 설정 기본값·저장·잘못된 값(422)·방해금지 시간대 제외·끈 분류 제외.
- 발송은 `httpx` 를 가짜로 바꿔서: 커밋 후에만 호출, 롤백이면 호출 없음, 본인 제외, 제목만 담김(본문·금액 문자열 없음), `DeviceNotRegistered` 토큰 삭제, 발송 오류가 호출 쪽에 안 번짐, `PUSH_ENABLED=false` 면 호출 없음.

## 5. 앱 설계

- 의존성: `npx expo install expo-notifications`(새 의존성, 사용자 승인). `app.json` `plugins` 에 `expo-notifications` 추가(안드로이드 알림 색 `color` 는 `theme` 토큰값과 같은 hex 하나). `expo-device`·`expo-constants` 는 이미 있다.
- `features/notifications/push.js`(순수 함수와 얇은 래퍼) + `usePushRegistration.js`:
  1. 로그인 상태에서만, 실제 기기일 때만(`Device.isDevice`, 에뮬레이터는 시도하되 실패를 삼킨다) 안드로이드 채널 `default` 를 만들고 권한을 요청한다.
  2. 허용되면 `getExpoPushTokenAsync({ projectId })`(`projectId` 는 `app.json` `extra.eas.projectId`) 로 토큰을 받아 `PUT /notifications/push-token`.
  3. 거절·실패는 조용히 넘기고 앱 사용에는 영향이 없다(알림함은 그대로).
  4. 로그아웃 시 `DELETE /notifications/push-token` 을 먼저 부른다.
- 푸시를 누르면 `/notifications` 로 이동한다(분류별 상세 이동은 `routeFor` 확장과 함께 후속).
- 앱이 켜져 있을 때 푸시가 오면 상단 배너로 보이게 하고 안 읽은 개수를 다시 읽는다(10초 폴링 PR 과 별개로 즉시 반영).
- 서버 호출은 `features/notifications/api.js` 에서만, JSDoc 필수, 하드코딩 색 금지, 시험은 `tests/` 순수 함수 위주.

## 6. 환경·빌드 (코드 밖에서 사람이 할 일)

- 안드로이드 FCM 자격: Firebase 프로젝트와 FCM 서비스 키를 EAS 에 올린다(`eas credentials`). **누가 Firebase 프로젝트를 소유할지 팀 결정이 필요하다.** 서버에는 비밀 키를 두지 않는다.
- development build: `eas build --profile development --platform android` 로 APK 를 만들어 팀 폰과 BlueStacks 에 설치한다. Metro 는 `EXPO_OFFLINE=1` 로 기존대로 붙인다.
- 이 PR 들은 자격 없이도 병합 가능하다(`PUSH_ENABLED=false` 가 기본이라 운영 동작은 그대로).

## 7. PR 분할(1단계) (각 약 400줄 이하, 한 목적)

1. **서버 A**: `push_tokens`·`push_settings` 리비전 + 모델·`db.md`, 토큰 등록·해제와 설정 조회·저장 API(+`openapi.json`), 시험, 요구사항 갱신, ADR.
2. **서버 B**: `shared/push.py` 발송·정리, 공통 차단 규칙, `notify()` 연결, `PUSH_ENABLED`·`.env.example`, 시험, 문서.
3. **앱**: `expo-notifications` 추가·`app.json` 플러그인, 등록·해제·탭 이동, 마이 > 알림 설정 화면(켜기·끄기, 분류, 내용 표시 방식, 방해금지), 시험, 문서.
4. **(별도, 이미 합의)** 10초 폴링 PR.

서버 PR 이 먼저 병합돼야 앱 PR 의 등록 API 호출이 동작한다. 마이그레이션은 임시 PostgreSQL 에서만 검증하고 공용 DB 는 통합 때 DB 담당자가 반영한다.

## 결정: 소통 메시지는 알림함에 저장하지 않고 푸시만 보낸다 (사용자 결정, 2026-11-05)

- 요구사항 "소통 메시지 알림은 제외"와 같은 방향이다(알림함은 지난 사건 기록, 메시지는 채팅방에서 본다).
- 그래서 `shared/push.py` 에 알림함 저장이 없는 **푸시 전용 함수**(`push_only`)를 둔다. `notify()` 는 알림함 저장 + 푸시, `push_only()` 는 푸시만. 두 함수는 같은 공통 차단 규칙과 발송기를 쓴다.
- 푸시 전용이라 읽음·안 읽은 수는 채팅의 기존 읽음 기록을 쓰고, 알림함 개수에는 더하지 않는다.
- 푸시를 누르면 알림함이 아니라 해당 채팅방으로 이동한다(`data` 에 `kind=chat`, 방 id. 2단계 설계에서 정한다).

## 결정 변경(2026-11-06, 사용자 결정): 소통 메시지 푸시는 암호화 없이 고정 문구만 보낸다

아래 두 결정(암호화 + 마스킹, `preview_mode` 로 내용 보이기)은 **이 결정으로 대체됐다**(이력으로 남긴다).
- 푸시는 **"새 메시지가 도착했어요" 한 문구**만 보낸다. 제목은 그 문구, 본문은 없고 보낸 사람·내용·방 이름·파일 이름을 싣지 않는다. `data` 에는 이동용 `kind=chat`·`room_id` 만 넣는다(1:1 상대는 앱이 방 목록으로 찾는다).
- 실제 메시지는 앱을 연 뒤 HTTPS + 인증 API 로 읽는다. 그래서 푸시 암호화·민감정보 마스킹·새 암호 라이브러리(PyNaCl·tweetnacl)는 **지금 도입하지 않는다**. 메시지 미리보기 암호화가 필요해지면 그때 PyNaCl + tweetnacl 조합을 검증한다.
- 받는 사람: 방 참여자(가족방은 구성원 전원, 1:1 은 상대)에서 보낸 사람·방 알림을 끈 사람·푸시/분류(`chat`)/방해금지를 끈 사람을 뺀다. 알림함에는 남기지 않는다(`push_only`).
- 합치기: 같은 묶음 번호(`batch_id`)의 사진은 첫 사진에서만, 같은 사람이 같은 방에 보낸 글은 10초 칸마다 첫 글에서만 푸시한다(고정 칸이라 칸이 바뀌면 다시 푸시). 같은 방의 푸시는 방 id 를 합치기 키(안드로이드 `tag`, iOS `collapseId`)로 붙여 잠금 화면에서 한 건으로 교체된다.
- 이번 단계에서 뺀 것: 지금 보고 있는 방 제외(앱이 켜져 있을 때 오는 푸시는 상단 배너로 보이고 보고 있는 방은 앱이 숨기는 방식으로 후속), @가비 답변 푸시, `preview_mode` 연동(설정 화면의 "메시지 내용 표시 방식"은 정리 대상).

## (대체됨) 결정: 소통 메시지 푸시는 암호화해서 보내고(방법 1), 민감정보 값만 가린다 (사용자 결정, 2026-11-05)

이 결정은 **2단계(소통)** 에 적용된다. 1단계의 알림함 사건(고정 제목)은 민감하지 않으므로 일반 푸시(제목+본문)로 보낸다.

- **암호화(방법 1)**: 기기가 로그인할 때 키 한 쌍을 만들고 **공개키만** `push_tokens` 에 등록한다. 서버는 소통 메시지 푸시를 그 공개키로 암호화한 **데이터 전용 푸시**(제목·본문 없음, 암호문만 `data` 에)로 보내므로 Expo·구글은 암호문만 본다. 앱이 푸시를 받아 개인키로 풀고 로컬 알림을 띄운다. 우리 서버는 채팅을 평문으로 가지고 있으므로 @가비 등 서버 기능은 영향이 없다.
- **민감정보 마스킹**: 암호화하기 **전에** `shared/privacy` 의 `detect()` 로 전화번호·이메일·주소·주민번호·카드·계좌·비밀번호(인증번호)의 **값만** `(연락처)` `(이메일)` `(주소)` `(주민번호)` `(카드번호)` `(계좌번호)` `(비밀번호)` 로 바꾼다. 이름은 그대로 둔다. 마스킹을 먼저 하고 100자로 자른다(숫자가 중간에서 잘려 탐지를 피하는 것을 막는다).
- **위험(감수)**: 데이터 전용 푸시는 앱이 꺼진 상태에서 코드가 실행되어야 해서 제조사 배터리 절약 기능에 막히면 알림이 늦거나 안 올 수 있다. iOS 는 별도 네이티브 확장이 필요해 범위 밖이다. 마스킹은 규칙 기반이라 놓치는 값이 있을 수 있다.
- **새 의존성(2단계 설계에서 승인 필요)**: 서버 암호 라이브러리(예: PyNaCl)와 앱 암호 라이브러리(예: tweetnacl). 직접 만든 암호 코드는 쓰지 않는다. 승인 전에는 추가하지 않는다.
- 설정 `preview_mode`(`full`/`sender`/`hidden`)는 복호화 뒤 알림에 무엇을 보일지를 정한다. 기본 `full`.

## 8. 열린 질문


- 안드로이드 FCM 키를 올릴 Firebase 프로젝트 소유자(팀 결정).
- BlueStacks 에서 푸시 토큰 발급·수신이 되는지(해 봐야 안다). 안 되면 팀의 실제 안드로이드 폰을 확인 기준으로 한다.
- 기본 ADR 번호는 구현 직전에 `git fetch` 후 가장 큰 번호 + 1 로 정한다(현재 목록 최대 0011).

## 9. 전체 단계(후속 설계서는 단계마다 따로)

| 단계 | 내용 | 비고 |
|---|---|---|
| 1 | 기반(이 문서): 토큰·설정·발송. 기존 알림함 사건(가입 요청·승인, 고객센터 답변, 일정 같이해요)을 푸시로 | 전체 흐름 검증 |
| 2 | 소통(P0): 가족방·1:1·멘션·사진/파일, 보고 있는 방 제외(서버가 활성 방을 알아야 함), 방 알림 끄기 설정 연동, @가비 답변(조건부) | `preview_mode` 사용, 알림함 저장 안 함 |
| 3 | 일정 즉시 알림: 새 일정·날짜 변경·취소(사소한 수정 제외)·할 일 배정 | 새 일정과 시작 전 알림은 분리 |
| 4 | 예약 푸시: `scheduled_pushes` 테이블 + 주기 작업. 일정 시작 전(일정에 알림 시각 필드 필요)·할 일 마감·정산 기한. 일정이 바뀌거나 취소되면 예약 줄을 갱신·삭제 | Expo 에 예약 기능이 없어 직접 관리 |
| 5 | 나머지: 가족 문서함(공유·확인 요청·기한), 정산 요청·완료, AI 작업·리포트, 보안 이벤트(최소 문구) | 코드에 있는 기능만 연결, 없는 기능은 제외 |
