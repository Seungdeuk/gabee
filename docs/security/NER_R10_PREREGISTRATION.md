# NER R10 사전 등록 (D1P·B1·C2·신규 이름 개선 — 학습 시작 전에 커밋, 이후 결과를 보고 기준을 바꾸지 않는다)

버전 r10-1.0, 2026-11-20. 범위: 가족 채팅방 개인정보(PERSON) 탐지·가명화와 소통 에이전트의 KoELECTRA-small NER. 정책 r9-1.1(한 글자 이름 제외, PERSON_ALIAS 는 별명 자체만, 이름+가족호칭은 이름 부분만 PERSON)을 유지한다. **이 문서 작성 시점에 R10 학습·파일럿·독립 평가는 실행하지 않았다.** 기준을 바꿔야 하면 변경 사유·시점을 별도 절로 남기고 바꾸기 전 기준의 결과도 함께 보고한다.

관련 문서: 독립 평가셋 설계 `NER_R10_EVALSET_SPEC.md`, 모델 분리 설계 `NER_R10_MODEL_SEPARATION_DESIGN.md`, R9 규격 `NER_R9_COMMON_SPEC.md`, R9 사전 등록 `NER_R9_PREREGISTRATION.md`, R9 결과 `NER_R9_FINAL_REPORT.md`.

## 1. 출발점과 보존

- 기준선(서비스): `v2b-koelectra-small-klue10-s7`, 지문 `46210943c45f`, 원래 디코더. 운영 모델 교체·배포는 이 문서 범위 밖이다.
- R9 최종 후보 F-full 시드 13(ONNX `997191d7874ca3d71e3030e232d566daafa2cd8c7f36d9cceb2cadb2447a9bdf`)은 독립 평가에서 노출·F1 을 개선했으나 스트레스 유형 D1P 노출이 16.0→20.0%(+4.0%p)로 악화되어 사전 등록 조건 5를 충족하지 못했고 운영 모델은 교체하지 않았다.
- **R9 봉인 평가셋은 열지 않고 재평가·학습·튜닝·후보 선정에 쓰지 않는다.** R10 생성기는 봉인 경로를 코드에서 참조하지 않으며(`build_r10_data.py` 의 `Guards10`), R9 문장·정답은 학습 데이터에 쓰이지 않는다. R9 결과는 개선 **방향**(유형)을 정하는 데만 썼다. R9 모델·산출물은 수정하지 않는다(R9 후보 모델은 비교 대상 `R9F` 로 읽기만 한다).
- 연구는 별도 worktree(`gabee-ner`, 브랜치 `feature/seungdeuk-ner-improve2`)에서만 한다. 운영 코드·푸시·PR·병합·배포 없음. ACCOUNT·공통 전송 래퍼·OCR·메인 AI 이미지 작업은 이번 범위가 아니다.

## 3. 학습 데이터 설계 (신규 `r10_full_train` 2,100행 + 모니터링 379행)

### 3-1. R9 학습 구성에서 확인한 D1P 약점 가설 (학습 데이터 통계에서 계산한 사실만)

R9 신규 데이터의 D1P 계열은 사람 쪽(`D1p`) 틀 35개(120행, F-full 신규 중 3.8%)에 비해 명사 쪽(`D1n`+`D1w`) 320행으로 사람:명사가 1:2.7이었고, 두 쪽은 같은 뼈대의 최소 대조쌍이 아니었다. 명사형 이름 단어 풀도 작았다(R10 생성기의 같은 기준으로 학습 분할에서 쓸 수 있는 단어가 28개뿐, 800행을 이 28개로 채우면 단어 암기가 된다). 이것은 **가설**이며 R9 봉인 결과로 검증한 원인이 아니다(원인 분석은 R9 에서 하지 않았다). R10 은 이 가설을 반증할 수 있게 D1P 쌍 구성을 따로 귀속 분석한다(§4).

### 3-3. 신규 이름 규칙과 이름 풀 분리

- **R10 개발셋 예약 구간**: 이름 부분 해시(`sha256("r10dev:"+이름) mod 5 == 0`)인 이름·단어는 R10 학습에서 쓰지 않고 R10 개발셋 전용이다.
- **R9에서 쓴 이름 부분**(R9 학습·검증 데이터의 PERSON·PERSON_ALIAS 값과 그 이름 부분)은 R10 학습의 일반 이름 생성에서 제외한다(명사형 이름 단어 D1P 풀은 의도적으로 R9 와 겹칠 수 있다: 같은 단어를 사람/명사 문맥에서 구분하는 것이 목적).
- 확장 명사형 이름 단어 목록을 R10 에 추가해 D1P 단어를 **128개**로 늘렸다(각 단어 최대 4회 사용).
- 신규 이름(unseen) 정의는 `NER_R10_EVALSET_SPEC.md` §3 과 같다(이름 부분이 참조 집합에 없고 길이 3 이상 부분 문자열 포함 관계도 아님).

## 4. 실험군·대조군 (모든 군 시드 7·13·21·42·99, 시드 추가·교체 금지, 실패한 실행은 재시작하지 않고 보고)

**용어 구분(R9 의 C0 와 혼동 금지)**: R9 의 **C0** 는 "R9 신규 데이터 없이 기존 데이터를 반복해 F-full 과 같은 행 수로 맞춘 볼륨 대조군"이었고 **R10 에서는 쓰지 않는다.** R10 의 볼륨 대조군은 **C10** 이며 기반 데이터가 R9F(= 기존 4,220 + KLUE 469 + R9 신규 3,126)다.

| 군 | 학습 데이터 | 행(KLUE 469 포함) | 역할 | 학습 |
|---|---|---:|---|---|
| S0 | 서비스 v2b(구정책 학습) | - | 기준선 | 안 함 |
| **R9F** | 기존 4,220 + R9 신규 3,126 + KLUE 469 (= R9 F-full 이 쓴 데이터) | 7,815 | R10 의 직접 출발점(R10-full − R9F = R10 신규 데이터와 그에 따른 스텝·KLUE 비중 변화의 합) | **R9 의 5시드 모델 재사용**(재학습 없음) |
| **C10** | R9F 데이터 + R9F 의 재라벨 안 된 비KLUE 행에서 시드별 비복원 추출 2,100행(`c10_extra_s{seed}`, 시드 `seed*1000+31`) | 9,915 | **볼륨·스텝 대조군**: R10-full 과 행 수·에폭당 스텝·KLUE 비중·재라벨 행 수가 같고 **새 내용이 없다** | 5시드 |
| **R10-full** | R9F 데이터 + `r10_full_train` 2,100 | 9,915 | **후보 선정 자격이 있는 유일한 군** | 5시드 |
| R10-D | R9F + D1P 쌍 400행(200 (쌍,단어) 묶음) | 8,215 | 귀속(보고용): 쌍 대조 학습 효과 | 5시드 |
| R10-BC | R9F + B1 200 + C2 200 | 8,215 | 귀속: 경계(B1·C2) | 5시드 |
| R10-N | R9F + 신규 이름 메신저 400 | 8,215 | 귀속: 신규 이름 일반화 | 5시드 |
| C10s | R9F + R9F 에서 추출한 400행(= C10 추가 2,100의 앞 400, 부분집합) | 8,215 | R10-D/BC/N 의 볼륨·스텝 대조군(R10-D 는 562행이 아니라 400행으로 맞춤) | 5시드 |

> R10-D 는 사람·명사 400행 + R9F 7,815 = 8,215행이다. 초기 점검에서 쌍 단위 추출이 562행이 되는 오류를 발견해 (쌍,단어) 묶음 단위(200묶음=400행)로 고쳤고, 고친 뒤 점검 결과(`r10_validation/r10_arm_precheck.json`)로 확인했다.

- 사전 점검 확인(학습 없이 데이터·스텝만): C10 과 R10-full 은 행 수 9,915·KLUE 469(4.73%)·에폭당 310스텝·총 최대 2,480스텝·워밍업 248·재라벨 행 292가 같다. C10s 와 R10-D/BC/N 은 행 8,215·에폭당 257스텝으로 같다. C10 추가 행 중 R10 신규 행은 0이다. 복사한 R9 데이터 파일은 원본과 해시가 같다(`copied_identical_to_r9`).
- 귀속 계산: 데이터 효과 = R10-full − C10, 버킷 효과 = R10-D/BC/N − C10s, 정책·볼륨 효과는 R9 에서 이미 분리했으므로 R10 에서 다시 하지 않는다. R9F 대비 R10-full 개선은 **신규 R10 내용이 아니라 단순 볼륨·스텝 증가 때문일 수 있으므로 C10 과 비교**한다.
- 총 학습 30회(R10-full 5 + C10 5 + 귀속 15 + C10s 5), 1회 약 2~3분 추정(행 수 R9 의 약 1.3배), GPU 3050 6GB 에서 VRAM 약 0.8~1GB(R8·R9 실측 기준). 파일럿으로 자원을 먼저 점검한다(**지금은 학습·파일럿을 실행하지 않았다**).

## 5. 비교 조건 고정 (모든 학습군 동일)

- 사전학습 체크포인트 `monologg/koelectra-small-v3-discriminator` 에서 처음부터. max_len 128, batch 32, lr 5e-5, 최대 8에폭, patience 2, warmup 10%, weight decay 0.01, fp16. 체크포인트(에폭) 선택은 `baseline_val` 겹침 F1 하나만.
- **KLUE**: 절대량 469행 고정(시드별 같은 표본, 모든 군 같은 입력 순서). 군별 KLUE 비중은 R9F 6.0% → C10·R10-full 4.73%, C10s·R10-D/BC/N 5.71%로 달라지지만 **C10 과 R10-full 이 같다.** KLUE 비중 하락(6.0→4.73%)이 일반 도메인 성능에 미치는 영향은 R9F 와의 비교에서 섞이므로 C10 비교로 분리한다(KLUE 오탐 보고).
- 라벨 정책 r9-1.1. 신규 학습 파일은 규격 검증기를 통과한 것만 쓴다.
- 신규 검증 행(모니터링 379행)은 학습 곡선·과적합 확인용이며 체크포인트 선택·후보 선정에 쓰지 않는다.
- 학습 스텝은 에폭당 스텝과 LR 스케줄이 같고, 조기 종료로 실제 종료 에폭·총 스텝은 군·시드마다 다를 수 있다(모두 기록·보고).

## 6. 개발 평가와 후보 선정 규칙 (독립 평가셋 열람 전에 고정)

### 6-1. 개발셋
1. **회귀 확인용(R9 와 같음)**: v7_namefreq, realistic_family, v14_realistic, nemotron_full, nemotron_given (노출·F1 매크로), 오탐 4집합. 1글자 이름 행 제외, 기준선(S0)은 같은 코드로 재계산. R9 에서 선정에 쓰였고 R9F 가 이 세트들에 이미 맞춰져 있으므로 **R10 의 일반화 증거로 쓰지 않는다**(R9 개발 매크로 노출 3.56%와 독립셋 11.29%의 격차가 보여 준 한계).
2. **R10 개발셋 `r10_dev`(신규, 824행, 학습에 쓰지 않음)**: `build_r10_dev.py` 로 생성, 학습 틀과 다른 3개 에이전트의 별도 틀 826개(틀 재사용 없음), 이름·명사 단어는 R10 예약 구간만, R9 학습에서 쓴 이름 부분 제외. 유형: D1P 152, D1(명사 쪽 쌍) 152, B1 150, C2 120, NEWNAME 150, D2 30, 가족호칭만 25, 지명·기관명 25, 명사만 20. PERSON 구간 775개, 서로 다른 값 490개, **이름 부분이 참조 집합에 없는 구간 705개(91%)**, 규격 검증 문제 0. 소표본 한계를 인정한다(유형당 120~152행, 군집 부트스트랩 사용).

### 6-2. 게이트 (서비스 S0 대비, 비율은 소수 둘째 자리 %p 로 반올림, 경계값은 통과)
R9 의 G1~G4 와 개선 요건을 **그대로** 적용한다(회귀 확인용 5세트): G1 오탐 매크로 +2.0%p 이하·어느 한 집합도 +5.0%p 이하, G2 과잉 병합 건수 S0 이하, G3 매크로 Exact F1 -1.0%p 이상, G4 세트별 전체 노출률 S0 대비 +1.0%p 이하, 개선 요건: 매크로 전체 노출률 S0 대비 -1.0%p 이하. 추가 게이트(R10 개발셋 `r10_dev`, 시드별 단일 모델 기준):

| 게이트 | 기준 |
|---|---|
| G5 (D1P) | D1P 전체 노출률이 S0 대비 +0.0%p 이하(악화 없음) **그리고 R9F 5시드 평균 대비 +1.0%p 이하** |
| G6 (D1 오탐) | D1 음성 문장(명사 쪽 쌍 + 명사만)에서 PERSON 을 낸 비율이 S0 대비 +3.0%p 이하 |
| G7 (B1·C2) | B1 전체 노출률, C2 전체 노출률 각각 S0 대비 +0.0%p 이하 |
| G8 (회귀) | 회귀 확인용 5세트 매크로 전체 노출률이 R9F 5시드 평균 대비 +0.5%p 이하(R9 성능 유지) |
| G9 (신규 이름) | NEWNAME 전체 노출률이 S0 대비 +0.0%p 이하(보고 전용 동반: 이름 부분 unseen 구간만의 노출률) |

### 6-3. 선정
- 선정 자격: **R10-full 시드 5개**만(C10·R10-D/BC/N·C10s·R9F 는 귀속·비교 보고용). 모든 게이트(G1~G9)와 개선 요건을 통과한 모델 중 **`r10_dev` 의 표적 유형(D1P·B1·C2·NEWNAME) 전체 노출률 단순 평균이 가장 낮은 하나**. 동률(0.1%p 이내)이면 회귀 확인용 5세트 매크로 전체 노출률, 그다음 비PERSON 오탐률, Exact F1, 시드 번호가 작은 쪽. 새 점수식은 만들지 않는다.
- **통과 후보가 없으면 교체를 권고하지 않고 결과를 보고하며 독립 평가셋을 열지 않는다.** 5시드 평균·표준편차·최악값과 C10·R9F 비교를 함께 보고한다.
- R10-full 이 C10 보다 표적 유형 노출을 낮추지 못하면(5시드 평균 차이 -1.0%p 미만) 개선을 새 데이터 덕으로 돌리지 않는다고 보고한다.

## 7. 독립 평가셋 최종 평가 (1회, 후보 확정 후)

- 대상: 서비스 모델과 §6 으로 선정한 후보 **1개**. 같은 평가 코드·설정, 대표와 스트레스 세트 따로(평균 내지 않음). 모델 예측은 최종 실행 전에 평가셋에 돌리지 않는다. 사전 점검: 규격 검증 오류 0, 이중 검수·합의 완료·봉인(SHA256), 평가 코드 만점/망가뜨린 예측 시험, 후보 ONNX 해시 고정(`--expect-onnx-sha`), 코드 해시 고정.
- 보고: 모델별·세트별 Exact P/R/F1, 보호 대상 Recall, 완전·부분·전체 PERSON 노출률, 비PERSON 오탐률, 과잉 병합, 유형별(A1~D3, D1P, D1, D2, A3N, NEWNAME) 노출률·정확 일치율·오탐률, `name_seen_in_reference` 층화(신규 이름 층), 짝지은 개선·악화 건수, 이름·틀 군집 부트스트랩 95% 신뢰구간(1,000회, 시드 고정), 문장당 CPU 지연·메모리, 5시드 평균·표준편차(개발 단계). 반복 이름·틀 의존성 한계를 명시한다.
- **교체 권고 조건 (모두 충족해야 함, 최종 결정은 사용자, 가장 중요한 지표는 PERSON 노출률)**
  1. 대표 세트 전체 노출률 차이(후보−서비스)의 95% 구간 상한이 0 미만이고 점추정 -1.0%p 이하.
  2. 대표 세트 비PERSON 오탐률 차이의 구간 상한이 +2.0%p 이하.
  3. 대표 세트 Exact F1 차이의 구간 하한이 -1.0%p 이상.
  4. 과잉 병합이 서비스 이하(대표·스트레스 각각).
  5. 스트레스 세트에서 **어떤 유형도** 점추정 노출률이 서비스 대비 +2.0%p 넘게 악화되지 않음.
  6. **D1P**: 점추정 노출률 차이 ≤ 0.0%p 그리고 95% 군집 부트스트랩 구간 상한 ≤ +4.0%p. (R9 에서 걸린 유형을 R10 에서 더 엄격하게 본다.)
  7. **B1·C2**: 각각 점추정 노출률 차이 ≤ 0.0%p.
  8. 부분 노출률(전체 중 일부만 가려진 비율)이 서비스 대비 +1.0%p 이하로 악화되지 않음(경계 오류의 부분 노출화 방지).
  9. **NEWNAME 층(독립셋의 이름 부분 unseen 구간)**: 구간 수가 150 이상이면 노출률 점추정 차이 ≤ -1.0%p; 150 미만이면 보고 전용(표본 부족으로 표기).
  10. 스트레스 세트 비PERSON 오탐률(D1·D2·A3N 포함)이 서비스 대비 +2.0%p 넘게 악화되지 않음.
  11. CPU ONNX 추론: 문장당 지연이 서비스 대비 +30% 이하, 모델 파일 크기·RSS 증가 +30% 이하(같은 아키텍처이므로 사실상 동일 예상).
- 하나라도 어기면 "교체 근거 불충분"으로 보고한다. 목표(전체 노출 5% 미만, 오탐 5% 이하, F1 90% 이상)는 세트별 기술 통계로만 보고한다. **F1 이 올라도 노출이 늘거나 특정 고위험 유형이 악화되면 교체를 권고하지 않는다.** 유의하지 않은 차이는 개선이라고 쓰지 않는다. 최종 결과를 본 뒤의 후보 교체·재학습·다른 시드·후처리·데이터 보강을 하지 않으며, 결과를 활용한 개선이 필요하면 그 평가셋은 개발용으로 분류하고 다음 최종 검증에는 새 독립셋을 쓴다.
- 한 글자 PERSON 이름은 이번 연구 범위에서 제외했고 **노출 위험이 해결되었다는 뜻이 아니다**(최종 보고서에 한계로 명시).

## 8. 서비스 교체 준비 (평가 통과 시에만 제안, 승인·배포는 별도)

기존 ONNX·설정 백업, 신규 ONNX 해시·버전 고정, tokenizer·`labels.json` 호환 확인, Regex+NER 통합 회귀, 소통 에이전트 가명화 결과 점검, CPU 지연 확인, 다른 에이전트의 공유 모델 영향 확인, 배포 전후 모델 지문 확인, 롤백 절차. 소통 에이전트만 교체하려면 **방안 B(기능별 모델 분리)** 가 필요하며 설계는 `NER_R10_MODEL_SEPARATION_DESIGN.md`. 공통 모듈 변경이므로 구현은 별도 승인 후.

## 10. 알려진 한계와 위험

- 학습·개발 틀 모두 LLM(Claude 계열) 작성이라 문체 균질성, 그리고 개발셋과 학습의 분포가 예상보다 가까울 수 있다(독립 평가셋은 다른 작성자 GPT).
- R9 개발 5세트는 이미 소비·튜닝되어 일반화 증거가 아니다. R10 개발셋은 소표본(유형당 120~152행)이다.
- D1P 약점 원인은 가설이다(§3-1). R10-D 귀속 군이 이를 반증할 수 있다.
- KLUE 비중이 6.0→4.73%로 내려가므로 일반 도메인 오탐 악화 가능성을 KLUE 오탐으로 따로 본다.
- 서비스 v2b ONNX 파일은 이 PC 에 없고 카드·토크나이저만 있다. 서비스 모델 평가는 서버에서 가져온 파일의 해시(`46210943c45f…`) 확인 후에만 한다.
- 합성 데이터이며 실제 가족 대화 분포를 대표한다고 주장하지 않는다. 한 글자 이름 제외.
