# NER R9 사전 등록 (학습 데이터 보강 효과의 분리 검증과 독립 평가셋 1회 검증)

작성일 2026-11-19, 버전 r9-1.0. **이 문서는 독립 평가셋을 열기 전, 후보 학습 전에 커밋한다.** 이후 결과를 보고 기준을 바꾸지 않으며, 바꿔야 하면 변경 사유와 시점을 별도 절로 남기고 바꾸기 전 기준의 결과도 함께 보고한다. 공통 데이터 규격은 `NER_R9_COMMON_SPEC.md`, 평가셋 작성 지시서는 `NER_R9_GPT_EVALSET_INSTRUCTIONS.md`.

사용자 결정(2026-11-19): 학습 데이터는 Claude Code, 독립 평가셋(대표·스트레스)은 ChatGPT가 작성, 사용자는 검토·최종 승인. 1글자 이름 연구 제외. 기존 데이터 상세 재집계 생략, 신규 40% 혼합, 동일 데이터·동일 학습 스텝 대조군 필수. 연구용 브랜치(`feature/seungdeuk-ner-improve2`)와 별도 worktree 에서만 작업하고 운영 모델·서비스 코드 수정, 푸시·PR·병합·배포는 하지 않는다.

## 1. 기준선·범위

- 기준선: 서비스 모델 `v2b-koelectra-small-klue10-s7`, 지문 `46210943c45f`, **원래 디코더**, 가족 이름 사전 비움, 추론 스레드 2. 모델·디코더·서비스 코드는 바꾸지 않는다. 디코더 변경 실험은 하지 않는다.
- **1글자 이름 제외**: 평가·학습·검증에서 1글자 PERSON 이름 문장을 뺀다(음성으로 바꾸지 않는다). 개발 평가셋에서도 정답 구간이 1글자인 행(R8 기준 v7 24, nemotron_given 26)을 빼므로 **기준선 개발 수치를 이 제외 규칙으로 다시 계산해 고정**한다(R8 수치와 다를 수 있음). 최종 보고서에 "1글자 이름의 노출 위험은 이번 연구로 해결되지 않았다"고 명시한다.
- 이 연구에서 쓰는 합성 데이터에 실제 가족 대화·실제 개인정보는 없다. 외부 유료 API 호출 없음.

## 2. 데이터 작성자 분리와 격리

- 평가셋 작성자는 학습 데이터를, 학습 데이터 작성 쪽(Claude)은 평가셋 문장·이름·정답·틀을 보지 않는다. Claude 는 인계된 평가셋 파일을 열어 읽지 않고, 검증기 출력(코드·건수·id)만 본다.
- 학습 데이터 생성기는 봉인된 평가셋을 **프로그램 안에서만** 읽어 이름·문장·틀·구간 값이 겹치는 후보를 **거르는 용도**로 쓴다(내용을 출력하거나 참고해 생성하지 않음, 보고서는 건수만).
- 평가셋 작성 지시서·공통 규격에 들어 있는 예시 문장·이름은 학습 데이터에서 제외하는 차단 목록에 넣는다.
- 기존 new180 은 R8 에서 1회 소비된 세트다(집계와 앞 12행만 열람). 개발·진단 참고용으로만 쓰고 **게이트에는 넣지 않는다.** 신규 독립 평가셋과 혼동하지 않는다.

## 3. 학습 데이터 구성

기존 데이터(고정, 모든 실험군 공통): `baseline_train` 540 + `synth_train` 3,680 + KLUE 표본 469(서비스 레시피의 KLUE 10% 절대량) = **4,689행**.
신규 데이터(Claude 작성, 합성): 전체 학습 샘플의 40% → 신규 N = 4,689 × 40/60 = **3,126행**(F-full). 기존은 삭제하지 않고 샘플링 비율만 60%로 유지한다.

신규 내부 비율(초기 실험 조건, 최적값 아님):

| 버킷 | 비율 | 행 수(F-full) | 내용 |
|---|---:|---:|---|
| `msg` | 60% | 1,876 | 다양한 가족 메신저 문장(고유 문장 구조, 목적·맥락 다양화, 오타·축약·띄어쓰기 오류, 다인물·별칭) |
| `err` | 25% | 782 | 오류 유형 특화: A1·A3(`err_A`≈274), B1·C1·C2(`err_B`≈235), D 대조쌍·Hard Negative(`err_D`≈273) |
| `mixed` | 15% | 468 | 일반 문어체, 메신저에 복사된 안내문, 반문어체 |

- 중복 집계: 한 행은 **하나의 주 버킷**만 가진다. 여러 유형에 걸치면 우선순위 `err_A` > `err_B` > `err_D` > `msg` > `mixed` 로 주 버킷을 정한다. 행마다 `train_bucket`, 보조 유형 목록을 기록하고, 실제 샘플링 결과가 목표 비율(±1%p)과 맞는지 빌드 보고서에 쓴다(맞지 않으면 학습하지 않는다).
- 고유 문장 구조를 우선한다: 이름만 바꾼 틀 반복을 피하고, 틀 재사용 상한과 4-gram 유사도를 빌드 보고서에서 확인한다. 이름·단어는 개발 평가셋·기존 풀·평가셋 차단 목록과 겹치지 않게 한다. 정답 누락·오프셋·중복 검사는 R8 빌더와 같은 수준으로 하고 공통 규격 검증을 통과해야 한다.
- 실제 풀(버킷별 최소): `msg` 1,876, `err_A` 782, `err_B` 782, `err_D` 782, `mixed` 468 (E1~E4 의 매칭 볼륨용으로 `err_*` 는 각각 782 이상 만든다).

## 4. 실험군(E1~E5, 대조군)

공통: 사전학습 체크포인트 `monologg/koelectra-small-v3-discriminator` 에서 처음부터, 레시피는 서비스·R8 과 같음(max_len 128, batch 32, lr 5e-5, 최대 8에폭, patience 2, warmup 10%, weight decay 0.01, fp16, 에폭 선택은 `baseline_val` 겹침 F1). **시드 5개(7, 13, 21, 42, 99)를 모든 실험군에 적용**하고 시드를 추가·교체하지 않는다. 실패한 실행은 재시작하지 않고 보고한다.

| 군 | 신규 데이터 | 목적 |
|---|---|---|
| C1 | 없음(기존 4,689행 그대로) | R8 방식 대조군 |
| **C0** | 없음, 기존 4,689행을 **F-full 과 같은 행 수·같은 에폭당 스텝 수**(7,815)가 되도록 고정 시드로 복원 추출 | **동일 데이터·동일 학습 스텝 대조군(필수)** |
| E1 | `msg` 782행 | 메신저체 보강 효과 |
| E2 | `err_A` 782행 | A1·A3 완전 미탐 감소 |
| E3 | `err_B` 782행 | B1·C1·C2 경계 개선 |
| E4 | `err_D` 782행 | D 오탐 감소 |
| F-full | 위 §3 구성 전체 3,126행 | 지정 초기 레시피 |
| E5 | 개별 효과가 확인된 버킷만 조합(아래 규칙), 신규 3,126행 유지 | 효과가 검증된 조합 |

E1~E4 는 볼륨을 같게(782행) 맞춘 **귀속 분석용**이다. E5 규칙: E1~E4 중 해당 군 시드 5개의 개발 매크로 노출 평균이 C0 대비 1.0%p 이상 낮고 §6 게이트 중 오탐·F1·세트별 노출 조건을 시드 평균 기준으로 위반하지 않은 군의 버킷만 포함하고, 총 신규 3,126행을 유지하도록 남은 버킷을 같은 비율로 키운다(`mixed` 는 항상 포함). 해당 군이 하나도 없으면 E5 는 실행하지 않는다.
**선정 자격은 F-full 과 E5 의 시드(최대 10개 모델)만 가진다.** E1~E4, C0, C1 은 효과 귀속과 재학습 잡음 구분용 보고에만 쓴다. 학습 전에 자원(RAM·VRAM·시간)을 R8 실측(1회 50~105초, VRAM 0.8GB)으로 추정하고 파일럿으로 점검한다.

## 5. 지표 정의

- 최종 예측: `ner.detect_with_ner(text, ())` 의 PERSON 구간. Exact: (start,end) 정확 일치 TP, 못 맞춘 정답 FN, 정답과 정확히 같지 않은 예측 FP. 모든 정답 구간을 채점(`r8_eval_lib.py`).
- 노출: 정답 구간 글자 중 PERSON 예측에 덮이지 않은 글자 수. 전부 안 덮임 = 완전 노출, 일부 = 부분 노출. **전체 노출률 = (완전+부분) / 정답 구간 수.** 비PERSON 오탐률 = PERSON 정답이 없는 문장 중 PERSON 을 낸 문장 비율. 과잉 병합 = 한 PERSON 구간이 서로 다른 두 개체 이상을 삼킨 문장 수(28건: r7b_adjacent 다중 구간 9 + 인접 스트레스 19).
- 보호 대상 Recall: 정책 MASK 4종(PERSON, ADDRESS, PHONE, EMAIL) 정답 구간이 한 글자도 남지 않고 가려진 비율, BLOCK(ACCOUNT)은 차단·값 가림·노출로 분리. 독립 평가셋에서만 산출(`evaluate_r8_new180.py` 의 정책 처리를 일반화한 평가 스크립트 사용).
- 분자·분모·건수를 함께 표기하고 Wilson 95% 신뢰구간, 짝지은 비교에는 이름·틀 단위 군집 부트스트랩(1,000회, 시드 고정)을 쓴다.

## 6. 개발 단계 후보 선정 규칙(독립 평가셋 열람 전에 고정)

개발 평가셋(소비됨, 1글자 이름 행 제외, 모든 구간 채점): 노출·F1 매크로 5개 = v7_namefreq, realistic_family, v14_realistic, nemotron_full, nemotron_given. 오탐 매크로 4개 집합 = v7 음성 78, family 음성 22, v14 음성 20, ambiguity_probe 의 PERSON 정답 없는 문장(90). 매크로는 **세트별 비율의 단순(무가중) 평균**이다. 비율은 소수 둘째 자리 %p 로 반올림해 비교하고 **경계값은 통과로 본다**(이하·이상).

| 게이트 | 기준(서비스 대비) |
|---|---|
| G1 | 오탐 매크로 +2.0%p 이하, 어느 한 집합도 +5.0%p 이하 |
| G2 | 과잉 병합 건수가 서비스 이하 |
| G3 | 매크로 Exact F1 이 -1.0%p 이상(1.0%p 를 넘어 하락하지 않음) |
| G4 | 개발 세트별 전체 노출률이 서비스 대비 +1.0%p 이하 |
| 개선 요건 | 매크로 전체 노출률이 서비스 대비 -1.0%p 이하(최소 1.0%p 개선) |

모든 게이트와 개선 요건을 통과한 모델 중 **매크로 전체 노출률이 가장 낮은 하나**를 선정한다. 동률(0.1%p 이내)이면 비PERSON 오탐률이 낮은 쪽, 그다음 Exact F1 이 높은 쪽, 그다음 시드 번호가 작은 쪽. **통과 후보가 없으면 교체를 권고하지 않고 결과를 보고하며 독립 평가셋을 열지 않는다.** 5시드 평균·표준편차·최악값과 C0·C1 비교를 함께 보고한다. new180 결과는 참고로 같이 표기하되 선정에 쓰지 않는다.

## 7. 독립 평가셋 최종 평가(1회)

- 대상: 서비스 모델과 §6 으로 선정한 후보 **1개**만, 같은 평가 코드·설정으로, 대표(`representative`)와 스트레스(`stress`) 세트에 각각. 두 세트 결과를 평균 내 하나의 서비스 성능으로 주장하지 않는다.
- 사전 검증: 공통 규격 검증 오류 0, 표본 검수 완료·봉인(매니페스트 SHA256 일치), 평가 코드의 정답=예측 만점 시험, 망가뜨린 예측 시험. 모델 예측은 최종 실행 전에 평가셋에 돌리지 않는다.
- 보고: 모델별·세트별 Exact P/R/F1, 보호 대상 Recall, 완전·부분·전체 노출률, 비PERSON 오탐률, 과잉 병합, 지연(문장당), 스트레스 유형(A1~D3, D1, D2, A3N)별 노출률·정확 일치율·오탐률, 이름이 학습 데이터에 있었는지(`name_seen_in_reference`) 층화, 서비스→후보 개선·악화 짝지은 건수, 군집 부트스트랩 95% 신뢰구간. 반복 이름·틀에 따른 표본 의존성 한계를 명시한다.
- **교체 권고 조건(대표 세트 기준, 모두 충족해야 함, 사용자가 최종 결정)**: (1) 전체 노출률 차이(후보-서비스)의 95% 군집 부트스트랩 구간 상한이 0 미만이고 점추정 -1.0%p 이하, (2) 비PERSON 오탐률 차이의 구간 상한이 +2.0%p 이하, (3) Exact F1 차이의 구간 하한이 -1.0%p 이상, (4) 과잉 병합이 서비스 이하, (5) 스트레스 세트에서 어떤 유형도 점추정으로 서비스 대비 노출률이 2.0%p 넘게 악화되지 않음. 하나라도 어기면 "교체 근거 불충분"으로 보고한다. 목표(전체 노출 5% 미만, 오탐 5% 이하, F1 90% 이상)는 세트별 기술 통계로만 보고하고 통과·실패를 따로 표기한다.
- 유의하지 않은 차이는 개선이라고 쓰지 않는다. 최종 결과를 본 뒤 후보 교체, 재학습, 다른 시드 선택, 후처리 조정, 데이터 보강을 하지 않는다. 결과를 활용한 추가 개선이 필요하면 해당 세트는 개발용으로 분류하고 다음 최종 검증에는 새 독립 평가셋을 쓴다.

## 8. 실행 순서(승인 단계)

1. 공통 스키마·라벨 정책·평가 코드 호환성 확정(완료: 시험 8개 통과).
2. 평가셋 생성 명세·자동 검증기·후보 선정 규칙 사전 등록(이 문서, 커밋).
3. GPT 평가셋 인계 → 검증기로 집계 확인 → 표본 검수 → 봉인.
4. Claude 가 신규 학습 데이터 제작(검증·격리 통과), 파일럿으로 자원 점검.
5. E1~E5, C0·C1 학습(5시드), 개발셋 평가.
6. §6 규칙으로 후보 1개 선정(없으면 보고하고 종료).
7. 봉인 평가셋 최종 1회 비교.
8. 성능·회귀·일반화 한계, 채택 권고 보고.
