# 한국어 개인정보 NER 검증 기록

가명화 모듈(`apps/api/app/shared/privacy/`)에 보강으로 붙인 경량 NER(KoELECTRA-small, ONNX)의 학습·비교·평가를 한곳에 모은 기록이다.
학습·평가 코드는 `ml/ner/`, 평가 데이터는 `apps/api/app/shared/privacy/eval/baseline_v2/`, 결과표는 `eval/results/` 에 있다.
모든 데이터는 합성이다. 아래 수치는 이 합성 데이터에서의 값이며 실제 가족 대화에서 같은 성능을 보장하지 않는다.
**모델 파일(`*.onnx`)·체크포인트·학습 산출물은 저장소에 올리지 않는다**(`.gitignore`, 크기 54MB~4GB, 라이선스 이유). 모델은 모델 카드의 SHA256 으로 식별한다.

## 1. 모델 비교 (val 분할, Baseline v2 val 180문장)

후보: `monologg/koelectra-small-v3-discriminator`(1,406만 파라미터, 54MB) 와 `klue/roberta-small`(6,751만 파라미터, 258MB).
CPU(4스레드) 100자 추론 중앙값은 KoELECTRA 약 11~14ms, RoBERTa 약 29~35ms 였다.

| 실험 | KoELECTRA | RoBERTa |
|---|---|---|
| KLUE 혼합 0% | F1 0.949, 오탐률 0.08 | F1 0.949, 오탐률 0.07 |
| KLUE 혼합 10% | F1 0.971, 오탐률 0.03 | F1 0.971, 오탐률 0.04 (시드 42) |
| KLUE 혼합 30% | F1 0.943, 오탐률 0.07 | F1 0.966, 오탐률 0.05 (시드 42) |
| v2b(모호 사례 제거) 10% | F1 0.980, 오탐률 0.009 | F1 0.981, 오탐률 0.028 (시드 42) |
| v2c(오탐 보강) 10% | F1 0.968, 오탐률 0.037 | F1 0.993, 오탐률 0.000 (시드 42) |

- F1 은 겹침(overlap) 기준 micro F1, 오탐률은 개인정보가 없는 음성 문장 중 무언가를 가린 비율이다. 1차 행은 시드 7 기준이다.
- KLUE 를 10% 섞은 설정이 두 모델 모두에서 가장 좋았다.
- RoBERTa v2c 의 0.993 은 시드 42 한 번의 값이고 시드 7 은 0.962 다. 180문장이라 시드 편차보다 차이가 작아 "최고 성능"으로 읽지 않는다.
- 선택: `v2b-koelectra-small-klue10-s7`. 시드 42 와 비교해 Baseline val F1 과 오탐률(0.9% 대 3.7%)이 모두 우세했다. 선택은 val 로만 했다.
- 한계: best 에폭과 시드를 같은 val 로 골랐으므로 val 수치는 약간 낙관적이다.

## 2. 독립 Test 평가: 규칙 단독 vs NER 단독 vs 규칙+NER

`scripts/eval_integration.py --final` 로 baseline_v2 의 test 분할(180문장, 정답 구간 176개)에서 비교했다. 이 스크립트가 test 를 읽는 유일한 경로이며, 학습·검증·모델 선택에 test 를 쓰지 않았다.
**test 는 이미 사용했다**(결과 파일 기준 2026-10-27). 스크립트 정책상 test 결과를 보고 모델·규칙·병합을 고치지 않으며, 고쳐야 하면 새 분할을 만든다. 같은 test 로 다시 재면 독립 평가가 아니다.

| 방식 | 정밀도 | 재현율 | F1 | 보호 대상 재현율 | 음성 오탐률 | 평균 처리(문장당) |
|---|---:|---:|---:|---:|---:|---:|
| A 규칙 | 1.000 | 0.528 | 0.691 | 0.561 | 0/28 | 0.03ms |
| B NER 단독(전체 라벨) | 0.963 | 0.443 | 0.607 | 0.433 | 1/28 | 4.76ms |
| C 규칙+NER(서비스 경로) | 0.985 | 0.767 | **0.863** | **0.823** | 1/28 | 4.81ms |

- 위 값은 mapped 라벨, exact(시작·끝 일치) 기준이다. 보호 대상은 가림이 기본인 종류(`mask_default=true`)다.
- NER 이 담당하는 5라벨(이름·별칭·주소·지명·기관)만 보면 규칙 재현율 0.350, NER 단독 0.975(F1 0.969), 규칙+NER 0.875(F1 0.921)다.
- 규칙+NER 로 가림이 완전한 보호 구간 비율이 0.561 에서 0.817 로 올랐다. 대신 오탐 1문장(3.6%)과 문장당 약 4.8ms 가 더해졌다.
- 한계: 합성 안전 픽스처 180문장이다. 실제 구어체 대화에서의 성능은 확인하지 못했다.

## 3. 오류 분석 (val)

최종 모델의 Baseline val 오류는 4건(놓침 1, 경계 1, 오탐 2)이다. 구어체·오타가 섞인 합성 val(1,427문장)은 107건(놓침 49, 경계 21, 라벨 혼동 21, 오탐 16)이다.

- **조사 때문에 생기는 경계 오류**: `정채은이랑` 에서 이름을 "정채은이" 로, `송숙자하고` 에서 "송" 으로 자른다.
- **띄어쓰기를 없앤 입력**(`구민서하고약속있음`)과 **2글자 이름**(`조준`)은 거의 놓친다.
- **라벨 혼동**: 사람 이름이 기관·지명·별칭으로 분류되는 경우(`심해원`, `시안`).
- 같은 유형의 오류가 더 큰 모델(RoBERTa)에서도 남으므로 원인은 모델 크기보다 데이터·라벨링 쪽이다.

**경계 오류 분석(합성 val, PERSON)**: 조사가 붙어 이름이 길게 잡힌 오류와 이름 뒤쪽이 잘려 빠진 오류를 나눠 셌다.

| 모델 (시드) | 조사까지 길게 잡힘 | 이름 뒤쪽이 잘림(일부 노출) |
|---|---:|---:|
| KLUE 10% (7) | 7 | 7 |
| AI Hub 10% (7) | 14 | 0 |
| AI Hub 10% (42) | 13 | 1 |

- 조사가 붙은 경우(`정채은이`, `임은서도`)는 조사 한 글자까지 같이 가려질 뿐 개인정보가 남지 않는다. 조사를 규칙으로 잘라내면 이름이 `이`·`은`·`하`·`도` 로 끝나는 실제 이름(`김하은` 등)이 잘려 일부가 노출될 수 있어 서비스 코드에 넣지 않았다.
- 이름 뒤쪽이 잘려 일부가 남는 오류는 AI Hub 데이터를 섞은 모델에서 사실상 사라졌다.
- 놓친 이름(합성 val 41건, 시드 42)의 대부분(34건)이 `내 친구 이름이 나무 이래` 한 문장의 변형이다(`나무` 는 일반 명사와 겹치는 이름). 서로 다른 사례는 몇 개 안 되며, 이를 맞추려고 학습 문장을 val 에 맞춰 늘리면 평가가 오염되므로 하지 않았다.

## 4. 라이선스 (서비스 투입 전 확인 필요)

- KLUE-NER 데이터는 CC BY-SA 4.0 이다. 학습 데이터의 일부(문장 기준 10%)로 썼고, 원문은 저장소에 두지 않는다.
  출처 표시(KLUE 논문·저자)는 지켜야 하고, 이 데이터로 학습한 모델 파일을 배포하면 동일조건변경허락(SA)이 적용될 수 있다(법적 해석은 확정되지 않음).
  서버 안에서만 실행하고 파일을 밖으로 내보내지 않는 현재 사용 방식에서의 영향은 확인하지 못했다.
- 기반 모델 `monologg/koelectra-small-v3-discriminator` 는 코드 저장소(monologg/KoELECTRA)가 Apache-2.0 이고, 가중치 라이선스는 모델 페이지에 명시가 없다. v3 사전학습 말뭉치(모두의 말뭉치·나무위키 등)의 상업 이용 조건은 확인하지 못했다.
  Apache-2.0 의무: 원 저작권 고지와 라이선스(전문 또는 링크)를 제품 설명서·고지란에 포함한다(https://github.com/monologg/KoELECTRA).
- **KLUE 를 뺀 재학습 결과(v2b 데이터, 같은 설정, 시드 7·42, val 만 사용, test 미사용)**:

  | 설정 | Baseline val F1(겹침) | Baseline val 오탐률 | 합성 val F1 | 합성 val 오탐률 |
  |---|---|---|---|---|
  | KLUE 10% (시드 7 / 42) | 0.980 / 0.974 | 0.009 / 0.037 | 0.954 / 0.952 | 0.033 / 0.103 |
  | KLUE 0% (시드 7 / 42) | 0.962 / 0.968 | 0.046 / 0.046 | 0.965 / 0.945 | 0.033 / 0.031 |

  - Baseline val 에서는 시드 평균 F1 이 약 0.012 낮고 오탐률이 약 0.023 높다. 합성 val 에서는 F1 이 같고 오탐률은 오히려 낮다.
  - 차이가 시드 사이의 편차(KLUE 10% 의 오탐률 0.009 대 0.037)와 비슷한 크기라서, 시드 2개로는 KLUE 의 효과가 있다고 단정할 수 없다. 더 확실히 하려면 시드를 늘려야 한다.
  - KLUE 0% 의 Baseline val 오류는 8건(시드 7) / 6건(시드 42)이다. 오탐 대부분이 "송장 …"(송장을 사람으로 인식)이고 "박수"가 더해진다. KLUE 가 이 유형을 줄였을 가능성이 있다. 합성 데이터에 일반 명사 어려운 음성을 늘려 보완할 수 있으나 이번에는 하지 않았다.
  - 결론: KLUE 를 빼도 val 성능 손실은 작아 보인다. 라이선스 때문에 KLUE 를 쓰지 않는 선택이 가능하다.
- **KLUE 대신 AI Hub 데이터를 섞은 결과(같은 비율 10%, 같은 설정, 시드 7·42, val 만 사용)**: AI Hub 「대규모 웹데이터 기반 한국어 말뭉치 데이터」(한국지능정보사회진흥원, 2021)의 라벨링 데이터에서 파일 900개를 시드 고정으로 뽑아 21,000문장으로 변환했다(`ml/ner/data/build_aihub_ner.py`).

  | 설정 (시드 2개 평균) | Baseline val F1 | Baseline val 오탐률 | 합성 val F1 | 합성 val 오탐률 | 합성 aug 틀 F1 |
  |---|---|---|---|---|---|
  | KLUE 10% | 0.977 | 0.023 | 0.953 | 0.068 | 0.894 |
  | KLUE 0% | 0.965 | 0.046 | 0.955 | 0.032 | 0.891 |
  | **AI Hub 10%** | **0.981** | 0.028 | **0.966** | **0.017** | **0.933** |

  - 개별 시드: AI Hub 10% 는 Baseline val F1 0.993 / 0.968, 오탐률 0.009 / 0.046. 시드 42 는 KLUE 0% 와 비슷하다(오류 6건, "송장"·"박수" 오탐 남음).
  - 합성 val 에서는 두 시드 모두 AI Hub 10% 가 KLUE 10% 이상이다. Baseline val 은 시드 편차 안에서 같거나 약간 좋다. KLUE 를 AI Hub 로 바꿔도 성능이 떨어지지 않는다고 볼 수 있다. 다만 시드 2개·180문장이라 우열을 단정하지는 않는다.
  - **시드를 5개(7, 42, 13, 21, 99)로 늘린 결과(평균±표준편차, val 만 사용)**

    | 설정 | Baseline val F1 | Baseline val 오탐률 | 합성 val F1 | 합성 val 오탐률 | 합성 aug 틀 F1 |
    |---|---|---|---|---|---|
    | KLUE 10% | 0.978±0.012 | 0.026±0.017 | 0.946±0.017 | 0.049±0.040 | 0.874±0.034 |
    | KLUE 0% | 0.968±0.011 | 0.037±0.016 | 0.949±0.011 | 0.024±0.015 | 0.859±0.053 |
    | **AI Hub 10%** | 0.976±0.011 | 0.030±0.019 | **0.961±0.009** | **0.014±0.016** | **0.911±0.047** |

    - Baseline val 에서는 AI Hub 10% 와 KLUE 10% 가 같은 수준이다(F1 0.976 대 0.978, 시드 편차 안). 같은 시드끼리 비교하면 AI Hub 가 F1 에서 5개 중 2개, 오탐률에서 1개 우세했다.
    - 합성 val 에서는 AI Hub 10% 가 F1 에서 5개 시드 모두 우세하고, 오탐률은 4개 우세·1개 동률이다. 오탐을 줄이는 음성 예시로서의 역할이 KLUE 보다 낫다고 볼 수 있다.
    - KLUE 를 아예 빼면(0%) Baseline val F1 이 약 0.010, 오탐률이 약 0.011 나빠진다. AI Hub 를 섞으면 이 손실이 사라진다.
    - 한계: val 180문장과 합성 val 이다. test 는 쓰지 않았다. 시드별 편차가 커서 한 시드의 값으로 우열을 말하지 않는다.
  - **이 데이터에는 사람(PS)·장소(LC) 태그가 없다**(17개 분야 표본 약 48만 문장의 태그는 CV·OG·TM·AF·FD·TR·NW 뿐이고, 사람 이름은 원문에서 "(이름)" 으로 가려져 있다). 그래서 기관(OG) -> ORGANIZATION 만 라벨로 쓰고, 이름이 없는 일반 문장은 일반 명사를 사람으로 오인하는 오탐을 줄이는 음성 예시로 쓴다. 이름·주소 인식은 합성 데이터에 의존한다.
  - 변환에서 금융기관명이 든 문장, "(이름)" 같은 가림 표시가 든 문장, Baseline train/val 과 같은 문장을 뺐다. 원문과 변환본은 저장소에 올리지 않는다.
  - **AI Hub 이용 조건(2026-11-03 확인)**: AI Hub 문의(FAQ) 안내문(https://www.aihub.or.kr/aihubnews/faq/list.do?currMenu=146&topMenu=104, 2026-11-03 확인)에 따르면, 데이터를 학습에 활용해 만든 AI 모델·서비스·연구 결과물 등 2차 저작물은 영리·비영리 목적으로 활용하거나 판매·배포할 수 있다. 모델 가중치·코드를 공개해야 하는 의무(SA 같은 것)는 없다. 이용정책 요약에서는 이 밖에 국외 이용·반출이 별도 합의 대상이고, 일부 기관 제공 데이터는 별도 이용조건이 있다고 나온다(이 데이터셋은 기관 제공 데이터가 아닌 것으로 보이나 신청 시 동의서 확인 필요).
  - **지켜야 할 조건**
    - 결과물에 데이터셋의 정식 명칭(「대규모 웹데이터 기반 한국어 말뭉치 데이터」)과 AI 허브(aihub.or.kr)를 출처로 표기한다. 이용정책 요약에는 한국지능정보사회진흥원(NIA)의 사업결과임을 밝히라는 문구도 있으므로 함께 적는다. 모델을 배포·공개하면 모델 카드와 문서에 넣는다.
    - 다운로드한 원본과 단순 가공본(우리 변환본 `aihub_train.jsonl` 포함)을 외부에 공개·공유·재배포하거나 제3자에게 줄 수 없다. 저장소에 올리지 않고 학습 PC 에만 둔다. 변환기 코드와 개수 통계는 데이터가 아니라 올려도 된다.
    - 권리는 데이터 구축 수행기관과 NIA 에 있다.

## 5. API 부하 측정 (가명화 경로)

`scripts/loadtest_preview.py` 로 실제 uvicorn 서버(프로세스 1개, 임시 SQLite)에 동시 요청을 보냈다. 대상은 `POST /family-chat/ai/preview` 다.
이 API 는 규칙+NER 가명화를 거치지만 외부 AI 를 부르지 않는다. 합성 대화 100줄(이름·전화·주소·이메일·계좌 포함)을 요청마다 가명화한다.
NER 설정은 스레드 2, 동시 추론 2(서비스 기본값)다. 단계마다 서로 다른 사용자가 10번씩 연속 요청했다(사용자당 분당 20회 제한 때문에 단계 사이에 62초 쉼). 결과 원본은 `eval/results/load_preview_*.json`.

| 조건 | 동시 접속 | 처리량(req/s) | P50 | P95 | P99 | 메모리 최고 |
|---|---:|---:|---:|---:|---:|---:|

### 기사체 — AI-Hub 쪽에서만 늘어난 부분

기사체 오류 11건(AIHub10%) 중 6건(완전미탐)이 두 틀에 몰려 있다:

- `목격자 {N}(37)씨는 "놀랐다"고 전했다` — AIHub10%는 이 틀에서만 3건을 완전히 놓쳤다(예: "목격자 오소훈(37)씨는…" → 예측 없음). KLUE10%는 이 틀에서 전부 맞혔다.
- `{N} 대표가 사업 계획을 공개했다` / `{N} 의원이 개정안을 제출했다` — AIHub10%는 "유영건 대표가"를 ORGANIZATION으로, "배기형 의원이"를 완전미탐으로, "배채건 의원이"를 경계오류("배채"만)로 놓쳤다. KLUE10%는 이 두 틀에서 전부 맞혔다.
- 반대로 두 모델이 **똑같이** 틀린 것도 있다: `검찰은 {N|를/를} 참고인으로 소환했다`(둘 다 "성병소"를 ORGANIZATION으로), `{N} 연구원이 논문을 공개했다`(둘 다 "주경은"을 "주경"까지만). 이건 AI-Hub 교체와 무관한, 두 모델이 같이 가진 약점이다.

**해석**: "괄호 안 나이·따옴표 인용"과 "직함+이/가"가 바로 붙는 문장은 가족 대화체 학습 데이터(`ml/ner/data/synth.py`, 전부 구어체)에도 없고, AI Hub 말뭉치에도 PERSON 태그가 없어(8절) 합성 데이터에만 의존한다. KLUE-NER(뉴스 말뭉치)를 섞은 KLUE10%는 이런 격식체 문장을 일부 봤을 가능성이 있고, AI Hub 로 바꾼 모델은 이 격식체 "이름+직함" 조합을 학습 중에 거의 못 봐서 완전미탐·ORGANIZATION 오분류로 이어진 것으로 보인다(확정은 아니다 — KLUE-NER 학습 문장 중 정확히 이 틀과 겹치는 게 있는지는 보지 않았다). "참고인"·"연구원이"처럼 두 모델이 같이 틀리는 틀은 데이터 교체와 무관한 별도 약점이라 3단계(재학습)에서 데이터를 어느 쪽으로 보강해도 안 고쳐질 수 있다.
